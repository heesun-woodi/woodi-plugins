# 퍼널 검증 가이드 — STEP 1·2에서 읽는다

> STEP 1(공통 퍼널)과 STEP 2(축 퍼널)에서 숫자를 받기 전에 읽는다.  
> 숫자를 내기 전에 분모를 확인하고, 받은 다음에 세 가지를 검산한다.

---

## 1. 분모 게이트 — 퍼널 표를 내기 전에 반드시 한다

퍼널 표를 요청하기 전에 분모를 1문장으로 확정한다.

> "이 전환율의 분모와 분자를 정확히 말해줘."

분모가 다르면 이후 Gap·Uplift·계약수 증분이 전부 무효다. 표를 먼저 받고 나서 분모를 묻는 것은 순서가 틀렸다.

| ❌ 틀린 순서 | ✅ 맞는 순서 |
|---|---|
| 퍼널 표 요청 → 숫자 받음 → "분모가 뭐예요?" | "분모가 정확히 누구예요?" → 확인 → 퍼널 표 요청 |

P3(축 핵심 KPI 합의)의 `정의 (분자 / 분모)` 열은 이 단계에서 채운다. 분모가 1문장으로 특정되지 않으면 STEP 2를 진행하지 않는다.

---

## 2. 숫자를 믿기 전 확인 3가지

숫자가 나왔을 때 바로 시트에 적지 않는다. 아래 세 가지를 먼저 확인한다.

### ① 분모를 되묻는다

```
이 전환율의 분모와 분자를 정확히 말해줘.
```

전환율 이름이 같아도 분모가 다르면 완전히 다른 숫자다. 특히 "설치→상담 전환율"처럼 워크숍 전에 이미 쓰던 지표는 분모를 다시 확인한다.

### ② 합계를 검산한다

코호트별로 쪼갠 숫자의 합이 전체 숫자와 대략 맞는지 확인한다. 크게 어긋나면 중복 집계 또는 필터 누락이다.

```
각 코호트의 도달 수를 더하면 전체 도달 수와 맞아야 해. 합계를 한 번 보여줘.
```

### ③ 전환율 100% 초과 = 즉시 멈춤

100%를 넘는 전환율은 데이터가 아니라 신호다. **모집단 혼입**을 의심한다.

> **이 고객사의 실전례**: 주간 퍼널 시트에서 '설치→상담 전환율'이 31주 중 6주간 100%를 초과했다(최대 114%). 원인은 신규 유입과 CRM 리터치 재오픈이 같은 분모에 섞인 것이었다. 상담 DB의 약 40%는 신규 유입, 나머지 약 60%는 기존 유저 CRM 재오픈이었다.

**재계산 방법**: 신규 코호트와 기존 유저 재오픈을 분리해 각각 집계한다.

```
신규 코호트(기간 내 첫 세션 발생) 기준으로만 이 전환율을 다시 계산해줘.
기존 유저 재진입은 분자에서 빼줘.
```

신규 코호트 기준으로 재계산해도 100%를 넘으면 코호트 정의가 틀린 것이다. 다시 잡는다.

## 3. 이벤트를 못 찾을 때

클로드가 여정 단계에 해당하는 이벤트를 못 찾으면 아래 순서로 재프롬프트한다.

**① 키워드 탐색**

```
이벤트명에 '상담' 또는 'consult'가 포함된 이벤트를 전부 나열해줘.
```

한국어 단계명("상담방 오픈")으로 찾으면 실패한다. 영어 키워드 또는 한국어 키워드 둘 다 시도한다.

**② 이벤트 정의 되묻기**

후보가 보이면 그 이벤트가 정말 그 단계인지 확인한다.

```
이 이벤트는 어떤 상황에서 발생하나? 언제 찍히는 이벤트인지 설명해줘.
```

발생 볼륨이 앞 단계보다 크면 매핑이 틀렸거나 모집단이 다른 것이다.

**③ 후보가 없으면 계측 공백으로 기록한다**

| ❌ 하지 않는다 | ✅ 한다 |
|---|---|
| "비슷한 이벤트로 대체해줘" | P2 이벤트명 칸을 공란으로 두고 메모에 `계측 공백`을 기록한다 |

계측 공백 자체가 워크숍 산출물이다. 없는 데이터를 있는 것처럼 대체하지 않는다.

---

## 4. 완전주 원칙

퍼널 집계는 **최근 4주 완전주**를 사용한다. 부분주는 제외한다.

- 완전주: 월요일 시작 ~ 일요일 끝이 모두 포함된 주
- 부분주: 집계 기간의 첫 주 또는 마지막 주가 잘린 경우

```
최근 4주 완전주 기준으로 집계해줘. 부분주는 포함하지 마.
```

데이터가 오래된 경우(앰플리튜드 최신 날짜가 몇 달 전) 가용한 최신 완전주 구간을 명시하고 진행한다. 집계 기간은 퍼널 표 상단에 반드시 고정 표기한다.

---

## 5. 숨은 단계 발굴 — 축 퍼널을 잘게 쪼개는 이유

공통 퍼널 5단계를 그대로 축 퍼널로 쓰면 누수 위치를 특정할 수 없다. 축 퍼널은 **공통 퍼널의 축 구간을 더 잘게 쪼갠 것**이다. 공통 5단계면 축은 8단계쯤이 정상이다.

쪼갤 때 던지는 질문:

> "두 단계 사이에 화면이나 행동이 하나 더 있지 않나요?"

예시:
- 공통: `점검신청 진입 → 상담방 오픈`
- 축: `점검신청 진입 → 폼 작성 시작 → 폼 작성 완료 → 점검신청 제출 → 상담방 오픈`

잘게 쪼갤수록 어느 구간에서 누수가 집중되는지 특정된다. 이것이 STEP 4 Gap 분석의 전제다.

단계 수가 3개 이하로 나왔다면 아직 덜 쪼갠 것이다.

```
이 구간을 화면 단위·폼 항목 단위까지 더 쪼갤 수 있는 이벤트가 있는지 찾아줘.
```
