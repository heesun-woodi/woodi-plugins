# 근거 검토 (팩트체크)

## 왜 이 스킬이 있나

학원 블로그 글의 수치·일정·법령이 틀리면 수강생이 잘못 준비하고, 학원 신뢰가 깎인다. 이 스킬은 초안의 사실 주장을 **실제로 열어 본 출처**와 한 줄씩 대조해
`factcheck.md` 리포트 하나를 쓴다. 고치는 일은 writer가 B'에서 한다 — 검토자는 판정과 수정 제안만 남긴다(자기 승인 금지 구조).

- 수행 주체: `blog-fact-checker` 에이전트(`/clark-blog:blog-run` C 단계). 메인이 직접 돌려도 절차는 같다.
- 전제: cwd = 작업 폴더. 지식 파일은 cwd의 `knowledge/`에서만 읽는다(`law-sources.md`가 조회처·접근성의 정본).
- 입력: 초안 파일(`work/posts/NNN-slug/draft.md` 또는 `draft-v2.md`), 같은 폴더의 `research.md`(있으면), `knowledge/law-sources.md`, `knowledge/academy-profile.md`.
- 산출물: 같은 폴더의 `factcheck.md` **하나만**. 재검토(r2)면 기존 `factcheck.md`를 덮어쓰지 말고 `factcheck-r2.md`로 쓴다(발주 프롬프트가 파일명을 주면 그것을 따른다).
- 유형별 조회처·명령·요령: `references/claim-types.md`.

## 판정 4종 (정의 고정)

| 판정 | 언제 | 필수로 적을 것 |
|---|---|---|
| **PASS** | 이번 검토에서 **실제로 열어 본** 출처의 문구가 초안 문장과 일치한다. 시점이 바뀌는 값(수수료·합격률·일정)은 초안에 기준 시점("2026년 기준" 등)이 적혀 있을 때만 PASS | 근거 원문 1~2줄 인용 + URL(법령은 조문 번호·시행일자) |
| **FAIL** | 출처 문구와 초안 문장이 다르다(숫자·조건·대상·기관이 틀림, 단정이 과함) | 근거 인용 + URL + **수정 제안(바꿀 문장)** — 없으면 FAIL로 쓰지 않는다 |
| **출처필요** | 확인할 출처를 찾지 못했다, 또는 찾은 출처에 해당 내용이 없다 | 어디를 봤는지(URL) + 제안: 문장 삭제 또는 "확인 필요"·"큐넷/고용24에서 최신 내용 확인" 문구로 바꾸기 |
| **시점확인** | ① 연·월이 든 일정·금액·합격률이 출처와 맞지만 초안에 기준 시점 표기가 없다, 또는 ② 출처 사이트가 껍데기·차단이라 내용을 열지 못했다 | 조회 일시 + URL + 제안: "(YYYY년 M월 큐넷 기준)" 표기 추가. ②면 "이랑 확인"을 붙인다 |

**지어내기 금지 규칙(가장 중요)**: 출처 페이지를 이번 검토에서 실제로 열어 해당 문구를 확인하지 못했으면 **PASS를 주지 않는다**. 기억·상식·writer가 적은 출처 요약은 근거가 아니다.
페이지가 껍데기(JS가 채우는 빈 틀)·차단·타임아웃이면 PASS 금지 → 시점확인 + "이랑 확인". 근거 인용 칸은 출처 원문을 그대로 옮긴 1~2줄이어야 하고, 의역·요약을 인용처럼 쓰지 않는다.

## 0. 전제 확인

```bash
ls knowledge/law-sources.md knowledge/academy-profile.md
ls work/posts/<NNN-slug>/
```

`knowledge/`가 없으면 "작업 폴더가 아닙니다. 먼저 `/clark-blog:blog-setup`을 실행하세요."라고 반환하고 중단한다.
초안 파일이 없으면 `## 질문`에 "초안 파일 경로 확인 필요"를 적어 반환한다. `law-sources.md`의 **접근성 기록**을 먼저 읽어 어느 출처가 본문 가능/껍데기/차단인지 파악해 둔다.

## 1. 주장 추출

초안에서 검증 대상 문장을 **빠짐없이** 뽑아 id를 붙인다(C1, C2 …, 초안 등장 순).

- 반드시 포함: 숫자(톤수·시간·금액·합격률·기간·나이), 날짜·회차, 법령명·조문, 기관명(큐넷·한국산업인력공단·고용24·시청/구청 등), 자격·면허 이름,
  "반드시/무조건/누구나/없다/불가능/유일/100%" 류 단정문, 학원 정보(주소·전화·과정·지원 형태·강점).
- 제외: 감상·의견("처음엔 다들 긴장합니다")과 일반 상식 수준의 조작 요령. 애매하면 넣는다.
- 주장 유형(하나만 고른다): `시험일정` / `접수` / `수수료` / `응시자격` / `면허종류·톤수` / `갱신·안전교육` / `국비·내일배움카드` / `법령조항` / `학원정보` / `기타수치`.
- 한 문장에 주장이 둘 이상이면 C3a·C3b처럼 나눈다. 초안 문장은 **원문 그대로** 옮긴다(맞춤법도 고치지 않는다).
- `research.md`가 있으면 거기 적힌 출처 URL을 먼저 다시 열어 확인한다 — writer가 적은 출처도 검증 대상이다. 링크가 죽었거나 내용이 다르면 그 출처에 기댄 주장은 근거 없음으로 본다.

## 2. 유형별 조회

`references/claim-types.md`의 매핑표·명령을 따른다. 요약:

| 주장 유형 | 1차 조회 |
|---|---|
| 법령조항·응시자격·면허종류·톤수·갱신·안전교육 | law.go.kr DRF: `lawSearch.do`로 현행 MST 확인 → `lawService.do?MST=…`(XML)에서 해당 조문·별표 인용 |
| 수수료·합격률·출제기준 | 큐넷 종목 7875 탭 조각: `crf00503s02`(일정·수수료), `crf00503s01`(검정현황) |
| 시험일정·접수 | 큐넷 월간 일정 `crf021.do?id=crf02103…` (종목 탭은 정기 일정이 비어 있음 → 단정 금지) |
| 국비·내일배움카드 | 고용24·한국산업인력공단 — 제도 상세가 curl로 안 보이면 시점확인 + "이랑 확인" |
| 학원정보 | `knowledge/academy-profile.md` 대조 |
| 기관 공지 | 해당 기관 사이트(`law-sources.md` 접근성 기록의 우회 URL 사용) |

- 조회 명령: `curl -sL -A "Mozilla/5.0" --max-time 20 "<URL>"` (Bash) 또는 WebFetch. WebFetch가 실패하면 curl로 한 번 더 시도한다. 요청 사이 0.5초 이상 간격, 순차 실행.
- 큰 응답(법령 XML 등)은 **작업 폴더 밖 임시 디렉터리**(`T=$(mktemp -d)`)에 저장해 grep한다. 작업 폴더에는 `factcheck.md` 외 아무것도 남기지 않는다.
- `korean-law` MCP(`search_law`/`get_law_text`)가 이 세션의 도구 목록에 있으면 법령 조회에 우선 쓰고, 없으면 DRF를 쓴다. 어느 쪽이든 인용에는 조문 번호와 시행일자를 적는다.
- 각 출처마다 접근 결과(본문 가능/껍데기/차단/타임아웃 + 바이트 수)를 기록해 머리말에 쓴다.

## 3. 판정

위 "판정 4종" 정의대로 각 주장에 하나씩 준다. 추가 규칙:

- 학원정보: `academy-profile.md`와 일치하면 PASS(근거 = 해당 행 인용 + `knowledge/academy-profile.md`). 다르면 FAIL. 프로필에 없는 학원 주장(장비 대수·합격률·수상 등)은 출처필요.
- 학원이 시험 장소라는 사실·암시(금칙어 목록 포함)는 사실 여부와 무관하게 **FAIL**(계약 조항) — 수정 제안은 해당 문장 삭제 또는 "실기 위주 교육"류 표현으로 교체.
- 단정문("무조건 합격", "누구나 가능")은 출처 조건(나이·결격사유·면허 요건 등)이 붙어 있으면 FAIL로 보고 조건을 붙인 문장을 제안한다.
- 법령 인용은 `lawSearch`의 **현행** 판본 기준. `LM=` 호출은 공포만 되고 아직 시행 전인 판본을 돌려줄 수 있으니 `<시행일자>`가 오늘 이후면 현행 MST로 다시 조회한다(`claim-types.md` 참고).

## 4. `factcheck.md` 작성

형식(이 순서·제목 그대로 — blog-run과 writer가 기계적으로 읽는다):

```markdown
# 팩트체크 — <글 폴더명>

- 검토 일시: 2026-10-06 14:20 (KST)
- 초안 파일: work/posts/001-.../draft.md
- 검토자: blog-fact-checker (r1)
- 조회처 접근 결과:
  - law.go.kr DRF lawSearch/lawService: 본문 가능 (건설기계관리법 MST 283763 시행 2026-08-28, 시행규칙 MST 285023 시행 2026-03-24)
  - 큐넷 crf00503s02 (jmCd=7875): 본문 가능 (5,389바이트)
  - 고용24 훈련과정: 껍데기 → 국비 주장 이랑 확인

| id | 주장 유형 | 초안 문장(원문 그대로) | 판정 | 근거 인용(원문 1~2줄) + URL | 수정 제안 |
|---|---|---|---|---|---|
| C1 | 면허종류·톤수 | … | PASS | "3. 3톤 미만의 지게차" — 건설기계관리법 시행규칙 제73조제2항(시행 2026-03-24) https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&MST=285023&type=XML | — |
| C2 | 수수료 | … | 시점확인 | "필기 실기 14,500원 25,200원" — https://www.q-net.or.kr/crf005.do?id=crf00503s02&gSite=Q&gId=&jmCd=7875 (2026-10-06 조회) | 문장 끝에 "(2026년 10월 큐넷 기준)" 추가 |
| … (C3~C9 생략 — 실제 리포트는 모든 행을 적는다) | | | | | |

요약: PASS 5 | FAIL 1 | 출처필요 1 | 시점확인 2

## B'에서 반영할 것
1. C4 (FAIL) — "<초안 문장>" → "<수정 제안 문장>" (근거: …)
2. C7 (출처필요) — "<초안 문장>" → 삭제 또는 "<확인 필요 문구>"

## 시점 표기 권고
- C2 — "(2026년 10월 큐넷 기준)" 추가

## 질문
- (이랑에게) 고용24에서 이 과정의 자부담 비율을 확인해 주실 수 있을까요? — C9 관련
```

- **요약 줄은 정확히 이 형식 한 줄**: `요약: PASS <n> | FAIL <n> | 출처필요 <n> | 시점확인 <n>` (blog-run이 이 줄을 읽어 FAIL+출처필요 합계로 B' 범위를 정한다). 합계 = 표의 행 수.
- `## B'에서 반영할 것`: FAIL·출처필요 항목만 id 순서로 번호를 매긴다. 0건이면 제목 아래에 `없음` 한 줄.
- `## 시점 표기 권고`: 시점확인 항목. 0건이면 `없음`. (B' 생략 판단에는 쓰지 않는다 — writer가 B'에서 SEO 작업 때 함께 반영.)
- `## 질문`: 메인/이랑이 답해야 진행되는 것만. 없으면 절 자체를 생략.
- 표 칸 안의 `|`는 `\|`로 이스케이프한다. 출처 URL은 전체 주소로 쓴다(단축 금지).

## 5. 금지

- 초안 파일(`draft.md`·`draft-v2.md`·`final.md`)과 `research.md`, `knowledge/`는 **절대 수정하지 않는다**. 쓰는 파일은 `factcheck.md`(또는 지정된 r2 파일) 하나.
- 사용자에게 직접 묻지 않는다 — 막히면 `## 질문` 절에 적어 반환한다. 서브에이전트를 발주하지 않는다.
- 출처 없는 PASS, 출처 문구를 지어낸 인용, 열지 않은 URL을 근거로 적는 것 금지.

## blog-run(메인)에 주는 규칙

- `요약:` 줄의 FAIL + 출처필요 = 0 → B'의 팩트 반영 생략 가능: 메인이 `draft.md`를 `draft-v2.md`로 복사하고 B'는 SEO·관련글 링크 치환(+시점 표기 권고)만 수행.
- FAIL + 출처필요 ≥ 1 → B'에서 `## B'에서 반영할 것`을 전부 반영. 게이트 2 이후 사실 문장이 바뀌면 C를 r2로 재발주한다.
- `## 질문`이 있으면 메인이 이랑에게 묻고 답을 `gates.md`에 기록한 뒤 진행한다.
