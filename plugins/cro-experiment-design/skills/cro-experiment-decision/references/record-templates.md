## D6b — repo EXP 파일 블록 (4백틱 코드블록 1개)

**이 스킬에서 코드블록은 이것 하나뿐이다.** 세 자리에 붙을 내용을 하나의 4백틱 펜스에 담고, 자리마다 주석 줄로 구분한다. 🚫 펜스 종류를 바꾸지 않는다 — 내용에 3백틱이 들어갈 수 있다.

**상단 1줄(고정)**

> 붙이는 자리 — {EXP 파일 경로}의 `## 2` · `## 3` · `## 4`. 아래 블록을 자리별로 나눠 붙여넣고, commit은 직접 해 주세요.

````markdown
<!-- ## 2. 실행 기록 — 아래 1~3줄을 기존 불릿 끝에 붙입니다 -->
- 종료 판정 — {판정} · 흐름도 경로 {밟은 경로} · 판정일 {YYYY-MM-DD}
- 연장 — 1회 · {이전 종료일} → {새 종료일} · 연장 결정일 {YYYY-MM-DD}
- variant 축소 — {variant} · 축소 시점 {YYYY-MM-DD} · 사유 {누적 {값}/필요 {값} · 대조군 대비 stat-sig {값}% 열세 · 팀 합의} · 남은 군 판정은 축소 시점 이후 데이터로 재집계 `코치 확인 필요`

<!-- ## 3. 결과 — 표를 채우고 아래 불릿을 잇습니다 -->
| 층 | 지표 | 대조군 | 실험군 | 차이 | 비고 |
|---|---|---|---|---|---|
| **Primary** | {지표명} | {전환율} ({전환}/{노출}) | {전환율} ({전환}/{노출}) | 절대 {값}%p | |
| Secondary | {지표명} | | | | |
| Guardrail | {지표명} | | | | 허용 {기준} |

- **판정**: {판정} — 근거: 흐름도 경로 {밟은 경로}
- 표본·기간: {실제 확보 표본} / {런칭일} ~ {종료일}
- **예상 대비**: 설계 예상 {값}%p · 실측 {값}%p

<!-- ## 4. 학습 — 이 줄 하나만 채웁니다 -->
- 배운 것: ⚠️SP3
- 가설 검증 여부: ⚠️SP3
- 다음 액션: {So Next} — {한 줄 사유}
- 후속 반영: ⚠️SP3
````

**하드 규칙**

- **`연장` 줄은 결정이 `연장`일 때만 낸다.** 종료·지속이면 그 줄을 빼고 낸다.
- **`variant 축소` 줄은 D4b 6열이 `축소`일 때만 낸다.** 3조건이 전부 `예`가 아니면 이 줄을 내지 않는다 — 조건 미충족 축소는 「실험 설계 잘못됨」이다. **DEC-021 결정 2-b 조건 ③(축소 시점·사유 기록)이 착지하는 자리가 여기다.**
- **`예상 대비`는 숫자만 적는다** — 「그 차이가 말해주는 것」은 `⚠️SP3`다.
- **`## 4`에서 채우는 것은 `- 다음 액션:` 한 줄뿐이다** — 나머지 셋은 `⚠️SP3`로 자리만 남긴다.
- 🚫 **`## 1. 설계`를 건드리지 않는다** — ed 소관이다.
- 🚫 **머리말 `status` 값을 블록 안에서 바꾸지 않는다** — 상태 변경은 D6c의 **안내**다.
- 템플릿의 `저모수 대체 판정` · `비고` 줄은 건드리지 않는다 — 있으면 그대로 두고, 없으면 만들지 않는다.
- `## 3` 결과 표의 열은 템플릿 그대로 여섯이다 — `층` · `지표` · `대조군` · `실험군` · `차이` · `비고`. 늘리거나 줄이지 않는다.

## D6c — 상태 변경 안내 표

**안내 표다 — 🚫 스킬이 바꾸지 않는다.**

| 대상 | 현재값 | 변경값 | 누가 |
|---|---|---|---|
| EXP 파일 머리말 `status` | {running / 확인 불가} | {final — 결정이 `종료`일 때 / running 유지 — `연장`·`지속`일 때} | 담당자 |
| 노션 가설 DB `진행상태` | {실험 진행중 / 확인 불가} | {실험 종료 / 사람이 select 값을 추가해야 함} | 담당자 |
| 실험 대장 `README.md` 해당 행 | {진행 중 / 확인 불가} | {분석 완료} | 코치 |
| 노션 실험설계서 3장 `종료 예정일` | {이전 종료일 / 확인 불가} | {새 종료일 — 연장일 때만 / 변경 없음} | 담당자 |

**비고 1줄(고정)**

> EXP `## 4`의 나머지(배운 것·가설 검증 여부·후속 반영)는 SP3 결과 보고서에서 채웁니다 — `status: final`은 「분석 완료」가 아니라 「이 실험은 끝났다」는 표시로 씁니다.

**하드 규칙**

- 결정이 `연장`이면 1행은 `running` 유지이고 4행이 채워진다 — **두 행이 동시에 움직이는 일은 없다.**
- **`확인 불가`인 현재값으로 변경값을 제안하지 않는다** — 무엇에서 무엇으로 바꾸는지 모르면 안내가 아니다.
- 노션 select에 어휘가 없으면 **사람이 추가한다** — 🚫 스킬이 select 값을 추가하지 않는다.
