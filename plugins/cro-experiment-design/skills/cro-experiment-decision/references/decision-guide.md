# 종료 의사결정 규칙집 — 흐름도 · 게이트 · 연장 · So Next · 기록 위치

> **규칙만 적는다.** 왜 순차검정을 중간에 읽어도 되는지, 왜 피킹이 위양성을 올리는지 같은 이론은 여기에도 산출물에도 쓰지 않는다 (dc 계약 §5). 값이 어긋나면 `references/output-contract.md`가 이기고, 임계값은 `references/thresholds.md`가 이긴다.

## 1. 종료 흐름도 (em 계약 §7-11 문자 그대로 · 재정의 금지)

```
진행 → [모든 variant 누적 n ≥ 필요 n AND 최소 관찰 기간 AND 요일 주기 ≥1회]?
  아니오 → 지속 (헬스 모드, 예상 도달일만 보고)
  예 → [SRM 정상]?  아니오 → 「실험 설계 잘못됨」 종착 (리프트 불문, 결과 불사용)
     예 → [Primary stat-sig ≥ 95%]?
        예 · 실험군 > 대조군 · MDE 달성 · Guardrail 전부 허용 기준 안 → WIN 종료
        예 · 실험군 < 대조군                                          → LOSE 종료
        예 · 그 밖(MDE 미달 또는 Guardrail이 허용 기준을 벗어남)      → INCONCLUSIVE 종료
        아니오 → [stat-sig ≥ 80% AND 지속 시 결과가 변할 수 있고 자원 trade-off 수용]?
              예 → 지속 (연장, 종료일 재고정)   /   아니오 → INCONCLUSIVE 종료
```

- `INCONCLUSIVE`는 하나다 — 유의하지 않은 경우 · MDE 미달 · Guardrail이 허용 기준 밖이 **같은 종착**이고, 어느 경로로 왔는지는 D3 `밟은 경로`에 남는다.
- **판정 근거는 Primary 하나다.** Secondary의 유의성은 판정 조건이 아니고, Guardrail은 `WIN`을 **막을 수만** 있다.
- 별도 종착 「실험 설계 잘못됨」 트리거 6종 (em §7-11): SRM · Primary 이벤트 미수집 · variant jumping · 실험 중 배분 비율 변경 · 실험 중 variant 추가/제거 · 실험 중 sticky bucketing 변경. **이 중 「variant 제거」만 §5의 예외를 받는다.**

## 2. 종료 4게이트 (전부 충족해야 판정으로 내려간다)

| # | 게이트 | 판정 기준 | 미충족이면 |
|---|---|---|---|
| 1 | variant별 필요 n | **가장 작은 군** 누적 ≥ 설계서 `variant별 필요 n`. 합계로 선언하지 않는다 | `지속` — 대사 정본 ⑦ |
| 2 | 최소 관찰 기간 | 런칭일 + 설계서 `최소 관찰 기간` ≤ 기준일 | `지속` |
| 3 | 요일 주기 | 관찰 구간에 요일 1주기 이상 포함 | `지속` |
| 4 | SRM 정상 | 카이제곱 p가 임계값 ① 밖 (🚫 비율 차이로 판단하지 않는다) | 경보면 **「실험 설계 잘못됨」 · 결과 불사용** |

- 게이트 1~3 미달 상태에서 `종료` 결정을 받지 않는다 — 방법론 출처 `cro-methodology-kb/08_monitoring-stopping.md` 종료 4게이트, 코치 룰은 DEC-021 결정 2-a.
- 게이트 4는 다른 행을 채우기 **전에** 판정을 닫는다 (dc §7-3).

## 3. 조기 종료 — 허용 3 · 금지 3

| | 사유 | 근거 |
|---|---|---|
| **허용** | 데이터가 오염되고 있다 (SRM 경보 · Primary 이벤트 미수집) | dc §7-3 · 판정은 「실험 설계 잘못됨」 |
| **허용** | Guardrail이 설계서의 중단선에 닿았다 | 설계서 E7 `조기 종료 조건(숫자)` |
| **허용** | 설계서에 **미리 숫자로 적어 둔** 조기 종료 조건에 닿았다 | ed E7 · 시작 뒤에 만든 조건은 조건이 아니다 |
| **금지** | 이기고 있어서 지금 끝내고 싶다 | 결과를 본 뒤 종료 시점을 옮기는 것은 판정 조작 |
| **금지** | 지고 있어서 표본이 아깝다 | 「지는 것도 통계적 유의성을 확보하고 져야 한다」 (2026-09-11 회의록 `[01:01:27]`) |
| **금지** | 릴리즈·일정이 급하다 | 일정은 종료 기준이 아니다 — 연장·지속 결정으로 다룬다 |

- 샘플 게이트 미달 상태의 **예외는 위 「허용」 중 둘뿐이다** — 설계서 조기 종료 조건 도달 / 「실험 설계 잘못됨」 트리거 (dc §7-2 · DEC-021 결정 2-a). 세 번째 예외를 세션에서 만들지 않는다.
- 「필요 n을 낮춰서 도달시키자」는 설계값 수정이다 — `cro-experiment-design` STEP 4로 라우팅한다.

## 4. 연장 규칙 (임계값 ③)

- **연장은 1회뿐이고, 연장하면 새 종료일을 그 자리에서 못박는다.** 무기한 연장은 없다.
- **두 번째 연장 요청은 차단한다** — D0 `연장 이력`이 `1회`면 `연장` 선택지를 **제거**하고 재설계(`cro-experiment-design`)로 라우팅한다. 두 번 밀린 실험은 기간 문제가 아니라 설계 문제다.
- **연장 결정은 두 질문을 같이 묻는다** (대사 정본 ⑧): ① 지금 추세가 이어질 때 **결과가 바뀔 여지가 있는가** ② **종료일 지연과 지면 점유를 수용할 수 있는가**. 둘 다 「예」일 때만 연장이고, 하나라도 「아니오」면 종료다.
- **연장 종료일 제안 = `max(예상 도달일, 최소 관찰 종료일)`** — `scripts/reach_estimate.py`가 계산한다. 더 짧게 잡으면 같은 자리에서 또 미달이다.
- **`--project`(도달 시점 예상 stat-sig)는 샘플 게이트 도달 후에만 돌린다.** 잔여 n·예상 도달일은 도달 전에도 낸다 — 표본 진행 상황이지 승패가 아니다.
- α와 종료 시점을 결과를 본 뒤 옮기지 않는다.

**진 실험의 연장 기준 (DEC-023)** — 방향이 열세일 때는 위의 두 질문 대신 **「힌트」**를 묻는다 (대사 정본 ⑫).

- **유일한 연장 사유는 「더 돌리면 왜 졌는지의 힌트를 더 얻을 수 있다」다.** 「유의하게 지는 것을 확인하기 위해」는 연장 사유가 아니다 — 유의성을 채우려고 기간을 늘리지 않는다.
- **힌트는 Secondary·Guardrail에서 얻는다.** 이미 보이면 접고, 아무리 봐도 모르겠고 더 돌려도 모를 것 같으면 접고 다른 데서 찾는다.
- 🚫 **「좀 더 높다」는 근거가 아니다** — 보조 지표를 주장에 쓰려면 유의성을 계산해야 힘이 생긴다.

## 5. variant 축소 3조건 (임계값 ⑦ · 3군 이상에서만)

| # | 조건 | 확인 자리 |
|---|---|---|
| ① | 해당 군 누적 노출 **≥ 필요 n의 50%** | D4b 2열 |
| ② | 대조군 대비 **stat-sig ≥ 95% 열세** | D4b 3열 |
| ③ | **팀 합의** — 구조상 그 군만 내릴 수 있고 개발에서 확인됐다 | D4b 4열 · 대사 정본 ⑨ |

- **하나라도 못 채우면 축소하지 않는다.** 채우지 않고 내리면 그 실험은 em §7-11 트리거 #6에 걸려 「실험 설계 잘못됨」이고 결과는 불사용이다.
- **축소 시점을 기록에 남기고, 남은 군의 판정은 축소 시점 이후 데이터로 재집계한다** — 축소 전후를 이어 붙이지 않는다. 재집계 기준은 `코치 확인 필요` (DEC-021 미결 4).
- **2군 실험에는 적용되지 않는다** — 2군에서 한 군을 내리는 것은 축소가 아니라 종료다.
- 축소는 **결정**이다 — D4b 6열은 항상 빈칸으로 나가고 사람이 `축소`/`유지`로 답한다.

## 6. So Next 진입 조건표 (`cro-methodology-kb/10_decision-learning.md` Step 2 전사)

| So Next | 진입 조건 | 대응 판정 | 이어지는 실행 |
|---|---|---|---|
| **전면 반영** (KB10 `Rollout`) | Primary 개선 + Guardrail 문제 없음 + 비즈니스 해석 가능 | **`WIN` 전용** | 타겟·솔루션 그대로 점진 롤아웃 · 반영 후 모니터링 |
| **수정 후 재실험** (KB10 `Iterate` / `Retest`) | 신호는 있으나 구현·세그먼트·지표 보완 필요 → `(설계 수정)` · 또는 데이터·구현·트래픽 문제로 판단 불가 → `(동일 설계·구현 수정)`, 이전 데이터는 폐기 | `INCONCLUSIVE` · `실험 설계 잘못됨` | 보완 지점 명시 → 후속 설계서(ed) → ICE 재평가 |
| **폐기** (KB10 `Stop`) | 개선 신호 없음 또는 Guardrail 악화 | `LOSE` · stat-sig가 낮은 `INCONCLUSIVE` | 해당 문제영역의 다음 솔루션 후보 재검토 (hb·hg) |
| **연장** | D4a `결정`이 `연장`일 때만 — 판정이 `지속`이고 §4의 두 질문에 둘 다 「예」 | `지속` | 새 종료일 못박기 · 노션 3장 종료 예정일 갱신 |

**배포 반영 판단 (DEC-023 · dc §7-10)** — **실험의 승자 판정과 운영 반영은 다른 결정이다.**

- 승자는 **Primary 하나**로 정하고, 반영 가능 여부는 **「Primary 승 AND Guardrail·Secondary 불하락」**이다.
- **설계서의 자체 가드레일 허용 범위가 「불하락」을 대체하지 않는다** — 허용값은 조기 종료 판단용이지 반영 판단용이 아니다.
- **하락은 점추정 방향으로 본다**(임계값 ⑩ · `코치 확인 필요`). 유의하지 않다고 하락을 지우지 않는다.
- **Primary에서 진 군도 Guardrail 유의 승이면 `반영 후보`다** — 그 군을 반영할지, 그 군을 대조군으로 둔 후속 실험으로 갈지는 사람이 정한다.
- `전면 반영`의 자격은 그대로 **`WIN` 전용**이다 — `WIN`인데 반영 못 하는 경우가 생길 뿐이다.

- **`전면 반영`은 `WIN` 전용이다.** 「95%는 못 넘겼지만 방향이 좋으니 반영하자」는 `INCONCLUSIVE`의 처리이며 여기로 넘어가지 않는다.
- **`INCONCLUSIVE`가 두 갈래로 갈리는 기준은 「신호가 있는가」다** — MDE 미달·Guardrail 밖이면 `수정 후 재실험`, stat-sig 자체가 낮으면 `폐기`. **스킬이 단정하지 않고 둘 다 `충족`으로 두고 사람에게 묻는다.**
- **「실험 설계 잘못됨」으로 종료하면 `전면 반영`은 불가능하다** — 결과를 쓰는 것이기 때문이다.
- 원어(`Rollout`·`Iterate`·`Stop`·`Retest`)는 이 표의 인용 괄호 안에서만 쓴다.
- 실패 레벨 3진단(가설 / 솔루션 / 실행)과 학습 로그 등록은 **여기서 하지 않는다** — `⚠️SP3`.
