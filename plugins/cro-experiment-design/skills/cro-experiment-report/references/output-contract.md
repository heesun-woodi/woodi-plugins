## 0. 실험 결과 보고서의 정의

> **"실험 결과 분석의 핵심은 가설을 검증한 결과 + So Next 공유다."** (푸드케어 「캠페인 종료 의사결정 및 결과 분석」 2025-09-08)
> 보고서는 **새로 판정하는 자리가 아니라 이미 나온 판정을 설명하는 자리**다. 이 계약이 표 스키마로 강제하는 것이 그 순서다.

**결과 보고서는 세 층이다.** 이 셋을 섞으면 스킬이 판정을 다시 내리거나, 사람이 근거 없이 확정한다.

| 층 | 무엇인가 | 누가 하는가 | 이 계약의 자리 |
|---|---|---|---|
| **판정** | dc가 흐름도를 밟아 이미 낸 **값** — `WIN` / `LOSE` / `INCONCLUSIVE` / `지속` / `실험 설계 잘못됨` | **dc에서 승계** (이 스킬은 만들지 않는다) | S2b — 기록이 없거나 잠정이면 `잠정` 라벨 |
| **해석** | 그 값이 **왜 나왔고 무엇을 배웠는가** — 유형별 분석 · 세그먼트 힌트 · 후속 가설 초안 | **스킬이 초안을 만든다** (근거 태그 필수) | S3 · S4 · S5 · S6 |
| **확정** | 해석을 받아 **운영 반영·후속 실험을 고르는 것** | **사람** (참가자·코치) | S6a 4-3 — **dc 승계값이 없으면 빈칸** |

- **해석이 판정을 대신하지 않는다.** 숫자를 다시 계산해도 좋지만, 그 값으로 판정 어휘를 바꾸지 않는다 (§7-2).
- **판정이 없으면 보고서는 「중간 리포트」다.** 종료·결정이 확인되지 않으면 전 출력 상단에 **`중간 리포트 — 판정 잠정`** 라벨을 고정한다 (§7-1).
- **완벽한 보고서를 매번 만들려 하지 않는다.** 「아직 해석할 수 없다」는 것이 정상 산출물이며, 미확보 칸은 지우지 않고 `확인 불가` · `코치 확인 필요` · `표본 부족` · `⚠️확인필요`로 남긴다.

### 0-1. 실험설계 · 모니터링 · 종료 의사결정 · 결과 보고서의 경계

| | 실험설계 (ed) | 모니터링 (em) | 종료 의사결정 (dc) | **결과 보고서 (er — 이 계약)** |
|---|---|---|---|---|
| 시점 | 런칭 **전** | 런칭 **후** ~ 판정 가능까지 | **판정 가능 시점 ~ 종료 결정·기록** | **종료 후** — 미종료면 「중간 리포트」 라벨 |
| 목적 | 세팅 준비 — 「누가 봐도 같은 그림」 | 유효성 확인 — 「이 실험을 믿을 수 있는가」 | **끝내기 — 「끝내도 되는가, 끝냈다는 것을 어디에 남기는가」** | **학습 회수 — 「왜 그랬고 다음은 무엇인가」** |
| 숫자를 | **정한다** (필요 n · MDE · 종료 기준) | **읽는다** (설계값 전사 + 실측 조회) | **받는다** (em M4·M5b·M5c 또는 화면값을 그대로) | **해석한다** — 판정·결정은 dc 기록을 **승계**하고, 기록이 없거나 잠정이면 dc §7-1 흐름도를 **문자 그대로 참조해 경로 1줄만** 기록한 뒤 판정에 `잠정` 라벨을 붙인다 |
| Primary | 1개로 확정 | 유의성 판정의 유일한 근거 | **결정의 유일한 근거** — Secondary로 결정하지 않는다 | **verdict의 주어** — 유형 분류(S3)는 Primary 하나로만 한다 |
| 산출 | 노션 1-4·1-5·3장 + EXP `## 1` | **화면 리포트뿐 — 기록물 없음** | **결정 표 + 노션 4장 「결과」·「후속 액션」 블록 + EXP `## 2`·`## 3`·`## 4 다음 액션` 블록 + 상태 변경 안내** | **노션 4장 4-1·4-2·4-3 전문 블록 + EXP `## 3` 나머지(`저모수 대체 판정`·`예상 대비`) + `## 4` 나머지(`배운 것`·`가설 검증 여부`·`후속 반영`) 블록 + 로컬 초안 파일** |
| 어휘 | — | 판정 5 | 판정 5 + **결정 3** + **So Next 4** | **승계 + 근거 태그 4종(신설)** — EXP 템플릿의 `{승/패/무/판정 불가}`는 고치지 않고 dc 5어휘로 적는다 |
| 이 계약이 하는 것 | 결손 발견 → ed 라우팅 | 판정값을 입력으로 받음 | **전부** | **`⚠️SP3` 칸을 채운다** — 채우면 그 플래그는 사라진다 |
| 하지 않는 것 | | | why·배운 것(`⚠️SP3`) | **종료 결정·So Next 확정(dc 소관, 빈칸 승계) · 노션 쓰기 · 설계 재평가 · 판정 재정의** |

- **경계를 넘으면 거부한다.** 「이번엔 우리가 판정을 다시 내려 보자」는 이 스킬의 일이 아니다 — dc 기록을 승계하거나 `잠정`으로 남긴다 (§5 · §7-9).
- **er·dc·em은 같은 흐름도를 쓴다.** dc §7-1은 em §7-11의 문자 그대로이며, 이 계약도 **재정의를 금지한다.**
- **`⚠️SP3`의 소유가 이 계약으로 넘어온다.** dc v1.2 §5가 그 사실을 1줄로 적고 있으며, er가 그 칸을 채우면 플래그는 사라진다 (§5 · §7-8).

## 2. 입력 규격

### 2-1. 세션 단위 — 실험 1건

이 세션의 입력은 **실험 1건**이다. 여러 건을 요청받으면 1건씩 순서대로, 매 건 S0부터. 실험 1건 = 설계서 1장 = EXP 파일 1개 = 보고서 1개다.

- **보고서는 실험 단위이지 variant 단위가 아니다.** 다군 실험의 군별 결과는 한 보고서 안의 행이며, 군마다 보고서를 나누지 않는다.

### 2-2. 필수 입력 2종 + 보조 4종

| # | 입력 | 없을 때 |
|---|---|---|
| 1 | **노션 실험설계서 URL** (또는 본문 붙여넣기) | S1 진행 불가 → §10 종료 경로. 설계값 없이 해석하지 않는다 |
| 2 | **앰플리튜드 Experiment 설정 URL 또는 대시보드 URL** (또는 화면 값 붙여넣기) | S2a 전부 `확인 불가` → 해석 없이 S1·S1b까지만 |
| 3 | dc 기록 블록 (보조 — 노션 4장 「결과」·EXP `## 2` 종료 판정 절) | S2b `상태`가 `dc 기록 없음` → 판정 `잠정`, 결정·So Next 빈칸 (§7-2) |
| 4 | 재계산 구간 (보조 — 오염·합류 구간이 있을 때) | 오염이 있었는데 구간을 모르면 S2a 전체를 `⚠️확인필요`로 병기 |
| 5 | 정성 자료 (보조 — 인터뷰·병행 릴리즈 로그) | S5b `필요 여부`가 `필요 — 자료 없음`이 된다 |
| 6 | 코치 사전 조사 노트 (보조) | S4 `발견` 열이 실측·계산 근거만으로 채워진다 |

- **입력 3번이 이 계약의 갈림길이다** — dc 기록이 확정이면 승계하고, 잠정이면 병기하고, 없으면 `잠정`이다 (§7-2 S2b 상태 3값).
- **스킬이 URL을 만들지 않는다** — 노션·앰플리튜드·외부 유의성 계산기 모두 같다. 받은 URL만 쓰고, 열리지 않으면 열리지 않았다고 말한다 (§5 · §7-9).

### 2-3. 접근 경로 사다리 — em §2-3 승계 (인용)

> **em 계약 §2-3의 「읽기 예외」를 그대로 승계한다.** 노션·앰플리튜드를 **「읽는 데」** ① MCP ② claude-in-chrome(Chrome으로 URL 열어 읽기) ③ 붙여넣기 / 실쿼리 재구성 순으로 쓴다. **예외는 「읽기」에만 적용되며, 기입은 여전히 사람이 한다** (§4 · §7-9).

| 소스 | 1순위 | 2순위 | 3순위 | 실패 시 |
|---|---|---|---|---|
| **노션 설계서** | 노션 MCP fetch | Chrome으로 URL 열어 읽기 | 참가자 붙여넣기 | S1 진행 불가 → 종료 경로 |
| **앰플리튜드** | MCP 실험 분석 / 차트 / 대시보드 조회 | Chrome으로 화면 열어 값 읽기 | **화면에 없는 지표만** 퍼널 실쿼리 재구성 | `확인 불가` |

- ⚠️ **참가자 계정은 이 노션에 게스트로 초대된 상태여서 노션 MCP로 페이지를 읽을 수 없다** (2026-09-07 확인). **참가자 세션의 실질 1순위는 2순위·3순위 경로다** — 1순위를 시도해 실패를 확인하는 절차는 유지하되, **실패를 결함으로 취급하지 않는다.**
- **경로가 내려갈수록 `출처` 열이 길어진다** — 이것이 의도다. 어느 경로로 읽었는지가 해석의 신뢰도를 결정하므로, 출처가 비어 있으면 그 행은 `확인 불가`다.
- **담당자가 세팅한 화면이 실측 수의 정본이다** (em §0 승계). **판정에 쓰는 통계값의 정본은 dc §3-3의 계산 구현 우선순위 ⑨를 따른다** — 이 계약은 그 순위를 재정의하지 않는다 (§7-2).
- **앰플리튜드 도구명을 이 계약이 고정하지 않는다** — 조회 **목적**(「실험 분석 조회」 · 「차트 조회」 · 「대시보드 조회」 · 「퍼널 실쿼리」)만 서술하고, 실제 도구명은 세션에 노출된 것을 쓴다 (em·ed·dc 관례 승계).

**`출처` 열 고정 형식 — 8형식(em 6 + dc 7 + er 8).** em 6형식과 dc의 7번을 승계하고, **8번만 er 신설이다.**

| # | 경로 | 형식 |
|---|---|---|
| 1 | 노션 MCP | `노션 MCP {page-id 앞 8자} {조회일시}` |
| 2 | Chrome 읽기 | `Chrome 읽기 {경로 축약} {조회일시}` |
| 3 | 붙여넣기 | `붙여넣기 {일시}` |
| 4 | 앰플리튜드 대시보드 차트 | `Amplitude 대시보드 차트 「{차트 제목}」 {기간} {경로}` |
| 5 | 앰플리튜드 실쿼리 | `Amplitude 실쿼리 {이벤트A→B, 필터, 기간}` |
| 6 | 앰플리튜드 실험 분석 | `Amplitude 실험 분석 「{실험명}」 {기간} MCP 실험 조회` |
| 7 | 모니터링 리포트 | `모니터링 리포트 {일자}` |
| 8 | **repo 파일 (er 신설)** | `repo 파일 {SSOT 상대 경로} {절 제목} {읽은 일시}` |

- **화면 표시값을 인용할 때는 형식 6 뒤에 `— 표시값(순차검정)`을 붙인다** (dc 승계).
- **형식 8은 dc 기록·EXP 파일을 repo에서 읽었을 때 쓴다.**
- **dc 기록에서 승계한 값의 출처는 형식 1·2·3·8 중 dc 기록을 실제로 읽은 경로다** — 「dc가 그렇게 적었다」는 출처가 아니라 **그 기록을 어디서 읽었는가**가 출처다.

### 2-4. 프로젝트 제약

리스트·시트·노션에 근거 사용 금지 규칙이 명시돼 있으면 스킬 기본 절차보다 우선한다. S0에서 한 번 확인하고 전 단계에 적용한다. 금융·보험 도메인이므로 **원천 PII는 어떤 표에도, 어떤 블록에도 옮기지 않는다** — 위치만 말하고 `[마스킹]` (§7-9 · 게이트 **G5**). **세그먼트 분해에서도 같다** — 집계값만 옮기고 개별 행은 읽지 않는다. **세션 리플레이는 집계만 인용한다** (§7-6).

- **2·3행은 스킬이 채우지 않는다** (§0 · §7-9). dc 기록에 있으면 승계하고, 없으면 빈칸이다.
- **상태 ②·③이면 S6a 4-3의 「운영 반영」과 「실험 지속 여부」 둘 다 `잠정 — 종료 의사결정 확정 후 v{n+1}`이다** (§7-2).
- **계산값을 낼 때는 `statsig.py`를 경로로 호출한다** — `--treatment`를 실험군 수만큼, `--bonferroni {축소 후 비교 수 = 판정 군 수 − 1}`를 붙인다(em·ed와 같이 K = 비교 수; 대조군은 세지 않는다 — 판정 군 3이면 K=2, α=0.025). 🚫 **스크립트를 복사하지 않는다.**
- **계산기 값이 함께 제시되면 dc §3-3의 계산 구현 우선순위(임계값 ⑨)를 따라 병기한다** — 이 계약은 그 순위를 재정의하지 않는다.
- **`잠정` 라벨이 붙은 판정으로 So Next를 확정하지 않는다.**
- **dc 원문이 판정 5어휘(`WIN` / `LOSE` / `INCONCLUSIVE` / `지속` / `실험 설계 잘못됨`)로 적혀 있지 않으면**(예: 「승」·「미달」) **`판정` 값 셀에 원문을 인용하고 대응 어휘를 병기하며 `코치 확인 필요`를 붙인다** — 🚫 **대응은 스킬이 확정하지 않는다.**
- **dc 지시 구간의 끝이 기준일보다 앞서면 기준일까지 연장하고, 연장했다는 사실을 그 행 `출처`에 적는다**(5행). **dc 판정과 대조할 때는 dc 지시 구간 값도 한 행 더 낸다.**

### 3-5. S3. 결과 유형 분류 표 — 3열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 유형 | `T1 WIN` / `T2 LOSE` / `T3 INCONCLUSIVE` / `T4 실험 설계 잘못됨` (+ 혼합이면 뒤에 ` · M`) |
| 2 | 근거 | S2b 1행의 판정 어휘와 그 출처 행 번호 — **Primary 하나로만** |
| 3 | 분석 초점 라우팅 | §7-4 매트릭스의 해당 행 — `T{n} 질문 {개수}개 → S4` |

**하드 규칙**

- **유형은 판정 5어휘에서 기계적으로 나온다.** `WIN`→T1 · `LOSE`→T2 · `INCONCLUSIVE`→T3 · `실험 설계 잘못됨`→T4.
- **판정이 `지속`이면 T 분류를 하지 않는다** — 「중간 리포트」로 닫고 S4는 유형 없이 진행 상황만 적는다 (§7-1).
- **`M`은 플래그이지 판정이 아니다** — Primary와 Guardrail·Secondary의 방향이 어긋날 때 붙인다. **하락 판정은 임계값 ⑩(점추정 방향)을 따르며 `코치 확인 필요`를 병기한다** (§7-3).
- **군마다 유형이 다를 수 있다** — 그때는 군마다 1행을 내고, 보고서 전체의 유형은 **Primary 판정이 있는 군들의 목록**으로 적는다. 하나로 합치지 않는다.

### 3-6. S4. 유형별 분석 표 — 4열 + 선두 `#`

|---|---|---|
| 1 | 질문 | **§7-4 매트릭스의 고정 질문 그대로** — 스킬이 질문을 바꾸거나 줄이지 않는다 |
| 2 | 확인한 데이터 | 어느 표의 어느 행을 봤는가 (`S2a 3행` · `S5a 축 {이름}`) / `확인 불가` |

**하드 규칙**

- **선두에 `#` 행 번호 열을 둔다** — 4열 앞에 붙이고 열 개수에는 세지 않는다 (§5).
- **게이트 G3** — **태그 없는 해석 문장을 출력하지 않는다.** 3열이 채워졌는데 4열이 비면 그 행은 무효다.
- **`[해석]`에는 근거 행 번호를 병기한다** — `[해석] S2a 3·5행에서 …`. 번호 없는 `[해석]`은 `[가정]`이다.
- **질문을 지우지 않는다.** 답을 못 찾은 질문도 남기고 3열을 `확인 불가`로 둔다 — 무엇을 못 봤는지가 다음 실험의 입력이다.
- **M 플래그가 붙으면 §7-4 매트릭스 M행 질문을 T 질문 뒤에 덧붙인다** — 대체하지 않는다.

### 3-7. S5a. 세그먼트 표 — 11열 + 선두 `#` / S5b. 정성 판정 표 — 2열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 축 | 사용자가 고른 축 이름 (`설계서 사전 선언 구간` · `디바이스` 등) |
| 2 | 구간 | 그 축의 값 (`D-30 이내` · `모바일` 등) |

| 10 | 표본 판정 | `충족` / `표본 부족` — 임계값 ⑤ 기준 |

**하드 규칙**

- **선두에 `#` 행 번호 열을 둔다** — 11열 앞에 붙이고 열 개수에는 세지 않는다 (§5).
- **게이트 G4 — 사전 선언 구간만 판정한다.** 11열이 `판정`인 행은 S1 `사전 선언 구간`에 있는 구간뿐이며, `--bonferroni {비교 수 × 선언 구간 수}`로 보정한다(비교 수 = 판정 군 수 − 1).
- **탐색적 축은 `힌트`다** — 8열 p에 고정 접미 `보정 전`을 붙이고 11열은 `힌트`다. 🚫 **탐색적 세그로 승패를 말하지 않는다.**
- **임계값 ⑤ 미달 구간은 `표본 부족`이고 해석 문장을 0건 낸다** — 숫자는 표에 남기되 그 행으로 문장을 만들지 않는다.
- **축은 매번 묻는다** (§7-5). 스킬이 고정하지 않는다.
- **`LOSE`·`INCONCLUSIVE`는 3축 이상 분해한다** (KB09 Step 4).
- **게이트 G5 — 집계만 옮긴다.** 개별 사용자 행·원천 식별자는 어떤 열에도 넣지 않는다 (§2-4).

## 5. 문장·서술 규칙

- **근거 태그 4종을 해석 문장에 반드시 붙인다** — `[실측]` / `[계산]` / `[해석]` / `[가정]`. **태그 없는 해석 문장은 출력하지 않는다** (게이트 G3). `[해석]`에는 근거 행 번호를 병기하고, 번호가 없으면 `[가정]`이다.
- **`#` 행 번호 열은 S2a·S5a·S4의 선두 필수 열이며 열 개수에 세지 않는다** — G3의 근거 행 번호는 이 열을 가리킨다.
- **규칙 적용 절차의 서술(보정 계수·구간 선택·표 구성 설명)에는 태그를 붙이지 않고, 데이터에서 끌어낸 판단에만 붙인다.**
- **라벨 문구에 내부 계약 코드를 쓰지 않는다** — 노션 4장에 붙는 블록에는 내부 코드(dc)가 나타나지 않아야 하므로 `종료 의사결정 확정 후 v{n+1}`로 적는다.
- **`잠정` 라벨의 위치는 세 곳으로 고정한다** — ① 전 출력 **상단 1줄** ② S2b 1행 `판정` 값 뒤 ③ S6a **4-1 ①번 줄**과 **4-3 두 불릿**. 그 밖의 자리에 흩뿌리지 않는다.
- **`⚠️SP3`를 채우면 그 플래그는 지운다.** dc가 남긴 자리를 채우면서 플래그를 함께 남기면 다음 사람이 또 비어 있다고 읽는다. **채우지 못한 칸은 `⚠️SP3`가 아니라 `확인 불가`·`표본 부족`·`⚠️확인필요`로 남긴다.**
- **이론을 설명하지 않는다.** 왜 다중비교 보정이 필요한지, 왜 탐색적 세그가 힌트인지는 **이 산출물에 쓰지 않는다** — 근거는 스킬의 `references/analysis-guide.md`에 있고, 산출물은 규칙의 적용 결과만 낸다.
- **겪는 증상으로 쓴다.** 「세그 표본 미달」보다 「이 구간은 전환이 {N}건뿐이라 이 숫자로는 말할 수 없습니다」가 먼저 오고, 용어는 **쓰이는 자리에 1줄**로만 붙인다.
- **도구명은 한글로 쓴다 — 「앰플리튜드」.** 다만 `출처` 열의 고정 형식(§2-3)은 §2-3의 8형식과 문자 단위로 맞춰야 하므로 `Amplitude` 표기를 그대로 둔다. **도구 이름은 문서에 고정하지 않는다** — 조회 목적만 말한다.
- 🚫 **「위반」이라는 말을 쓰지 않는다.** Guardrail은 규칙이 아니라 **허용 범위**이므로, 벗어난 상태는 `아니오 — {지표명} {실측} vs 허용 {기준}`으로 적는다 (dc §5 승계).
- **판정·결정·So Next 어휘를 재정의하지 않는다.** 흐름도는 dc §7-1을 **인용**하고 다시 그리지 않는다.
- **존재하지 않는 URL·수치·이벤트명·차트 제목을 만들지 않는다.** 조회가 안 되면 `확인 불가`다. 「대략 이 정도일 것」으로 채우지 않는다.
- 열 이름·순서는 §3과 문자 단위로 동일. 임의 추가·삭제·재배열 금지.
- 셀 안 줄바꿈 금지(콤마·슬래시·`→` 사용). **셀 첫 글자에 `=`·`+` 금지** (시트 수식 오인).
- **ICE = I + C + E 합산**(각 1~10, 최대 30) · **BIAS = 27항목**(DEC-003) — 언급할 일이 있으면 이 표기만 쓴다. 이 계약은 둘 중 어느 것도 계산하거나 재정의하지 않는다.
- **실측 수치를 이 계약 본문에 하드코딩하지 않는다** — 출처 경로만 가리킨다. 예시의 가상 수치는 `[예시 — 가상 수치]`를 명시하면 허용된다.

## 7. 분석 규칙 (정본 — 위반 금지)

> **⚠️ 임계값은 이 계약이 정의하지 않는다.** 정본은 **`references/thresholds.md`(DEC-021 · DEC-023)** 한 곳이며, 이 절은 **번호로만 인용한다.**
> 이 계약이 쓰는 것은 넷이다 — **⑤ 수집 최소 요건**(세그 표본 판정 · §7-5) · **⑥ 베이지안 병행 해석 구간**(저트래픽 대체 판정 · §7-4 T3 · S6b `저모수 대체 판정`) · **⑨ 판정 계산의 구현 우선순위**(§7-2) · **⑩ 가드레일·세컨더리 「하락」 판정**(§7-3 M 플래그).
> **부속 「외부 유의성 계산기 URL」은 `⚠️확인필요`다** — 🚫 **스킬이 URL을 지어내지 않는다.** 값은 참가자가 계산기를 돌려 제시하고, 스킬은 병기·검산만 한다.
> **§7-1·§7-2·§7-7·§7-9는 임계값이 아니라 규칙이므로 확정 대기 대상이 아니다** — 즉시 적용한다.

**7-1. 종료 확인 게이트 G1 (하드).** **종료·결정이 확인되지 않은 실험의 보고서는 「중간 리포트」다.**

- S0 `종료일/상태`가 `{날짜} 종료`가 아니거나, `dc 기록 유무`가 `dc 기록 확정`이 아니면 **전 출력 상단에 `중간 리포트 — 판정 잠정` 라벨을 고정**한다.
- **막는 것은 「최종 보고」이지 「분석」이 아니다** — 유형 분류·유형별 질문·세그먼트·정성 판정은 그대로 한다. 막히는 것은 **S6a 4-3의 확정 문장**뿐이다.
- **판정이 `지속`이면 S3를 하지 않는다** — T 분류 없이 「중간 리포트」로 닫고, S4는 「지금까지 무엇을 봤는가」만 적는다.
- **파일명이 그 사실을 담는다** — `interim`이 라벨과 같은 뜻이다 (§7-8).

**7-2. 판정 정본 우선순위 게이트 G2 (하드).** **판정은 만드는 것이 아니라 받는 것이다.**

| 순위 | 출처 | 취급 |
|---|---|---|
| 1 | **dc 확정 기록** | 문자 그대로 승계. 스킬이 다시 계산해도 **어휘를 바꾸지 않는다** |
| 2 | **계산값** | dc 기록이 없거나 잠정일 때. **구현 순위는 임계값 ⑨를 따른다** — 이 계약이 재정의하지 않는다 |
| 3 | **화면 표시값** | 대조로 병기. 정본이 아니다 (DEC-022) |

- **dc §7-1 흐름도는 인용만 한다.** 판정 경로를 적어야 할 때는 **흐름도의 분기를 밟은 순서 1줄**만 남기고, 🚫 **흐름도를 다시 그리거나 조건을 바꾸지 않는다.**
- **S2b `상태` 3값의 정의**

| 상태 | 언제 | 처리 |
|---|---|---|
| **① `dc 기록 확정`** | dc 기록이 있고 판정일이 재계산 구간 끝 이후이며 `⚠️확인필요`가 붙어 있지 않다 | **문자 그대로 승계.** 결정·So Next도 그대로 |
| **② `dc 기록 있음 — 잠정·구간 불일치`** | dc 기록은 있으나 **판정일이 재계산 구간 끝보다 앞서거나** 기록에 `⚠️확인필요`가 붙어 있다 | **원문 승계 + 재계산 구간의 `[계산]` 값 병기.** 판정에 `잠정` 라벨, 결정·So Next는 **빈칸** |
| **③ `dc 기록 없음`** | dc 기록을 찾지 못했다 | `⚠️dc 미기록 — 계산값 잠정`. 판정은 계산값 기준 `잠정`, 결정·So Next 빈칸 |

- **상태 ②의 실제 사례가 EXP-A-002다** — 9/16 종료 의사결정 세션에서 구두 판정이 나왔고 **같은 자리에서 오염 구간 재계산 지시가 함께 나왔다.** 판정일이 재계산 구간의 끝보다 앞서므로 그 판정은 `잠정`이며, 재계산 구간의 계산값을 `[계산]`으로 병기한다. 🚫 **두 값 중 마음에 드는 쪽을 고르지 않는다.**
- **상태 ②③이면 S6a 4-3의 「운영 반영」과 「실험 지속 여부」 둘 다 `잠정 — 종료 의사결정 확정 후 v{n+1}`이다.**
- **군마다 상태가 다를 수 있다** — 그때는 군마다 1줄로 상태를 적는다.
- **스크립트 출력에서 옮기는 것은 `차이`·`p`·`CI`·`베이지안` 행이고, `판정`·`모드` 행은 옮기지 않는다** — 판정은 승계값이며 **영문 판정값은 출력에 나타나지 않는다.**

**7-3. 결과 유형 분류 (하드).** **유형은 Primary 판정 하나에서 기계적으로 나온다.**

| 판정 | 유형 |
|---|---|
| `WIN` | **T1 WIN** |
| `LOSE` | **T2 LOSE** |
| `INCONCLUSIVE` | **T3 INCONCLUSIVE** |
| `실험 설계 잘못됨` | **T4 실험 설계 잘못됨** |
| `지속` | **분류하지 않는다** — 「중간 리포트」 (§7-1) |

- **혼합 플래그 `M`은 판정이 아니라 덧붙임이다.** Primary와 Guardrail·Secondary의 방향이 어긋날 때 유형 뒤에 ` · M`으로 붙인다.
- **「하락」의 판정 기준은 임계값 ⑩의 기본값 — 점추정 방향이다.** 실측이 대조군보다 낮으면 하락으로 본다. 유의성은 함께 계산해 병기하되, **유의하지 않다는 이유로 하락을 없던 것으로 하지 않는다.**
- **⑩은 `코치 확인 필요` 상태다** — M 플래그를 붙일 때마다 그 문구를 병기한다. 유의한 하락만 하락으로 볼지는 DEC-023 미결 2다.
- 🚫 **「좀 더 높다」를 근거로 삼지 않는다.** Secondary·Guardrail을 주장에 쓰려면 **유의성을 계산해야** 힘이 생긴다 (dc §7-4 승계).

**7-4. 유형별 분석 초점 매트릭스 (S4 고정 질문 — 정본).** **유형이 정해지면 질문 세트가 정해진다. 스킬이 질문을 고르지 않는다.**

| 유형 | 고정 질문 | 확인 데이터 | 출처 |
|---|---|---|---|
| **T1 WIN** | 왜 이겼나(Rationale R# 중 작동한 것·BIAS 전술) / 후속 퍼널이 따라왔나(Secondary·Guardrail 방향) / 다른 타겟·화면 확장 가능성 / 더 올릴 여지 / **배포 반영 조건 충족?** | Primary 폭·MDE 대비, Secondary 패턴, Guardrail 안전성, 두드러진 세그 | 푸드케어 페이지·KB09 Step 3·dc §7-10 |
| **T2 LOSE** | 왜 졌나 — **실패 부검 3관점**(문제가 진짜였나 / 솔루션이 문제를 건드렸나 / 전달 방식이 나빴나) / **후속 퍼널 중 실험군이 이긴 곳이 있나** / Counter-rationale C# 중 실현된 것 / 세그 힌트 / 연장은 유의성이 아니라 「힌트를 더 얻을 수 있는가」로만 | Secondary·Guardrail 방향, 사전 선언 구간, 노출 실제 도달 | KB09·KB10 실패 3레벨·DEC-023 ③·우디 9/16 |
| **T3 INCONCLUSIVE** | 표본·기간·MDE 재점검(모수 부족 vs 효과 미미) / 노출이 실제로 일어났나(슬롯 노출 이벤트 vs 배정) / **세그 ≥3축 분해 → 특별히 높거나 낮은 코호트** / 신뢰구간·베이지안 대체 해석(저트래픽 프레임) | CI 0 포함 여부, 베이지안 확률, 세그 표 | 푸드케어 「Stat-sig X」·KB09 저트래픽 3종·임계값 ⑥ |
| **T4 실험 설계 잘못됨** | 설계 실수 3유형 체크(우선순위 낮음 / 지표 허술 / 왜인지 알 수 없는 variant 구성) / SRM·정의 불일치·오염 구간 / **정상 모집단 구간만으로 재계산 가능한가**(5-1 룰) / Retest 조건 | 배정 비율, 이벤트 정의, 구간별 유입 | 푸드케어 「실험설계 문제」·우디 9/16 5-1 |
| **M 혼합** (T1~T3에 덧붙임) | Primary 승 + Guardrail 하락 → **반영 보류, 왜 하락했나** / Primary 미달 + Guardrail·Secondary 유의 승 → **「어느 정도 증명된 것」과 후속 실험 경로**(EXP-A-002 A군 사례) | KB10 Implement 매트릭스 3행 | DEC-023 ②·KB10 |

- **질문을 줄이지 않는다.** 답을 못 찾은 질문도 S4에 행으로 남기고 `확인 불가`로 둔다.
- **M행 질문은 T행 질문을 대체하지 않고 뒤에 덧붙인다.**
- ⚠️ **이 매트릭스는 후보값이다** (DEC-024 결정 ④). 푸드케어 페이지 + KB09/10 + 9/16 룰을 합친 초안이며, **우디 확정 대상**이다. 구글 문서 보강분은 `⚠️확인필요`로 덧붙인다.

**7-5. 세그먼트 규칙 게이트 G4 (하드 + 임계값 ⑤).** **축은 스킬이 고정하지 않는다 — S5 진입 시 매번 묻는다.**

**고정 질문 (S5 진입 시 1회)**

> `어떤 축으로 쪼갤까요? 후보는 여섯 가지입니다 — ① 설계서 사전 선언 구간 ② 디바이스 ③ 신규/재방문 ④ 연령대 ⑤ 유입 경로 ⑥ 후속 퍼널 단계. 사전 선언 구간은 항상 포함합니다. 판정에 쓸 수 있는 것은 사전 선언 구간뿐이고, 나머지는 힌트로만 씁니다.`

- **사전 선언 구간은 항상 포함한다** — 사용자가 고르지 않아도 넣는다. S1 `사전 선언 구간`이 `없음`이면 그 실험에는 **판정 가능한 세그먼트가 없다**고 적는다.
- **선언 구간만 판정한다** — `--bonferroni {비교 수 × 선언 구간 수}`로 보정하고(비교 수 = 판정 군 수 − 1), S5a 11열을 `판정`으로 둔다.
- **탐색적 축은 `힌트`다** — p에 고정 접미 `보정 전`을 붙이고 11열은 `힌트`, 🚫 **승패를 말하지 않는다.**
- **임계값 ⑤ 미달 구간은 `표본 부족`이고 해석 문장을 0건 낸다.**
- **`LOSE`·`INCONCLUSIVE`는 3축 이상 분해한다** (KB09 Step 4) — 힌트를 얻는 것이 그 두 유형의 핵심이기 때문이다.
- **게이트 G5 — 집계만 옮긴다** (§2-4).

**7-6. 정성 필요 판정 (S5b).** **정성은 「데이터가 왜 그런지 모를 때」 부른다.**

**필요 판정 기준 — 하나라도 해당하면 `필요`**

| # | 조건 |
|---|---|
| 1 | S4의 「왜」 질문에 `[해석]`을 붙일 근거 행이 없다 (= `[가정]`으로만 답이 나온다) |
| 2 | Primary와 Secondary·Guardrail의 방향이 어긋나 정량만으로 원인을 좁힐 수 없다 (M 플래그) |
| 3 | 세그먼트 3축을 분해해도 두드러진 코호트가 없다 |

- **질문 후보는 3~5개다** — 각 줄 끝에 근거 행 번호를 붙인다. 번호가 없으면 질문이 아니라 궁금증이다.
- **조사를 실행하지 않는다** — 「실험 결과 디브리프」 계약(`wd-output-contract.md`)으로 넘긴다는 **안내 1줄**까지가 이 계약이다.

**7-7. 배포 반영 판단 게이트 G6 — dc §7-10 승계 (인용).** **실험의 승자 판정과 운영 반영 여부는 다른 결정이다.**

> **"프라이머리가 이겨야 되고 가드레일이나 세컨더리가 최소한 떨어지면 안 된다."** (코치 2026-09-16 `[00:44:25]` · dc §7-10)

| 판단 | 기준 | 어디서 |
|---|---|---|
| **실험 승자** | Primary 하나로만 | dc §7-1 흐름도 · S2b 1행 |

- **이 계약은 dc §7-10을 재정의하지 않는다 — 인용해 문장으로 옮길 뿐이다.**
- **「불하락」은 설계서의 자체 허용 범위로 대체되지 않는다** (dc §7-10 승계). 설계서에 「-2%p까지 허용」이라 적혀 있어도, 실측이 떨어졌으면 반영 조건을 충족하지 못한다.
- **`WIN`인데도 반영하지 못하는 경우가 있고, Primary에서 진 군이 반영 후보가 되는 경우가 있다** — 둘 다 **M 플래그**의 자리이며 S6a 4-3에 그대로 적는다.
- 🚫 **「이겼으니 반영하면 된다」를 스킬이 적지 않는다.** 반영 확정은 사람이다 (§0).

| **SR-5** | **세그먼트 판정과 힌트가 구분됐다** — S5a 11열이 `판정`인 행이 전부 사전 선언 구간이고 보정이 적용됐으며, 탐색적 축은 `힌트` + `보정 전`이고 승패 문장이 0건이다 | Critical |
| **SR-6** | **배포 반영과 승이 구분됐다** — S6a 4-3 첫 불릿이 dc §7-10 룰 문장이고, dc 승계값이 없으면 `잠정 — 종료 의사결정 확정 후 v{n+1}`이다. 「이겼으니 반영」이 0건이다 | Critical |
| **SR-7** | **수치에 출처가 전수로 붙었다** — S1·S2a·S5a의 모든 수치에 §2-3 8형식의 출처가 붙어 있고, 형식 밖의 표기가 0건이다 | Recommended |
| **SR-8** | **`⚠️SP3` 잔존이 0건이다** — er가 채운 칸에 플래그가 남아 있지 않고, 못 채운 칸은 `확인 불가`·`표본 부족`·`⚠️확인필요`로 적혔다 | Recommended |
| **SR-9** | **잠정 라벨이 일관된다** — `중간 리포트`·`잠정`이 §5의 세 자리(상단·S2b 1행·S6a 4-1 ①과 4-3 두 불릿)에 모두 있거나 모두 없다. 파일명의 `interim`/`final`이 라벨과 일치한다 | Recommended |
| **SR-10** | **신설 어휘 목록 밖의 신조어가 0건이다** — **판정·결정·So Next·유형·상태·라벨 자리에** §6 표 밖의 어휘가 0건이고, 영문 enum 노출이 0건이며 「위반」이 0건이다(서술문의 일반 한국어는 대상이 아니다) | Recommended |

- **채점은 dc DR·em MR·ed R1과 동일하다**: **Warning은 Pass로 카운트** · **품질 점수 = Pass ÷ 판정 대상 × 100%**(`N/A`는 분모 제외) · **등급 `A(90%+)` / `B+(80%+)` / `B(70%+)` / `C(50%+)` / `D(<50%)`**.
- **해당하지 않는 항목은 `N/A`다** — 판정이 `지속`이라 S3를 하지 않은 「중간 리포트」면 SR-6이 `N/A`, 세그먼트를 낼 표본이 전혀 없으면 SR-5가 `N/A`, 피드백 전 v1이면 S7 관련 판단이 `N/A`다.
- **Critical이 하나라도 `Fail`이면 품질 등급과 무관하게 「이 보고서는 다시 봐야 한다」로 닫는다** — 점수가 높아도 해석의 성립 요건이 깨진 것이다.
- **SR2 리뷰 리포트 구성(순서 고정)**: ① Quick Status(유형·라벨·품질 점수·등급) ② Critical 미충족 ③ Recommended 미충족 ④ 잘 된 부분(위치와 함께) ⑤ **질문 누락 점검**(§7-4 매트릭스의 해당 행 질문 중 S4에 없는 것) ⑥ 보완 가이드(항목 → 단계 라우팅 / dc·ed·wd 소관이면 그쪽 라우팅).

## 10. 완료 판정 체크 및 종료 경로

### 수행 모드 — 9항목

- [ ] 1. **S0 12행이 채워졌고** 접근 경로 2행이 실제 시도 결과이며, `종료일/상태`와 `dc 기록 유무`로 **보고서 라벨이 정해졌다** (§7-1)
- [ ] 2. **S1 16행이 전사**됐고 재평가·수정이 0건이며, 결손은 `⚠️확인필요`로 남았다. **S1b 매핑이 기록됐고 고치라는 요구가 0건이다**
- [ ] 3. **S2a의 모든 수치에 §2-3 8형식의 출처가 붙었다** — 램프업·오염 제외 1줄이 있고, 재계산 구간이 있으면 구간별 행이 나뉘어 있다
- [ ] 4. **S2b 5행이 채워졌고 `상태`가 3값 중 하나다** — 판정이 승계 또는 계산값이고, `결정`·`So Next`는 dc 기록이 없으면 빈칸이다 (§7-2)
- [ ] 5. **S3 유형이 Primary 판정 하나에서 나왔다** — `지속`이면 S3가 없고 「중간 리포트」로 닫혔다. M 플래그에는 `코치 확인 필요`가 병기됐다
- [ ] 6. **S4가 §7-4 매트릭스의 고정 질문을 전부 담았고, 모든 `발견` 행에 근거 태그가 붙었다** (G3)
- [ ] 7. **S5a의 축이 사용자에게 물어서 정해졌고 사전 선언 구간이 포함됐다** — `판정` 등급이 선언 구간뿐이고, 표본 부족 구간의 해석 문장이 0건이다 (G4 · ⑤)
- [ ] 8. **S6a·S6b가 코드블록 2개로 나왔고 S6c 안내가 붙었다** — 4장 섹션 제목이 원문 그대로이고, EXP 블록이 er 소유 5칸뿐이다
  - ⚠️ **dc 승계값이 없으면 S6a 4-3 두 불릿이 `잠정 — 종료 의사결정 확정 후 v{n+1}`이다** — 확정 문장이 하나라도 있으면 이 항목은 미충족이다 (§7-2 · G6)
- [ ] 9. **붙여넣기·commit이 사람 몫으로 안내됐고, 스킬이 노션·파일·git에 쓴 적이 0건이다** (§4 · §7-9 · G7)

### 리뷰 모드 완료 조건

- SR-1~SR-10 **전 행 판정** + SR2 6구성 전부 출력.
- 해당하지 않는 항목은 `N/A`이고 **분모에서 빠진다**.
- **Critical이 하나라도 `Fail`이면 품질 등급과 무관하게 「다시 봐야 한다」로 닫는다.**

### 종료 경로

세션 내 해소 불가 항목은 무한 루프 대신 아래 표로 종료한다.

| 항목 | 원인 | 해소 조건 | 담당 |
|---|---|---|---|
| **미종료 실험** | 종료·결정이 아직 없다 | 「중간 리포트 — 판정 잠정」으로 내고, 종료 의사결정 확정 후 `final v{n+1}` 재실행 | 참가자 → dc 세션 |

| **앰플리튜드 미연결** | 도구 미노출 + 화면 접근 불가 | **참가자가 화면 값을 붙여넣는다** | 참가자 |
