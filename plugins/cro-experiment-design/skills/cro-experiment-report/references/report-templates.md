# 보고서 빈 틀 — 상단 라벨 · S6a · S6b · S6c · S7

> **필드 이름과 섹션 제목은 노션 「실험설계서 템플릿_(ver CRO)」 4장 원문 및 `habitfactory-cro-ssot/50_reference/experiment-template.md` §3·§4와 문자 단위로 같다.** 이름을 바꾸거나 번역·축약하지 않는다.
> **붙여넣기와 commit은 사람이 한다** — 스킬은 블록을 만드는 데까지다 (게이트 G7).
> **코드블록은 S6a·S6b 둘뿐이고 합쳐 정확히 2개다.** 펜스는 **4백틱**이며 종류를 바꾸지 않는다 — 내용에 3백틱이 들어갈 수 있기 때문이다. **이 파일 안에서 그 4백틱 블록을 보여 줄 때는 5백틱으로 감싼다.**

## 1. 상단 라벨 문구 2종 (문자 그대로 — 변경 금지)

**전 출력의 첫 줄에 이 둘 중 하나를 그대로 쓴다.** 라벨은 S0 `종료일/상태`와 `dc 기록 유무`가 정한다 (게이트 G1).

| 라벨 | 조건 | 문구 |
|---|---|---|
| **interim** | `종료일/상태`가 `{날짜} 종료`가 아니거나 `dc 기록 유무`가 `dc 기록 확정`이 아니다 | `중간 리포트 — 판정 잠정 · {기준일} 스냅샷 · 종료 의사결정 확정 후 v{n+1}` |
| **final** | 둘 다 충족한다 | `결과 보고서 — 판정 확정 · {종료일} 종료 · 종료 의사결정 {판정일} 승계` |

- **`잠정` 라벨의 위치는 세 곳으로 고정한다** — ① 전 출력 **상단 1줄** ② S2b 1행 `판정` 값 뒤 ③ S6a **4-1 ①번 줄**과 **4-3 두 불릿**. 🚫 그 밖의 자리에 흩뿌리지 않는다.
- **`final` 라벨에는 `중간 리포트`·`잠정`을 쓰지 않는다** — 셋이 한꺼번에 있거나 한꺼번에 없다 (리뷰 SR-9).
- **파일명의 `interim`/`final`이 이 라벨과 같은 값이다** (§7-8).

**하드 규칙**

- **섹션 제목 3종은 템플릿 원문 그대로다** — `4-1) 실험 결과 분석 요약` · `4-2) 실험 Metric 결과 및 배움` · `4-3) 실험 결과 후속 액션`. 번역·축약하지 않는다.
- **4-1은 번호 목록 5줄 고정이고 각 줄 끝에 근거 태그 1개다.** 참가자가 요약만 읽는 자리이므로 🚫 줄을 늘리거나 줄이지 않는다.
- **「결과 데이터」는 굵은 소제목 + 표다** — 🚫 **토글을 만들지 않는다.** `<details>`가 노션 붙여넣기에서 살지 않을 수 있다.
- **「결과 데이터」 표의 열 6개는 dc D6a와 문자 일치한다** — `층` · `지표` · `대조군` · `실험군` · `차이` · `비고`.
- **군이 3개 이상이면 `실험군` 열을 `실험군1`·`실험군2`로 확장하고, 대응은 표 아래 1줄(variant 키 ↔ 번호)로 밝힌다** — 예: `실험군1 = {variant 프로퍼티 값} · 실험군2 = {variant 프로퍼티 값}`. 🚫 알파벳 표기는 쓰지 않는다 — 번호가 전역 표기다.
- **정성이 없으면 `(필요시) 심층 인터뷰 결과 분석` 줄을 내지 않는다.**
- **판정이 「실험 설계 잘못됨」이면 「결과 데이터」 표의 수치 칸을 `결과 불사용`으로 채운다** — 숫자를 남기면 나중에 누군가 그 숫자를 쓴다.
- **S1 `병행 릴리즈`가 `있음`이면 4-2에 「혼입 변수 있음」을 명시하고 이 실험만의 효과로 단정하지 않는다.**
- 🚫 **PII·원천 식별자를 블록에 넣지 않는다** (게이트 G5).

## 4. S6c — 로컬 초안 파일 안내 표 (3열 · 4행)

**안내 표다 — 파일을 쓰는 것은 사람이다** (게이트 G7).

| 항목 | 값 | 비고 |
|---|---|---|
| 파일명 | `{EXP-ID}_result-report_{interim\|final}_v{n}_{YYYYMMDD}.md` | |
| 저장 위치 | `30_deliverables/experiments/reports/` — 그 경로가 없으면 `./reports/` | |
| 담는 것 | 보고서 전문(S6a·S6b 본문) + 부록 | 부록 순서는 아래 |
| 남은 일 | 붙여넣기·commit은 사람 몫 — 무엇을 어디에 붙이는지 1줄 | |

- **`{EXP-ID}`는 S0 1행 그대로 · `{interim|final}`은 G1이 정한 라벨 · `{n}`은 1부터 · `{YYYYMMDD}`는 출력일.**
- **라벨이 `interim`에서 `final`로 바뀌어도 `v{n}`은 이어서 센다** — 🚫 1로 되돌리지 않는다.

**로컬 초안 파일의 전문 순서(고정)**

1. 상단 라벨 1줄
2. `4-1) 실험 결과 분석 요약` — 번호 5줄
3. S6a 본문 (`4-2)` · `4-3)`)
4. S6b 본문 (EXP 소유 5필드)
5. **부록** — S0~S5 표 전부(S0 · S1 · S1b · S2a · S2b · S3 · S4 · S5a · S5b) · 출처 목록 · 변경 이력(S7, 피드백 후)

- **부록의 표 순서는 단계 순서와 같다.** 피드백 전 v1이면 S7이 없고, 그 자리는 비운다.
- **출처 목록은 §2-3의 8형식 그대로 나열한다** — 형식 밖의 표기를 만들지 않는다.

## 5. S7 — 변경 이력 표 (5열)

| # | 코멘트 요지 | 분류 | 반영 위치 | 처리 |
|---|---|---|---|---|

**하드 규칙**

- **반영하면 v{n+1} 전문을 다시 낸다** — 🚫 바뀐 부분만 내지 않는다.
- **S7 표는 v1부터의 전 이력을 담는다** — 직전 버전의 변경만 담지 않는다.
- **거부한 코멘트도 표에서 지우지 않는다** — 무엇을 왜 안 바꿨는지가 기록의 절반이다.
- **`판정·결정 어휘 변경`은 거부이고 5열에 `거부 — 판정은 dc 소관`으로 적는다.** 거부 문구는 SKILL.md S7의 고정 대사를 그대로 쓴다.
- **`구조`는 부분 거부다** — 4장 구조(4-1·4-2·4-3)는 바꾸지 않고, 부록 구성은 자유롭게 바꾼다.
