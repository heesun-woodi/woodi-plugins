> **v1.1 구분 (2026-09-07):** Amplitude 실험 화면의 리프트·신뢰구간·유의성 표시는 **순차검정(mSPRT)** 결과라 샘플 도달 전에 읽어도 위양성이 통제된다 — 스킬은 이 표시값을 **항상 인용**한다(출처에 `— 표시값(순차검정)`). 피킹 게이트(계약 §7-6)가 막는 것은 **스킬 자체가 고정표본 검정(z·p·CI·베이지안·WIN/LOSE)을 도달 전에 반복 계산하는 것**이다. 둘을 섞지 않는다.

## 1. 통계적 해석 관점 (덱 요지)

기본 판정 기준은 **p ≤ 0.05**다. 트래픽이 적어 표본이 충분히 안 찰 것으로 보이면 p 하나에 의존하지 않고 **95% 신뢰구간 + 베이지안 승자확률을 병행**한다. Primary가 어느 쪽이든, **Secondary와 Guardrail은 동시에 체크**한다 — Primary가 WIN이어도 Guardrail이 위반되면 판정이 뒤집힌다.

## 2. 판정 3분류

| 판정 | 정의 |
|---|---|
| Win | 실험군이 대조군 대비 **통계적으로 유의미하게** 우수 |
| Loss | 실험군이 대조군 대비 **통계적으로 유의미하게** 열등 |
| Inconclusive | 통계적 유의성 없음(무승부) |

단순 수치 비교("A가 B보다 높음")나 통계적 검증 없는 확정적 결론은 판정이 아니다. (KB09 L30-40)

## 3. 실험 도구와 분석 도구는 수치가 다르다 — 4원인

| 원인 | 설명 |
|---|---|
| 모수 정의 차이 | 실험 도구="실험 노출 유저" vs 분석 도구="페이지 뷰 유저" |
| 식별자 차이 | user id vs device id vs 세션 |
| 집계 시점·타임존 | 데이터 반영 지연, 일자 경계 |
| 중복 제거 방식 | 유니크 처리 기준 차이 |

**두 도구의 절대값이 다른 것은 정상이다. 문제는 방향과 크기가 다를 때다** — 방향이 엇갈리면 판정 전에 반드시 해소한다. (KB09 L42-52)

## 4. 판정 플로우·판정 규칙표

```
1. p < 0.05인가? → No: Inconclusive / Yes: 다음
2. 실험군 > 대조군인가? → No: Loss / Yes: Win 후보
3. Guardrail은 안전한가? → No: 배포 보류·원인 분석 / Yes: 배포 가능
```

| 조건 | 판정 |
|---|---|
| 개선 + p<0.05 + MDE 달성 + Guardrail OK | ✅ 승자(전체 반영) |
| 개선 + p<0.05 + Guardrail 하락 | ⛔ 보류(가드레일 우선 거부권) |
| 개선 + p≥0.05 또는 MDE 미달 | ⏸ 보류/추가 검증 |
| 개선폭 ≈0 또는 음수 | ❌ 기각 |

판정 기준은 Primary 지표 1개에 대해서만 적용한다. Secondary/Guardrail의 유의성 자체는 판정 조건이 아니다(Guardrail은 거부권만). (KB09 L83-108)

## 5. z-test·95% CI 공식

```
p̂_c = 전환_c / 노출_c
p̂_t = 전환_t / 노출_t
p̄   = (전환_c + 전환_t) / (노출_c + 노출_t)         # 풀링 SE용
SE_pool = √[ p̄(1−p̄)(1/노출_c + 1/노출_t) ]
z = (p̂_t − p̂_c) / SE_pool → 양측 p

SE_unpool = √[ p₁(1−p₁)/n₁ + p₂(1−p₂)/n₂ ]           # CI용(미풀링)
95% CI = (p̂_t − p̂_c) ± 1.96 × SE_unpool
```

`scripts/statsig.py`가 이 두 공식을 각각 z/p와 CI 계산에 그대로 쓴다(7-1 풀링 SE, 7-2 미풀링 SE — 용도가 다르므로 혼용하지 않는다). (KB09 L208-234)

## 6. 골든 예시 — statsig.py 검산 대상

KB09 저트래픽 예시 1의 원표다. 이 값은 `statsig.py`로 재현 가능한 검산 기준으로 쓴다.

| 그룹 | 노출 | 전환 | 전환율 |
|---|---|---|---|
| Control | 886 | 171 | 19.3% |
| Variation 1 | 909 | 185 | 20.35% |

재현 결과: 차이 +1.05%p, p≈0.58~0.61, 95% CI≈[−2.6%p, +4.7%p], 베이지안 승자확률≈71%. 0을 포함해 유의하지 않음, 구간은 넓지만 대부분 양수 영역, 베이지안 71%는 "신중한 낙관" 구간(§9)이라 소프트 롤아웃 검토가 가능하다는 해석까지 원표와 일치한다.

## 7. ⚠️ 경고 — KB09 예시 2·3 수치는 오라클 아님

**KB09 예시 2(1000/180 vs 1000/210)·예시 3(1200/240 vs 1200/264)의 기재 수치(p 0.07/0.09, CI [+0.1,+5.9]/[−0.2,+4.2], 베이지안 93%/96%)는 원표에서 재현되지 않는다.** 재계산 결과는 p 0.090/0.229, CI [−0.47,+6.47]%p/[−1.26,+5.26]%p, 베이지안 95%/88%다. 이 두 예시는 **해석 서술("p만 보면 애매하지만 신뢰구간·베이지안은 방향성을 준다")의 예시로만 읽고, 수치 오라클로 쓰지 않는다.** KB 정오표 후속 과제로 남아 있다(이 스킬의 소관 밖).

## 8. p-value 4대 오해

| # | 오해 | 사실 |
|---|---|---|
| 1 | p는 "효과가 클 확률"이다 | 아니다 — 크기는 개선폭·CI로 본다 |
| 2 | p는 "가설이 맞을 확률"이다 | 아니다 — 귀무가설 하 관측 확률이다 |
| 3 | p≥0.05는 "효과 없음"의 증명이다 | 아니다 — "이 표본으론 우연을 못 배제"일 뿐 |
| 4 | p<0.05면 반영해도 된다 | 아니다 — MDE 달성·가드레일·비즈니스 해석이 남아 있다 |

(KB09 L242-249)

## 9. 베이지안 승자확률 해석 3구간

`⚠️확인필요 — 코치 확정`

| 승자 확률 | 해석 | 액션 |
|---|---|---|
| 50~70% | 약한 신호 | 보류 |
| 70~90% | 신중한 낙관 | 신중 |
| 90% 이상 | 강한 신호 | 강한 신호 |

단독 판정 근거 아님 — p·CI와 다른 질문에 답한다(MR-6).

p-value와 베이지안은 상반된 값이 아니라 **다른 질문에 답한다**(§17). 함께 보면 강하다. (KB09 L263-286)

## 10. MDE — 실측 차이가 이 값을 넘겼는가

설계 단계에서 Baseline·트래픽·기간으로 정한 "이 표본·기간으로 확실히 잡아낼 수 있는 최소 개선폭"이다. **실측 차이가 설계 때의 MDE를 못 넘기면 p와 무관하게 "표본 부족 → 보류"**다. (KB09 L288-294)

## 11. 통계 함정 체크

표본·기간 부족인데 "이겼다" 단정 / p<0.05를 "효과가 크다"로 오해 / 다중 변형 비교로 거짓양성 증가(경계값은 "경계"로 표기) / 노벨티 효과(초기 과대)·조기 종료 / 가드레일·QA 무시한 채 Primary만 보고 반영. (KB09 L296-301)

## 12. 한 줄 요약

**p = 우연인가 · 베이지안 = 얼마나 확신하나 · MDE = 표본이 충분했나 — 셋을 같이, 그리고 가드레일은 거부권.** (KB09 L304-306)

## 13. 저트래픽 대체 판정 3종

| 프레임 | 요지 |
|---|---|
| 신뢰구간 해석 | 0을 포함하는가 → 넓은가 → 대부분 양수 영역인가 순으로 읽는다. "최악의 경우에도 손해가 없나?" |
| 베이지안 승자확률 | §9 3구간 표를 그대로 적용 |
| 순차 실험(Sequential Testing) | 너무 높거나 낮을 때만 종료(Goldilocks). **실험 시작 전 설계서에 규칙을 명시한 경우에만** 허용 — 사후 적용은 peeking |

(KB09 L310-340)

## 14. 결과 판정 시트 — M5a/b/c의 원형

KB09 템플릿 1(원표·개선폭·역산 검증·통계·가드레일·판정 4단 구조)이 em 계약 M5a(원표)·M5b(통계)·M5c(판정)의 원형이다. 열 이름·순서는 계약 §3가 정본이며, 이 템플릿은 그 구성 논리만 참고한다. (KB09 L392-417)

## 15. SRM 임계·Kohavi 필터·Amplitude 엔진

- **SRM 임계**: 카이제곱 적합도 검정, 일반 가설검정과 반대로 **기각되지 않는 것이 정상**. Microsoft는 보수적으로 p<0.0005를 경보 임계로 쓰고, 다른 문헌은 p<0.01·p<0.1도 제시한다(⚠️확인필요 — 코치 확정) — 문헌 주석. 이 프로젝트의 후보는 p<0.001 경보 / p<0.01 주의(계약 §7 머리 목록 1, ⚠️확인필요 — 코치 확정). Amplitude 자동 감지는 sequential chi-squared, alpha=.01(모니터링 가이드 §12와 동일 수치).
- **Kohavi 종료 후 해석 필터 4가지**: Twyman의 법칙(이례적으로 좋은 결과일수록 먼저 의심) · 노벨티/프라이머시 효과(일자별 리프트 추이를 시계열로 확인) · Intention-to-Treat(최초 배정 그룹 기준 유지, 중간 이탈자 재분류 금지) · 가드레일 지표 사후 확인.
- **Amplitude 통계 엔진 4종**: Sequential testing(기본값, mSPRT, always-valid) / T-test(고정 기간, peeking 시 위양성 인플레이션) / Bayesian(승자확률 직접 산출) / Thompson Sampling(밴딧, 판정용 아님 — 최적화용).
- **최소 데이터 요건**: conversion 계열은 treatment/control **각각 최소 25건 전환 + 100건 노출**, average 계열은 최소 100건 노출. 미달이면 화면에 숫자가 안 뜨는 것이 정상이며 버그가 아니다.
- **stat-sig% 표시**: Amplitude는 유의성을 **"1 − p-value"** 로 표시한다(§17에서 재확인). 신뢰구간이 0을 포함하면 유의한 차이 없음.
- **Bonferroni 보정**: 여러 metric·variant를 동시 검정할 때 적용하는 다중비교 보정. **보정을 켰다면 결과에 "Bonferroni 보정 적용"을 명시**한다 — 보정 방법을 밝히지 않은 p-value는 비교 불가능한 숫자다.

(KB09 L648-763)

## 16. `statsig.py` 사용 예 — [예시 — 가상 수치]

```
python3 "$CLAUDE_PLUGIN_ROOT/skills/cro-experiment-monitoring/scripts/statsig.py" \
  --control 909 185 --treatment 931 201 \
  --ratio 50 50 --gate-n 900 \
  --min-days 14 --launch 2026-09-15 --today 2026-09-29 \
  --mde-rel 0.10 --baseline 0.203 \
  --alpha 0.05 --seed 20260907 --format md
```

위 입력값은 CLI 옵션 형태를 보여주기 위한 가상 수치이며, 실제 실험의 결과 수치가 아니다. **JSON 키는 `diff_pp, lift_rel_pct, …`(고정)이고, md 출력 행 이름은 계약 M5b 10행과 문자 단위로 일치해야 한다** — 둘은 서로 다른 이름 체계이므로 혼동하지 않는다.

## 17. stat-sig %·CI·베이지안은 서로 다른 질문에 답한다

stat-sig % = `(1 − p) × 100` — Amplitude 화면 표시값과 같은 정의다. 이 값이 크다고 CI가 좁아지거나 베이지안 확률이 같이 오르는 것이 아니다 — **p는 "우연인가"에, CI는 "효과 크기의 범위는 어디인가"에, 베이지안은 "실무적으로 얼마나 확신하는가"에 각각 답한다.** 셋 중 하나만 보고 판정하지 않는다(§12 한 줄 요약과 동일 원칙).
