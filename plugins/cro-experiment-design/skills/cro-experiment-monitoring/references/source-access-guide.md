# 접근 경로 가이드 — 노션·Amplitude 읽기, 대시보드 지표 매핑, PII 규칙 (계약 v1.1)

> 정본: `references/output-contract.md`(em-output-contract.md **v1.1**) — 이 파일과 어긋나면 계약이 이깁니다. 접근 사다리·출처 열 형식은 계약 §2-3이 정본이며, 이 파일은 경로별 절차와 알려진 함정만 보강한다. **담당자가 세팅한 화면이 정본이다(계약 §0)** — 이 파일의 §7 절차는 화면의 정의를 그대로 **기록**하는 절차이지, 설계서와 대조해 판정을 막는 게이트가 아니다(v1.1 — v1.0의 「정의 일치 게이트」는 폐지).

— M0(인테이크 + 접근 경로 확정)에서 먼저 읽고, M2(대시보드 지표 매핑)·M3(헬스)·M5(판정)에서 소스를 다시 확인할 때마다 참조한다.

## 1. 접근 경로 사다리

**이 스킬은 ed 계약과 달리 노션·Amplitude를 읽는 데 MCP/Chrome을 1순위로 쓴다. 기입은 여전히 사람이 한다.** 입력 URL은 **Amplitude 대시보드 URL 또는 Experiment 설정 URL** 둘 다 1순위다(실전 첫 건은 Experiment URL이었다).

| 소스 | 1순위 | 2순위 | 3순위 | 실패 시 |
|---|---|---|---|---|
| 노션 설계서 | 노션 MCP fetch | claude-in-chrome으로 URL 열어 읽기 | 참가자 붙여넣기 | M1 진행 불가 → 종료 경로 |
| Amplitude | MCP로 대시보드·차트·실험 분석 조회 | Chrome으로 화면 열어 값 읽기 | **화면에 없는 지표만** 설계서 정의 + variant 프로퍼티로 실쿼리 재구성 | `확인 불가` |

⚠️ **참가자 계정은 노션에 게스트로 초대된 상태여서 1순위(노션 MCP)가 열리지 않는다** (2026-09-07 확인). 시도해 실패를 확인한 뒤 Chrome 경로로 내려가는 것이 참가자 세션의 정상 경로다. Chrome 경로에서는 ① 그 브라우저에 노션 로그인이 되어 있어야 하고 ② 접힌 토글은 펼쳐져 있어야 읽힌다. 프로젝트 종료 후 문서가 고객사 내부 노션으로 이관되면 1순위가 열린다.

각 단계는 상위 경로가 막혔을 때만 내려간다 — 노션 MCP가 있는데 Chrome으로 먼저 열지 않고, 화면에 있는 지표를 실쿼리로 다시 조회해 대조하지 않는다(계약 §7-12 「담당자 세팅 재감사 금지」).

⚠️ **MCP 서버를 이 세션에서 새로 추가했다면 도구가 바로 보이지 않는다** — `/mcp`로 재연결하거나 세션을 재시작한 뒤 시작한다. 도구가 0개로 보이면 「미연결」이 아니라 재인증 문제일 수 있다(§5-0).

## 2. 출처 열 고정 형식 (6종 · 계약 §2-3)

| 형식 | 쓰는 경우 |
|---|---|
| `노션 MCP {page-id 앞 8자} {조회일시}` | 1순위로 노션 페이지를 fetch했을 때 |
| `Chrome 읽기 {경로 축약} {조회일시}` | claude-in-chrome으로 페이지·대시보드를 직접 읽었을 때 |
| `붙여넣기 {일시}` | 참가자가 값을 직접 붙여넣었을 때 |
| `Amplitude 대시보드 차트 「{차트 제목}」 {기간} {경로}` | 대시보드 화면의 차트 값을 옮겼을 때 |
| `Amplitude 실쿼리 {이벤트A→B, 필터, 기간}` | 화면에 없는 지표를 설계서 정의로 재구성해 조회했을 때 |
| `Amplitude 실험 분석 「{실험명}」 {기간} MCP 실험 조회` | Experiment 분석 화면(등록 metric·노출·표시값)을 읽었을 때 |

**화면 표시값(리프트·신뢰구간·유의성 표시)을 인용할 때는 형식 뒤에 `— 표시값(순차검정)`을 붙인다** — 스킬 자체 계산값과 구분한다(계약 §7-6). 도구명(MCP 함수명 등)을 출처 열에 고정하지 않는다 — 조회 목적과 조건을 서술한다.

## 3. 노션 MCP 경로 절차 — 섹션은 번호가 아니라 제목으로 찾는다

ed 계약 §3-9가 정립한 규칙을 그대로 승계한다. 구 템플릿 페이지는 번호가 같아도 내용이 다른 섹션이 실물로 관측됐다(예: `3-5) 실행 순서`가 종료 기준 섹션이 아닌 경우) — **번호로 판정하지 않는다.** 이 스킬이 노션 페이지에서 찾는 섹션은 제목 문자열로 매칭한다.

- `1-4) 실험 지표 (Result)`
- `1-5) 실험 세팅`
- `3-1)` ~ `3-5)` (종료 기준·조기 종료·최소 관찰 기간 등, 신규 템플릿에서만 `3-5)`에 정규 존재)

페이지가 이 제목들과 다르면 참가자 페이지의 실제 섹션 제목을 기준으로 다시 매핑하고, 차이를 M1 표의 비고에 남긴다. 제목 자체가 없으면 「결손」으로 처리하고 ed STEP 4/5로 라우팅한다(§2-3 표 「실패 시」 열).

## 4. Chrome 읽기 절차 (노션·Amplitude 공통)

1. 페이지 열기 → 본문 읽기 → **표에 있는 값만** 옮긴다. 눈대중 추정·보간 금지.
2. 접힌 토글·스크롤 아래 섹션에 값이 숨어 있을 수 있다 — 필요한 섹션까지 펼치고 스크롤한 뒤 읽는다.
3. 화면에 유저 단위 원천 데이터(개별 유저 행)가 보이면 §8 PII 규칙을 먼저 적용한다.

## 5. Amplitude 대시보드 읽기 절차

### 5-0. MCP 경로가 제공하는 조회 능력 (2026-09-07 실측 — 도구명은 고정하지 않는다)

해빗팩토리 사내 MCP Central을 경유한 Amplitude MCP는 다음 **조회 목적**을 지원하는 것이 확인됐다. 1순위(MCP 차트 읽기)에서 이 순서로 시도한다.

1. **URL → 객체 조회**: `app.amplitude.com` 대시보드·차트·실험 URL을 그대로 넘겨 해당 객체(대시보드 구성·차트 정의·값)를 받는다. 대시보드 URL 1순위 처리의 진입점이다.
2. **대시보드 읽기**: 대시보드 ID로 포함 차트 목록·각 차트 정의를 읽는다.
3. **저장 차트 값 읽기**: 차트 ID로 데이터(시계열·그룹별 값)를 받는다 — 차트 정의(이벤트·분모·세그먼트)를 함께 받아 M2 매핑 표의 입력으로 쓴다.
4. **Experiment 결과 읽기**: Amplitude Experiment 객체에서 variant별 노출·지표·엔진 표시값(1−p)을 읽는다 — M5b `Amplitude 엔진 표시값(참고)` 행의 출처.
5. **피처 플래그·배포 읽기**: 배분 비율·bucketingKey·활성 여부를 읽어 M1 분배 비율과 대조한다(M6 「실험 중 배분 변경」 점검).
6. **실쿼리(세그먼테이션·퍼널)**: §6 폴백.
7. **택소노미 조회**: 이벤트·프로퍼티 존재 여부(M3b 수집 상태).

🚫 **쓰기 계열(차트 저장·이름 변경·대시보드 편집·실험/플래그 생성·수정·공유)은 모니터링에서 호출하지 않는다** — 계약 §7-12.

⚠️ 사내 게이트웨이는 Amplitude 쪽 OAuth가 만료되면 도구 목록을 **빈 배열**로 돌려준다. 도구가 하나도 안 보이면 「미연결」이 아니라 재인증 문제일 수 있다 — MCP Central 리소스 관리 페이지에서 Amplitude를 연결 해제 → 연결하기로 재인증(사람 몫). 그래도 없으면 사다리 2순위(Chrome)로.

값을 옮기기 전에 **차트 제목·기간·세그먼트·분모 이벤트를 먼저 기록**한다. 이 네 가지를 먼저 적어두지 않으면 나중에 값만 남고 그 값이 무엇을 재는지 복원할 수 없다. 값은 화면에 표시된 **집계만** 옮기고, 원천 데이터를 계산·가공하지 않는다.

## 6. Amplitude 실쿼리 재구성 절차 (화면에 없는 지표만)

화면(대시보드·실험 분석)에 **등록되지 않은 지표**만 실쿼리로 채운다 — 실전에서 이 경로를 타는 것은 대개 설계서 Secondary다. 조회 목적을 **서술 문장**으로 남기고 도구명·함수명은 고정하지 않는다. 예: "점검신청 진입(분모) 대비 상담 시작(분자) 전환, variant 프로퍼티 `is control`, 런칭일부터 오늘까지."

- 💡 **이 경로의 속도는 설계서가 정한다.** 이벤트명이 실제 택소노미 이름 그대로(+분모·전환창) 적혀 있으면 바로 조회하고, 말로만 적혀 있으면 `확인 불가`로 두고 되묻는다 — 설계 단계에서 정확히 적어 두면 대시보드를 따로 만들지 않아도 된다 (ed 계약 §3-4).
- **군마다 1회씩 따로 조회한다** — 퍼널에 variant 프로퍼티 `is {값}` 필터를 걸어 control·treatment… 각각 실행한다. 🚫 **group-by(세그먼트 분할)를 쓰지 않는다** — 2026-09-07 실측에서 group-by 퍼널 응답의 세그먼트 라벨이 비어 어느 블록이 어느 군인지 순서로 추정해야 했다(계약 §3-4a).
- 실쿼리 행의 산출물은 **전환율(전환/노출)까지**다. 리프트·유의성은 계산하지 않는다(계약 §7-6).
- 분해형 Secondary(예: 구간별 분해)는 필터를 구간 조건으로 바꿔 **구간 × variant** 표로 낸다.

## 7. 대시보드 지표 매핑 절차 (M2 · 계약 §3-3 · §7-10 권고)

담당자가 세팅한 화면의 정의가 정본이다. 이 절차는 **기록**이며 판정을 막는 게이트가 아니다(v1.1 — v1.0의 「정의 일치 게이트」 폐지).

1. 화면에 등록된 지표마다 이름·분자/분모 이벤트·전환창·variant 분기 방식을 **화면에 적힌 대로** M2 표에 옮긴다.
2. 설계서 E3 정의와 나란히 놓고 `설계서 대비` 열을 채운다 — 값 도메인은 `동일` / `차이 — {내용}(참고)` / `설계서에 없음` / `화면에 없음`.
3. `차이`는 리포트 끝 **「참고」 1줄**로만 남긴다. 판정·헬스·진행률은 화면 정의 기준으로 그대로 진행한다.
4. `화면에 없음`인 지표만 §6의 실쿼리 재구성 대상이다.

## 8. PII 규칙

Chrome 화면이나 실쿼리 응답에 유저 단위 원천 데이터(개별 유저 행, user id 목록 등)가 보이면 **집계값만** 대화·산출물에 옮기고 원문을 그대로 출력하지 않는다. ed 계약 §2-4·§7-10의 규칙을 그대로 승계한다. 클라이언트가 금융/보험 도메인이라 raw PII는 원천적으로 접근 범위 밖이다.

예를 들어 "user_id 12345가 6번 노출됨" 같은 원문 행은 옮기지 않고, "노출 909건, 전환 185건"처럼 집계된 숫자만 옮긴다. 스크린샷을 텍스트로 옮겨 적는 과정에서도 개별 행이 섞여 들어오지 않았는지 다시 확인한다.

| 값별 유니크 합 > 실제 유니크 | 한 사람이 여러 값(예: 플랫폼)에 걸쳐 잡히면 값별 유니크를 단순 합산한 수치가 전체 유니크를 초과한다 — 값별 비중은 상한값으로만 읽는다 | ssot `30_deliverables/diagnosis/goaltree-downstream-correction.md` |
| 웹뷰 user_id 이중 카운트 | 앱과 웹뷰의 `user_id`가 다르면 같은 사람이 두 명으로 세어져 배정이 갈리고 퍼널이 끊어진다 | ssot `30_deliverables/experiments/EXP-A-001-inspection-coverage-gap.md` L177-193 |
| 배포 3개 (ios/aos/web) | 배정값 수신 주체(웹 SDK 직접 수신 vs 앱→웹뷰 전달)에 따라 Amplitude deployment 구성이 갈린다 — 세 배포가 같은 실험을 재고 있는지 확인 없이 합산하지 않는다 | 〃 |

이 함정들은 M2 매핑 표와 M6 이상 징후 체크에서 발견되면 `⚠️확인필요`로 표기하고, 원인을 밝히기 전에는 그 지표로 판정하지 않는다.
- **퍼널 응답은 CSV 형태**(`Segment / Date / Conversion / 단계별 노출 … / Total` 행)로 오며, group-by를 걸면 세그먼트 라벨이 비어 블록 순서로 군을 추정해야 한다 → 군별 `is` 필터로 따로 조회(§6). (2026-09-07 실측)
- **날짜 필터는 유닉스 초**이며 KST 하루 경계로 맞춘다(예: 9/3 00:00 KST = 1788361200). ISO 문자열은 거부된다. (2026-09-07 실측)
- 설계서가 인용한 저장 차트 ID가 **접근 불가**(다른 소유자·미공유)일 수 있다 — 그때는 화면에 있는 값이나 실쿼리로 대체하고 출처에 그 사실을 적는다.
