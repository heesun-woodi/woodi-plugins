## 0. 실험 모니터링의 정의

> **"모니터링은 판정이 아니라 확인이다."** (8/10 세션 블록 C-1)
> 진행 중에 봐도 되는 것은 **데이터 유입 · 배분 비율 · 장애 수준 가드레일** 셋뿐이고, 「지금 이기고 있는가」는 진행 중에 보는 것이 아니다. 이 계약이 표 스키마로 강제하는 것이 그 경계다.

> **"담당자가 세팅해놓은 대시보드를 믿어야 해. 그걸 기반으로 기본적인 모니터링을 해."** (코치 정정 2026-09-07 · v1.1)
> **담당자가 세팅한 Amplitude 대시보드·실험 분석 화면이 정본이다.** 이 계약은 그 화면의 지표 정의·군 수·배분·전환창을 **그대로 기록하고 그 위에서** 모니터링한다. 설계서와 다른 점은 **게이트로 막지 않고** 리포트 끝 「참고」 1줄로 남긴다 (§7-10 · §7-13). 실쿼리 재구성은 **화면에 없는 지표에만** 쓴다.

**두 원칙은 충돌하지 않는다.** 첫째는 **스킬이 무엇을 계산해도 되는가**의 경계이고, 둘째는 **어느 화면의 숫자를 읽는가**의 정본이다. 화면이 이미 표시하는 리프트·신뢰구간·유의성은 **읽어서 인용하는 것**이고(순차검정 기반이라 중간에 읽어도 위양성이 통제된다 — KB09 B), 스킬이 고정표본 통계를 새로 계산해 승패를 부르는 것이 **판정**이다 (§7-6).

**2관점 (우디 덱)** — 모니터링은 서로 다른 질문 두 개를 서로 다른 시점에 묻는다.

| 관점 | 언제 | 무엇을 묻는가 | 이 계약의 표 |
|---|---|---|---|
| **① 운영 안정성** | 런칭 후 1~2일 집중, 이후 매일 | variant 시안이 실제로 노출되는가 · 트래픽이 정상 유입되는가 · 지표 이벤트가 실제로 수집되는가 | M2 · M3a · M3b · M6 |
| **② 통계적 해석** | **화면 표시값은 상시**, 스킬 계산은 샘플·기간 조건 충족 후에만 | 화면은 지금 무엇을 표시하는가 → 필요 n에 도달했는가 → Primary가 유의한가 → Secondary·Guardrail은 반대로 가지 않았는가 | M3c · M4 · M5a · M5b · M5c |

- **관점 ②의 스킬 계산 부분은 관점 ①을 통과한 뒤에만 열린다.** SRM이 떠 있으면 리프트가 아무리 예뻐도 그 결과는 쓰지 않는다 (§7-7). **화면 표시값 인용(M3c)은 이 제한을 받지 않는다** (§7-6).
- **Primary가 WIN이어도 Secondary·Guardrail은 반대 결과가 나올 수 있다** (우디 덱 슬라이드 4). Guardrail은 성공을 증명하지 않는다 — **`WIN`을 막을 수만 있다.**

**2모드** — 이 스킬의 산출물은 모드에 따라 다르다. 모드는 스킬이 정하지 않고 **M4의 숫자가 정한다**.

| 모드 | 진입 조건 | 출력하는 표 | 🚫 출력하지 않는 것 |
|---|---|---|---|
| **헬스** | 필요 n 미달 **또는** 최소 관찰 기간 미충족 **또는** SRM 경보 | M0 · M1 · M2 · M3a · M3b · **M3c** · M4 · M6 · M7a(헬스) · M7b(1줄) | **스킬 자체 계산의 차이·p·베이지안·WIN/LOSE 판정** (`scripts/statsig.py`의 z·p·CI·베이지안·판정) — **Amplitude 화면 표시값(리프트·신뢰구간·유의성 표시) 인용은 허용** |
| **판정** | 전 variant 누적 n ≥ 필요 n **AND** 최소 관찰 기간 충족 **AND** 요일 주기 ≥1회 **AND** SRM 정상 | 위 전부 + M5a · M5b · M5c · M7a(판정) · M7b(`## 3` 표) · M7c | 결과 보고서의 why 서술 · So Next 확정 |

- 헬스 모드 🚫 열은 **스킬이 만들어내는 숫자**만을 가리킨다. 화면에 이미 있는 값을 옮겨 적는 것은 「확인」이고, 스킬이 고정표본 검정을 돌려 승패를 부르는 것이 「판정」이다. 인용할 때는 출처에 **「Amplitude 표시값(순차검정)」** 을 붙여 구분한다 (§2-3 · §3-4a).

- 「SRM 정상」은 **경보(alarm, p<0.001 후보)가 아님**을 뜻한다. **주의(warn, 0.001≤p<0.01 후보)는 판정 모드를 막지 않되** M3b #5에 `⚠️이상`으로 남기고 M5c 판정 근거에 병기한다 (⚠️확인필요 — 코치 확정).

## 2. 입력 규격

### 2-1. 세션 단위 — 런칭된 실험 1건

이 세션의 입력은 **런칭된 실험 1건**이다. 여러 건을 요청받으면 1건씩 순서대로, 매 건 M0부터. 실험 1건 = 설계서 1장 = EXP 파일 1개 = 헬스 로그 1줄/일이다.

### 2-2. 필수 입력 2종 + 보조 1종

| # | 입력 | 없을 때 |
|---|---|---|
| 1 | **노션 실험설계서 URL** (또는 본문 붙여넣기) | M1 진행 불가 → §9 종료 경로. 설계값 없이 진행률·판정을 만들지 않는다 |
| 2 | **Amplitude 대시보드 URL 또는 Experiment 설정 URL** (또는 화면 값 붙여넣기) | 실측 열 전부 `확인 불가` → 헬스 모드로만 종료 |
| 3 | 런칭일 (보조 — 없으면 질문) | 경과일·최소 관찰 기간·요일 주기를 판정할 수 없다 → M4 4줄 중 2줄이 `확인 불가` |

- **입력 2번은 두 표기 모두 1순위다** — 담당자가 세팅한 것이 대시보드일 수도, Amplitude Experiment 설정·분석 화면일 수도 있다. **어느 쪽을 받았는지 M0에 적고, 받은 화면을 정본으로 삼는다** (§0). 둘 다 있으면 실험 분석 화면을 우선한다 — 리프트·신뢰구간·유의성 표시가 거기 있다.
- **스킬이 URL을 만들지 않는다.** 받은 URL만 쓰고, 열리지 않으면 열리지 않았다고 말한다 (§5).

### 2-3. 접근 경로 사다리 — **명시 예외 조항**

> **ed 계약 §2-2·기존 스킬의 「노션 MCP 비전제」 관례와 달리, 이 스킬은 노션·Amplitude를 「읽는 데」 ① MCP ② claude-in-chrome(Chrome으로 URL 열어 읽기) ③ 붙여넣기/실쿼리 재구성 순으로 쓴다. 예외는 「읽기」에만 적용되며, 기입은 여전히 사람이 한다.**

이 예외를 두는 이유는 모니터링이 **주기 작업**이라는 데 있다 — 매일 반복해야 하는 확인을 매번 붙여넣기로 만들면 그 확인은 실제로 수행되지 않는다. 대신 **읽기 예외가 기입 예외로 번지지 않도록** §7-12에 하드 규칙으로 못 박는다.

| 소스 | 1순위 | 2순위 | 3순위 | 실패 시 |
|---|---|---|---|---|
| **노션 설계서** | 노션 MCP fetch | claude-in-chrome으로 URL 열어 읽기 | 참가자 붙여넣기 | M1 진행 불가 → 종료 경로 |
| **Amplitude** | MCP 실험 분석 / 차트 / 대시보드 조회 | Chrome으로 화면 열어 값 읽기 | **화면에 없는 지표만** — 지표 정의 + variant 프로퍼티로 MCP 실쿼리 재구성 | `확인 불가` |

**`출처` 열 고정 형식 6종** — M3a의 `출처` 열과 M2·M3b·M3c·M5a의 실측 근거는 아래 여섯 중 하나의 형식으로만 적는다.

| # | 경로 | 형식 |
|---|---|---|
| 1 | 노션 MCP | `노션 MCP {page-id 앞 8자} {조회일시}` |
| 2 | Chrome 읽기 | `Chrome 읽기 {경로 축약} {조회일시}` |
| 3 | 붙여넣기 | `붙여넣기 {일시}` |
| 4 | Amplitude 대시보드 차트 | `Amplitude 대시보드 차트 「{차트 제목}」 {기간} {경로}` |
| 5 | Amplitude 실쿼리 | `Amplitude 실쿼리 {이벤트A→B, 필터, 기간}` |
| 6 | **Amplitude 실험 분석** | `Amplitude 실험 분석 「{실험명}」 {기간} MCP 실험 조회` |

- **화면 표시값(리프트·신뢰구간·유의성 표시)을 인용할 때는 형식 6 뒤에 `— 표시값(순차검정)`을 붙인다** — 스킬 자체 계산값과 구분하기 위한 표기이며, M3c와 M5b `Amplitude 엔진 표시값(참고)` 행에 쓴다 (§7-6).
- **Amplitude 도구명을 이 계약이 고정하지 않는다** — 조회 **목적**(실험 분석 조회 / 차트 조회 / 대시보드 조회 / 퍼널 실쿼리)만 서술하고, 실제 도구명은 세션에 노출된 것을 쓴다. 도구가 노출되지 않으면 2·3순위로 내려간다 (ed §7-10 관례 승계).
- **경로가 내려갈수록 `출처` 열이 길어진다** — 이것이 의도다. 어느 경로로 읽었는지가 판정의 신뢰도를 결정하므로, 출처가 비어 있으면 그 행은 `확인 불가`다.
- **담당자가 세팅한 화면이 정본이다** (§0). 화면에 있는 값은 그대로 옮기고, **실쿼리 재구성은 화면에 없는 지표에만** 쓴다 — 화면에 있는 지표를 다시 조회해 대조하지 않는다 (§7-10 · §7-12).
- ⚠️ **참가자 계정은 이 노션에 게스트로 초대된 상태여서 노션 MCP로 페이지를 읽을 수 없다** (2026-09-07 확인). 참가자 세션의 **실질 1순위는 2순위 경로(Chrome으로 URL 열어 읽기)** 다 — 1순위를 시도해 실패를 확인하는 절차는 유지하되, 실패를 결함으로 취급하지 않고 대사 정본 ①로 바로 내려간다. 프로젝트 종료 후 문서가 고객사 내부 노션으로 이관되면 1순위가 실제로 열린다.

### 2-4. 프로젝트 제약

리스트·시트·노션에 근거 사용 금지 규칙이 명시돼 있으면 스킬 기본 절차보다 우선한다. M0에서 한 번 확인하고 전 단계에 적용한다. 금융·보험 도메인이므로 **원천 PII는 어떤 표에도 옮기지 않는다** — 위치만 말하고 `[마스킹]` (§7-9). **Chrome으로 대시보드를 여는 경로에서도 같다** — 화면에 개별 사용자 행이 보이면 집계값만 옮기고 개별 행은 읽지 않는다.

## 3. 표별 열 정의 (이름·순서 고정)

### 3-1. M0. 인테이크·접근 경로 표 — 2열 (항목/값)

**행 9개(순서 고정)**: `실험 ID` · `노션 URL` · `대시보드 URL` · `가설 ID` · `런칭일` · `오늘(경과일)` · `노션 접근 경로` · `Amplitude 접근 경로` · `모드 잠정`

| 행 | 값 도메인 |
|---|---|
| 실험 ID | `EXP-{A\|B}-{3자리}-{슬러그}` — 입력 그대로. **스킬이 채번하지 않는다** (§6) |
| 노션 접근 경로 | `MCP` / `Chrome` / `붙여넣기` |
| Amplitude 접근 경로 | `MCP 차트` / `Chrome 대시보드` / `MCP 실쿼리 재구성` / `확인 불가` |
| 모드 잠정 | **`헬스` 고정** — M4에서만 바뀐다 |

- **`모드 잠정`은 M0에서 항상 `헬스`다.** 판정 모드는 M4의 숫자가 열어 주는 것이며, 참가자의 요청이나 스킬의 판단으로 열리지 않는다 (§7-6).
- 접근 경로 두 행은 **실제로 시도한 결과**를 적는다. 시도하지 않고 3순위를 적지 않는다.

### 3-2. M1. 설계서 추출 표 — 4열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 항목 | 아래 18행 중 해당 |
| 2 | 값 | **설계서 원문 그대로.** 단위·표기까지 옮긴다 |
| 3 | 설계서 출처 섹션 | `1-4)` · `3-2)` · `3-5)` · `EXP §1 분배와 기간` 등 **읽은 자리** |
| 4 | 비고 | 결손이면 `결손 → ed STEP {N}` · 애매하면 `⚠️확인필요` |

**행 18개(순서 고정)**: `Primary 정의(분자/분모)` · `Secondary(각 1행)` · `Guardrail + 허용 기준(각 1행)` · `Baseline` · `Target` · `MDE(rel/abs)` · `판정 군 수` · `variant별 필요 n` · `총 필요 샘플` · `분배 비율` · `최소 관찰 기간` · `예상 기간` · `조기 종료 조건(숫자)` · `판정 기준 3조건` · `램프업 여부·구간` · `병행 릴리즈` · `Amplitude 실험 키 / variant 프로퍼티명` · `순차 검정 사전 선언 여부`

**하드 규칙**

- **전사만 한다. 계산하지 않고 수정하지 않는다.** 설계서에 없는 값을 이 표에서 만들어내지 않는다 — 없으면 `결손`이다.
- **`variant별 필요 n` 또는 `MDE`가 결손이면 판정 모드로 갈 수 없다.** 대사 정본 ④로 ed STEP 4(E6 샘플사이즈·기간)로 라우팅하고, 그 세션은 헬스 모드로 완결한다.
- **`조기 종료 조건` 또는 `판정 기준 3조건`이 결손이면** ed STEP 5(E7 분배·종료 기준)로 라우팅한다. 결손인 상태에서 스킬이 기준을 대신 정하지 않는다 — 시작 후에 정한 기준은 판정 조작이다.
- **라우팅 안내는 결손 건수와 무관하게 한 번에 낸다.** 2건 이상이면 항목을 묶어 대응 STEP도 함께 묶는다 (ed §3-2 승계).
- `판정 기준 3조건`은 **`stat-sig 유의` AND `실측 차이 ≥ 설계 MDE` AND `Guardrail 전부 허용 내`** 세 조건이 설계서에 적혀 있는지를 본다. 하나라도 없으면 `⚠️확인필요`.
- `Amplitude 실험 키 / variant 프로퍼티명`은 M2 `variant 분기 방식`과 M3a 조회의 전제다. 실물 관례는 이벤트 프로퍼티 `type_experiment_variant`(값 `control` / `treatment`)이며, **실험별로 다를 수 있으므로 설계서 값을 그대로 읽는다.**
- `순차 검정 사전 선언 여부`가 `없음`이면 **스킬의 중간 판정 경로가 없다** — 스킬이 고정표본 통계로 승패를 부르는 것은 도달 후다 (§7-6). **Amplitude 화면 표시값 인용은 이 행과 무관하다** — 화면의 유의성 표시는 그 자체가 순차검정이다 (KB09 B).

### 3-3. M2. 대시보드 지표 매핑 표 — 7열

**담당자가 세팅한 화면이 정본이다** (§0). 이 표는 화면의 정의를 **기록**하는 표이고, 설계서와 맞는지 **감사하는 게이트가 아니다** (v1.1 — §7-10).

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 설계 지표(층) | M1의 지표 + `Primary` / `Secondary` / `Guardrail` |
| 2 | 설계 정의 | 분자 / 분모 (설계서 원문) |
| 3 | 차트 제목 | 대시보드·실험 분석 화면의 제목 그대로. 없으면 `차트 없음` |
| 4 | 차트 이벤트(분자/분모) | 화면이 실제로 세는 이벤트 |
| 5 | variant 분기 방식 | `프로퍼티 {이름}` / `세그먼트 저장분` / `실험 키 연동` / `분기 없음` |
| 6 | **설계서 대비** | `동일` / `차이 — {내용}(참고)` / `설계서에 없음` / `화면에 없음` |
| 7 | 불일치 내용·조치 | 무엇이 어긋났는가 · 어느 값을 쓸 것인가 (화면 값이 기본) |

**하드 규칙**

- **차이가 있어도 M5를 막지 않는다.** v1.0의 「Primary 불일치면 M5 금지」는 **폐지됐다** — 차이는 리포트 끝 「참고」 1줄로 남기고 화면 기준으로 모니터링한다 (§7-10 · §7-13).
- **`화면에 없음`인 지표만 실쿼리로 재구성한다.** 화면에 있는 지표를 다시 조회해 대조하지 않는다 — 담당자 세팅을 재감사하지 않는다 (§7-12).
- **분모가 설계서의 Trigger Point와 다르면 `차이 — 분모 {화면 정의} vs 설계 {설계 정의}(참고)`로 적는다.** 값을 쓰지 못하게 만드는 사유가 아니라, 두 군이 어느 모집단 위에서 비교되고 있는지를 밝히는 기록이다 (ed §3-6).
- `차트 없음`은 결함이 아니다 — 3순위 실쿼리 재구성으로 내려가고, 그 사실을 7열에 적는다.
- **차트 값과 실쿼리 값이 둘 다 있고 다르면, 둘을 모두 적고 어느 쪽을 썼는지 명시한다.** 평균하지 않는다.

### 3-4. M3a. variant 누적 표 — 7열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | variant | `control` / `treatment` / `treatment_b` … (설계서 프로퍼티 값 그대로) |
| 2 | 노출(n) | Primary 분모 기준 순유저 수 |
| 3 | 전환(Primary 분자) | Primary 분자 기준 건수 |
| 4 | 전환율 | 전환 ÷ 노출, 소수 1자리 % |
| 5 | 설계 분배 비율 | M1 `분배 비율` |
| 6 | 실측 비율 | 노출 ÷ 전체 노출 |
| 7 | 출처 | §2-3의 6형식 중 하나 |

**하드 규칙 — 이 표에 스킬 계산값 열이 없는 것이 규칙이다.**

- **스킬이 계산한 `차이` · `리프트` · `p` · `stat-sig` · `승/패` 열을 이 표에 추가하지 않는다.** 헬스 모드에서 그 숫자가 존재할 자리를 스키마 차원에서 없앤 것이며, 피킹 게이트(§7-6)의 구조적 보장이다. 참가자가 요청해도 추가하지 않는다.
- **Amplitude 화면 표시값은 이 표가 아니라 M3c에 적는다** (§3-4a). 두 표를 나눈 이유가 이것이다 — M3a는 스킬이 조회한 건수, M3c는 화면이 표시하는 값이다.
- 노출은 **전환 수가 아니라 노출 수** 기준이다 (종료 게이트 G2).

### 3-4a. M3c. Amplitude 표시값 표 — 지표 × 군 (v1.1 신설 · 도달 전에도 출력)

**담당자가 세팅한 화면이 표시하는 값을 그대로 옮기는 표다.** 스킬이 계산하지 않고 **읽어서 인용한다** — 그래서 필요 n 도달 전에도 낸다 (§7-6).

**열 구성**: `지표` · `control 기준선` · 그다음 **실험군마다 1열**

| 열 | 내용 |
|---|---|
| 지표 | 화면이 표시하는 지표명 (M2 3열의 차트 제목과 대응) |
| control 기준선 | `{전환율}% ({전환}/{노출})` |
| 실험군 각 열 | `{전환율}% ({전환}/{노출}) · 표시 리프트 {값} · 신뢰구간 {구간} · 표시 판정 {값}` |

**행 커버리지 — 지표 3층 전부다** (v1.1 추가 정정 2026-09-07)

- **설계서의 Primary · Guardrail · Secondary를 전부 행으로 넣는다.** Secondary가 빠진 표는 미완성이다 — 설계서가 Secondary를 정해 둔 이유가 「Primary만으로는 무엇이 움직였는지 모른다」는 것이기 때문이다.
- **행마다 채우는 경로가 다르다.** M2 `설계서 대비`가 판별한다.

| M2 값 | 채우는 경로 | 출처 | 리프트·신뢰구간·표시 판정 칸 |
|---|---|---|---|
| `동일` / `차이 — {내용}(참고)` | **화면 표시값을 그대로 옮긴다** | §2-3 형식 6 + `— 표시값(순차검정)` | 화면 값 그대로 |
| **`화면에 없음`** | **variant별 실쿼리로 채운다** (아래 규칙) | `Amplitude 실쿼리 {이벤트A→B, 필터, 기간}` | **`화면 미표시`** — 🚫 스킬이 계산해 채우지 않는다 (§7-6) |

- **`화면에 없음`인 Secondary의 실쿼리 규칙 (하드)**: **퍼널로 만들고, variant 프로퍼티 `is {값}` 필터를 걸어 군마다 1회씩 따로 조회한다.** 🚫 **group-by(세그먼트 분할)를 쓰지 않는다** — group-by는 라벨이 누락되거나 뒤섞여 어느 값이 어느 군인지 알 수 없는 함정이 있다. 군 수만큼 조회가 늘어나는 것이 의도된 비용이다.
- **분해형 Secondary는 구간 × variant 표로 낸다.** 설계서 Secondary가 「구간별 분해」처럼 한 지표가 아니라 분해 축이면, 행을 구간으로 두고 열을 variant로 둔 별도 표를 M3c에 덧붙인다. 이 표도 실쿼리 규칙을 그대로 따른다.
- 실쿼리로 채운 행은 **전환율(전환/노출)까지가 산출물**이다. 리프트를 계산하면 §7-6 위반이므로, 「Secondary가 어디로 움직였나」는 **두 전환율을 나란히 놓는 것까지**다.

**하드 규칙**

- **화면 표시 행에는 화면에 있는 값만 적는다.** 화면이 리프트를 표시하지 않으면 그 칸은 `화면 미표시`이고, **스킬이 대신 계산해 채우지 않는다** — 그것이 §7-6 위반이다.
- **출처는 행마다 다르다** — 화면 행은 §2-3 형식 6 + `— 표시값(순차검정)`, 실쿼리 행은 형식 5. 표 아래에 경로별로 남긴다.
- **표시 판정 어휘는 화면의 것을 그대로 옮긴다** (`유의하지 않음` 등). 계약 §6의 판정 다섯 어휘(`WIN`/`LOSE`/…)로 번역하지 않는다 — 그 번역이 판정이다.
- **신뢰구간은 「0 포함 여부」를 함께 적는다** — 화면 표시값을 해석하는 유일한 서술이며, 그 이상(왜 그런가·다음에 무엇을)은 §0-1 범위 밖이다.
- 값이 서로 다른 두 화면(대시보드 차트 vs 실험 분석)에서 나오면 **둘을 모두 적고 어느 화면을 썼는지 명시한다.** 평균하지 않는다.

### 3-5. M3b. 헬스 체크 표 — 5열 + 부속 일별 추이 표

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | # | 1~8 고정 |
| 2 | 항목 | 아래 8행 |
| 3 | 정상 기준 | 아래 8행의 기준 |
| 4 | 실측 | 조회값 또는 `확인 불가` |
| 5 | 판정 | `정상` / `⚠️이상` / `확인 불가` |

**행 8개(순서 고정)**

| # | 항목 | 정상 기준 |
|---|---|---|
| 1 | variant 시안 노출 확인 | 사람이 실제 화면에서 각 variant를 직접 확인했다 — **스킬이 판정하지 않고 확인 여부만 받는다** |
| 2 | 데이터 유입 | Primary·Secondary·Guardrail 전 지표에 이벤트가 들어옴 (0건 지표 없음) |
| 3 | 일별 노출 추이 | 예상 일 트래픽의 **±30% 이내** `⚠️확인필요 — 코치 확정` (출처: KB08 8단계-A #2) |
| 4 | 시간대 이상 | 특정 시간대에 노출·전환이 끊긴 구간이 없음 |
| 5 | SRM 카이제곱 p | 설계 비율 대비 유의한 불일치 없음 — **경보 `p < 0.001` / 주의 `p < 0.01`** `⚠️확인필요 — 코치 확정` (출처: KB08 A-4 Kohavi / B-1 Amplitude α=.01) |
| 6 | 중복 노출 / variant jumping | 동일 유저가 양쪽 군에 잡히지 않음 |
| 7 | 장애 수준 Guardrail | 결제 실패율·에러율·로딩시간에 급변 없음 |
| 8 | 수집 최소 요건 | variant별 **25전환 + 100노출** 이상 `⚠️확인필요 — 코치 확정` (출처: KB09 B-2 Amplitude) |

**부속 일별 추이 표 — 3열**: `일자` · `노출 control·treatment` · `비고`

- 런칭일부터 오늘까지 1일 1행. `노출 control·treatment` 열은 두 값을 `/`로 구분해 한 칸에 적는다 (셀 안 줄바꿈 금지 — §5).
- `비고`에는 스파이크·다운·릴리즈·프로모션·장애를 적는다. **이 열이 §7-11 「외부 이벤트」(G4) 판정의 근거다.**
- **일별 추이 표에도 전환율을 넣지 않는다** — 노출만 본다. 일별 전환율은 사실상 매일 판정이다.
- 5번 SRM은 **절대 비율 차이(예: 48:52)로 판단하지 않는다.** 반드시 카이제곱 통계량·p로 판정한다 (§7-3) — 저트래픽에서는 검정력이 낮아 실제로 깨져도 안 잡히고, 반대로 표본이 작으면 우연한 변동이 크게 튄다.
- 1번은 **사람의 확인을 받는 행이다.** 확인을 받지 못하면 `확인 불가`이며, 스킬이 「노출되고 있을 것」으로 채우지 않는다.

### 3-6. M4. 진행률 표 — 6열 + 하단 4줄

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | variant | M3a와 같은 값 |
| 2 | 누적 n | M3a 노출(n) — **램프업 구간 제외** (§7-8) |
| 3 | 필요 n | M1 `variant별 필요 n` |
| 4 | 진행률 | 누적 n ÷ 필요 n, 정수 % |
| 5 | 예상 도달일 | 최근 7일 평균 일 유입 기준 산출일. 산출 불가면 `확인 불가` |
| 6 | 비고 | 램프업 제외 건수 · 가장 작은 군 표시 |

**하단 4줄(순서 고정)**

1. **최소 관찰 충족**: `충족` / `미충족 — {잔여 일수}` (M1 `최소 관찰 기간` 대비)
2. **요일 주기 포함**: `1회 이상 포함` / `미포함 — {시작·종료 요일}`
3. **조기 종료 조건 도달** (v1.1 신설): `미도달` / `도달 — {조건} (화면 표시 {값})` / `조건 없음 — ⚠️확인필요` — M1 `조기 종료 조건(숫자)`을 **M3c 화면 표시 리프트와 대조**한다. **도달 사실만 적고 중단 결정은 하지 않는다** (§7-12).
4. **보고 문장 (고정 — 변경 금지)**: 「샘플 목표 대비 진행률 XX%, 예상 종료일 M/D, 헬스 이상 {없음/있음}.」

**하드 규칙**

- **조기 종료 조건 대조가 v1.1에서 가능해졌다** — 화면 표시 리프트를 도달 전에도 인용할 수 있게 됐기 때문이다 (§7-6). 설계서 조건이 「군당 500명 시 −8%p」 형태면 표본 조건과 리프트 조건을 **둘 다** 확인해 적는다.
- **보고 문장에 리프트를 넣지 않는다.** 말하는 순간 팀 전체가 피킹을 시작한다 (KB08 8단계-B). 문장의 형태를 바꾸지 않고, 세 칸만 채운다. **화면 표시 리프트는 3줄과 M3c에 적고, 이 고정 문장에는 넣지 않는다.**
- **모드는 여기서 확정된다.** 전 variant 진행률 100% 이상 **AND** 최소 관찰 충족 **AND** 요일 주기 포함 **AND** SRM 정상 → `판정`. 하나라도 미달이면 `헬스`.
- 「SRM 정상」은 **경보(alarm, p<0.001 후보)가 아님**을 뜻한다. **주의(warn, 0.001≤p<0.01 후보)는 판정 모드를 막지 않되** M3b #5에 `⚠️이상`으로 남기고 M5c 판정 근거에 병기한다 (⚠️확인필요 — 코치 확정).
- **진행률 병목은 가장 작은 군이다.** 전체 합계 진행률로 도달을 선언하지 않는다 (ed §7-17 승계).
- **진행률이 100%를 넘어도 종료를 강제하지 않는다.** 종료 판정은 M5·§7-11이 하고, 이 표는 게이트를 열어 주기만 한다.

### 3-7. M5a. 원표 — 4열 (판정 모드에서만)

**열**: `군` · `노출` · `전환` · `전환율`

- **지표별로 표를 따로 낸다** — Primary 1개 + Guardrail 각 1개 + Secondary 각 1개. Primary 표를 먼저 낸다.
- `군` 값은 2군이면 `대조군` / `실험군`이다. **다군이면 스크립트 라벨은 `실험군1`·`실험군2`(번호)이며, M5a `군` 열에는 이 라벨을 그대로 쓰고 표 아래 1줄에 `실험군1 = {variant 프로퍼티 값}` 대응을 밝힌다** — `실험군 B` 같은 알파벳 표기는 쓰지 않는다.
- KB09 템플릿 1의 `[원표]` 자리와 같은 내용이다 — **역산 검증**(보고서 lift와 일치하는지)을 표 아래 1줄로 남긴다.

### 3-8. M5b. 통계 표 — 2열 (항목/값)

**행 10개(순서 고정)**: `절대 차이(%p)` · `상대 리프트` · `z` · `p(양측)` · `stat-sig(1−p)` · `95% CI(미풀링)` · `베이지안 P(실험군>대조군)` · `MDE 달성` · `다중비교 보정` · `Amplitude 엔진 표시값(참고)`

- `scripts/statsig.py`의 md 출력은 이 10행(`Amplitude 엔진 표시값(참고)`은 `—`)을 낸 뒤 부속 4행(`SRM 카이제곱 p` · `SRM 판정` · `모드` · `판정`)을 덧붙인다 — 부속 4행은 M5b에 옮기지 않고 각각 M3b #5 · M4 모드 · M5c 판정에 옮겨 적는다. `Amplitude 엔진 표시값(참고)`은 스킬이 대시보드에서 읽어 채운다.
- **행 이름을 바꾸지 않는다.** 이 행 이름은 `scripts/statsig.py`의 md 출력과 **문자 단위로 일치**해야 한다 — 스킬이 계산 결과를 옮겨 적을 때 이름이 다르면 대조가 끊긴다.
- `MDE 달성`: `달성` / `미달` — 실측 절대 차이가 M1 `MDE(abs)` 이상인가. **유의성과 별개의 질문이다.**
- `다중비교 보정`: `해당 없음(2군)` / `Bonferroni α={값}({K}비교)` / `⚠️확인필요` — M1 `판정 군 수`가 3 이상이면 보정 없이 판정하지 않는다.
- `Amplitude 엔진 표시값(참고)`: 도구가 자체 계산해 보여주는 값을 **참고로만** 병기한다. Amplitude는 유의성을 **`1 − p-value`** 로 표시하므로, 이 계약의 `stat-sig(1−p)`와 같은 축이다 (KB09 B-3). **엔진 값이 이 표의 계산과 다르면 둘을 모두 적고 차이를 `코치 확인 필요`로 남긴다** — 어느 쪽으로도 단정하지 않는다.
- 값이 없는 행은 `—`로 둔다. **헬스 모드에서는 이 표 전체를 출력하지 않는다** (§7-6).

### 3-9. M5c. 판정 표 — 2열 (항목/값)

**행 4개(순서 고정)**: `Guardrail 전부 허용 내` · `판정` · `판정 근거(흐름도 경로)` · `So Next 후보`

| 행 | 값 도메인 |
|---|---|
| Guardrail 전부 허용 내 | `예` / `아니오 — {지표명} {실측} vs 허용 {기준}` |
| **판정** | `WIN` / `LOSE` / `INCONCLUSIVE` / `지속` / `실험 설계 잘못됨` |
| 판정 근거(흐름도 경로) | §7-11 흐름도의 분기를 **밟은 순서대로** 적는다 |
| So Next 후보 | `전면 반영` / `수정 후 재실험` / `폐기` / `연장` — **복수 허용, 확정은 사람** |

**하드 규칙**

- **판정은 Primary 하나로만 한다.** Secondary·Guardrail의 유의성은 판정 조건이 아니다 — 다만 **Guardrail이 허용 기준을 벗어나면 `WIN`이 되지 못한다**(그 경우 판정은 `INCONCLUSIVE`이며 별도 이름을 붙이지 않는다 — §7-11).
- **`WIN`은 3조건 전부일 때만이다** — `stat-sig 유의` AND `실험군 > 대조군` AND `실측 차이 ≥ 설계 MDE` AND `Guardrail 전부 허용 내`. 하나라도 미달이면 `WIN`이라 부르지 않는다.
- **`판정 근거`가 비어 있으면 판정을 출력하지 않는다.** 「유의했으니 WIN」은 근거가 아니다 — 흐름도의 어느 경로를 어떤 값으로 밟았는지가 근거다.
- **`So Next 후보`는 후보다.** 스킬이 하나로 좁히지 않고, why 서술도 하지 않는다 (§0-1 — 결과 보고서 범위 밖).
- 단순 수치 비교(「A가 B보다 높음」)는 판정이 아니다 (8/10 세션 블록 D-1).

- 등급을 스킬이 올리거나 내리지 않는다 — 위 기본 등급을 그대로 쓰고, 관측 내용만 채운다.

### 3-11. M7a. 노션 4장 블록 ★ 착지 (코드블록)

노션 실험설계서 페이지 **4장(실험 결과)** 에 붙일 내용을 **코드블록(raw markdown)**으로 출력한다 — 참가자가 붙여넣는다.

| 모드 | 블록 형태 |
|---|---|
| **헬스** | 소절 제목 「실험 진행 중 — 헬스 로그 {일자}」 + M4 고정 보고 문장 1줄 + M3b `⚠️이상` 행만 + 다음 확인 예정일 |
| **판정** | KB09 **템플릿 1(결과 판정 시트)** 골격 — `[원표]`(M5a) → `절대·상대 개선폭` → `역산 검증` → `[통계]`(M5b) → `[가드레일]` → `판정`·`가드레일 게이트` |

- **헬스 블록에 원표를 넣지 않는다.** 진행률과 이상 여부까지다.
- 판정 블록은 **템플릿 1의 항목 순서를 바꾸지 않는다.** 항목이 비면 `⚠️미정`으로 남긴다.
- **기존 4장 내용을 덮어쓰지 않는다** — 추가·정정분만 담고, 충돌하면 `기존: … → 정정: …`으로 표기한다 (ed §3-9 승계).
- 4장에 소절이 없으면 **소절 제목을 블록 안에 포함해 출력하고** 「이 소절은 이 페이지에 없으므로 새로 만들어 붙여넣으세요」를 한 줄 병기한다.

### 3-12. M7b. repo EXP 파일 블록 ★ 착지 (코드블록)

`50_reference/experiment-template.md`의 `## 2. 실행 기록` · `## 3. 결과`에 붙일 내용을 출력한다. **`## 1. 설계`와 `## 4. 학습`은 건드리지 않는다.**

| 대상 | 내용 |
|---|---|
| `## 2. 실행 기록` — 헬스 로그 | **1일 1줄 append** — `{YYYY-MM-DD} · 노출 c {n}/t {n} · 헬스 {정상\|이상: 항목} · 진행률 {XX}%` |
| `## 2. 실행 기록` — 진행률 로그 | **주 1회 1줄** — M4 고정 보고 문장 그대로 |
| `## 2. 실행 기록` — 병행 릴리즈 | `겹치는 항목` · `혼입 판단` 두 줄 (M6 #10 결과) |
| `## 3. 결과` — 결과 표 | 템플릿 **5열**: `층` · `지표` · `대조군` · `실험군` · `차이` · `비고` |
| `## 3. 결과` — 하단 | `판정`(M5c) · `표본·기간` · `저모수 대체 판정`(CI·베이지안 병기 시) · `예상 대비` |
| status 안내 | `draft → running`(런칭 확인 시) / `running → final`(판정 확정 시) — **파일은 스킬이 쓰지 않는다** |

- **결과 표는 `## 3. 결과`의 기존 5열 형식으로 변환해 넣는다.** 템플릿의 열을 늘리거나 줄이지 않는다.
- **`## 3. 결과`는 판정 모드에서만 낸다.** 헬스 모드는 `## 2`의 1줄 append까지다.
- 코드블록 안에 코드블록이 중첩되므로, 출력 시 **바깥 펜스를 4백틱(````)으로 연다** (ed §3-10 승계).
- **착지는 git SSOT이고, 커밋은 코치 또는 서기가 한다.** 스킬은 블록만 출력하고 파일에 쓰지 않는다 (§7-12).
- 채우지 못한 칸은 지우지 않는다 — `⚠️미정` 또는 `코치 확인 필요`로 남긴다.

### 3-13. M7c. 속성 변경 안내 표 — 4열 (판정 모드)

**열**: `속성` · `현재값` · `변경값` · `비고` (ed §3-11 E8c와 같은 형식)

| 속성 | 안내 |
|---|---|
| 진행상태 | `실험설계 완료` → `실험 진행중`(런칭 후) / `실험 종료`(판정 확정 후). **`실험 진행중`은 노션 select에 이미 있다** (v1.1 정정) — `현재값`에 조회한 실제 값을 적고 `변경값`에 목표 어휘를 적는다. **속성 변경은 여전히 사람이 한다** (§7-12) |
| 실험번호 | 변경 없음 — 확인만 |
| 점수 총합 | **formula — 직접 입력 금지** |

- **select 어휘를 없다고 미리 단정하지 않는다** (v1.1 정정). `실험 진행중`은 이미 존재하므로, 스킬은 **현재값을 확인만** 한다. **목표 어휘가 실제로 select에 없을 때만** `변경값`에 `⚠️확인필요 — select 어휘 추가 필요(사람)`로 낸다.
- **없는 select 값을 있는 것처럼 쓰지 않는다** — 확인하지 못했으면 `현재값`을 `확인 불가`로 둔다.
- ICE(I/C/E) 속성은 이 표에 넣지 않는다 — 모니터링은 ICE를 건드리지 않는다 (§7-12).

## 7. 공식 · 판정 규칙 (정본 — 위반 금지)

> **⚠️ 임계값 6항목은 이 계약이 확정하지 않았다 — 코치 확정 대기.** 아래는 **후보**이며 본문에서 쓰일 때마다 `⚠️확인필요 — 코치 확정`을 병기한다. **확정 전에는 이 값으로 종료를 선언하지 않는다** — 도달 사실만 보고하고 판단은 코치가 한다. 반면 **7-6·7-7·7-8·7-9·7-10·7-12·7-13은 임계값이 아니라 규칙이므로 확정 대기 대상이 아니다** — 즉시 적용한다. (v1.1: 7-10은 하드 게이트에서 **권고**로 격하됐고, 7-13이 신설됐다.)
> 1. **SRM 경보 임계** `p < 0.001` 경보 / `p < 0.01` 주의 — KB08 A-4(Kohavi 게이트) / B-1(Amplitude sequential chi-squared α=.01) → M3b #5 · §7-3
> 2. **지속 판단 임계** stat-sig ≥ 80% — 우디 덱 슬라이드 5 「실험종료 프로세스」 → §7-11
> 3. **연장 횟수 제한** 1회 + 종료일 재고정 — KB08 9단계 연장 결정 기준(덱에는 없음 → 제안) → §7-11
> 4. **노출 추이 이상** 예상 일 트래픽 ±30% — KB08 8단계-A #2 → M3b #3
> 5. **수집 최소 요건** variant별 25전환 + 100노출 — KB09 B-2(Amplitude) → M3b #8
> 6. **베이지안 병행 해석** 50~70% 보류 / 70~90% 신중 / 90%+ 강한 신호 — KB09 §4 → §7-4

**7-1. two-proportion z 검정 (풀링 SE) → 양측 p.** (KB09 §1 정본)

```
p̂_c = 전환_c / 노출_c
p̂_t = 전환_t / 노출_t
p̄   = (전환_c + 전환_t) / (노출_c + 노출_t)          # 풀링 전환율
SE  = √( p̄ · (1 − p̄) · (1/노출_c + 1/노출_t) )
z   = (p̂_t − p̂_c) / SE
p   = 2 · (1 − Φ(|z|))                              # 양측
  Φ = 표준정규 누적분포
  |z| > 1.96 ≈ p < 0.05
절대 차이(%p) = (p̂_t − p̂_c) × 100
상대 리프트(%) = (p̂_t − p̂_c) / p̂_c × 100
```

**7-2. 95% 신뢰구간 (미풀링 SE).** 차이의 구간이며, **p와 다른 질문에 답한다** — p는 「차이가 0일 리 없는가」, CI는 「차이가 얼마쯤인가」다.

```
SE_diff = √( p̂_c(1 − p̂_c)/노출_c + p̂_t(1 − p̂_t)/노출_t )   # 미풀링
CI95    = (p̂_t − p̂_c) ± 1.96 × SE_diff
```

- **해석 순서**: ① 0을 포함하는가 → ② 넓은가 → ③ 대부분 양수인가. 0을 포함하면 유의한 차이가 없다 (KB09 B-3). **7-1의 SE(풀링)와 7-2의 SE(미풀링)는 다른 값이다** — 같은 SE로 둘을 계산하지 않는다.

**7-3. SRM — 카이제곱 적합도 검정 (설계 비율 대비).**

```
E_i = 전체 노출 × 설계 비율_i                        # 기대 노출
χ²  = Σ (O_i − E_i)² / E_i                          # O = 실측 노출
df  = k − 1                                          # k = 판정 군 수
p   = 1 − F_χ²(χ², df)
```

- **절대 비율 차이(%)만 보고 판단하지 않는다** — 반드시 χ²·p로 판정한다 (KB08 A-3).
- 경보 `p < 0.001` / 주의 `p < 0.01` `⚠️확인필요 — 코치 확정` (출처: KB08 A-4 Kohavi 게이트 / B-1 Amplitude sequential chi-squared α=.01).

**7-4. 베이지안 승자확률 — Beta(1,1) 사후.**

```
사후_c ~ Beta(1 + 전환_c, 1 + 노출_c − 전환_c)
사후_t ~ Beta(1 + 전환_t, 1 + 노출_t − 전환_t)
P(실험군 > 대조군) = Pr[ θ_t > θ_c ]
  균등 사전 Beta(1,1) 고정
  몬테카를로로 계산할 경우 seed를 고정해 재현 가능하게 한다
```

- 병행 해석 구간: `50~70% 보류` / `70~90% 신중` / `90%+ 강한 신호` `⚠️확인필요 — 코치 확정` (출처: KB09 §4 베이지안 승자확률 해석 기준). **「베이지안이면 아무 때나 봐도 된다」는 과장이다** (KB08 A-2 ③). 정지 규칙은 여전히 해석에 영향을 주며, 이 계약에서 베이지안은 **저트래픽 병행 해석용 보조**이고 §7-6을 풀어 주지 않는다.

**7-5. stat-sig 표시.** `stat-sig(%) = (1 − p) × 100`. Amplitude가 유의성을 `1 − p-value`로 표시하므로 축을 맞춘 것이다 (KB09 B-3). **95% = p 0.05 · 80% = p 0.20**에 대응한다.

**7-6. 피킹 게이트 (하드 — 스킬 자체 계산에만).** **필요 n 도달 전에는 스킬이 고정표본 통계를 계산해 승패를 부르지 않는다** — 대상은 `scripts/statsig.py`가 내는 차이·리프트·z·p·CI·베이지안·`WIN`/`LOSE` 판정이다 (v1.1 재정의).

- **Amplitude 화면이 표시하는 리프트·신뢰구간·유의성은 도달 전에도 항상 인용한다.** 근거: Amplitude Experiment의 유의성 표시는 **순차검정(mSPRT)** 기반이라 중간에 읽어도 위양성이 통제된다 (KB09 B). 인용할 때는 출처에 **「Amplitude 표시값(순차검정)」** 을 붙여 스킬 계산값과 구분하고, M3c에 적는다 (§3-4a).
- **금지되는 것은 스킬의 고정표본 계산이고, 순차검정으로 설계된 화면 표시값이 아니다.** 고정표본 검정(§7-1·§7-2)은 「표본을 사전 고정하고 그 시점에 1회 검정」을 전제로만 유효하다. 그 전제를 깨고 매일 계산하면 잘못된 승자 채택 확률이 **+57%**, 5회 확인 시 위양성률 약 15% · 20회 약 30%로 올라간다 (KB08 A-1 · 8/10 세션 C-2).
- 참가자가 「지금 이기고 있나요」로 물으면 **거부가 아니라 대사 정본 ⑥**이다 — 화면 표시값을 그대로 읽어 주고, **스킬의 WIN/LOSE 판정만 필요 n 도달 후로 미룬다** (§3-9 · §7-11).
- **스킬 계산의 예외는 하나뿐이다** — M1 `순차 검정 사전 선언 여부`가 `있음`이고 그 규칙이 **실험 시작 전에 설계서에 적혀 있는** 경우. 사후에 꺼내 쓰면 그냥 피킹이다.
- **α를 결과를 본 뒤 옮기지 않는다. 종료 시점도 결과를 본 뒤 옮기지 않는다.** 판정 조작이다.

**7-7. SRM 우선 (하드).** **SRM 경보가 있으면 게이트 도달 여부와 무관하게 판정 필드를 출력하지 않는다.**

- SRM은 「배분이 틀어졌다」는 신호이자 거의 모든 경우 **데이터 신뢰도 전체를 무너뜨리는 신호**다. 리프트가 아무리 예뻐도 그 결과는 쓰지 않는다 (KB08 8단계-A).
- Kohavi 등은 이를 조직 차원의 게이트로 명시한다 — **SRM이 감지된 실험은 결과 대시보드를 자동으로 숨긴다.** 이 계약의 M5 마스킹이 그 경량 버전이다.
- 종착은 §7-11의 「실험 설계 잘못됨」이며, 원인 진단 순서는 대사 정본 ⑤에 있다. **원인 불명 SRM의 기본값은 출시 보류다.**

**7-8. 램프업 구간 제외 (하드).** **램프업 구간과 설정 변경 구간의 관측치는 M4 누적 n과 M5a 원표에서 제외한다.**

- 램프업 구간은 노출 조건이 본 실험과 다르다 — ed §3-8이 「램프업 구간 관측치는 판정에 쓰지 않는다」로 못 박은 것과 같은 규칙의 실행면이다.
- 제외 건수를 **M4 `비고`에 남긴다.** 제외했다는 사실이 보이지 않으면 제외하지 않은 것과 구분되지 않는다.
- 배분 변경·variant 추가/제거·sticky bucketing 토글 이력이 있으면 **제외가 아니라 §7-11 종착이다** (M6 #6·#7·#8).

**7-9. PII 집계만 (하드).** **원천 PII를 어떤 표에도 옮기지 않는다.** 발견하면 값을 출력하지 말고 위치만 말한다.

- **Chrome으로 대시보드·노션을 여는 경로에서도 같다.** 화면에 개별 사용자 행(이름·연락처·증권번호·보험료·계약 정보)이 보이면 **집계값만** 옮기고 개별 행은 읽지 않는다. 「읽기 예외」는 접근 경로의 예외이고, **PII 규칙의 예외가 아니다.**
- 금융·보험 도메인 기본 제약이며, 참가자 동의로 풀리지 않는다.

**7-10. 매핑 기록 (권고).** **담당자가 세팅한 화면의 지표 정의를 그대로 기록하고, 설계서와 다른 점은 참고로 남긴다.** (v1.1 — v1.0의 「정의 일치(하드)」에서 격하)

- **M2 `설계서 대비` 열에 `동일` / `차이 — {내용}(참고)` / `설계서에 없음` / `화면에 없음`을 적는다.** 차이가 있어도 **M5를 막지 않는다** — v1.0의 하드 게이트(「Primary 불일치면 M5 금지」)는 폐지됐다.
- **화면에 없는 지표만 실쿼리로 재구성한다** (§7-12). 화면에 있는 지표를 다시 조회해 대조하지 않는다. **실제로 이 경로를 타는 것은 대개 화면에 등록되지 않은 Secondary다** — 조회 방법은 §3-4a가 정한다(퍼널 + variant 프로퍼티 `is` 필터로 군마다 1회, **group-by 금지**).
- 설계서↔세팅 차이는 **리포트 끝 「참고」 1줄**로만 남긴다 (§7-13). 전환창 미기재 · 군 수 다름 · 배분 다름 · 배타 조건 다름이 그 예다.
- **분모가 설계서의 Trigger Point와 다르면 그 사실을 기록한다** — 노출 정의가 곧 분모이므로, 어느 모집단 위에서 비교되고 있는지가 참고 1줄의 내용이 된다.
- KB08 8단계-A #7과 같은 항목이지만, **처방이 달라졌다** — v1.0은 「값을 쓰지 말라」였고 v1.1은 「무엇이 다른지 적고 화면 기준으로 진행하라」다. 재집계 요청은 담당자 판단 사항으로 넘긴다.

**7-11. 종료 흐름도 (정본).** 판정은 **이 흐름도를 밟은 경로로만** 내린다. 경로 없이 나온 판정은 판정이 아니다.

```
진행 → [모든 variant 누적 n ≥ 필요 n AND 최소 관찰 기간 AND 요일 주기 ≥1회]?
  아니오 → 지속 (헬스 모드, 예상 도달일만 보고)
  예 → [SRM 정상]?  아니오 → 「실험 설계 잘못됨」 종착 (리프트 불문, 결과 불사용)
     예 → [Primary stat-sig ≥ 95%]?
        예 · 실험군 > 대조군 · MDE 달성 · Guardrail 전부 허용 기준 안 → WIN 종료
        예 · 실험군 < 대조군                                          → LOSE 종료
        예 · 그 밖(MDE 미달 또는 Guardrail이 허용 기준을 벗어남)      → INCONCLUSIVE 종료
        아니오 → [stat-sig ≥ 80% AND 지속 시 결과가 변할 수 있고 자원 trade-off 수용]?
              예 → 지속 (연장, 종료일 재고정)   /   아니오 → INCONCLUSIVE 종료
```

- 첫 분기는 **종료 4게이트 G1~G3**이고, **G4(기간 중 외부 이벤트 없음)** 는 M6 #14로 별도 확인한다 — G4가 깨지면 해당 구간을 제외하고 재집계하거나 재실험을 검토한다 (KB08 9단계 · 8/10 세션 C-3).
- **`INCONCLUSIVE`는 하나다 — 별도 이름을 붙이지 않는다.** 유의하지 않은 경우, MDE에 못 미친 경우, Guardrail이 허용 기준을 벗어난 경우가 **같은 종착**이다. 「가드레일 때문에 못 쓴다」와 「차이를 확인하지 못했다」는 **다음에 할 일이 같기 때문에**(고치고 다시 하거나 접는다) 판정을 쪼개지 않는다. 어느 경로로 왔는지는 `판정 근거`에 남고, Guardrail 실측은 M5c 첫 행에 남는다.
- 🚫 **「위반」이라는 말을 쓰지 않는다.** Guardrail은 규칙이 아니라 **허용 범위**이므로, 벗어난 상태는 `아니오 — {지표명} {실측} vs 허용 {기준}`으로 적는다.
- 「유의성이 나올 때까지 기다린다」는 종료 기준이 아니고, 「p<0.05가 떴으니 지금 끝내자」도 종료 사유가 아니다.
- 지속 판단 임계 `stat-sig ≥ 80%` `⚠️확인필요 — 코치 확정` (출처: 우디 덱 슬라이드 5 「실험종료 프로세스」). 연장은 **1회 + 종료일 재고정** `⚠️확인필요 — 코치 확정` (출처: KB08 9단계 연장 결정 기준 — 덱에는 없어 제안). **무기한 연장 금지**이며, 연장하면 새 종료일을 못박고 그 날짜를 다시 지킨다.

**별도 종착 「실험 설계 잘못됨」 트리거** (하나라도 해당하면 리프트 불문 결과 불사용)

**7-12. 스킬이 하지 않는 것 (하드).**

노션·EXP 파일 **직접 기입**(읽기는 §2-3 예외로 허용, 쓰기는 어느 경로로도 안 한다) · 노션 select 어휘 **추가** · Amplitude 실험 **설정 변경**(배분·variant·플래그·on/off) · **조기 종료 결정**(조건 도달 사실만 보고하고 결정은 사람) · **설계값 수정·재계산**(필요 n · MDE · Target · Baseline · 지표 3층 · 종료 기준 = ed 소관) · ICE 재산정 · BIAS 재진단 · **결과 보고서의 why 서술과 So Next 확정** · 존재하지 않는 차트·수치·이벤트명·URL 생성 · **필요 n 도달 전 스킬 자체의 승패 판정**(화면 표시값 인용은 제외 — §7-6).

- **담당자 세팅을 재감사하지 않는다** (v1.1 추가). 지표 정의·군 수·배분·전환창·배타 조건이 설계서와 달라도 **세팅을 고치라고 요구하지 않고, 게이트로 막지 않고, 대조 재쿼리를 돌리지 않는다.** 차이는 **리포트 끝 「참고」 1줄**로 남기고 화면 기준으로 모니터링한다 (§7-10 · §7-13).

**7-13. 기본 리포트 규칙 (하드 — v1.1 신설).** **기본 산출물은 5블록 「기본 리포트」이고, M0~M7 전체 표는 「상세」를 요청받을 때만 낸다.**

**5블록 순서 고정**

| 블록 | 내용 | 값의 출처 |
|---|---|---|
| ① variant별 트래픽 | 표(`variant` · `노출` · `비중`) + SRM 1줄(카이제곱 p · 화면 자체 SRM 표시) | M3a · M3b #5 |
| ② 지표별 전환율 | 표(`지표` · `control` · 실험군별 `전환율(전환/노출) · 표시 리프트`) — **Primary·Guardrail·Secondary 전부**를 행으로 넣는다. 화면 미등록 Secondary는 variant별 실쿼리로 채우고 출처를 `Amplitude 실쿼리`로 표기하며 리프트 칸은 `화면 미표시`다 (§3-4a) | **M3c** |
| ②′ 분해형 Secondary | 설계서 Secondary가 「구간별 분해」류면 **구간 × variant 표**를 ② 바로 아래에 덧붙인다 (§3-4a) | **M3c** 부속 |
| ③ 유의성 | 1~3문장 — 신뢰구간 0 포함 여부 · 화면 표시 판정 | **M3c** (「Amplitude 표시값(순차검정)」 출처 병기) |
| ④ 진행률·종료 판단 | 필요 n 대비 %, 예상 도달일, 설계서의 다음 점검일, 조기 종료 조건 도달 여부, **결론 1줄** | M4 표 + 하단 4줄 |
| ⑤ 이상 징후 | **있는 것만 불릿.** 없으면 「세팅 이상 없음」 | M3b `⚠️이상` 행 + M6 `있음` 행 |
| 「참고」 | **설계서↔세팅 차이 1줄 — 있을 때만** | M2 `설계서 대비` 열의 `차이` 값 |

- **길이 상한: 표 3개 + 불릿 10개 이내** (v1.1 추가 정정 — Secondary 표와 분해형 표가 늘어난 만큼 조정). 넘으면 상세 모드로 넘겨야 하는 분량이다.
- **결론 1줄 어휘는 셋뿐이다** — `실험 지속` / `담당자 판단 필요 — {사유}` / `종료 판정 가능`. 새 어휘를 만들지 않는다 (§6).
- **「참고」는 마지막 1줄이고 블록이 아니다.** 차이가 없으면 아예 쓰지 않는다.
- 블록 ②·③은 **화면 표시값**이고, 블록 ④의 종료 판단은 **표본 조건**이다. 두 근거를 섞어 승패를 부르지 않는다 — 스킬의 `WIN`/`LOSE`는 M5까지 미룬다 (§7-6 · §3-9).
