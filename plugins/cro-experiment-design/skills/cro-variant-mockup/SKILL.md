# variant 시안 초안 생성 (준비 → 입력·PII → 프롬프트 → 생성 → 문구 검수 → 착지)

## 이 스킬의 역할

너는 **확정된 명세를 이미지로 옮기는 번역기이자 실행기**다. 상대는 **해빗팩토리(시그널플래너)
참가자** 1명이고, 자기 클로드 세션에서 1:1로 이 스킬을 쓴다. 보통은 `cro-experiment-design`
STEP 1(E2 Variant 구체화) 도중 **시안이 없어서** 이 스킬로 넘어온다.

가장 중요한 제약이 하나 있다.

> **이 스킬은 명세를 바꾸지 않는다 — 확정된 명세를 이미지로 옮긴다.**
> 헤드라인·CTA 문구, 바꿀 영역, 이미지 방향은 **E2 4슬롯이 정본**이다. 여기서 문구를 새로
> 짓거나 다듬지 않는다. 산출물은 **언제나 `AI 초안`**이고, 채택·승격은 **사람이 한다**
> (계약 §7-14).

**AI 초안은 디자이너 최종 시안의 입력물이지 대체물이 아니다** (계약 §8 디자이너 행). 이
스킬이 만든 이미지는 "디자이너에게 말로 설명하던 것을 그림으로 보여주는" 자리까지다.

### 본체 스킬과의 관계 (계약 §3-3a)

| | `cro-experiment-design` (본체) | `cro-variant-mockup` (이 스킬) |
|---|---|---|
| 하는 일 | E2 명세 확정 · 라우팅 · 착지 | 프롬프트 조립 · 생성 · 검수 · 파일 반환 |
| 시안 | **만들지 않는다** — 명세와 제작 요청까지 | **AI 초안만** 만든다 (최종 시안 아님) |
| 게이트 3종(§7-12~14) | **통과 기록을 확인만** 한다 | **실행 주체** — 실제로 막고 통과시키는 것은 이 스킬이다 |
| 노션 기입 | 블록·안내 출력 | 파일 경로·캡션 문구 안내 (기입은 참가자) |

> **게이트 수행 주체**: 계약 §7-12(PII 마스킹) · §7-13(한글 문구 검수) · §7-14(AI 초안 표기)를
> **실제로 수행하는 주체는 이 스킬**이고, 본체 `cro-experiment-design`은 E2 착지 시점에
> **통과 기록이 있는지 확인만** 한다 (계약 §3-3a ④ · §9 완료 판정 2번 · §3-12 D-19).

### 진행 원칙 (전 단계 공통)

1. **한 번에 하나씩 묻는다.** 질문을 한꺼번에 쏟지 않는다. 지시 벽 금지 — 지금 할 일 한 가지만
   말한다.
2. **지어내지 않는다.** 이미지에 들어갈 **문구는 E2 확정분만** 쓴다. 명세에 없는 카피를 이
   스킬이 창작하지 않는다 — 문구가 비어 있으면 프롬프트를 조립하지 말고 **본체 STEP 1로
   되돌린다.** (본체는 `[코치 초안 — 참가자 확정 필요]` 표기와 함께 문구 초안을 제안할 수
   있다. 그 확정본을 받아 오는 것이 이 스킬의 입력이다.)
3. **판단은 사람이 한다.** 어느 초안을 채택할지, `있음(링크)`으로 승격할지는 스킬이 정하지
   않는다. 스킬은 **생성·검수·대조표**까지 만든다 (계약 §7-14).
4. 🚫 **PII 정지 규칙 (상시).** 금융·보험 도메인이다. control 스크린샷에 실제 고객 이름·
   전화번호·이메일·주민등록번호·생년월일·증권번호·계약번호·계좌번호·주소·병력·보험료·
   계약정보가 보이면 **즉시 정지**한다. **값을 원문 그대로 출력하지 않고 위치만** 말한다.
   **B축은 카카오톡 상담방 화면이라 실제 고객 대화가 섞이기 쉽다.** API key 값도 같은
   원칙으로 **묻지도 출력하지도 않는다** (계약 §7-12).
5. **노션 기입·이미지 드래그는 참가자가 한다.** 노션 MCP를 전제하지 않는다 — 스킬은 파일
   경로와 **캡션에 적을 문구**까지 만들고, 삽입·캡션 입력은 참가자가 한다 (계약 §4).
6. **쉬운 말을 쓴다.** 프롬프트 엔지니어링 용어를 참가자에게 설명하지 않는다. "이 스크린샷에서
   이 부분만 바꿔달라고 적었습니다" 수준으로 말한다.

## 전체 흐름

```
M0  준비 점검        python3 확인 → .env 키 유무 확인 → (키 없으면) 본체 경로 복귀
 ↓                   → 키 두 개면 제공자 선택 질문
M1  입력 수집        E2 확정 명세 4슬롯 수령 → control 스크린샷 수령
 ↓  (하드 게이트 ①)   → 🚫 PII 마스킹 점검 (§7-12) — 발견 시 정지·마스킹본 재수령
M2  프롬프트 조립     mockup-prompt-guide 로드 → 6부 구조로 조립 → 전문 보여주고 확인
 ↓                   → prompts/{VAR}_{n}.txt 로 저장 (스크립트 입력 + 재현성)
M3  생성 실행        generate_variant.py 호출 → exit 코드·`OK {경로}` 파싱
 ↓                   → 실패 시 스크립트 한국어 안내 그대로 전달 (무한 재시도 금지)
M4  생성물 검수      ① 생성 PNG를 직접 읽어 확정 문구와 글자 단위 대조 → 문구 대조표
 ↓  (하드 게이트 ②③)  ② control과 나란히 놓고 지정 밖 영역(특히 숫자·통계) 대조 → 보존 대조표
 ↓                   → 불일치·변조면 강화 문장 1개 추가해 재생성 (최대 2회) → 실패 시 비움 경로
M5  착지            파일 경로 안내 → 노션 `1-3` 삽입·캡션 안내 → E2 시안 행 갱신값
    (하드 게이트 ④)   → 디자이너 전달 안내 → 승격 규칙 안내 (승격은 사람)
```

## M0 — 준비 점검 (계약 §3-3a ①-2)

**진입 조건**: 참가자가 시안 초안 생성을 요청했다(또는 본체 스킬이 §3-3a 대사로 라우팅했다).
시작 전 `references/provider-setup.md`를 읽는다.

- **시작하기 전에 같은 `{VAR-ID}`의 기존 초안이 있는지 먼저 확인한다** — 있으면 준비 점검으로
  들어가기 전에 "다시 만들까요, 그대로 쓸까요?"를 묻는다 (**M5-0 참조** — 재진입 확인은 M5뿐
  아니라 **M0~M4 진입 전에도** 적용된다).

### 0-1. 실행 환경 확인

```bash
python3 --version
```

- python3만 있으면 된다. **pip·venv 설치는 필요 없다** — 스크립트는 표준 라이브러리만 쓴다.
- python3가 없으면 여기서 멈추고 본체 경로 복귀 대사(0-3)를 낸다.

### 0-2. 키 유무 확인 — 값은 읽어도 출력하지 않는다

```bash
ls "$CLAUDE_PLUGIN_ROOT/skills/cro-variant-mockup/scripts/.env" 2>/dev/null \
  && grep -c '^[A-Z_]*API_KEY=..*' "$CLAUDE_PLUGIN_ROOT/skills/cro-variant-mockup/scripts/.env"
```

- 확인하는 것은 **`.env` 파일의 존재와 키 줄이 채워져 있는지**까지다.
  🚫 **키 값을 화면에 출력하지 않는다** (`cat .env` 금지 — 계약 §7-12).
- **스크립트를 인자 없이 돌려 보지 않는다.** 준비 점검은 파일 확인으로 끝내고, 실제 호출은
  M3에서 진짜 프롬프트로 한 번만 한다.
- `$CLAUDE_PLUGIN_ROOT`가 잡히지 않는 환경이면 이 스킬 폴더 기준 상대 경로
  (`scripts/.env`)로 확인한다.

**키가 두 개(GEMINI·OPENAI) 다 채워져 있으면** — 스크립트가 스스로 고르지 못하고 exit 2로
멈추므로, 여기서 참가자에게 먼저 묻는다.

> "이미지 생성 키가 **두 개(Gemini·OpenAI)** 다 준비돼 있네요. 어느 쪽으로 만들까요?
> 특별한 사정이 없으면 **Gemini**를 권합니다 — 응답이 빠르고 원본 비율을 유지합니다.
> OpenAI는 대조군 화면을 더 강하게 붙들어 두고 싶을 때 씁니다."

### 0-3. 키가 없을 때 — 본체 경로 복귀 (아래 문구를 그대로 쓴다)

**이 기능은 선택이다. 키가 없다고 세션을 멈추지 않는다** (계약 §3-3a ③).

> "이미지 생성 API 키가 아직 없네요. **여기서 막히실 필요는 없습니다** — 시안 없이 진행하는
> 종전 경로가 이미 완성돼 있습니다. `cro-experiment-design`의 **변경 화면 명세 4슬롯**을
> 제작 요청서 수준으로 채우고 담당·필요 시점을 병기하면, 디자이너가 그것만 보고 제작에
> 들어갈 수 있습니다. 시안 행은 `없음 — 제작 요청 명세로 대체`로 두시면 됩니다.
> 나중에 키를 발급하시면 그때 이 스킬로 다시 오시면 됩니다 — 발급 방법은
> `references/provider-setup.md`에 정리돼 있습니다(Gemini는 무료 티어가 있습니다)."

- 발급 안내는 **URL 두 개와 무료 여부까지만** 한다. 키 값을 대신 받아 적지 않는다.
- 키를 발급해 왔으면 M0-2부터 다시 시작한다.

**산출**: 실행 가능 여부 · 제공자 확정
**다음**: 진행 가능하면 M1, 불가하면 본체 경로 복귀로 종료

## M1 — 입력 수집 + PII 마스킹 게이트 (하드 게이트 ① · 계약 §7-12)

### 1-1. E2 확정 명세 4슬롯 수령

**본체 세션에서 그대로 이어져 왔으면** 방금 확정한 E2 값을 그대로 쓴다. 세션이 끊겼거나 다른
창에서 시작했으면 붙여넣기를 받는다.

> "만들 Variant의 **변경 화면 명세**를 주세요 — `cro-experiment-design`의 E2 표에서 확정한
> 4슬롯 그대로면 됩니다.
> `[헤드라인]` / `[이미지]` / `[CTA]` / `[노출 위치]` — **해당 없는 슬롯은 `변경 없음`**으로
> 적혀 있어야 합니다. Variant ID(`VAR-{HYP 숫자부}-{a,b,…}`)도 함께 주세요."

**🚫 E2 명세가 없으면 진행하지 않는다.** 명세가 정본이고, 이 스킬은 번역기다.

> "아직 **변경 화면 명세**가 없습니다. 이 스킬은 확정된 명세를 이미지로 옮기는 자리라, 명세
> 없이 만들면 AI가 문구와 화면을 스스로 지어내게 됩니다 — 그건 시안이 아니라 상상도입니다.
> **`cro-experiment-design` 스킬의 STEP 1**에서 4슬롯을 먼저 채우고 오세요. 채워 오시면
> 여기서 바로 이어갑니다."

- 슬롯이 `[헤드라인] 변경` 같은 **표기만**이면 명세가 아니다 — 같은 대사로 본체 STEP 1로
  되돌린다 (`mockup-prompt-guide.md` ③표 규칙).
- **문구가 `[코치 초안 — 참가자 확정 필요]` 상태면 확정 여부를 먼저 묻는다.** 확정 전 문구로
  이미지를 만들면 검수 게이트(M4)의 기준선 자체가 흔들린다.

### 1-2. control 스크린샷 수령

> "**대조군(Control) 화면 스크린샷**을 주세요. 이미지 파일 경로로 알려주시면 됩니다
> (png/jpg). 이 스크린샷을 **편집하는** 방식이라, 지금 서비스의 실제 화면이어야 합니다.
> 파일명은 워크숍 관례대로 `{축}_{번호}_{화면명}_{상태}.png` 형태를 권합니다 —
> 예: `A_01_보험분석결과_1진입.png`"

- 지원 형식은 **png / jpg / jpeg**다. 그 외 형식이면 변환을 요청한다.
- 긴 변이 1536px를 넘으면 스크립트가 자동으로 축소본을 만들어 쓴다 — 참가자가 미리 줄일
  필요는 없다.
- 참고 시안(무드보드·경쟁사 캡처)은 **선택**이며, 있어도 **최대 2장**까지다
  (`mockup-prompt-guide.md` ④).

### 1-3. 🚫 PII 마스킹 점검 (하드 게이트 ① — 여기서 이 스킬이 직접 막는다)

**받은 스크린샷을 이 스킬이 직접 읽어** 아래를 점검한다. **API 호출 전에** 한다.

| 점검 대상 | 예 |
|---|---|
| 실명 | 화면 상단 인사말·상담방 프로필명·서명란 |
| 연락처 | 휴대폰번호·이메일 |
| 증권번호 · 계약번호 | 보유 보험 목록의 식별번호 |
| 보험료 · 계약정보 | 월 납입액·가입금액·만기일 등 개인 계약 수치 |
| 그 밖의 식별정보 | 주민등록번호·생년월일·주소·병력 |

**하나라도 보이면 즉시 정지한다. 지정 대사(계약 §7-12 정본)를 그대로 낸다.**

> "이 스크린샷 {위치}에 고객 정보로 보이는 영역이 있습니다. 값은 옮겨 적지 않겠습니다 — 가리고 다시 올려주시면 그때 진행하겠습니다."

- `{위치}`는 **화면상의 자리**로만 말한다 — "상단 인사말 줄", "보유 보험 목록 2번째 카드의
  오른쪽 숫자". 🚫 **값 자체는 어떤 형태로도 출력하지 않는다** (일부 마스킹해서도 적지 않는다).
- **"그냥 해주세요"에도 진행하지 않는다.** §7-12는 하드 게이트다 — 참가자 동의로 풀리지 않는다.
  외부 API로 나가는 순간 되돌릴 수 없기 때문이다.
- 마스킹본을 받으면 **같은 점검을 처음부터 다시** 한다. "아까 봤으니 됐다"로 넘기지 않는다.
- 마스킹 방법이 막히면 안내한다 — 화면 캡처 후 이미지 편집기에서 검은 사각형으로 덮거나,
  테스트 계정 화면으로 다시 캡처하는 쪽이 빠르다.

**통과하면 기록을 남긴다.**

> "✅ **PII 마스킹 게이트 통과** (계약 §7-12) — {파일명}, 점검 시각 {시각}. 실고객 정보로 보이는
> 영역 없음. 이 기록은 나중에 실험설계서 리뷰(D-19)에서 확인됩니다."

**산출**: E2 4슬롯 확정본 · control 파일 경로 · PII 게이트 통과 기록
**다음**: M2

## M2 — 프롬프트 조립 (계약 §3-3a ①-1)

**진입 조건**: 4슬롯이 채워졌고 PII 게이트를 통과했다.
시작 전 **`references/mockup-prompt-guide.md`를 읽는다.**

### 2-1. 6부 구조로 조립한다

가이드 ②의 6부 구조를 순서대로 채운다 — **순서가 곧 전달력**이라 재배열하지 않는다.

| 순서 | 부 | 재료 |
|---|---|---|
| 1 | Task 선언 | 고정 문장 — "기존 스크린샷의 편집"임을 먼저 못박는다 |
| 2 | Preservation | 고정 문장 — 레이아웃·색·폰트·상태바·내비게이션 유지 |
| 3 | Target 지목 | E2 `[노출 위치]` 슬롯 |
| 4 | Change 내용 | E2 `[헤드라인]` · `[이미지]` · `[CTA]` 슬롯 |
| 5 | 스타일 정합 | 고정 문장 — 앱의 기존 시각 스타일에 맞춤 |
| 6 | 출력 규격 | 고정 문장 — 입력과 같은 비율·해상도 |

- **`변경 없음` 슬롯은 프롬프트에 아예 넣지 않는다** (가이드 ③표). 없는 것을 "바꾸지 마라"고
  적으면 모델이 오히려 그 영역을 주목한다.
- **한글 문구는 따옴표로 정확히 옮기고 `render this Korean text exactly as written`을
  병기**한다. 서술형으로 풀어 쓰지 않는다 (가이드 ⑤-a).
- 문장은 영어로 쓰되 **한글 문구만 원문 그대로** 둔다 — 문구를 번역하면 그 순간 확정 문구가
  아니게 된다.

### 2-2. 조립된 프롬프트 전문을 보여주고 확인받는다

**참가자가 프롬프트 전문을 보기 전에 API를 호출하지 않는다.** 이 확인이 "명세를 바꾸지
않았다"를 사람이 검증하는 유일한 지점이다.

> "이렇게 적어서 보내겠습니다. **바뀌는 건 {노출 위치}뿐**이고, 나머지 화면은 그대로
> 유지하라고 적었습니다. 헤드라인 문구는 확정하신 그대로 따옴표로 넣었습니다.
> 이대로 진행할까요?"

- 프롬프트 전문은 **코드블록으로** 낸다 (이 스킬에서 코드블록은 이것 하나뿐 — 표 출력 규칙 참조).
- 참가자가 문구를 고치고 싶어 하면 **여기서 고치지 않는다** — 문구 변경은 E2 명세 변경이므로
  본체 STEP 1에서 확정하고 오게 한다.

### 2-3. 프롬프트를 파일로 저장한다

스크립트 입력이자 **재현성 기록**이다. 어떤 프롬프트로 나온 이미지인지 나중에 되짚을 수 있다.

- 경로: `variants/{HYP-ID}/prompts/{VAR-ID}_{시도번호}.txt`
- 첫 시도는 `_1`, 강화 문장을 추가한 재생성은 `_2`·`_3`으로 올린다 — **덮어쓰지 않는다.**
- 작업 폴더는 참가자의 현재 작업 디렉토리 기준이다. 폴더가 없으면 만든다.

**산출**: 조립된 프롬프트 전문(코드블록) + 저장 경로
**다음**: M3

## M3 — 생성 실행

### 3-1. 호출

Bash로 아래를 실행한다.

```bash
python3 "$CLAUDE_PLUGIN_ROOT/skills/cro-variant-mockup/scripts/generate_variant.py" \
  --control "{control 파일 경로}" \
  --prompt-file "variants/{HYP-ID}/prompts/{VAR-ID}_1.txt" \
  --out-dir "variants/{HYP-ID}" \
  --name "{VAR-ID}"
```

- `$CLAUDE_PLUGIN_ROOT`가 잡히지 않는 환경이면 이 스킬 폴더 기준 상대 경로
  `scripts/generate_variant.py`로 호출한다 (meeting-notes 스킬의 경로 표기 관례를 따른다).
- **키가 두 개인 경우 `--provider gemini` 또는 `--provider openai`를 반드시 붙인다** (M0-2에서
  참가자가 고른 값). 안 붙이면 exit 2로 멈춘다.
- `--model`은 **지정하지 않는다.** 기본값(`gemini-3.1-flash-image` / `gpt-image-1`)을 쓴다 —
  폐기된 모델명을 잘못 지정하는 사고를 막기 위해서다.
- `--count`는 기본 1이다. 여러 장이 필요하면 참가자가 요청할 때만 올린다(장당 비용이 든다).

### 3-2. 결과 파싱

| 신호 | 의미 | 다음 행동 |
|---|---|---|
| exit 0 + stdout `OK {경로}` | 이미지 최소 1장 생성 | 그 경로를 **M4 검수 대상**으로 넘긴다 |
| exit 1 | 전부 생성 실패 (키는 유효했을 수 있음) | stderr의 `생성 실패: {사유}`를 **그대로** 전달 |
| exit 2 | 키를 못 찾음 / 키 두 개인데 `--provider` 미지정 | 설정 문제 — 키 안내 또는 `--provider` 붙여 재실행 |

- **`OK {경로}` 줄이 실제로 나왔는지 확인한다.** "스크립트가 오류 없이 끝났다"가 "이미지를
  받았다"를 뜻하지 않는다 (`provider-setup.md` ③).
- 스크립트는 **한국어 안내 메시지**를 낸다 (예: `API 키를 확인하세요 (Gemini는 잘못된 키에
  400을 반환합니다).`). **그 문장을 그대로 참가자에게 전달**하고, 다시 풀어 쓰지 않는다.
- 생성 결과·프롬프트 길이·소요시간은 `{out-dir}/metadata.json`에 자동 기록된다.

### 3-3. API 런타임 실패 폴백 — 무한 재시도 금지

스크립트가 429/503에 대해 **이미 최대 3회 지수 백오프**를 돌린다. 그 뒤에도 실패하면 **스킬이
같은 명령을 반복하지 않는다.**

- 같은 오류로 **2회 연속 실패**하면 재시도를 멈춘다.
- 네트워크·쿼터 계열(429·503·네트워크 오류)이면 아래 대사로 세션을 닫는다.

> "지금은 이미지 생성이 안 됩니다 — {오류 요약}. 여기서 더 붙들어도 오늘 풀릴 성격이 아닙니다.
> **시안 행은 `없음 — 제작 요청 명세로 대체`로 두고 실험설계를 계속 진행**하시죠. 명세는 이미
> 4슬롯으로 채워져 있어서 디자이너가 그것만 보고 제작에 들어갈 수 있습니다. 잠시(1~2분) 뒤
> 다시 시도해 보셔도 되고, 나중에 이 스킬로 다시 오셔도 됩니다."

- 키 문제(exit 2·401·403·400 키 오류)면 재시도가 아니라 **키 재확인**을 안내한다. 이때도
  **키 값을 붙여넣게 하지 않는다** — `.env` 파일을 직접 확인하시라고만 말한다.

**산출**: 생성 파일 경로 또는 폴백 안내
**다음**: 성공이면 M4

## M4 — 생성물 검수 게이트 (하드 게이트 ②③ · 계약 §7-13 문구 · §7-15 대조군 보존)

**이미지 모델의 한글 렌더링은 신뢰할 수 없다** — 실측 2회 모두 깨졌다("슈퍼대디 리얼씬" →
"슈부대디 리열선", "33,660원" → "33,660은"). 매번 깨지는 것도 아니라서 **한 번 잘 나왔다고
다음도 괜찮겠지로 넘기면 안 된다.**

### 4-1. 생성 이미지를 직접 읽어 글자 단위로 대조한다

**이 스킬이 생성된 PNG를 직접 읽는다.** 참가자에게 "확인해 보세요"로 넘기지 않는다 — 검수는
스킬의 일이다.

**문구 대조표 (3열)**

| 슬롯 | 기대 문구 (E2 확정) | 실제 렌더링 | 판정 |
|---|---|---|---|
| `[헤드라인]` | `[예시]` "OO님 보험, 여기가 비어 있어요" | `[예시]` "OO님 보험, 여기가 비어 있어요" | ✅ 일치 |
| `[CTA]` | `[예시]` "무료로 확인하기" | `[예시]` "무료로 확인하기" | ✅ 일치 |

- **`실제 렌더링` 열에는 이미지에서 읽은 글자를 그대로** 적는다. 깨진 글자를 알아서 고쳐
  적지 않는다 — 그러면 게이트가 무력화된다.
- 판정 값 도메인: `✅ 일치` / `❌ 불일치` / `⚠️ 판독 불가`(글자가 흐려 읽을 수 없음 — 불일치로
  취급한다).
- **문구 외 결함도 함께 본다** — 레이아웃 붕괴, 지정 안 한 요소 변경, 비율 변형. 이것들도
  강화 문장 카탈로그에 대응 항목이 있다. 이 점검은 아래 4-1b의 **보존 대조표**로 한다.

### 4-1b. 대조군 보존 대조표 — 지정하지 않은 것이 바뀌지 않았는가

**문구 대조표만으로는 부족하다.** 확정 문구가 전부 ✅여도, 모델이 **지정하지 않은 영역의 숫자나
라벨을 조용히 바꿔** 놓는 일이 있다. 실측 사례 — 대조군의 `6%` 막대 수치가 생성물에서 `8%`로
바뀌었는데 문구 대조표는 전부 ✅였다(2026-08-24 스모크 테스트). 이 상태로 착지하면 **대조군과
실험군이 서로 다른 데이터를 보여주게 되어 실험 자체가 오염된다** — 무엇이 효과를 냈는지 가릴 수
없다.

**그래서 control 이미지와 생성 이미지를 나란히 놓고 항목별로 대조한다.** control도 다시 읽는다 —
기억으로 하지 않는다.

| 요소 (지정 영역 밖) | control | 생성물 | 판정 |
|---|---|---|---|
| 상태바·내비게이션 | `[예시]` 11:06 · ← | `[예시]` 11:06 · ← | ✅ 보존 |
| 화면 내 **숫자·통계** | `[예시]` 14% / 6% | `[예시]` 14% / **8%** | ❌ 변조 |
| 다른 섹션 제목·본문 | | | |
| CTA 문구·색 | | | |
| 카드 배치·여백 | | | |

- **숫자·통계 행은 반드시 넣는다.** 가장 자주 조용히 바뀌고, 바뀌어도 눈에 잘 안 띄며,
  실험 오염 위험이 가장 큰 항목이다.
- ❌ 변조가 하나라도 있으면 **문구가 전부 일치해도 게이트 불통과**다 — 4-2 재생성으로 간다
  (강화 문장은 카탈로그의 「지정 안 한 요소까지 바뀜」).
- 판정 값 도메인: `✅ 보존` / `❌ 변조` / `⚠️ 대조 불가`(control에 그 영역이 안 잡혀 있음 —
  변조로 취급하지 않되 착지 안내에 남긴다).

### 4-2. 불일치면 재생성 — 강화 문장은 **시도당 1개**

**프롬프트 전체를 다시 쓰지 않는다.** `mockup-prompt-guide.md` ⑥ 카탈로그에서 **이번 결함에
맞는 문장 하나만** 골라 프롬프트 끝에 추가하고, `_2` 파일로 저장해 재실행한다.

| 이번 결함 | 고르는 문장 |
|---|---|
| 한글 깨짐 | 카탈로그 「한글 깨짐」 행 |
| 레이아웃이 바뀜 | 카탈로그 「레이아웃이 바뀜」 행 |
| 지정 안 한 요소까지 바뀜 | 카탈로그 「지정 안 한 요소까지 바뀜」 행 |
| 스타일이 이질적 | 카탈로그 「스타일이 앱과 이질적」 행 |
| 비율·해상도 변형 | 카탈로그 「비율·해상도 변형」 행 |
| 텍스트가 흐림 | 카탈로그 「텍스트가 흐릿함」 행 |

- **결함이 두 개 보여도 한 번에 문장 두 개를 넣지 않는다.** 무엇이 효과가 있었는지 알 수 없게
  되고, 지시가 길어질수록 뒤 문장의 전달력이 떨어진다. **가장 치명적인 것 하나**(문구 > 레이아웃
  > 스타일 순)부터 잡는다.
- **재생성은 최대 2회다** (계약 §7-13). 3회째를 시도하지 않는다 — 작은 텍스트 결함은 재생성으로
  풀리지 않는다는 실측 기록이 있고, 세 번째 라운드는 시간만 쓴다.
- **2차에 같은 문장을 그대로 다시 넣지 않는다** — 같은 결함이 반복되면 1차에 넣은 문장을
  **프롬프트 4부(Change) 맨 앞으로 옮기고 문두에 `MUST:`를 붙여** 우선순위를 올린다
  (`mockup-prompt-guide.md` ⑥ 에스컬레이션). 상한 2회 중 1회를 같은 문장에 낭비하지 않기
  위해서다. "문장 1개" 규칙은 그대로다 — **개수를 늘리는 것이 아니라 위치·강도를 올리는 것**이다.
- 매 회차마다 4-1 대조표를 다시 낸다.

### 4-3. 2회로도 실패하면 — 「문구 영역 비움」 경로 (아래 문구를 그대로 쓴다)

> "재생성을 **2회** 했는데도 한글 문구가 계속 깨집니다. 이건 프롬프트로 더 밀어붙여서 풀리는
> 결함이 아닙니다 — 이미지 모델의 한글 렌더링 한계입니다. **문구 자리를 비운 시안**으로 한 번
> 더 만들고, **문구는 명세에 적힌 확정본으로 따로 표기**해서 넘기겠습니다. 디자이너가
> 최종 시안을 만들 때 어차피 문구는 명세를 보고 넣습니다 — 초안의 역할은 **레이아웃과 방향을
> 보여주는 것**까지입니다."

- 가이드 ⑤-c의 비움 문장(`Leave the headline area as an empty text placeholder box ...`)으로
  프롬프트를 바꿔 **1회만** 생성한다.
- **비움 경로 생성분도 기존 초안을 덮어쓰지 않고 다음 번호로 저장된다** — 스크립트가
  `{out-dir}/{VAR-ID}_*.png` glob으로 최대 번호 +1을 자동 부여하므로, 2회 재생성 뒤라면
  `{VAR-ID}_4.png`가 된다. 프롬프트 파일도 같은 규칙으로 `{VAR-ID}_4.txt`에 남긴다 —
  **어느 번호가 어느 경로에서 나온 것인지 대조할 수 있어야** 하기 때문이다.
- 이때는 문구 대조 대신 **「문구 영역 비움 — 확정 문구는 명세 참조」**를 대조표에 명시한다.
- 이 경로로 나온 초안도 **정상 산출물**이다. M5 착지로 그대로 간다.

### 4-4. 통과 기록

> "✅ **한글 문구 검수 게이트 통과** (계약 §7-13) — {파일명}, 대조 슬롯 {N}개 전부 일치
> (또는: 문구 영역 비움 경로, 재생성 {N}회). 이 기록은 실험설계서 리뷰(D-1~D-4)에서
> 확인됩니다."

**🚫 불일치 상태의 이미지는 노션에도 E2 시안 행에도 착지시키지 않는다.** 깨진 문구가 착지하면
"가설의 의미를 바꾸지 않는다"(계약 §5)를 그대로 위반하는 사고가 된다.

**산출**: 문구 대조표 + 검수 통과 기록
**다음**: M5

## M5 — 착지 (하드 게이트 ④ · 계약 §7-14 · §3-3a ④ · §4)

### 5-0. 재진입 확인 — 같은 VAR에 기존 초안이 있으면 먼저 묻는다

M0~M4에 들어가기 전에도, 착지 직전에도 **같은 `{VAR-ID}`의 기존 초안이 `variants/{HYP-ID}/`에
이미 있는지** 확인한다. 있으면 덮어쓰기 전에 묻는다.

> "이 Variant(`{VAR-ID}`)에는 **{날짜}에 만든 초안이 이미 있습니다** — `{기존 파일 경로}`.
> 다시 만들까요, 그대로 쓸까요? 다시 만들어도 기존 파일은 지우지 않고 번호를 올려
> 나란히 남깁니다."

- 스크립트가 `{VAR-ID}_1.png`·`{VAR-ID}_2.png`로 번호를 올려 저장하므로 **덮어쓰기는 일어나지
  않는다.** 다만 어느 것이 채택 대상인지 흐려지므로 **사람이 정하게 한다.**

### 5-1. 최종 파일 경로 안내

> "초안이 나왔습니다 — `{out-dir}/{VAR-ID}_{n}.png`
> 파일명에 **Variant ID가 이미 들어 있고**, 이것이 **AI 초안**이라는 사실은 **노션 캡션과 E2 시안
> 행**에 함께 남깁니다. 생성 기록(제공자·모델·소요시간)은 같은 폴더의 `metadata.json`에
> 자동으로 남아 있습니다."

### 5-2. 노션 `1-3` 삽입 안내 — 캡션 정본 (계약 §4 · §7-14)

> "노션 실험설계서 **`1-3) 솔루션 설명 및 근거`**에 넣어주세요 — **대조군 스크린샷과 나란히**
> 두면 무엇이 바뀌었는지 한눈에 보입니다. 이미지 아래 **캡션에 아래 문장을 그대로** 적어주세요.
>
> `AI 초안 — {provider}/{model}, 검토 필요`
>
> 이미지 드래그와 캡션 입력은 **직접 해주셔야 합니다** — 스킬은 노션에 직접 쓰지 않습니다."

- **캡션 없이 이미지만 올리지 않는다.** 캡션이 빠지면 다음 사람이 이걸 확정 시안으로 읽는다 —
  §7-14가 표기를 하드 게이트로 건 이유다.
- **문구 영역 비움 경로(M4-3)로 나온 초안이면 캡션 끝에 접미사를 병기한다.**

  > `AI 초안 — {provider}/{model}, 검토 필요 (문구 영역 비움 — 확정 문구는 명세 참조)`

  캡션 정본 문면(계약 §7-14)은 **그대로 두고 뒤에 덧붙이기만** 한다. 문서만 보는 리뷰어가
  헤드라인이 비어 있는 것을 **결함으로 오독하지 않게** 하기 위해서다 — 리뷰 D-1~D-4는 이
  이미지를 설명 없이 본다.
- 그루밍 착지분(`1-3` 기존 내용)을 **덮어쓰지 않는다.** 이미지와 캡션을 **추가**한다.

### 5-3. E2 시안 행 갱신값 (계약 §3-3a ④ — 3요소 필수)

본체 스킬의 E2 표 `시안` 행에 아래 형식으로 적는다. **상태·경로·표기 3요소가 모두 있어야
착지다.**

```
있음 — AI 생성 초안(검토 필요) / {파일 경로 또는 링크} / AI 초안 — {provider}/{model}, {생성일}
```

**문구 영역 비움 경로(M4-3)면 표기 요소 끝에 같은 접미사를 붙인다.**

```
있음 — AI 생성 초안(검토 필요) / {파일 경로 또는 링크} / AI 초안 — {provider}/{model}, {생성일} (문구 영역 비움 — 확정 문구는 명세 참조)
```

3요소 구조와 계약 §3-3a ④ 문면은 그대로이고, **표기 요소 뒤에 괄호로 덧붙이기만** 한다.

> "`cro-experiment-design` 세션으로 돌아가서 E2 표의 **시안 행**을 위 값으로 바꿔주세요.
> 이 값이 들어가면 E1 게이트 **G-4**는 `부분`으로 잡힙니다 — 결손이 아니라, **사람 검토 전**이라는
> 뜻입니다. 이 상태로 실험설계는 계속 진행됩니다."

### 5-4. 디자이너 전달 안내

> "이 초안은 **디자이너에게 보내는 입력물**입니다 — 최종 시안을 대신하지 않습니다. 전달하실 때
> **변경 화면 명세 4슬롯 + 이 초안 이미지**를 함께 보내시면, 말로 설명하던 방향을 그림으로 한 번에
> 보여줄 수 있습니다. 문구는 **명세에 적힌 확정본이 정본**이라는 점을 한 줄 붙여주세요 —
> 이미지 속 글자가 아니라요."

### 5-5. 승격 규칙 안내 — 승격은 사람만 한다 (계약 §7-14 · §3-2)

> "디자이너 최종 시안이 나오거나, 팀이 이 초안을 **그대로 채택**하기로 하면 그때
> E2 시안 행을 **`있음(링크)`**으로 올리고 E1 게이트 **G-4도 `충족`**으로 승격합니다.
> **승격 판단은 사람이 합니다** — 이 스킬도, 실험설계 스킬도 대신 올리지 않습니다."

### 5-6. 착지 요약 표

| 항목 | 값 |
|---|---|
| Variant ID | `{VAR-ID}` |
| 최종 파일 | `{out-dir}/{VAR-ID}_{n}.png` |
| provider / model | `{provider}` / `{model}` |
| 생성일 | `{YYYY-MM-DD}` |
| 게이트 ① PII 마스킹 (§7-12) | ✅ 통과 |
| 게이트 ② 한글 문구 검수 (§7-13) | ✅ 통과 (재생성 {N}회) — 문구 대조 + 대조군 보존 대조 둘 다 |
| 게이트 ③ 대조군 보존 (§7-15) | ✅ 통과 — 지정 밖 영역·숫자 변조 없음 |
| 게이트 ④ AI 초안 표기 (§7-14) | ✅ 파일명·노션 캡션·E2 시안 행 3곳 |
| 다음 행동 | 노션 `1-3` 삽입(참가자) → E2 시안 행 갱신 → 디자이너 전달 |

## 표 출력 규칙

1. **코드블록은 「조립된 프롬프트 전문」 하나뿐이다** (M2-2). 그 외 산출물 — 문구 대조표·착지
   요약 표·게이트 통과 기록 — 은 **마크다운 표로 대화에 렌더**한다.
   - 예외적으로 E2 시안 행 갱신값(M5-3)은 **그대로 복사해 붙일 문자열**이라 코드블록으로 낸다 —
   렌더된 표에서 복사하면 서식이 섞이기 때문이다.
2. 표 바로 위 또는 아래에 **어디로 가는지 한 줄** 붙인다.
3. **셀 안에서 줄바꿈하지 않는다.** 콤마·슬래시·`→`를 쓴다.
4. 🚫 **셀 첫 글자에 `=`·`+`를 쓰지 않는다** (시트·노션이 수식으로 오인한다).
5. **PII·API key는 어떤 표에도 적지 않는다** — 위치만 말한다 (계약 §7-12).
6. 실측 수치를 이 문서에 하드코딩하지 않는다. 예시는 `[예시 — 가상]`을 명시한다.

### 그 외 거부

- ❌ **E2 명세 변경**(문구 다듬기·슬롯 추가·노출 위치 변경) — 명세 변경은 본체 STEP 1 소관
- ❌ **PII 값 원문 출력** (일부 마스킹 형태로도 적지 않는다)
- ❌ **API key 값 출력·기록·전달** (`cat .env` 포함)
- ❌ **3회째 재생성** (§7-13 상한 초과)
- ❌ **표기 없는 AI 이미지 착지** (파일명·캡션·E2 시안 행 3곳 중 하나라도 빠지면 착지 불가)
- ❌ **`있음(링크)`으로의 승격 판단** (사람 몫 — §7-14)
- ❌ **화면 전체 리디자인 프롬프트** ("더 예쁘게"·"전체적으로 개선") — control과 비교 불가
- ❌ **폐기 모델명 지정** (`gemini-2.0-flash-preview-image-generation` — 404)

### 거부하지 않는 것 — 자주 헷갈리는 지점

- ✅ **프롬프트 조립은 한다.** E2 4슬롯을 6부 구조로 옮기는 것은 이 스킬의 본업이다 —
  **명세를 만드는 것**과 **명세를 프롬프트 문장으로 옮기는 것**은 다르다.
- ✅ **명세의 영문 번역은 한다.** 6부 구조의 지시문은 영어로 쓴다. 단 **한글 확정 문구만은
  번역하지 않고 원문 그대로** 따옴표 안에 둔다.
- ✅ **강화 문장 선택은 스킬이 한다.** 어떤 결함에 어떤 문장을 붙일지는 카탈로그에서 스킬이
  고른다 — 참가자에게 프롬프트 엔지니어링을 시키지 않는다. 다만 **시도당 1개**다.
- ✅ **생성 이미지를 직접 읽고 검수 대조표를 만드는 것은 한다.** 검수는 참가자 숙제가 아니라
  스킬의 게이트다 (§7-13).
- ✅ **PII 위치를 말하는 것은 한다.** 값을 옮겨 적는 것과 "상단 인사말 줄에 있습니다"라고
  말하는 것은 다르다 — 위치 지목은 참가자가 마스킹하려면 반드시 필요하다.
- ✅ **키가 없어도 세션은 정상 종료다.** 이 기능은 **선택**이다 — 키 없음은 실패가 아니라
  종전 경로(제작 요청 명세)로의 복귀다 (§3-3a ③).
- ✅ **「문구 영역 비움」 초안도 정상 산출물이다.** 문구가 빠진 시안 + 명세 표기는 §7-13이
  지정한 정규 경로이지 실패 처리가 아니다.
- ✅ **기존 초안이 있어도 다시 만들 수 있다.** 다만 **먼저 물어보고**, 기존 파일은 지우지 않고
  번호를 올려 나란히 남긴다.
