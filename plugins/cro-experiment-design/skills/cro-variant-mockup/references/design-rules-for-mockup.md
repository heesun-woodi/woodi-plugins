## ① 우선순위 — 디자인 가이드는 세 번째다

이 스킬은 빈 화면에 새로 그리지 않고 **control 스크린샷을 편집**한다. 그래서 디자인 가이드는 **바뀌는 영역의 모양**에만 적용되고, 아래 두 가지보다 앞서지 않는다.

| 순위 | 기준 | 무엇을 정하나 | 디자인 가이드와 부딪히면 |
|---|---|---|---|
| 1 | **E2 확정 명세 4슬롯** | 문구 · 바꿀 영역 · 이미지 방향 | 명세가 이긴다. 가이드를 이유로 문구를 줄이거나 바꾸지 않는다 |
| 2 | **control 보존** (계약 §7-15) | 지정 **밖** 영역 전부 | control이 이긴다. 기존 화면이 가이드와 달라도(예: 기존 카드에 그림자) **고치지 않는다** — 고치는 순간 대조군 보존 위반이다 |
| 3 | **디자인 가이드** | 지정 **안** 영역의 색·서체·카드·버튼·에셋 | — |
| 4 | 모델 재량 | 위 셋이 정하지 않은 나머지 | — |

- **명세 자체가 가이드와 부딪히면 조용히 고치지 않는다.** 예: 명세가 "초록 배경 버튼"(br-green은 컴포넌트 fill 금지)이나 "그림자 있는 카드"를 지정했다. 이때는 조립을 멈추고 이렇게 말한다.

  > "명세의 {항목}이 시그널플래너 디자인 가이드({근거 절})와 다릅니다 — 가이드는 {규칙}입니다. 명세를 바꾸는 건 실험설계 STEP 1에서 하실 일이라, 여기서는 **명세대로 만들지, STEP 1로 돌아가 고칠지**만 정해주세요."

  명세대로 가기로 하면 명세대로 만들고, ⑤ 대조표의 그 행을 `⚠️ 이탈 — 명세 지정`으로 적는다 — 재생성 사유가 아니고, 절대 규칙 행이면 **게이트에서 면제**된다(계약 §7-19 · DEC-027 결정 4). 면제는 **명세가 그 요소를 지정했을 때만**이다.
- **텍스트 밀도 규칙**(원문 Overview — 상위 뎁스에서는 라벨과 값만 보여준다)은 **명세를 쓰는 쪽의 규칙**이다. 이 스킬은 문구를 더하지도 빼지도 않는다. 명세 문구가 많아 보이면 위 대사처럼 짚기만 한다.

## ③ 프롬프트 5부(스타일 정합) — 시그널플래너 문장

`mockup-prompt-guide.md` ②의 5부 표준 문장을 **아래 기본 문장으로 바꿔 넣고**, 이번 변경에 해당하는 조건 문장만 뒤에 붙인다. **해당 없는 조건 문장은 넣지 않는다** — 없는 요소를 언급하면 모델이 그 요소를 새로 만든다(가이드 ③표의 「변경 없음」 원칙과 같은 이유).

**기본 문장 (항상)**

```
Match the Signal Planner app design system for the changed area only: flat design with no drop shadows and no outlines around cards; the single accent color is violet #501EFF; text in dark gray #212529 or #495057; Korean sans-serif (Pretendard style) in regular or bold weight only, no oversized display type. Do not restyle anything outside the changed area.
```

**조건 문장 (이번 변경에 있는 것만)**

| 변경에 이것이 있으면 | 붙이는 문장 |
|---|---|
| 새 카드 · 박스 | `Any new card has 16px rounded corners, no shadow, no border, and about 20px inner horizontal padding; rows inside a card are separated only by a thin 1px #E9ECEF horizontal line.` |
| └ 놓이는 배경이 `#F1F3F5` | `The new card is solid white on the light-gray background — not a pastel tint.` |
| └ 놓이는 배경이 흰색 | `The new card uses a light-gray #F1F3F5 fill (or a very pale tint of the accent color).` |
| 주 버튼 | `The main button is a solid #501EFF fill with bold white text and 6px corner radius, spanning the width inside the page margins.` |
| 보조 버튼 | `Secondary buttons are white with a thin #501EFF or #CED4DA border — never a second solid violet button.` |
| 반복되는 강조 표시 | `Repeated highlight marks use indigo #5C7CFA rather than #501EFF.` |
| 부족·잉여 표시 | `Mark shortfalls in red #F03E3E and surpluses in violet #501EFF; do not use green, sky blue, or yellow as UI fills.` |
| 아이콘 · 캐릭터 · 사물 일러스트 | `Where an icon or illustration is needed, do not draw a new one: place a plain light-gray #E9ECEF rounded placeholder square at the same size as comparable icons in the screenshot.` |
| 바텀시트 | `Show it as a bottom sheet with 36px rounded top corners over a dark dimmed background.` |

- **크기는 px보다 「스크린샷 속 기존 요소와 같은 크기」로 적는다.** 가이드의 px는 디자인 단위이고 스크린샷은 기기 배율(대개 3배)로 찍혀 있어, px 숫자를 그대로 주면 모델이 크기를 틀리게 잡는다. **색상 hex는 그대로 적어도 된다.**
- 5부 전체가 길어지면 뒤 문장의 전달력이 떨어진다. 조건 문장은 **많아야 3개**까지만 고르고, 넘치면 변경의 핵심 요소(주로 카드·버튼) 쪽을 남긴다.

## ④ 에셋 지정 — 아이콘·일러스트는 파일명으로 넘긴다

원문의 "반드시 지킬 것"은 §1 Asset이다 — **아이콘과 일러스트는 새로 그리지 않고 라이브러리 파일을 쓴다.** 그런데 생성 스크립트는 control 한 장만 모델에 보내므로 모델은 실제 에셋을 볼 수 없다. 그래서 **초안에는 자리표시만 두고, 어느 파일이 들어갈지는 에셋 지정표로 따로 넘긴다.** AI가 흉내 내 그린 아이콘이 초안에 들어가면 다음 사람이 그걸 브랜드 에셋으로 읽는다 — 문구 게이트와 같은 이유다.

1. E2 `[이미지]` 슬롯에 아이콘·캐릭터·사물이 필요한지 본다. control에 **이미 있는 아이콘은 보존 대상**이라 지정하지 않는다.
2. 로컬 디자인 가이드 §1.1(아이콘) · §1.2(캐릭터 `smi-*`) · §1.3(사물 `obj-*`) 목록에서 **파일명으로 내용을 짐작해** 후보를 고른다. **목록에 없는 파일명을 지어내지 않는다.** 맞는 것이 없으면 `에셋 없음 — 디자이너 확인`으로 둔다.
   - **로컬 디자인 가이드가 없으면**(M0에서 경로를 못 찾음) 목록을 볼 수 없으므로 파일명을 고르지 않는다. 자리표시는 그대로 두고 지정표 상태를 `에셋 목록 없음 — 디자이너 확인`으로 적는다. 기억이나 추측으로 파일명을 채우지 않는다.
3. 후보는 **자리마다 1~2개**, `[스킬 제안 — 참가자 확정 필요]`를 붙여 보여준다. 확인용 주소는 로컬 원문 frontmatter의 `assets.base-url` 뒤에 파일명을 붙인 것이다 — 스킬이 받아서 직접 열어 보고 파일명 짐작이 맞는지 확인해도 된다(작업 폴더 밖 임시 경로에 받는다). 주소를 이 저장소 문서에 옮겨 적지 않는다.
4. 프롬프트에는 ③의 「아이콘 · 캐릭터 · 사물 일러스트」 조건 문장만 넣는다. **파일명을 프롬프트에 적지 않는다** — 모델이 파일명을 글자로 렌더링한다.
5. 확정된 지정은 M5에서 **에셋 지정표**로 디자이너 전달물에 붙인다.

> 22×22는 아이콘의 **출고 규격**(원문 §1.1)이고, 화면에서 차지하는 크기(원문 §4의 24×24, §7.3의 40×40 원형 안 32px 등)와는 다른 축이다. 지정표의 표시 크기는 참고값이고, 실제 크기는 control 화면의 비슷한 요소에 맞춘다.

|---|---|---|---|
| `[예시 — 가상]` 진단 카드 1행 좌측 | `icon-multicolor-shield-2-piece.png` | 22×22 (배경 박스 없음) | 참가자 확정 |

## ⑤ M4 디자인 대조표 — 바뀐 영역만 본다 (절대 규칙 = 하드 게이트 §7-19)

§7-13 문구 대조표와 §7-15 보존 대조표를 낸 **다음에** 이 표를 낸다. **지정 영역 안만** 본다 — 밖은 §7-15 소관이다.

| 구분 | 점검 항목 | 기준 | 생성물 | 판정 |
|---|---|---|---|---|
| **게이트 ①** | 그림자 · 카드 외곽선 | 둘 다 없음 | | |
| **게이트 ②** | 금지 fill | br-sky / br-green / br-yellow가 버튼·카드·배지 fill로 쓰이지 않음 | | |
| **게이트 ③** | 아이콘 · 일러스트 | 자리표시만 · 새로 그린 아이콘·캐릭터·사물 없음 | | |
| 권고 | 강조색 | `#501EFF` 하나 (반복 강조는 `#5C7CFA`) | | |
| 권고 | 카드 반경 · 배경 대비 | 16px · Neutral100 위 파스텔 카드 없음 | | |
| 권고 | 서체 굵기 · 크기 | Regular/Bold만 · 디스플레이급 대형 글자 없음 | | |
| 권고 | 버튼 형태 | 주 버튼 보라 채움 1개 · 보조는 선/회색 | | |

- **게이트 행**은 원문이 「예외 없이 금지」·「반드시 지킬 것」으로 정한 규칙이다(DEC-027 결정 3). 판정 값: `✅ 준수` / `❌ 위반` / `⚠️ 이탈 — 명세 지정`(① 경로 — 면제) / `해당 없음`. **`❌ 위반`이 하나라도 있으면 착지시키지 않는다.**
- **권고 행** 판정 값: `✅ 정합` / `⚠️ 이탈` / `⚠️ 이탈 — 명세 지정` / `해당 없음`. 재생성 사유일 뿐 착지를 막지 않는다.
- **명세에 없는 문구가 새로 생겼으면 이 표가 아니라 §7-13 문구 게이트 불통과다** — 그쪽 경로로 간다.

## ⑥ 위반·이탈이 나오면 — 재생성 상한을 나눠 쓴다

- 재생성은 §7-13의 **최대 2회를 모든 결함이 함께 쓴다.** 디자인 결함 때문에 상한이 늘지 않는다.
- 한 번에 강화 문장 1개 규칙도 그대로다. 결함이 여럿이면 **문구(§7-13) > 대조군 보존(§7-15) > 디자인 절대 규칙(§7-19) > 레이아웃 · 스타일 · 디자인 권고** 순으로 하나만 잡는다. 문구와 보존은 실험을 오염시키고, 절대 규칙 위반은 브랜드를 오염시키며, 권고 이탈은 디자이너가 최종 시안에서 바로잡을 수 있다.
- 강화 문장은 `mockup-prompt-guide.md` ⑥ 카탈로그의 「디자인 가이드 이탈」 행을 쓴다.
- **2회로도 게이트 행 `❌ 위반`이 남으면 「위반 영역 비움 초안」을 1회 만든다** (SKILL.md M4-3b · `mockup-prompt-guide.md` ⑤-d).
  - ③ 새로 그린 에셋 → 같은 자리·같은 크기의 무채색 `#E9ECEF` 자리표시.
  - ① 그림자·외곽선 · ② 금지 fill → 요소 안의 문구·배치는 두고 **면만 무채색 평면**(카드 `#F1F3F5`, 버튼·배지 `#CED4DA`, 그림자·외곽선 없음). 요소를 통째로 비우면 헤드라인·CTA까지 사라진다.
  - 문구 비움과 동시에 필요하면 한 번으로 합친다. 비움 초안도 다시 판정받고, **그래도 남으면 착지하지 않는다** — `없음 — 제작 요청 명세로 대체`.
- **권고 행 `⚠️ 이탈`이 상한 뒤에도 남으면 착지한다.** 대신 M5 착지 요약 표의 「디자인 권고 항목」 행과 디자이너 전달 안내에 적어 넘긴다 — 예: `디자인 가이드 이탈: 카드 반경 — 최종 시안에서 교정`. 노션 캡션 정본 문면(§7-14)은 건드리지 않는다.

## ⑦ 원문이 갱신됐을 때

- **참가자**: 코치가 새 `design.md`를 나눠 주면 로컬 파일을 **통째로 바꾼다**(부분 수정하지 않는다). 경로가 같으면 `.env`는 그대로 둔다. 에셋 목록은 로컬 파일만 바뀌면 바로 반영된다.
- **플러그인 관리자(코치)**: 이 파일 ② 표와 ③ 문장의 hex 값을 새 원문 frontmatter `colors` · `components`와 대조하고, 머리말의 「기준 원문」 날짜를 새 `updated:`로 올린다.
- **어긋났을 때**: M0에서 로컬 원문 `updated:`가 기준 원문 날짜보다 뒤면 참가자에게 이렇게 알리고 진행한다 — 막지 않는다.

  > "갖고 계신 디자인 가이드가 {로컬 날짜} 판인데, 스킬의 초안용 규칙은 {기준 날짜} 판 기준입니다. 색·카드 규칙이 바뀌었을 수 있어요 — 이번 초안은 진행하고, 코치께 규칙 갱신을 요청해 주세요."
