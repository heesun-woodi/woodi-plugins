# 이미지 생성 제공자 설정 가이드

이 문서는 **M0 준비 점검** 단계에서 읽습니다 — 워크숍 시작 전에 참가자가 미리 키를 발급받아 두었는지 확인할 때 사용하세요.

이 스킬(`cro-variant-mockup`)의 `scripts/generate_variant.py`는 참가자가 올린 control 스크린샷을 참조 이미지로 삼아, Gemini 또는 OpenAI의 이미지 생성 API로 variant 시안 초안을 만듭니다. python3 표준 라이브러리만 사용하므로 별도 설치(pip, venv)는 필요 없지만, **API 키만큼은 참가자 각자 발급**해야 합니다 — 두 제공자 모두 개인 계정 기준 무료/유료 정책이 있어 팀 공용 키를 쓸 수 없습니다.

## ① 제공자 비교

| | Gemini (권장) | OpenAI (대안) |
|---|---|---|
| 발급 URL | https://aistudio.google.com/apikey | https://platform.openai.com/api-keys |
| 무료 여부 | 무료 티어 있음 (참가자 대부분 이걸로 충분) | 무료 티어 없음 — 결제수단 등록 필요 |
| 기본 모델 | `gemini-3.1-flash-image` | `gpt-image-1` |
| 장당 비용 | 약 $0.04 | 약 $0.04 (모델·해상도에 따라 변동) |
| 특징 | 응답 속도 빠름(7~11초대, 실측), image-to-image 안정적 | control 이미지 보존력 강화 옵션(`input_fidelity=high`) 지원 |
| 출력 방향 | 원본 비율 유지 | 기본 세로 1024x1536 (모바일 화면 비율) |

특별한 사정이 없으면 **Gemini**로 시작하세요. 무료 발급이 더 쉽고 실측 속도도 빠릅니다. OpenAI는 Gemini 계정 발급이 막혀 있거나, control 이미지 보존력을 더 강하게 걸고 싶을 때의 대안입니다.

키를 두 개 다 발급해 두는 것 자체는 문제 없습니다. 다만 그 경우 스크립트가 어느 쪽을 쓸지 스스로 정할 수 없으므로, 실행할 때마다 `--provider gemini` 또는 `--provider openai`를 직접 지정해야 합니다.

## ② 키 세팅 절차

1. `scripts/.env.example`을 같은 폴더에 `.env`라는 이름으로 복사합니다.
   ```bash
   cp scripts/.env.example scripts/.env
   ```
2. 위 표의 발급 URL에서 키를 받아 `.env` 파일을 열고 `GEMINI_API_KEY=` 또는 `OPENAI_API_KEY=` 뒤에 붙여넣습니다. 앞뒤 공백이나 따옴표는 넣지 않아도 됩니다.
3. **`.env` 파일은 저장소에 커밋하지 마세요.** 개인 키는 개인 소유입니다 — 다른 참가자와 공유하거나 노션·슬랙에 붙여넣지 마세요. `.env`가 실수로 git에 올라가지 않도록 `.gitignore`에 포함되어 있는지도 한 번 확인하세요.
4. `.env` 파일을 스크립트와 다른 위치에 두고 싶다면 실행 시 `--env <경로>`로 직접 지정할 수 있습니다. (탐색 순서: `--env` 인자 → 실행 위치의 `.env` → 환경변수 순으로 키를 찾습니다.)

## ③ 동작 확인 — 원칙: "이미지 실수신은 실키 1장 생성으로만 증명"

가짜 키나 빈 키로 스크립트를 돌리면 인증 오류(401 등)까지는 확인할 수 있지만, **이미지가 실제로 생성되는지는 확인되지 않습니다.** 즉 "스크립트가 오류 없이 끝났다"가 "이미지를 받았다"를 의미하지 않습니다. 준비 점검에서는 반드시 진짜 키로 이미지 1장을 실제로 생성해 눈으로 확인하세요.

확인 명령 예시:

```bash
python3 scripts/generate_variant.py \
  --control 아무_스크린샷.png \
  --prompt "이 화면과 같은 레이아웃으로, 버튼 색만 파란색으로 바꿔줘." \
  --out-dir /tmp/imagegen-check \
  --name SMOKE-TEST
```

마지막 줄에 `OK /tmp/imagegen-check/SMOKE-TEST_1.png`가 뜨고, 그 경로를 열었을 때 실제 이미지가 보이면 준비 완료입니다.

종료 코드로도 대략적인 상태를 구분할 수 있습니다 — 참고용이지, 이 코드만 보고 "이미지가 왔다"고 판단하지는 마세요(이미지 확인은 눈으로 직접):

| 종료 코드 | 의미 |
|---|---|
| 0 | 요청한 이미지가 최소 1장 이상 생성됨 (`out-dir`에서 직접 확인) |
| 1 | 요청한 이미지가 전부 생성 실패 (키는 유효했을 수도 있음 — 프롬프트·모델·요청 형식 문제일 수 있음) |
| 2 | 키를 찾지 못했거나, 키가 두 개 다 있는데 `--provider`를 지정하지 않음 (설정 문제, API 호출 자체가 일어나지 않음) |

## ④ 함정 목록

| 함정 | 설명 |
|---|---|
| responseModalities 조용한 실패 | Gemini는 `generationConfig.responseModalities`를 빠뜨리면 HTTP 200과 함께 텍스트만 돌려주고 이미지는 주지 않습니다 — 오류가 나지 않아서 알아채기 어렵습니다. `generate_variant.py`는 이 값을 항상 지정하고, 이미지 파트가 없으면 명시적으로 실패 처리하도록 방어되어 있으니 스크립트를 그대로 쓰면 이 함정은 신경 쓰지 않아도 됩니다. |
| `gemini-2.0-flash-preview-image-generation` 폐기 | 이 모델명은 404로 폐기되었습니다 — `--model`로 직접 지정하지 마세요. 기본값(`gemini-3.1-flash-image`)을 그대로 쓰세요. |
| 한글 텍스트 렌더링 신뢰 불가 | 생성된 이미지 속 한글 문구(가격, 버튼 라벨 등)는 오타·왜곡이 실측으로 2회 확인되었습니다(예: "슈퍼대디"→"슈부대디", "33,660원"→"33,660은"). 매번 재현되는 것도 아니라서 "한 번 잘 나왔으니 다음도 괜찮겠지"라고 넘기면 안 됩니다. 이 스크립트는 이미지를 생성만 하고 글자를 검수하지 않습니다 — 생성된 이미지 속 문구를 확정 문구와 글자 단위로 대조하는 검수는 스킬(cro-variant-mockup) 소관이니, 스크립트 산출물을 그대로 채택하지 말고 반드시 검수 게이트를 거치세요. |
| Gemini는 잘못된 키에도 400을 반환 | 다른 API는 보통 인증 실패를 401/403으로 알려주지만, Gemini는 키가 틀려도 HTTP 400(`"API key not valid"`)을 반환합니다 — 상태코드만 보면 "요청 형식이 잘못됐나?" 하고 엉뚱한 곳을 찾기 쉽습니다. 스크립트가 이 경우를 구분해 안내한다 — 400 응답 본문에서 이 케이스를 감지하면 "API 키를 확인하세요" 메시지를 정확히 띄웁니다. |
| 429 (요청 과다) | 스크립트가 429/503 응답에 한해 최대 3회까지 지수 백오프로 자동 재시도합니다(2초 → 4초 간격). 그래도 실패하면 잠시(1~2분) 쉬었다가 다시 실행하세요. |
| "가짜 키로도 안 죽으니 됐다"는 착각 | 가짜 키는 401/400급 오류까지만 확인해 줍니다. 이미지가 실제로 오는지는 진짜 키로 1장을 생성해봐야만 압니다 — 아래 ③ 항목을 반드시 거치세요. |

## ⑤ 비용·안전 원칙

- API 키는 **개인 소유**입니다 — 팀 공유 키를 만들지 마세요. 키가 유출되면 발급 페이지에서 즉시 재발급(폐기)하세요.
- control 스크린샷은 **마스킹을 거친 뒤에만** 외부 API로 전송됩니다(마스킹 게이트는 스킬이 담당). 보험 도메인 PII(이름·연락처·주민번호·계약번호 등)가 남아있는 원본 스크린샷을 직접 이 스크립트에 넣지 마세요.
- 이 스크립트로 만든 이미지는 **AI 초안**입니다. 참가자·팀에 공유할 때는 "AI 생성 초안"임을 표시하고, 최종 시안 채택은 사람이 결정합니다(스킬의 원칙과 동일 — 시안 제작을 대행하는 것이 아니라 초안 생성만 돕습니다).
- 생성 결과와 프롬프트·모델·소요시간은 `{out-dir}/metadata.json`에 자동 기록됩니다. 이 파일에는 API 키가 절대 포함되지 않지만, control 이미지 경로는 그대로 남으므로 공유 전에 확인하세요.

## ⑥ 문제가 계속되면

- 401/403이 반복되면: 키를 다시 복사해 붙여넣었는지, `.env` 파일 경로가 맞는지 확인하세요. 공백이나 줄바꿈이 섞여 들어가지 않았는지도 점검하세요.
- 404가 뜨면: `--model`을 직접 지정했다면 오타나 폐기된 모델명(위 함정 목록 참고)이 아닌지 확인하세요.
- 이미지는 왔는데 내용이 이상하면(레이아웃 붕괴, control과 무관한 결과): 프롬프트 파일 내용을 다시 검토하세요 — 이 스크립트는 프롬프트 품질을 검증하지 않습니다.
- 그래도 안 풀리면 코치에게 공유하세요. 이때도 `.env`나 키 값 자체는 절대 붙여넣지 말고, 오류 메시지와 사용한 명령만 공유하면 충분합니다(스크립트가 키를 출력에 섞지 않도록 설계되어 있어, 오류 메시지에 키가 노출될 걱정은 하지 않아도 됩니다).

이 문서는 준비 점검용 참고 자료입니다 — 시안 프롬프트를 어떻게 쓰는지, 생성된 이미지를 어떻게 검수·채택하는지는 스킬 본체(`SKILL.md`)와 `mockup-prompt-guide.md`를 따르세요.
