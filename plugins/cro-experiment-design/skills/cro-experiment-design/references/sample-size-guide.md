# 샘플사이즈·기간 계산 가이드 — Step 워크시트

> 정본: `references/output-contract.md` §3-7(E6)·§7-1~7-4 — 이 파일과 어긋나면 계약이 이깁니다.

— STEP 4(E6 샘플사이즈·기간 표) 산출 시 읽는다. 이 표는 계약을 **실제로 계산하는 워크시트**다 — 계약과 열 이름·공식·판정 값이 문자 단위로 일치해야 한다. 원 출처: `cro-methodology-kb/06_experiment-design.md` §③④⑤, 타기업 세션 덱 4/5부, 노션 템플릿 `3-2`.

## Step 0. 입력값 수집

E6는 항상 **입력값 표(출처 열 포함) → 계산 → 결과 → 실현성 판정**의 4단 구조로 낸다. 입력값을 먼저 보여주지 않은 계산 결과는 출력하지 않는다.

| 항목 | 무엇을 채우는가 | 출처 우선순위 |
|---|---|---|
| Baseline (p0) | Primary의 현재 전환율 | ① Amplitude 실쿼리(조회조건 명시) ② `problem-areas.md`·`goaltree-downstream-correction.md` 실측(차선) |
| 일 UV | 실험 지면의 일 순방문자 — **분모** | 실쿼리 또는 참가자 답. 스킬이 추정하지 않는다 |
| Variant 수 | 대조군 포함 전체 그룹 수 | E5·E2에서 확정된 값 |
| MDE | Step 1에서 확정 | — |

각 값에는 **출처가 필수**다. 출처 없이 표를 내지 않는다.

**일 UV = 전체 앱 UV가 아니다.** E5의 `Trigger Point`가 곧 노출 정의이고 노출 정의가 곧 분모다. "실험 지면에 트리거 조건을 통과해 진입한 유저"가 일 UV의 정의이지, 앱 전체 일 UV가 아니다. 지면을 좁게 잡을수록 일 UV가 작아지고 기간이 늘어난다는 점을 계산 전에 미리 알려준다.

### ⚠️ Baseline 오염 경고 (필수 확인)

Baseline을 뽑기 전에 **아래 구간이 오염 구간인지** 반드시 확인한다 (`funnel-data-analysis.md` 진단 근거):

- **명절 연휴 주간**(예: 추석 연휴가 낀 주)은 처리 지연으로 지표가 급락했다가 다음 주 급반등하는 패턴이 관측됐다 — 그 주만 떼어 보면 baseline이 심하게 왜곡된다.
- **프로모션·대형 캠페인 주간**도 동일한 이유로 제외한다.
- **2025-12월 데이터는 baseline 산정에 사용하지 않는다** — 저단가 상품 믹스 시프트 또는 집계 기준 변화로 의심되는 폭증이 관측된 구간이라 정상 baseline을 대표하지 않는다.
- **CRM(Braze) 리터치 유입이 혼입된 지표는 주의한다** — 신규 유입과 기존 유저 재접촉이 하나의 전환율에 섞여 있으면, 실제로는 신규 유입 전환이 좋아지지 않았는데도 리터치 비중이 늘어난 것만으로 지표가 개선된 것처럼 보일 수 있다. 실험 지면이 리터치 채널과 겹치면 이 문제를 특히 의심한다.
- **권장**: 최근 **4주 이상**의 정상 주간 평균을 쓴다. 2~4주보다 넉넉히 잡는 편이 특이치 영향을 줄인다.

오염 구간이 섞여 있으면 비고에 `오염 구간 포함 — {사유}`로 남기고 그대로 진행하지 않는다.

## Step 1. MDE 정하기

**Absolute(%p)와 Relative(%)를 구분한다.** 계산기 입력은 관례적으로 Relative, 결과 보고는 **둘 다** 적는다.

> 예: Baseline 5%, Relative MDE 20% → Absolute MDE = 5% × 20% = **1%p** (5% → 6%)

"20% 개선"이라고만 쓰면 6%(rel 해석)인지 25%(abs 해석)인지 알 수 없다 — 이 혼동이 실무 사고의 대부분을 차지한다.

**이 STEP은 그루밍(hg)의 Target 확정에서 넘어온 MDE 근사치를 실험설계 수준으로 재확정하는 자리다.** hg 계약은 Target 3법(벤치마크/MDE 근사/내부 Gap)으로 Target을 확정하면서 MDE는 근사값만 두고 "실험설계에서 재확정"을 강제한다 — 여기가 그 재확정 지점이다.

**MDE 규칙 (하드, §7-4)**: **MDE(Relative) ≤ Target 상대 개선율.** 가설이 "N% 개선"을 목표로 하는데 MDE를 N%보다 크게 잡으면, 목표대로 개선돼도 그 개선을 감지하지 못하는 설계가 된다 — 감지 못하면 "표본 부족 → 보류"로 끝난다. MDE > Target이 나오면 계산을 진행하지 않고 되돌린다. **Target을 올리는 것은 이 스킬의 소관이 아니다** — hg 스킬로 라우팅한다.

**Target 미확정 분기**: Target이 미확정인 채 진행 중이면(E1 G-2 결손 override) MDE ≤ Target 검증은 보류하고, E6 결과 전체에 `⚠️잠정 — Target 미확정`을 표기한다(계약 §7-4).

MDE는 통계가 정해주는 값이 아니라 **"이만큼은 올라야 롤아웃할 가치가 있다"는 의사결정 임계값**이다. ICE의 Impact 판단과 같은 근거를 쓴다.

## Step 2. 샘플사이즈 계산

### 공식

```
n = 2 × (Z_α/2 + Z_β)² × p̄(1-p̄) / δ²

  Z_α/2 = 1.96  (α = 0.05, 기본값 고정)
  Z_β   = 0.84  (검정력 80%, 기본값 고정)
  p0    = Baseline 전환율
  p1    = p0 × (1 + MDE_relative)
  p̄     = (p0 + p1) / 2
  δ     = p1 − p0   (= MDE Absolute)

n은 Variant당 필요 샘플이다.
```

**α·검정력은 시작 전에 합의하고 못박는다.** 결과를 본 뒤 α를 0.10으로 옮기는 것은 판정 조작이다.

### 손계산 절차 (한 줄씩 대입해서 보여준다)

1. p1 = p0 × (1 + MDE_relative)
2. p̄ = (p0 + p1) / 2
3. δ = p1 − p0
4. n = 2 × (1.96 + 0.84)² × p̄(1-p̄) / δ²
5. 총 필요 샘플 = n × Variant 수(대조군 포함)

결과만 던지지 않는다. 4단계를 다 보여준 뒤에 값을 낸다.

### 워크드 예시 (가상 수치 — 검산용)

> Baseline 55%, MDE Relative 6%, Variant 수 2개(Control + A). **가상 수치이며 실측값이 아니다.**

| 단계 | 계산 | 값 |
|---|---|---|
| p1 | 0.55 × (1 + 0.06) | 0.583 (58.3%) |
| δ (Absolute) | 0.583 − 0.55 | 0.033 (3.3%p) |
| p̄ | (0.55 + 0.583) / 2 | 0.5665 |
| p̄(1-p̄) | 0.5665 × 0.4335 | 0.245578 |
| (Z_α/2+Z_β)² | (1.96+0.84)² = 2.8² | 7.84 |
| n | 2 × 7.84 × 0.245578 / 0.033² | **약 3,536명** (Variant당) |

> **검산용 결과값: n ≈ 3,536명/Variant.** (0.033² = 0.001089, 분자 2×7.84×0.245578 ≈ 3.8507 → 3.8507/0.001089 ≈ 3,535.96 → 올림 3,536)

### Evan Miller 계산기 교차검증 (권장 — 노션 `3-2`가 지목하는 도구)

[Evan Miller Sample Size Calculator](https://www.evanmiller.org/ab-testing/sample-size.html)에서 아래를 입력해 손계산 결과와 대조한다.

| 계산기 필드 | 입력값 |
|---|---|
| Baseline conversion rate | p0 (예: 55) |
| Minimum Detectable Effect | Absolute 또는 Relative 선택 후 δ 또는 MDE_relative 입력 (위 예시라면 Absolute 선택 시 3.3, Relative 선택 시 6) |
| Statistical power | 80% (기본값) |
| Significance level | 5% (기본값) |

**손계산과 계산기 값이 ±10% 이내면 통과.** 크게 어긋나면 Absolute/Relative 입력 단위를 혼동했는지부터 의심한다.

## Step 3. 기간 계산

```
총 필요 샘플 = 총 필요 샘플 (Step 2 결과)
예상 기간(일) = 총 필요 샘플 ÷ 실험 지면 일 UV
```

노션 템플릿 `3-2`의 안내식(샘플사이즈 × variants 수 ÷ 일 UV)과 동일하다.

> 위 예시 이어서: 총 필요 샘플 = 3,536 × 2 = 7,072명. 일 UV 500명(가상)이라면 예상 기간 = 7,072 ÷ 500 = **14.14일 → 15일**(올림).

### 최소 관찰 기간 (샘플 충족과 무관하게 지킨다)

- **최소 7일** — 요일 효과(주말/평일 편차)를 잡기 위해 필수.
- **최소 1 비즈니스 사이클** 권장.
- 계산상 2~3일 만에 샘플이 찬다는 결과가 나와도, **최소 관찰 기간이 이긴다** — 5일 만에 샘플이 찼다고 5일에 끝내지 않는다. 계산된 기간이 최소 관찰 기간보다 짧으면 최소 관찰 기간으로 올려 쓴다.

## Step 4. 실현성 판정

| 예상 기간 | 판정 | 조치 |
|---|---|---|
| **≤ 28일** | ✅ 진행 | 그대로 실행 (단, 최소 관찰 기간은 별도로 지킨다) |
| **28~90일** | ⚠️ 조건부 | 아래 조정 순서를 1개 이상 적용하고 재계산 |
| **> 90일** | 🔁 재설계 | 조정으로 안 되면 실험 자체를 다시 설계 — E2·E5로 되돌아간다 |

### 초과 시 조정 순서 (이 순서로 묻는다 — 계약 §3-7과 일치)

1. **지면을 확대**할 수 있는가 (대상 화면을 하나 더 붙인다)
2. **타겟을 재정의**할 수 있는가 (전체 → 특정 진입 경로·세그먼트로 좁혀 Baseline을 올린다)
3. **MDE를 상향**할 수 있는가 — 단, Step 1의 상한(`MDE ≤ Target 상대 개선율`)을 넘지 않는 선에서만
4. **Primary를 더 앞쪽 선행지표로** 옮길 수 있는가 (모수가 커지고 Baseline이 올라간다)
5. (그 다음) **Variant 수를 축소**한다 — A/B/n → A/B

조정 없이 "그냥 오래 돌리면 된다"로 넘어가지 않는다.

### 트래픽 확보 방법 (덱 4/5부 요약)

위 5단계 조정으로도 부족할 때 검토하는 보조 수단:

1. 필요 트래픽이 찰 때까지 실험 기간을 연장한다 (단, 최소·최대 기간 룰 안에서만)
2. 트래픽이 충분한 지면의 가설 우선순위를 먼저 올린다
3. Variant 개수를 최소화한다
4. 소규모 코호트보다 모수가 큰 유저 그룹을 대상으로 잡는다

## 조견표 (그룹당 필요 샘플 — 자릿수 감을 먼저 잡는 용도)

> 출처: `cro-methodology-kb/06_experiment-design.md` §③ 조견표. 계산기·손계산 전에 "이 baseline이면 대략 몇 명이 필요한지" 감을 잡는 용도다 — 정밀 판정은 반드시 Step 2의 손계산 또는 계산기로 한다.

| Baseline 전환율 | 기대 상승률(Relative) | 그룹당 필요 샘플 |
|---|---|---|
| 1% | +10% | ~150,000 |
| 1% | +20% | ~40,000 |
| 2% | +15% | ~25,000 |
| 3% | +10% | ~50,000 |
| 3% | +20% | ~15,000 |
| 5% | +10% | ~30,000 |
| 5% | +20% | ~8,000 |
| 10% | +10% | ~15,000 |
| 10% | +20% | ~4,000 |
| 40~50% | +10% | ~2,000 |

**즉시 읽히는 함의**: Baseline이 낮을수록 필요 표본이 폭증한다(1%/+10%는 그룹당 15만 명). Baseline이 높은 지면일수록 실험 효율이 좋다(40~50% 구간은 +10%(rel)를 2,000명으로 잡아낸다). Baseline을 못 올리면 MDE를 올려야 하는데, 3%/+10%(5만)와 3%/+20%(1.5만)는 3배 이상 차이 난다.

## 자주 하는 실수

| 실수 | 증상 | 교정 |
|---|---|---|
| **MDE Relative/Absolute 혼동** | Baseline 5%에서 "20% 개선"을 목표로 잡았는데, Relative로 읽으면 목표가 6%(+1%p)인데 Absolute로 잘못 읽어 25%(+20%p)로 계산 — 표본·기간이 완전히 다르게 나온다 | 표에 **둘 다** 병기하고, 계산기 입력 필드에서 Absolute/Relative 중 무엇을 선택했는지 확인 |
| **일 UV를 전체 앱 UV로 잘못 잡기** | 기간이 실제보다 훨씬 짧게 나온다 | 분모는 **트리거 조건을 통과한 유저**다(Step 0). 앱 전체 DAU가 아니라 실험 지면 진입 유저 수를 쓴다 |
| **Baseline을 오염 주간에서 뽑기** | 명절·프로모션·2025-12월 데이터가 섞여 baseline이 왜곡된다 | Step 0의 오염 경고를 먼저 확인하고, 최근 4주 이상 정상 주간 평균을 쓴다 |
| **다중 비교 보정 누락** | Variant가 3개 이상(A/B/n)이거나 판정 지점이 여러 개면, 비교 쌍이 늘어날수록 우연히 유의해 보이는 결과(거짓양성)가 늘어난다 | 실제 참가자 사례에서 **2개 판정 구간을 비교하는 설계에 다중비교 보정을 적용해 표본을 다시 계산한 선례**가 있다 — Variant 3개 이상이거나 판정 지점이 2개 이상이면 보정 적용 여부를 먼저 확인하고, 판정이 1개뿐이면 보정이 필요 없다는 점도 함께 명시한다 |

## 검산 체크리스트 (표를 내기 전 스스로 확인)

- [ ] 입력값 표에 Baseline·MDE·α·검정력·Variant 수·일 UV가 전부 있고, **각 값에 출처가 붙어 있다**
- [ ] Baseline이 오염 구간(명절·프로모션·2025-12월)을 피했다 — 포함됐다면 비고에 명시했다
- [ ] MDE Absolute와 Relative를 **둘 다** 적었다
- [ ] `MDE(Relative) ≤ Target 상대 개선율`을 확인했다 — 위반이면 계산을 진행하지 않고 hg로 되돌렸다
- [ ] p1 → p̄ → δ → n → 총 샘플 → 기간을 **한 줄씩** 대입해 보여줬다
- [ ] Evan Miller 계산기로 교차검증했고, 손계산과 ±10% 이내다
- [ ] 계산된 기간과 최소 관찰 기간(7일) 중 **큰 값**을 최종 기간으로 썼다
- [ ] 28일 룰로 실현성을 판정했고, 28일 초과 시 조정 순서 5단계를 순서대로 검토했다
