## 0. 실험설계서 구체화의 정의

> **"실험설계서는 문서 산출물이 아니라 이해관계자 정렬 도구다."** (KB 06)
> 가설 한 줄로 시작해 기획·디자인·개발·데이터가 함께 Sync하며 구체화해 나가는 **과정 자체가 실험 설계**다.

설계서가 없거나 성기면 공유 즉시 아래 질문이 쏟아진다 — 그리고 **답을 준비하는 것이 이 세션의 일**이다.

| 질문하는 쪽 | 실제로 나오는 질문 | 답을 만드는 표 |
|---|---|---|
| 데이터 분석 | "목표 지표는 무엇이고, 측정하려면 추가 태깅할 이벤트가 있나요?" | E3 · E4 |
| 데이터 분석 | "얼마나 개선돼야 실험군 성공인가요? 몇 명이 필요한가요?" | E6 · E7 |
| 서비스 기획 | "어떤 사용자에게 실험하는 거죠? 전체인가요?" | E5 |
| 개발 | "실험 화면은 누가 어떻게 구현하나요? 배포가 필요한가요?" | E2 |
| 마케팅 | "다음 달 프로모션과 실험 기간이 겹치지 않나요?" | E7 |

**설계서가 구체적일수록** 커뮤니케이션 비용이 줄고 · 역할별 업무 파악이 쉬워지고 · 일정이 구체화되고 · 이슈를 미리 발견한다.

### 0-1. 그루밍과 실험설계의 경계

| | 그루밍 (hg) | 실험설계 구체화 (ed — 이 계약) |
|---|---|---|
| 목적 | **설득 준비** — 근거를 채워 ICE를 올리고 스프린트 열차에 탈 우선순위를 주장 | **세팅 준비** — 같은 가설을 "누가 봐도 같은 그림"으로 옮겨 실행 가능 여부를 판정 |
| 산출 단위 | 가설 1건의 근거 | 실험 1건의 설계서 |
| Variant | 후보 2개 이상 + 시안 **확보 여부**까지 | 변경 화면 **명세**까지 (협업자가 제작 가능한 수준) + 시안이 없으면 **AI 초안 라우팅**(§3-3a) |
| 지표 | Primary 목표 · Guardrail **후보** | Primary 1개 **확정** + Secondary + Guardrail 1~2개 **확정** + 측정 가능성 |
| Target/MDE | Target 3법으로 확정, MDE는 **근사** (`실험설계에서 재확정` 강제) | MDE **정밀** 확정 → 샘플사이즈 → 기간 → 실현성 판정 |
| 착지 | 노션 1~2장 + 가설 DB 속성 | 노션 1-4·1-5·3장 + **repo EXP 파일** |

- **완벽한 v1.0을 한 번에 만들려 하지 않는다.** 지금 적을 수 있는 항목부터 채워 v0.1을 먼저 만들고, 이해관계자 1차 컨택 후 v1.0으로 올린다 (KB 06). 미확보 칸은 지우지 않고 `⚠️미정` 또는 `코치 확인 필요`로 남긴다.

## 2. 입력 규격

### 2-1. 세션 단위 — 가설(실험) 1건

이 세션의 입력은 **그루밍이 끝난 가설 1건**이다. 여러 건을 요청받으면 1건씩 순서대로, 매 건 STEP 0부터. 실험 1건 = 설계서 1장 = EXP 파일 1개다.

### 2-2. 입력 3형 — 어느 것이든 정상

| 형태 | 내용 | 비고 |
|---|---|---|
| **노션 페이지** | 실험설계서 템플릿 페이지 본문 붙여넣기 | **권장** — 그루밍 착지분(1-1~1-4·2장)을 그대로 재료로 쓴다 |

| 11 | 시안 상태 | hg G5b 산출분 **또는 이전 ed 세션의 E2 산출분**(재진입 시). `없음 — 참가자 준비 필요`면 E1 G-4 `부분`. `있음 — AI 생성 초안(검토 필요)`도 `부분`이며 §3-3a로 이어진다 |
| 12 | Uplift 최종 KPI 금액 | hg G3 낙관 시나리오 값. 없으면 E1 G-5 결손. 금액 표기 시 §5 단가 규칙 적용 |
| 13 | Guardrail 후보 | hg G5 산출분. 없으면 E1 G-6 결손 |
| 14 | ICE 합 | 입력 값을 옮겨 적기만 한다 — 공란이면 공란. 이 세션에서 재산정하지 않는다 (§7-8) |
| 15 | 실험 지면 | 질문 — E5 타겟 지면·E6 일 UV의 전제 |
| 16 | 일 UV | E6 입력 — 실쿼리 또는 참가자 답. **스킬이 추정하지 않는다**. 없으면 `⚠️미정`으로 두고 기간을 산출하지 않는다 |
| 17 | 진행상태 | 노션 select 원값 그대로 |
| 18 | 담당자 | 질문 — E8b frontmatter `owner`·실험 대장 행 재료 |

**E0 행으로 두지 않고 다른 표에서 점검하는 것 2건** — 인테이크에서 값을 옮겨 적을 대상이 아니라 **판정 대상**이기 때문이다.

| 항목 | 어디서 점검하는가 |
|---|---|
| Rationale · Counter Rationale | **E1 게이트 G-7** — 존재 여부만 확인하고, 없으면 hg로 라우팅한다. 내용은 E8b §1 「왜 통할 것인가」로 그대로 옮긴다 |
| 병행 릴리즈 예정 | **E7 `병행 릴리즈 확인`** — 실험 예정 기간이 정해진 뒤에야 `release-log.md`와 대조할 수 있으므로 STEP 5에서 확인한다 |

**입력형별 구조적 결손 패턴 — 값이 없는 것과 그 입력형에 자리가 없는 것을 구분한다.**

| 입력형 | 구조적으로 비어 있을 수 있는 필드 | 처리 |
|---|---|---|
| **repo H5b 섹션** | `시안 상태` · **이 가설 고유의** `Uplift 최종 KPI 금액` | H5b 스키마에 해당 칸이 없거나, hg가 산출물을 **노션에만 게재**한 경우다. **E1 G-4·G-5를 판정하기 전에 "같은 가설의 노션 실험설계서 페이지가 있는지" 먼저 묻는다.** 있으면 그 본문을 받아 재판정하고, 없을 때만 결손으로 확정한다. **입력형의 한계를 참가자의 결손으로 오판하지 않는다** |
| **hg G7a 블록** | `일 UV` · `실험 지면` · `담당자` | 그루밍 착지 블록에는 실험 운영 정보가 없다 — 결손이 아니라 **이 세션에서 처음 묻는 필드**다. E1 게이트 대상이 아니다 |
| **노션 페이지** | (구조적 결손 없음 — 권장 입력형) | 섹션이 비어 있으면 실제 결손이다 |

### 2-4. 프로젝트 제약 (hg §2-4 승계)

리스트·시트·노션에 근거 사용 금지 규칙이 명시돼 있으면 스킬 기본 절차보다 우선한다. STEP 0에서 한 번 확인하고 전 STEP에 적용한다. 금융·보험 도메인이므로 **원천 PII는 어떤 표에도 옮기지 않는다** — 위치만 말하고 `[마스킹]`.

## 3. 표별 열 정의 (이름·순서 고정)

### 3-1. E0. 인테이크 정규화 표 — 2열 (항목/값)

**행 18개(순서 고정)**: `HYP ID` · `EXP ID(제안)` · `실험명` · `축` · `PSR 전문` · `문제ID` · `R 노드` · `Baseline` · `Target (Absolute / Relative / 방법)` · `Variant 후보` · `시안 상태` · `Uplift 최종 KPI 금액` · `Guardrail 후보` · `ICE 합` · `실험 지면` · `일 UV` · `진행상태` · `담당자`

- **§2-3의 필수 필드 목록과 문자 단위로 대응한다** — 결손 시 처리는 §2-3 표를 따른다.
- `Rationale · Counter Rationale`과 `병행 릴리즈 예정`은 **E0 행이 아니다** — 각각 E1 G-7과 E7에서 점검한다 (§2-3).
- ICE는 **입력 값을 옮겨 적기만 한다.** 이 세션에서 재산정하지 않는다 (§7-8).

### 3-2. E1. 그루밍 완료 게이트 표 — 5열

hg §9 완료 판정 9항목 중 **실험설계에 실제로 필요한 것만** 추린 게이트다. 여기서 막히면 이 스킬은 진행하지 않고 되돌린다.

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 게이트 항목 | 아래 7항목 중 해당 |
| 2 | hg 대응 | 그루밍 계약의 어느 산출물인가 (`G3`/`G4`/`G5`/`G5b` 등) |
| 3 | 판정 | `충족` / `부분` / `결손` |
| 4 | 근거 | 판정 사유 한 줄 (입력의 어느 대목인지) |
| 5 | 대응 | `진행` 또는 `→ hg 스킬 {STEP}로 라우팅` |

**게이트 7항목**

| 항목 | 충족 기준 |
|---|---|
| G-1. PSR 전문 | 한 문장으로 존재하고 Target이 문장에 들어 있다 (DEC-005) |
| G-2. Baseline · Target | Baseline 확정 + Target이 3법(벤치마크/MDE 근사/내부 Gap) 중 하나로 **방법 병기**돼 있고 Absolute·Relative 둘 다 표기 |
| G-3. Variant 후보 2개 이상 | hg G5b 표에 후보가 2개 이상 (DEC-007) |
| G-4. 대조군·실험군 시안 | `있음(링크)` 또는 `해당 없음(문구 교체만)`. `없음 — 참가자 준비 필요`는 **부분** · `있음 — AI 생성 초안(검토 필요)`도 **부분** (사람 검토·채택 전이므로) |
| G-5. Uplift 최종 KPI 금액 | 양 축 모두 계약 금액까지 계산됐고 `1-2`에 1줄 병기 (DEC-007) |
| G-6. Guardrail 후보 | hg G5 하단에 후보가 1개 이상 |
| G-7. Rationale · Counter | Rationale 1유형 이상 + Counter Rationale 1줄 |

- **결손은 이 스킬이 채우지 않는다.** `결손`·`부분` 항목은 **해당 항목만** hg 스킬의 대응 STEP으로 라우팅한다 — **재그루밍(전체 재수행)이 아니다.** 예: G-2 결손 → hg STEP 3(G4 Target 확정)만 / G-5 결손 → hg STEP 2(G3 Uplift)만.
- **라우팅 안내는 결손 건수와 무관하게 한 번에 낸다.** 결손이 2건 이상이면 항목을 하나씩 따로 안내하지 않고 **목록으로 묶어 한 번에** 말한다 — 참가자가 hg 세션을 몇 번 열어야 하는지 알아야 하기 때문이다.

> **라우팅 대사(정본)**: `{항목ID·항목명 목록}이 채워지지 않았습니다. 이건 실험설계에서 채우는 게 아니라 그루밍 산출물이라, 가설 그루밍 스킬의 {대응 STEP 목록}에서 해당 부분만 채우고 오시면 됩니다 — 그루밍을 처음부터 다시 하는 게 아닙니다.`
> - 1건이면 목록 자리에 항목 하나만 들어간다 (`G-2 Baseline·Target`).
> - 2건 이상이면 쉼표로 묶고 대응 STEP도 함께 묶는다 (`G-2 Baseline·Target, G-5 Uplift 최종 KPI 금액` → `STEP 3, STEP 2`).
> - **결손 항목이 여러 개여도 "재그루밍"이라고 부르지 않는다.** 항목 수가 늘어난 것이지 작업 성격이 바뀐 것이 아니다.
- **G-4가 `부분`이면 진행할 수 있다** — 이 세션의 E2가 **제작 요청 명세**로 시안을 대체하기 때문이다 (§3-3). 나머지 항목이 `결손`이면 진행하지 않는다.
- **G-4 `부분`의 승격 규칙**: `있음 — AI 생성 초안(검토 필요)`은 사람이 검토해 **채택하면** E2 시안 행을 `있음(링크)`으로 올리고 G-4도 `충족`으로 승격한다 — 승격 판단은 스킬이 하지 않는다 (§7-14).
- 게이트 통과 여부와 무관하게 **판정 결과를 먼저 보여주고 사람의 판단을 받는다.** 스킬이 임의로 되돌리거나 임의로 통과시키지 않는다.

### 3-3. E2. Variant 구체화 표 — 항목 × Variant 매트릭스

**열**: `항목` · `Control` · `{Variant ID}` · `{Variant ID}` … (Variant 수만큼, 대조군 포함 좌→우)
**행(순서 고정 10행 + 선택 1행)**:

| # | 행 이름 | 내용 |
|---|---|---|
| 1 | 핵심 컨셉 | 이 Variant가 전달하는 한 줄 (Control은 `기존 화면 유지`) |
| 2 | 타겟 문제 (BIAS) | **정본 27항목**(`50_reference/bias-checklist.md`, DEC-003) 중 항목 번호와 이름. 축약판 15항목 표기 금지 |
| 3 | 적용 전술 | 어떤 전술로 그 문제를 건드리는가 |
| 4 | 변경 화면 명세 | **`[헤드라인] / [이미지] / [CTA] / [노출 위치]` 4슬롯 필수.** 디자인·개발 협업자가 **이 명세만으로 제작 가능한 수준**이어야 한다. 해당 없는 슬롯은 `변경 없음`으로 명시 |
| 5 | 시안 | `있음(링크)` / `없음 — 제작 요청 명세로 대체` / `해당 없음(문구 교체만)` / **`있음 — AI 생성 초안(검토 필요)`** (§3-3a — 파일 경로 또는 링크 병기 필수) |
| 6 | MVP-Actionable | 고객의 어떤 **구체적 행동**을 유도하는가 + 그 행동이 Primary와 일치하는가 — `통과`/`미통과(사유)` |
| 7 | MVP-Value | 고객의 어떤 **문제**를 (실마리라도) 해결해 주는가 — `통과`/`미통과(사유)` |
| 8 | MVP-Learnable | 이 결과로 가설의 참·거짓을 **확인할 수 있는가** — `통과`/`미통과(사유)` |
| 9 | MoSCoW | `Must have`(빼면 검증 불가) / `Won't have`(빼도 검증되는데 들어가 있음 → 제거 대상) 판정. 제거 대상은 사유 병기 |
| 10 | 방향·가치 정합 | PSR의 **[솔루션 핵심가치]**를 그대로 전달하는가 — `정합` / `이탈 의심 — {사유}` |
| (선택) | 구현 가능성 초기 판정 | `Amplitude Experiment 피처 플래그로 가능` / `앱 릴리즈 필요(~3주)` / `미정` — **E6 기간 산정 전에 판정한다.** 릴리즈가 필요한데 뒤늦게 알면 설계 전체를 다시 짜게 된다. **실행 계획·일정 수립은 범위 밖**(세팅 영역)이며, 여기서는 어느 쪽인지 표시만 한다 |

**4번 행은 "존재 여부 표기"가 아니라 "구체 문구·설명 기입"이다.** `[헤드라인] 변경` 같은 표기는 명세가 아니다 — 협업자가 그것만 보고 만들 수 있어야 한다.

> 예: `[헤드라인] "보장 구멍 3개가 발견됐어요" — 평서형 단정, 질문형 금지 · 고객이 아는 말로` / `[CTA] "무료로 확인하기" — 기존 "점검 신청"에서 교체` / `[이미지] 변경 없음` / `[노출 위치] 기존 배너 자리 그대로, 스크롤 없이 보이는 첫 화면`
>
> 좋은 예·나쁜 예 대비와 슬롯별 작성 요령은 reference(`variant-design-guide.md`) 소관 — 계약은 이 한 줄 기준까지다.

**표 아래 필수 2줄**

1. **Variant 간 차별점**: "A와 B는 무엇이 다른가"를 한 줄로. **차이가 "강도 차이"에 그치면 지적한다** — Variant는 강도가 아니라 **가설이 달라야** 한다 (KB 06 원칙 1). 차별점이 불명확하면 `⚠️ Variant 차별점 불명확 — A/B/n의 값어치 없이 기간만 늘어난다`.
2. **User Flow 3단계**: ① 실험군 진입 시점 ② 변경 UI와 상호작용 ③ Primary 지표 발생까지.

**규칙**

- **단일 축 변형**: 하나의 Variant는 하나의 변경 축(카피 / UI / 정보구조 / 혜택 / 신뢰요소 / 인터랙션)만 담는다. 축이 섞이면 승패는 나와도 원인을 분해할 수 없다.
- **이 스킬은 시안을 직접 만들지 않는다** — AI 초안이 필요하면 `cro-variant-mockup`으로 라우팅한다 (§3-3a). 4번 행(변경 화면 명세)을 **제작 요청서 수준**으로 쓰고, 담당(디자이너·개발)과 필요 시점을 병기한다. **받은 시안·초안은 링크로 착지시킨다.**
- **고객 언어 검증**: 명세에 들어간 문구가 **고객이 아는 말인가**를 묻는다. 내부·업계 용어(예: 보험 도메인의 전문 용어)가 헤드라인·CTA에 그대로 들어가면 `⚠️ 고객 언어 확인 필요`로 표시한다.
- **운영 분기가 있는 Variant**(고객 상태에 따라 문구가 자동으로 갈리는 경우)는 **두 가지를 함께** 확인한다.
  - **① 분기별로 지표를 볼 수 있는가** — E4에서 조회 가능 여부를 확인한다. 분기별 수치가 안 나오면 결과 해석이 막힌다.
  - **② 표본 산정에서는 분기를 판정 군으로 센다** (DEC-011). **분기별 수치를 보겠다고 선언한 순간 그 분기가 판정 단위**다 — E6 `판정 군 수`에 분기를 포함하고 다중비교 보정을 검토한다 (§3-7·§7-17). **무작위 배정 여부와 무관하며, 「탐색용이라 판정 아님」이라는 이름표는 면제 사유가 아니다.**
- **Won't have 판정을 1개 이상 시도한다.** 팀이 만든 첫 Variant에서 뺄 것을 찾는 것이 이 표의 실질 효용이다 (KB 06 — 자주 삭제되는 것: 과한 디자인, 부가 설명, 추가 혜택 정보, 배너·이미지 욕심).

### 3-3a. E2 부속 — AI 시안 초안 라우팅 (DEC-009, 2026-08-24 — 신설)

시안이 `없음`인 채로 E2를 닫기 전에 **AI 초안으로 메울 수 있는지**를 한 번 묻는다. 초안 생성은 페어 스킬 **`cro-variant-mockup`**이 하고, 이 스킬은 **라우팅과 착지만** 한다.

**① 라우팅 조건 — 셋 다 충족일 때만 제안한다**

1. E2 시안 행이 `없음 — 제작 요청 명세로 대체`이고, 4번 행(변경 화면 명세) 4슬롯이 채워져 있다.
2. 참가자가 **본인 이미지 생성 API key**를 갖고 있다 (Gemini / OpenAI). — **키 값은 묻지도 출력하지도 않는다** (§7-12).
3. **Control 화면 스크린샷을 제공할 수 있다.** image-to-image의 입력이라 없으면 성립하지 않는다.

**② 라우팅 대사(정본)**

> `시안이 아직 없네요. 변경 화면 명세 4슬롯이 채워져 있으니 이걸 그대로 프롬프트로 써서 AI 초안을 만들어 볼 수 있습니다 — variant 시안 초안 생성 스킬(cro-variant-mockup)이 하는 일이고, 본인 이미지 생성 API key와 대조군 화면 스크린샷이 있으면 됩니다. 나오는 것은 어디까지나 「AI 생성 초안 — 검토 필요」이고 디자이너 최종 시안을 대신하지 않습니다. 진행해 보시겠어요?`

**③ key가 없으면 종전 경로 그대로다 — 변화 없음.** 변경 화면 명세를 제작 요청서 수준으로 쓰고 담당·필요 시점을 병기한다 (§3-3). **AI 초안을 조건으로 걸어 세션을 멈추지 않는다.**

**④ 산출물 수령 시 기입 형식** — E2 5번 행에 아래 형식으로 적는다. 3요소(상태·경로·표기)가 모두 있어야 착지다 (§7-14).

> `있음 — AI 생성 초안(검토 필요) / {파일 경로 또는 링크} / AI 초안 — {provider}/{model}, {생성일}`

- 착지 전에 **게이트 4종(§7-12 PII 마스킹 · §7-13 한글 문구 검수 · §7-15 대조군 보존 · §7-14 표기)을 통과**해야 한다. 통과 기록을 대화에 남긴다 — 리뷰(§3-12 D-1~D-4)가 이 기록을 본다.
- 노션 이미지 삽입·캡션 기입은 종전대로 **참가자**가 한다 (노션 MCP 비전제 — §2-2).

### 3-4. E3. 지표 3층 확정 표 — 6열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 층 | `Primary` / `Secondary` / `Guardrail(비즈니스)` / `Guardrail(신뢰성)` |
| 2 | 지표 | **이벤트 → 이벤트 경로**로 표기 (예: `{지면 진입 이벤트} → {목표 행동 이벤트}`) |
| 3 | 정의 | 분자 / 분모를 명시 (분모 = 노출 정의 = E5 Trigger Point와 일치해야 한다) |
| 4 | 현재값 | 수치 + **출처 병기**(실쿼리 조회조건 / 골트리 / `problem-areas.md` / 참가자 제공) |
| 5 | 목표값 | Primary는 `Baseline → Target (+N%p / +M% rel)` 둘 다. Secondary는 `–`. Guardrail은 **허용 기준**(예: `현재 대비 -3% 이내`) |
| 6 | 선정 근거 | 왜 이 층에 이 지표인가 한 줄 |

**하드 규칙**

- **Primary는 정확히 1개.** 2개를 두는 순간 "하나는 이기고 하나는 졌을 때"의 판정 규칙이 사라지고, 사후에 이긴 쪽을 Primary라 부르는 결과 조작이 발생한다.
  - **선행성 판정 질문(필수 출력)**: *"문제를 겪는 고객에게 이 솔루션이 노출됐을 때 **가장 먼저 개선될 지표**인가? 최종 KPI처럼 멀리 있는 지표는 아닌가?"* — 답이 "아니다"면 지면과 더 가까운 선행지표로 옮긴다.
  - Primary는 hg가 확정한 PSR의 R(선행지표)과 **같아야** 한다. 다르면 정합 질문을 띄우고 확정은 사람이 한다.
- **Secondary는 2~5개.** 두 가지 임무를 갖는다 — ① **"왜"에 답한다**(Variant와 사용자 사이에서 실제로 일어난 상호작용) ② **하류가 이어졌는지 본다**(아래 형태 규칙을 지킨 경우에 한한다).
  - **하류 지표는 형태로 판정한다 — 기준은 "분모가 무엇인가" 하나다** (DEC-011).
    - ❌ **구간 전환율**은 넣지 않는다. 예: `상담방 오픈 → 상담 시작`. 분모(`상담방 오픈`)가 **처치의 결과**여서, 실험군이 더 많이 열수록 원래 열지 않았을 **한계 사용자가 섞여 개선이 성공할수록 구간 비율이 떨어진다**(선택편향). 이 형태는 Secondary에도 **Guardrail에도** 넣지 않는다.
    - ✅ **누적 전환율**은 넣는다 — **권장**. 예: `점검신청 진입 → 상담 시작`. 분모가 **E5 Trigger Point**여서 Primary와 같고, 실험군·대조군이 같은 모집단 위에서 비교되므로 표본도 판정도 오염되지 않는다.
    - 하류를 **몇 단계까지** 볼지는 선택이다 — 노출 지점 기준 누적이기만 하면 `→ 상담 시작`도 `→ 1차 정보 입력`도 정상이다. 더 내려갈수록 신호가 옅어지는 트레이드오프만 명시한다.
    - 매출이 궁금하면 **Uplift 시뮬레이션(hg 소관)**, 병목 같으면 **다음 실험의 문제영역 후보**다.
  - > **v1.1까지는 "Secondary에 다음 퍼널 단계를 넣지 않는다 / 하위 퍼널이 걱정이면 Guardrail"이었다.** 그 서술이 *구간*과 *누적*을 구분하지 않아 누적 퍼널까지 함께 막고, 하류 관심사를 Guardrail로 떠넘겨 §7-6 2관문에 걸리게 만들었다. **하류 관심사는 Guardrail이 아니라 누적 퍼널 Secondary로 받는다.**
  - 가설에 담긴 **중간 목표**는 반드시 Secondary로 측정한다 (실패 시 "중간 목표조차 안 올랐다"와 "올랐는데 안 이어졌다"를 구분하기 위해).
- **Guardrail은 1~2개** (비즈니스·신뢰성 각 계열에서 뽑되 총 1~2개로 좁힌다 — 실험 판정 회의에서 실제로 볼 수 있는 개수).
  - **2관문을 모두 통과한 지표만 Guardrail이다** (DEC-011). 하나라도 걸리면 Guardrail이 아니다.
    - **관문 ① 실패조건성(필수 출력)**: *"Primary가 아무리 좋아도 이 지표가 떨어지면 **실험 실패라고 말할 수 있는가**?"* — 답이 "아니다"면 Secondary이거나 관찰 대상일 뿐이다.
    - **관문 ② 인과 연결성(필수 출력)**: *"이 솔루션이 이 지표를 **움직일 수 있는 경로가 있는가**?"* — **개입 지점(E5 Trigger Point)보다 상류에 있는 지표는 자동 탈락**이다. 실험이 논리적으로 건드릴 수 없으므로 감시 대상조차 아니다. 예: `지면 진입 후 섹션 콘텐츠 교체` 실험에서 **그 지면의 도달률**(진입 이전 단계)은 Guardrail이 될 수 없다.
    - 관문 ①만 통과하고 ②에서 걸린 지표는 **Guardrail 목록에서 제외**한다 — Secondary로 내리는 것도 아니다(설명력이 없다). 실험과 무관한 지표이므로 설계서에서 뺀다.
  - Guardrail은 성공을 증명하지 않는다. **거부권만** 갖는다. 허용 기준을 **숫자로 사전 합의**한다 — 지표별 허용 기준 설정 예시(이탈률·하위 퍼널 전환율·CS 문의·SRM·로드 시간 등)는 reference(`metrics-guide.md`) 참조.
  - **개수를 1~2개로 좁힌 것은 KB 06 표(비즈니스 2~3 + 신뢰성 2~3) 대비 이 계약의 조정 사항이다** (머리말 ①). 판정 회의에서 실제로 거부권을 행사할 수 있는 개수로 두는 편이, 감시 목록만 길고 아무도 안 보는 것보다 낫다는 운영 기준이다.

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 지표 | E3의 지표명 (전 지표를 1행씩 — 누락 금지) |
| 2 | 층 | E3의 층 |
| 3 | 태깅 여부 | `측정 중` / `미태깅` / `확인 불가` |
| 4 | 확인 근거 | Amplitude 택소노미 **실쿼리 조회조건**(이벤트명·기간·필터) 또는 참가자·데이터 담당 확인 |
| 5 | 태깅 요청 명세 | 미태깅일 때 필수 — `이벤트명 / trigger 조건 / 프로퍼티 / 요청 대상` 4항목. 측정 중이면 `–` |
| 6 | 조치 기한 | `실험 시작 전` 고정 + 구체 날짜가 있으면 병기 |

**하드 규칙**

- **미태깅 지표를 P/S/G로 확정한 채 설계 완료로 처리하지 않는다.** 5열의 태깅 요청 명세(4항목 전부)가 있어야 통과다. 명세 없이 "나중에 태깅하면 됨"으로 넘어가지 않는다.
- **`확인 불가`도 정상 값이다** — MCP 미연결·권한 문제로 조회가 안 되면 멈추지 않고 `확인 불가` + `코치 확인 필요`로 두고 진행한다. 다만 완료 판정(§9)에서는 미충족으로 카운트한다.
- **실쿼리 결과 값만 쓴다.** 추정·보간으로 태깅 여부를 판단하지 않는다.
- 운영 분기가 있는 Variant는 **분기별 조회 가능 여부**를 별도 행으로 넣는다 (§3-3).

### 3-6. E5. 타겟·트리거 표 — 2열 (항목/값)

행(순서 고정 9행): `실험 유형`(A/B · A/B/n · MVT) · `Target Audience`(세그먼트 정의) · `타겟 지면·화면`(URL 또는 화면 식별자) · **`Trigger Point`** · `Device`(Mobile / Desktop / Both) · `제외 조건` · `코호트 조건` · `대상 규모(추정 모수 + 출처)` · **`타겟 세그먼트 겹침 확인`**

- **Trigger Point가 곧 노출 정의이고 노출 정의가 곧 분모다.** E3 3열의 분모와 **문자 단위로 일치**해야 한다 — 어긋나면 실험이 끝난 뒤 "우리가 본 게 뭐였나" 논쟁이 생긴다. 예: `실험 지면 진입 시` / `스크롤 N% 도달 시` / `특정 상태 조건 충족 상태로 진입 시`.
- **제외 조건 3종은 기본 검토 대상**: 내부 직원 · 리터치(직전 노출자) · 봇·크롤러. 해당 없으면 `해당 없음`으로 명시하고 비워두지 않는다.
- **`타겟 세그먼트 겹침 확인` (DEC-011 — 신설, 하드).** 같은 스프린트에 **진행 중이거나 예정인 다른 실험의 `Target Audience`와 교집합이 있는지** 확인하고 `없음` 또는 `있음 — {실험 ID}, 교집합 {비율}(산출 근거)`로 적는다.
  - **판정 단위는 지면이 아니라 세그먼트다.** 지면이 달라도 세그먼트가 겹치면 걸리고, 지면이 같아도 세그먼트가 배타면 걸리지 않는다.
  - **겹치면 §7-16(동시 진행 금지 2단 원칙)을 따른다.** 이 행이 `있음`인데 §7-16 처리가 없으면 E5를 닫지 않는다.
  - **E7 `병행 릴리즈 확인`이 이 행을 대신하지 못한다** — 그쪽은 `release-log.md`의 **릴리즈**만 본다. 동시 진행 **실험**은 여기서 잡는다.
- **A/B/n으로 갈 때는 "3안이 정말 서로 다른 가설을 담고 있는가"를 먼저 묻는다.** 같은 가설의 미세 변주 3개는 값어치가 없고 기간만 1.5배로 늘린다. MVT는 이 프로젝트 트래픽 규모에서 대부분 E6 실현성 판정에 걸린다.
  - **단, 비교축이 `실험 2개` vs `A/B/n 실험 1개`일 때는 후자를 권한다** (DEC-011). 세그먼트가 겹치는 실험 2개를 각각 대조군 포함 variant 2개로 돌리느니, **우선순위가 높은 실험 1개에 집중해 대조군 포함 3개 이상의 variant로 1개만** 돌리는 편이 같은 트래픽에서 얻는 인사이트가 많다. 위 억제 서술은 `A/B` vs `A/B/n`을 비교할 때의 것이며 이 항목과 충돌하지 않는다 — **비교 대상이 다르다.**

### 3-7. E6. 샘플사이즈·기간 표 — 입력값 표 + 계산 절차 + 결과 표 + 실현성 판정

계산은 **반드시 이 4단 구조로** 낸다. 입력값을 보여주지 않은 계산 결과는 출력하지 않는다.

**① 입력값 표 — 3열**

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 항목 | 아래 7항목 고정 |
| 2 | 값 | |
| 3 | 출처 | **필수** — `Amplitude 실쿼리(조회조건)` / `problem-areas.md` / `diagnosis/goaltree-downstream-correction.md` / `골트리 current` / `참가자 제공` 중 명시 |

행: `Baseline (p0)` · `MDE (Relative %)` · `MDE (Absolute %p = p0 × Relative)` · `유의수준 α = 0.05` · `검정력 = 80%` · **`판정 군 수 (대조군 + Variant + 운영 분기)`** · `실험 지면 일 UV`

- **Relative(%)와 Absolute(%p)를 한 표에 둘 다 적는다** — 예: `Baseline 5%` · `MDE Relative 20%` → `MDE Absolute 1%p`(5% → 6%). "20% 개선"이라고만 쓰면 6%(rel)인지 25%(abs)인지 알 수 없다. **계산기 입력은 관례적으로 Relative**, 결과 보고는 둘 다.
- **α·검정력은 기본값 고정**이며, 결과를 본 뒤 α를 옮기는 것은 판정 조작이다. 다른 값을 쓰려면 시작 전에 합의하고 설계서에 못박는다.
- **일 UV는 스킬이 추정하지 않는다** — 실쿼리 또는 참가자 답. 없으면 `⚠️미정`으로 두고 기간을 산출하지 않는다.
- Baseline은 **최근 2~4주 평균, 특이치(프로모션·장애·대형 캠페인) 제외**가 원칙이다. 오염 구간이 포함됐으면 비고에 남긴다.
- **`판정 군 수`는 무작위 배정 군의 개수가 아니라 「결과를 따로 읽을 단위」의 개수다** (DEC-011 — v1.1의 `Variant 수(대조군 포함)`를 대체한다). **대조군 + 실험군 Variant + 운영 분기**를 모두 센다. 배타적 배정으로 다른 실험과 트래픽을 나눈 경우(§7-16 원칙 2)도 그 분할을 반영한다.
  - 분기·군별로 판정한다면 **다중비교 보정**을 적용한다 — 예: Bonferroni는 α를 비교 수로 나눈다(3비교면 α = 0.05/3 ≈ 0.0167 → `Z_α/2 = 2.394`). 보정 적용 여부와 방식을 E7 `판정 기준`에 적는다.
  - **기간 병목은 전체 평균이 아니라 가장 작은 군의 일 유입으로 계산한다.** 군별 비중이 불균등하면 **가장 작은 군이 기간을 정한다** — 전체 평균으로 계산하면 "하루면 찬다"는 잘못된 결론이 나온다.

**② 계산 절차 — 공식을 노출한다**

```
n = 2 × (Z_α/2 + Z_β)² × p̄(1-p̄) / δ²

  Z_α/2 = 1.96 (α = 0.05)
  Z_β   = 0.84 (검정력 80%)
  p0    = Baseline 전환율
  p1    = p0 × (1 + MDE_relative)
  p̄     = (p0 + p1) / 2
  δ     = p1 − p0  (= MDE Absolute)

총 샘플 = n × 판정 군 수(대조군 + Variant + 운영 분기)
예상 기간(일) = 총 샘플 ÷ 실험 지면 일 UV
```

- 대입 과정을 **한 줄씩 보여준다**(p1 → p̄ → δ → n → 총 샘플 → 기간). 결과만 던지지 않는다.
- **[Evan Miller Sample Size Calculator](https://www.evanmiller.org/ab-testing/sample-size.html) 교차검증을 권장한다** — 노션 템플릿 `3-2`가 지목하는 계산기이며, 값이 크게 어긋나면 입력 단위(Absolute/Relative 혼동)를 먼저 의심한다.
- 조견표(KB 06 §③)로 **자릿수 감**을 먼저 잡는 것을 권한다: Baseline이 낮을수록 필요 표본이 폭증하고, 고전환 지면일수록 실험 효율이 좋다.

**③ 결과 표 — 3열 (항목 / 값 / 산출식)**

행: `Variant당 필요 샘플 (n)` · `총 필요 샘플` · `예상 기간(일)` · `최소 관찰 기간 반영 후 기간`

**④ 실현성 판정**

| 예상 기간 | 판정 | 조치 |
|---|---|---|
| **≤ 28일** | ✅ 진행 | 그대로 실행 (단, §3-8 최소 관찰 기간은 별도로 지킨다) |
| **28~90일** | ⚠️ 조건부 | 아래 조정 순서를 1개 이상 적용하고 재계산 |
| **> 90일** | 🔁 재설계 | 조정으로 안 되면 실험 자체를 다시 설계 — E2·E5로 되돌아간다 |

**초과 시 조정 순서 (이 순서로 묻는다)**

1. **지면을 확대**할 수 있는가 (대상 화면을 하나 더 붙인다)
2. **타겟을 재정의**할 수 있는가 (전체 → 특정 진입 경로·세그먼트로 좁혀 Baseline을 올린다)
3. **MDE를 상향**할 수 있는가 (단, 아래 MDE 규칙을 넘지 않는 선에서)
4. **Primary를 더 앞쪽 선행지표로** 옮길 수 있는가 (모수가 커지고 Baseline이 올라간다)
5. (그 다음) **판정 군 수 축소** → A/B/n을 A/B로, 분기별 판정을 전체 판정으로 (분기별 수치를 보겠다는 선언을 함께 거둔다)

**MDE 규칙 (하드)**: **MDE(Relative) ≤ Target 상대 개선율.** 가설이 "N% 개선"을 목표로 하는데 MDE를 N%보다 크게 잡으면, 목표대로 개선돼도 감지하지 못하는 설계가 된다. MDE > Target이 나오면 계산을 진행하지 않고 되돌린다 — **Target을 올리는 것은 hg 소관**이므로 그쪽으로 라우팅한다.

- **Target 미확정 상태로 진행 중이면 이 검증을 보류하고 §7-4a를 따른다** — E6 산출물 전체에 `⚠️잠정 — Target 미확정`을 달고, §9 완료 판정 7번은 `미충족`으로 남긴다. Target 확정 후 E6를 재계산한다.

### 3-8. E7. 분배·종료 기준 표 — 2열 (항목/값)

행(순서 고정 8행): `트래픽 분배 비율` · `실험 대상 트래픽 비중` · `램프업 필요 여부` · `판정 기준` · `조기 종료 조건` · `최소 관찰 기간` · `병행 릴리즈 확인` · `실험 예정 기간(시작~종료)`

| 항목 | 작성 규칙 |
|---|---|
| 트래픽 분배 비율 | 대조군 포함 전 그룹, **합 100%**. 균등 배분이 기본(2개 50:50, 3개 34:33:33). 불균등은 총 필요 샘플을 늘린다(가장 작은 그룹이 병목) |
| 실험 대상 트래픽 비중 | 지면 트래픽의 100%를 태울지 일부만 태울지. 리스크가 큰 변경은 일부만 |
| **램프업 필요 여부** | `필요 — {사유}` / `불필요`. 결제 흐름·신규 렌더링처럼 장애 리스크가 있는 변경이면 `필요`. **판정만 한다** — 단계별 트래픽 비율·통과 조건 등 램프업 실행 계획은 세팅 영역이라 범위 밖이다 |
| **판정 기준** | `Primary가 유의수준 5%에서 유의하게 개선`(stat-sig) **AND** `실측 차이 ≥ 설계 MDE` **AND** `Guardrail 전부 허용 기준 내` = 승. 하나라도 미달이면 승이라 부르지 않는다 |
| **조기 종료 조건** | Guardrail이 얼마 이하로 떨어지면 즉시 중단인지 **숫자로**. 신뢰성 계열(배분 편차·JS 에러·수집률 이상)도 포함 |
| 최소 관찰 기간 | **최소 7일** (요일 효과) · **최소 1 비즈니스 사이클** 권장. 샘플이 5일 만에 차도 5일에 끝내지 않는다 |
| 병행 릴리즈 확인 | `release-log.md`에서 실험 예정 기간과 겹치는 항목을 검색해 **영향 예상 지표가 겹치는지** 확인. 겹치면 `혼입 변수 있음`을 설계서에 명시. 없으면 `없음` |

- **실험 중간에 배분 비율을 바꾸지 않는다.** 시점별 유입 특성이 그룹 간에 달라져 해석 오류를 만든다.
- 리스크가 큰 변경(결제·신규 렌더링)은 램프업(A/A → 카나리 → 확대 → 전량)을 권하되, **램프업 구간 관측치는 판정에 쓰지 않는다.**

  - 어느 경우든 repo EXP 파일 쪽에는 §1의 정규 항목으로 항상 채워진다 (§3-10).
- ⚠️ **`3-5)`라는 번호만 보고 착지하지 않는다.** 구 템플릿에서 만들어진 페이지 중에는 **`3-5) 실행 순서`처럼 번호는 같지만 내용이 다른 섹션**이 있다(실물 관측). 번호로 판정하면 종료 기준을 실행 순서 칸에 붙이게 된다. 반드시 **섹션 제목**을 읽고 판정하며, 번호는 같고 제목이 다르면 「없음」으로 취급해 `3-3` 하위 소절 폴백으로 간다.
- **참가자 페이지가 템플릿과 다르면 페이지의 실제 섹션 제목을 기준으로 매핑**하고, 차이를 보고한다. (실물에서 `3-4-1) Primary 지표`, `3-5) 실행 순서` 같은 변형이 관측됨)
- 이미 채워진 섹션은 덮어쓰지 않고 **추가·정정분만** 담는다. 기존 내용과 충돌하면 `기존: … → 정정: …`으로 표기한다 (hg §3-8 승계).
- Baseline·Target을 정정하지 않는다 — 정정이 필요하면 hg 소관이다 (§3-2 라우팅).

## 7. 공식 · 판정 규칙 (정본 — 위반 금지)

**7-1. 샘플사이즈 공식.** `n = 2 × (Z_α/2 + Z_β)² × p̄(1-p̄) / δ²` — `Z_α/2 = 1.96`(α=0.05), `Z_β = 0.84`(검정력 80%), `p̄ = (p0+p1)/2`, `δ = p1 − p0`. n은 **Variant당** 필요 샘플이다. (KB 06 §③ 정본)

**7-2. 총 샘플·기간 공식.** `총 샘플 = n × 판정 군 수(대조군 + Variant + 운영 분기 — §7-17)` · `예상 기간(일) = 총 샘플 ÷ 실험 지면 일 UV`. 노션 템플릿 `3-2`의 안내식(샘플사이즈 × variants 수 ÷ 일 UV)과 동일하다.

**7-3. 28일 룰.** `≤28일 = ✅ 진행` / `28~90일 = ⚠️ 조건부` / `>90일 = 🔁 재설계`. 초과 시 조정 순서는 ① 지면 확대 ② 타겟 재정의 ③ MDE 상향 ④ Primary를 더 앞쪽 선행지표로 ⑤ 판정 군 수 축소. **조정 없이 "그냥 오래 돌리면 된다"로 넘어가지 않는다.**

**7-4. MDE 규칙.** **MDE(Relative) ≤ Target 상대 개선율.** 초과하면 계산하지 않고 되돌린다. MDE는 통계가 정해주는 값이 아니라 **"이만큼은 올라야 롤아웃할 가치가 있다"는 의사결정 임계값**이다. Absolute(%p)와 Relative(%)를 혼동하지 않는다 — 계산기 입력은 관례적으로 Relative, 결과 보고는 둘 다.

**7-4a. Target 미확정 분기 (E1 G-2 결손 상태로 진행 중일 때).** 위 규칙은 Target이 있다는 전제다. **E1 G-2가 `결손`인데 사람이 진행을 결정한 가설**은 비교 대상이 없어 규칙이 판정 불능이 된다 — 이때는 아래대로 한다.

| | 처리 |
|---|---|
| MDE ≤ Target 검증 | **보류한다.** 검증할 대상이 없으므로 위반도 준수도 아니다 — `판정 보류 — Target 미확정`으로 표기하고 규칙을 억지로 적용하지 않는다 |
| MDE 값 | 참가자가 정한 값으로 계산은 진행한다. **스킬이 Target을 대신 정하지 않는다** (hg 소관 — §7-11) |
| E6 산출물 | 입력값 표·결과 표·실현성 판정 **전체에 `⚠️잠정 — Target 미확정` 표기를 강제**한다. 표기 없는 E6는 출력하지 않는다 |
| E8a·E8b 착지 | 같은 표기를 그대로 달아 착지시킨다 — 노션·repo에 확정값처럼 보이는 숫자가 남지 않게 |
| §9 완료 판정 | **7번 항목(샘플사이즈·기간)은 `미충족`으로 남긴다.** 다른 항목이 다 통과해도 이 항목은 통과시키지 않는다 |
| 해소 | Target이 **hg STEP 3(G4 Target 확정)**에서 확정되면 **E6를 재계산**한다. 재계산 후 MDE ≤ Target을 그때 검증한다 |

- 이 분기는 **예외 허용이 아니라 미완 상태의 정직한 표기**다. 세션을 멈추지 않되 완료로도 치지 않는다 (hg §7-3a 「강등 경로」와 같은 취지).

**7-5. Primary 1개 규칙 (하드).** 실험당 Primary는 **정확히 1개**. 2개 이상이면 산출을 진행하지 않는다. 선행성 판정 질문(§3-4)을 반드시 출력하고 답을 받는다.

**7-6. Guardrail 1~2개 + 2관문 규칙 (하드).** **실패조건성**과 **인과 연결성** 두 판정 질문(§3-4)을 **모두** 통과한 지표만 Guardrail이다. **개입 지점(E5 Trigger Point)보다 상류에 있는 지표는 자동 탈락**이며, 관문 ②에서 걸린 지표는 Secondary로 내리지 않고 설계서에서 **뺀다**. 허용 기준을 **숫자로 사전 합의**하고, 결과를 본 뒤 기준을 옮기지 않는다. **구간 전환율 형태의 하류 지표는 Guardrail로 쓰지 않는다** (§3-4 — 분모가 처치의 결과라 선택편향).

**7-7. 최소 관찰 기간.** 샘플 충족과 무관하게 **최소 7일**(요일 효과), **1 비즈니스 사이클** 권장. 계산 기간이 이보다 짧으면 최소 관찰 기간이 이긴다.

**7-8. ICE · Uplift 공식은 이 계약이 재정의하지 않는다.** **hg-output-contract.md §7-1(ICE) · §7-3(Uplift) · §7-7(Target 3법)이 정본**이며, 어긋나면 hg가 이긴다. 이 계약은 그 값을 **읽어 쓰기만** 한다 — ICE 재산정·Uplift 재계산·Target 재산정 절차를 만들지 않는다. (참고: ICE = I + C + E 합산, 각 1~10, 최대 30. 곱셈·평균은 어떤 형태로도 출력하지 않는다.)

**7-9. BIAS는 27항목이 정본.** `50_reference/bias-checklist.md`(DEC-003, B 9 / I 7 / A 7 / S 4). 노션 템플릿에 내장된 축약판 4단계 표나 "15항목"·"16항목" 표기를 쓰지 않는다. 참가자 문서에 축약판 기준이 남아 있으면 `(축약판 기준 — 27항목 정본으로 재매핑 필요)`를 병기한다.

**7-10. 데이터 조회 규칙.** Amplitude MCP 실쿼리로 **Baseline 확인 · 일 UV · 택소노미(태깅 여부)**를 조회하는 것을 허용한다. **실쿼리 결과 값만 쓰고 추정·보간하지 않는다.** 조회조건(기간·필터·이벤트명)을 출처 열에 남긴다. 조회 실패·MCP 미연결이면 멈추지 않고 `확인 불가` + `코치 확인 필요`로 두고 진행한다. **골트리 정본값과 충돌하면 골트리 우선** + 차이를 `코치 확인 필요`로 기록한다.

**7-11. 스킬이 하지 않는 것 (하드).** 그루밍 재수행 · ICE 재산정 · Uplift 재계산 · PSR/Baseline/Target 수정 · **디자이너 최종 시안·와이어프레임 제작**(AI 초안 생성 보조는 `cro-variant-mockup` 소관 — §3-3a) · 새 가설·새 EXP ID 확정 채번 · BIAS 재진단 · 노션 속성 추가 · 실험 세팅·런칭·피처 플래그 조작 · 실험 결과 분석 · 근거 없는 수치·URL·이벤트명 생성.

**7-12. AI 시안 초안 — PII 마스킹 게이트 (하드).** control 스크린샷·참조 이미지에 실고객 정보(실명·연락처·증권번호·보험료·계약 정보 등)가 보이면 **마스킹본을 수령하기 전에는 외부 이미지 생성 API로 전송하지 않는다.** 발견하면 **값을 출력하지 말고 위치만** 말한다 (§2-4 PII 규칙과 같은 원칙). 지정 대사: `이 스크린샷 {위치}에 고객 정보로 보이는 영역이 있습니다. 값은 옮겨 적지 않겠습니다 — 가리고 다시 올려주시면 그때 진행하겠습니다.` **API key 값 자체도 같은 원칙**으로 묻지도 출력하지도 않는다.

**7-13. AI 시안 초안 — 한글 문구 검수 게이트 (하드).** 생성된 이미지의 문구를 **E2 4슬롯의 확정 문구와 글자 단위로 대조**한다. **불일치 이미지는 노션·E2 어디에도 착지시키지 않는다.** 재생성은 **최대 2회**이며, 매회 프롬프트를 전체 재작성하지 않고 **결함을 겨눈 강화 문장 1개를 추가**하는 방식이다. 2회로도 실패하면 **「문구 영역을 비운 시안 + 문구는 명세로 별도 표기」** 경로로 내린다. — 이미지 모델의 한글 렌더링은 **실측 2회 모두 실패**했고(문구·숫자 변형), 깨진 문구가 착지되면 §5 「가설의 의미를 바꾸지 않는다」·확정 문구 원칙을 그대로 위반하는 사고가 된다.

**7-15. AI 시안 초안 — 대조군 보존 게이트 (하드).** 생성된 이미지를 **control 스크린샷과 나란히 놓고, 명세가 지정하지 않은 영역이 바뀌지 않았는지** 항목별로 대조한다 — 상태바·내비게이션, **화면 내 숫자·통계**, 다른 섹션의 제목·본문, CTA, 카드 배치. **지정하지 않은 요소가 하나라도 변조됐으면 확정 문구가 전부 일치해도 착지시키지 않는다**(§7-13과 같은 재생성 경로로 내린다). — 2026-08-24 실키 스모크 테스트에서 확정 문구는 전부 일치했는데 **지정하지 않은 막대 수치가 `6%` → `8%`로 조용히 바뀐** 사례가 나왔다. 이 상태로 착지하면 대조군과 실험군이 **서로 다른 데이터를 보여주게 되어 무엇이 효과를 냈는지 가릴 수 없다** — 실험 자체의 오염이라 문구 오류보다 무겁다. **숫자·통계는 반드시 대조 항목에 넣는다**(가장 자주 바뀌고 가장 눈에 안 띈다).

**7-14. AI 시안 초안 — 표기 강제 (하드).** AI가 만든 이미지는 **파일명 · 노션 캡션 · E2 시안 행** 세 곳 모두에 `AI 초안`(+ provider/model)을 표기한다. **표기가 없는 AI 이미지는 착지시키지 않는다.** 사람이 검토해 **채택하면** E2 시안 행을 `있음(링크)`으로, E1 G-4를 `충족`으로 승격한다 — **승격은 사람만** 한다 (§3-2).

**7-16. 타겟 세그먼트가 겹치는 실험 — 동시 진행 금지 (하드, DEC-011).**

> **원칙 1 (기본).** **타겟 세그먼트가 겹치는 실험은 동시에 진행하지 않는다.**
> **원칙 2 (예외).** 그럼에도 꼭 해야 한다면, 각 실험의 트래픽이 겹치지 않도록 — **1명의 유저가 2개의 실험에 참여되지 않도록** — **배타적 설정**을 해서 진행한다.
> **이유.** **실험 결과 분석을 위해 꼭 필요한 부분**이다.

- **순위가 있는 원칙이다.** 배타적 설정은 대등한 선택지가 아니라 **차선**이다. 설계가 "동시 실행" 결론에 도달했으면 **"왜 동시에 해야 하는가"를 먼저 묻고**, 답이 서야 배타적 설정을 검토한다. 기본 경로는 **① 순차 실행** 또는 **② 우선순위 실험 1개로 합쳐 variant 확장**(§3-6)이다.
- **겹침 판정 단위는 세그먼트다** — 지면이 아니다 (§3-6 `타겟 세그먼트 겹침 확인`).
- **배타적 설정을 택하면 판정 군 수가 늘어난다.** 실험 2개를 상호 배타로 나누면 트래픽이 **4개**로 나뉜다 — §7-17에 따라 표본·기간을 재산정하고, 재산정 결과가 §7-3 28일 룰에 걸리면 원칙 1로 되돌아간다.
- **금지 — 직교 배정 + 상쇄 논증.** "독립 해시로 배정하면 다른 실험의 처치가 양 군에 같은 비율로 섞여 차이 계산 시 상쇄되고, 남는 것은 편향이 아니라 분산 증가다"라는 논증으로 겹침을 **정당화하지 않는다.** 상쇄는 **평균 차이**를 지켜줄 뿐, 결과를 놓고 **"무엇이 이 숫자를 만들었나"**에 답하게 해주지 않는다. 실험의 목적은 추정이 아니라 **가설 검증**이므로 변수 통제가 앞선다. 균형 검증 절차를 붙이더라도 결론은 같다.
- **적용 시점은 E5**(타겟을 정하는 순간 겹침이 결정된다). E7까지 가면 이미 늦다.

**7-17. 판정 군 수 규칙 (하드, DEC-011).** `판정 군 수`는 **무작위 배정 군의 개수가 아니라 「결과를 따로 읽을 단위」의 개수**다 — **대조군 + 실험군 Variant + 운영 분기**(+ §7-16 원칙 2의 배타적 분할). **분기별 수치를 보겠다고 선언한 순간 그 분기가 판정 단위**이며, **"탐색용이라 판정에 쓰지 않는다"는 이름표는 표본 산정의 면제 사유가 아니다.** 분기·군별 판정에는 **다중비교 보정**을 적용하고 방식을 E7 `판정 기준`에 적는다. **기간 병목은 전체 평균이 아니라 가장 작은 군의 일 유입으로 계산한다.** 분기별 Baseline이 서로 다르면 그 사실을 명시하고, 가장 불리한 군을 기준으로 실현성을 판정한다.

- [ ] 2. **Variant 2개 이상**이 E2 필수 10행으로 구체화됐고, 변경 화면 명세 4슬롯이 **구체 문구·설명으로** 채워졌으며, 전 Variant가 `방향·가치 정합`을 통과했다
  - ⚠️ **시안 행이 `있음 — AI 생성 초안(검토 필요)`이면 게이트 4종(§7-12~7-15) 통과 기록이 있어야 이 항목이 충족**이다 — 표기·문구 검수·**대조군 보존** 기록이 없으면 미충족이다
- [ ] 3. **Primary가 정확히 1개**이고 선행성 판정 질문에 답이 나왔다
- [ ] 4. **Guardrail이 1~2개**이고 **2관문(실패조건성 + 인과 연결성)** 판정 질문에 답이 나왔으며 허용 기준이 숫자다 — 개입 지점보다 상류 지표가 남아 있지 않다 (§7-6)
- [ ] 5. E3 전 지표가 `측정 중`이거나, 미태깅 지표에 **태깅 요청 명세 4항목 + 조치 기한**이 붙었다
- [ ] 6. E5의 Target Audience·Trigger Point·제외 조건·**`타겟 세그먼트 겹침 확인`**이 채워졌고, Trigger Point가 E3 분모와 일치한다 — 겹침이 `있음`이면 **§7-16 처리**(순차·합치기·배타적 설정)가 결정됐다
