# cro-experiment-design

그루밍이 끝난 가설의 **노션 실험설계서를 실험 세팅이 가능한 수준으로 구체화하는** 실험 설계 플러그인입니다. 해빗팩토리 CRO 코칭 Sprint 1 후반(8/24 스프린트 플래닝 이후)의 실험 설계 착수에서 사용합니다. v0.5.0부터 런칭 후 모니터링·종료 판정까지 담당합니다.

> **실험설계서 구체화란** — 그루밍 계약(`hg-output-contract.md` v1.1) §7-9가 명시적으로 범위 밖에 남긴 빈칸을 채우는 작업입니다. Variant 최종 문구·시안, 지표 3층, 측정 가능성, 타겟·트리거, 샘플사이즈·실험 기간, 분배·종료 기준 — 그루밍이 "무엇을 실험할지"를 정했다면, 이 플러그인은 "어떻게 세팅할지"를 정합니다.

## 무엇을 하나요

**수행 모드** (참가자용) — 가설(실험) 1건씩:

1. **인테이크 정규화 + 그루밍 완료 게이트** — 입력을 정규화하고, 그루밍이 실제로 끝났는지 7항목으로 점검합니다. 결손이 있으면 이 스킬이 채우지 않고 **해당 항목만 hg 스킬의 대응 STEP으로 라우팅**합니다 (재그루밍 전체 재수행이 아닙니다)
2. **Variant 구체화** — 대조군·실험군 **2개 이상**을 변경 화면 명세 4슬롯(헤드라인/이미지/CTA/노출 위치)으로 구체화하고, 시안 제작 요청과 착지를 돕습니다
3. **지표 3층 확정** — Primary **정확히 1개** + Secondary + Guardrail **1~2개**
4. **측정 가능성 점검** — 미태깅 지표는 태깅 요청 명세 4항목 + 조치 기한으로 명시합니다
5. **타겟·트리거** — Trigger Point(노출 정의)가 지표 분모와 일치하는지 확인합니다
6. **샘플사이즈·실험 기간 계산** — 입력값 표 → 공식 대입 → 결과 → **28일 실현성 판정**까지. 28일을 넘으면 MDE 상향을 포함한 조정 순서를 적용합니다
7. **분배·종료 기준** — 분배 비율(합 100%)·조기 종료 조건·최소 관찰 기간·병행 릴리즈 확인
8. **노션 + repo 착지** — 노션 실험설계서 페이지 갱신 블록과 git SSOT의 EXP 파일 블록, 속성 변경 안내를 출력합니다

**(선택) variant 시안 AI 초안 생성** — E2에서 시안이 없을 때, 참가자 본인 API key와 대조군 스크린샷이 있으면 페어 스킬 `cro-variant-mockup`으로 라우팅해 AI 초안(목업)을 만들 수 있습니다. key가 없으면 종전대로 제작 요청 명세 경로로 진행하며, 세션을 막지 않습니다. 자세한 내용은 아래 절을 참고하세요.

**리뷰 모드** (코치용) — "실험설계 리뷰"라고 말하면 진입: A군 22항목 + B군 7항목 판정 + 샘플사이즈 검산 재현 + 보완 가이드.

## 설치

이미 다른 CRO 플러그인을 쓰고 계시면 **업데이트만 하면 됩니다.**

```

/plugin install cro-experiment-design@woodi-plugins

```

## 시작하기

클로드에게 "실험설계서 구체화 시작"이라 말하고 **노션 실험설계서 페이지 본문을 붙여넣으면** 됩니다.

## 이 플러그인이 하지 않는 것

- 그루밍 재수행·ICE 재산정·Uplift 재계산·PSR/Baseline/Target 수정 → **`cro-hypothesis-grooming` 소관**
- 런칭 후 모니터링·종료 판정 → 동봉 스킬 `cro-experiment-monitoring`(v0.5.0) 소관
- 종료 결정·So Next 확정·기록 블록 → 동봉 스킬 `cro-experiment-decision`(v0.6.0) 소관 / why·배운 것·가설 검증 여부·후속 반영 → 이제 동봉 스킬 `cro-experiment-report`(v0.7.0)가 채웁니다

- **디자이너 최종 시안** 제작 대행 → 여전히 하지 않습니다. 명세 작성·제작 요청·받은 것의 착지까지만 합니다. **AI 초안(목업) 생성 보조**는 페어 스킬 `cro-variant-mockup`이 하며(계약 v1.1, DEC-009) — 참가자 본인 API key가 있어야 하는 **선택 기능**이고, 산출물은 항상 `AI 초안 — 검토 필요`로만 착지합니다
- 노션 자동 기입(붙여넣기 왕복) → 갱신 블록을 출력할 뿐, 노션 페이지를 직접 쓰지 않습니다

### v0.7.2에서 달라진 것 (DEC-025 결정 6 · 2026-09-22)

- **실험설계서에 「개발 리소스·일정 확인」 3행이 필수로 들어갑니다** — E6 샘플사이즈·기간 표의 실현성 판정 뒤에 **구현 담당 · 예상 구현 기간과 릴리즈 일정(앱 배포 주기 반영) · 일정 확인 상태**를 붙입니다. `미확인`이면 `⚠️미정`을 달고 노션 착지 안내에 「런칭 예정일은 개발 일정 확인 후 확정」이 덧붙습니다. 9/21 중간 회고에서 「개발자 일정을 고려하지 못하고 기술 구현 리소스만으로 Ease를 체크해 일정이 밀렸다」가 Problem으로 나온 자리입니다.
- **Ease를 기술 구현 난도만으로 매기지 않습니다** — 담당이 없거나 릴리즈 주기 밖이면 Ease 재검토를 권고합니다(재산정은 그루밍 스킬 소관이라 라우팅만).
- **리뷰 모드에 D-23이 추가됐습니다** — A군 23 + B군 7 = 30항목. 2026-09-22 이전 작성 설계서(스프린트 1·2)에는 소급 적용하지 않습니다.
- **계약이 `ed-output-contract.md` v1.5로 올라갔습니다** — §3-7 E6 ⑤ 신설 · §3-12 D-23 · §9 완료 판정 7-b. 저장소를 넘나드는 참조는 링크 대신 백틱 경로로 씁니다(사본이 정본과 바이트 동일해야 하므로).

### v0.7.1에서 달라진 것 (DEC-026 · 2026-09-22)

- **결과 보고서 4-2의 「결과 데이터」 표가 하나로 합쳐졌습니다** — Primary·Secondary·Guardrail **3층을 한 표에** 싣습니다. 노션 템플릿의 불릿 구조를 따라 표를 둘로 나눴더니 첫 표에 Primary 한 행만 남아 **Secondary가 없는 것처럼 읽혔습니다**(9/21 리포트 리뷰). 불릿 4개 구조는 그대로 두고 표의 자리와 개수만 바꿨으며, 둘째 불릿은 표를 다시 내지 않고 위 표에서 볼 행을 가리킵니다.
- **4-1 요약 줄에서 지표명을 축약하지 않습니다** — 요약의 지표명은 4-2 표 `지표` 열과 **문자 단위로 같게** 쓰고 **어느 군의 값인지도 밝힙니다.** 축약된 요약 줄이 뒤 표의 다른 행(다른 지표·다른 군)과 맞대 읽혀 「숫자가 이상하다」로 멈춘 자리입니다 — 두 값 다 맞았고, 이름이 줄어 있었을 뿐입니다.
- **계약이 `er-output-contract.md` v1.1로 올라갔습니다** — 위 2건이 §5와 §3-8에 들어갔고, 나머지 규칙(열 문자 일치·군 3개 이상 확장·토글 금지·「실험 설계 잘못됨」이면 `결과 불사용`)은 그대로입니다.

### v0.7.0에서 달라진 것 (DEC-024 · 2026-09-20)

- **결과 보고서 스킬 동봉** — 종료 의사결정이 `⚠️SP3`로 비워 넘긴 칸(「왜 그랬나」·「배운 것」·「가설 검증 여부」·「후속 반영」)을 채우는 `cro-experiment-report`가 새로 붙었습니다. 자세한 내용은 아래 「실험 결과 보고서」 절을 참고하세요.
- **`⚠️SP3`의 소유가 옮겨졌습니다** — 「결과 보고서 서술은 범위 밖(SP3)」이던 자리를 이제 **이 플러그인 안의 4호 스킬이** 맡습니다. 그 칸을 채우면 플래그는 사라집니다.
- **계약 `er-output-contract.md` v1.0이 제정됐습니다** — 기둥은 하나입니다: **해석은 판정을 다시 하지 않는다.** 판정은 종료 의사결정에서 승계하고, 기록이 없거나 잠정이면 `잠정` 라벨을 붙인 채 결정·So Next는 빈칸으로 둡니다.
- **근거 태그 4종이 신설됐습니다** — `[실측]`·`[계산]`·`[해석]`·`[가정]`. **태그 없는 해석 문장은 출력하지 않습니다**(게이트 G3). `[해석]`에는 근거 행 번호를 병기하고, 번호가 없으면 `[가정]`입니다.
- **결과 유형 4종 + 혼합 플래그가 생겼습니다** — `T1 WIN`·`T2 LOSE`·`T3 INCONCLUSIVE`·`T4 실험 설계 잘못됨`, 그리고 Primary와 Guardrail·Secondary의 방향이 어긋날 때 붙는 `M`. 유형이 정해지면 S4의 질문 세트가 정해집니다 — **스킬이 질문을 고르지 않습니다.**
- **「판정」과 「배포 반영」이 문서에서 갈라졌습니다** — 승자는 Primary 하나로 정하고, 반영 가능 여부는 「Primary 승 AND Guardrail·Secondary 불하락」입니다. **설계서의 자체 가드레일 허용 범위가 「불하락」을 대체하지 않습니다**(DEC-023 · dc §7-10 인용).
- **세그먼트는 판정과 힌트로 갈립니다** — 설계서에 **사전 선언된 구간만 판정**이고 보정을 걸며, 나머지 축은 `보정 전`을 붙인 `힌트`입니다. 탐색적 세그로 승패를 말하지 않습니다.
- **임계값 저장소가 10항목이 됐습니다** — DEC-023이 ⑨(판정 계산의 구현 우선순위)와 ⑩(가드레일·세컨더리 「하락」 판정)을 더했습니다. 값은 여전히 `skills/cro-experiment-decision/references/thresholds.md` 한 곳에서만 고칩니다.
- **계약 2건이 함께 개정됐습니다** — `dc-output-contract.md` v1.2(`⚠️SP3`의 인계 조항) · `em-output-contract.md` v1.2.2 (ed v1.4.2는 DEC-021 개정 그대로).

### v0.6.0에서 달라진 것 (DEC-021 · 2026-09-15)

- **종료 의사결정 스킬 동봉** — 판정이 나온 뒤 「끝낼지·늘릴지」와 그 기록을 담당하는 `cro-experiment-decision`이 새로 붙었습니다. 자세한 내용은 아래 「실험 종료 의사결정」 절을 참고하세요.
- **임계값 6항목이 확정됐습니다** — SRM 경보 `p < 0.001`·주의 `p < 0.01` / 지속 판단 `stat-sig ≥ 80%` / 연장 `1회 + 종료일 재고정` / 노출 추이 `±30%` / 수집 최소 `variant별 25전환 + 100노출` / 베이지안 `50~70 보류 · 70~90 신중 · 90+ 강한 신호`. 지속 판단과 연장은 우디 덱이 출처라 그대로 확정이고, 나머지 넷은 문헌값을 채택해 **세션 전 재확인**이 남아 있습니다. 값은 `skills/cro-experiment-decision/references/thresholds.md` 한 곳에서만 고칩니다.
- **모니터링·실험설계 계약이 인계를 받았습니다** — `em-output-contract.md` v1.2.1(M4·M5b·M5c가 종료 의사결정의 입력), `ed-output-contract.md` v1.4.2(§3-8a에 인계 조항 1개).
- **트리거 2문구가 옮겨졌습니다** — 「실험 종료해도 되나요」·「연장할까요」는 이제 `cro-experiment-decision`이 받고, 모니터링은 「종료 판정 가능한지 봐줘」까지입니다.
- **9/11 세션의 룰 2건이 규칙이 됐습니다** — ① 표본이 덜 찼으면 「지고 있다」는 이유로 종료 결정을 진행하지 않습니다(예외는 설계서에 미리 적어 둔 조기 종료 조건과 데이터가 잘못되고 있을 때 둘뿐). ② 성적이 낮은 variant만 내리는 것은 **충분히 봤고 · 대조군 대비 명확히 열세이고 · 팀 합의가 있을 때만** 가능하고, 축소 시점을 남긴 뒤 남은 군은 그 시점 이후 데이터로 다시 셉니다.

### v0.5.0에서 달라진 것 (DEC-018 · 2026-09-07)

- **모니터링 스킬 동봉** — 실험 런칭 이후 헬스 확인부터 종료 판정까지를 담당하는 `cro-experiment-monitoring`이 새로 붙었습니다. 자세한 내용은 위 「실험 모니터링·종료 판정」 절을 참고하세요.
- **노션 MCP 비전제 예외** — 이 플러그인 전체의 "노션 MCP를 전제하지 않는다" 관례를 `cro-experiment-monitoring`에 한해 **읽기에만** 유보합니다. 다만 참가자 계정은 코치 노션에 게스트로 초대돼 있어 실제로는 **Chrome으로 URL을 열어 읽는 경로**가 정상 경로입니다.
- **(같은 날 v1.2) 모니터링은 기록물을 남기지 않습니다** — 코치 정정 「모니터링 리포트는 어디에 문서로 기록할 필요가 없어. 그냥 보고 끝내는거야.」 반영으로 착지(노션 4장·EXP 블록·속성 안내)를 폐기했습니다. 종료 판정 결과의 기록도 결과 보고서 단계 소관입니다.
- **ed 계약 v1.4.2의 §3-8a**가 런칭 후 단계를 모니터링 스킬로 인계합니다 — 설계값(필요 표본·MDE·종료 기준)을 그대로 읽어 씁니다.
- **마켓플레이스 버전 표기 정정** — 마켓플레이스 목록의 0.2.x는 표기 드리프트였습니다. `plugin.json` 계보 0.4.0 → 0.5.0이 정본입니다.
- **코치 확정 대기 임계값 6항목** `⚠️확인필요 — 코치 확정` — 아래는 아직 코치가 확정하지 않은 후보값이며, 확정 전에는 이 값으로 종료를 선언하지 않습니다(계약 §7 머리 목록).

  | # | 임계값 | 후보 |
  |---|---|---|
  | 1 | SRM 경보 임계 | `p < 0.001` 경보 / `p < 0.01` 주의 |
  | 2 | 지속 판단 임계 | stat-sig ≥ 80% |
  | 3 | 연장 횟수 제한 | 1회 + 종료일 재고정 |
  | 4 | 노출 추이 이상 | 예상 일 트래픽 ±30% |
  | 5 | 수집 최소 요건 | variant별 25전환 + 100노출 |
  | 6 | 베이지안 병행 해석 | 50~70% 보류 / 70~90% 신중 / 90%+ 강한 신호 |

- **(같은 날 v1.1) 실전 테스트 후 정정 3건** — 첫 실전 테스트(EXP-A-002) 직후 코치가 방향을 정정해 계약을 v1.0에서 v1.1로 같은 날 개정했습니다: ① 정본의 위치를 설계서에서 **담당자가 세팅한 Amplitude 화면**으로 옮김(정의 일치 게이트 폐지 → 매핑 기록으로 격하) ② **Amplitude 화면 표시값(리프트·신뢰구간·유의성, 순차검정)은 샘플 도달 전에도 항상 인용** — 도달 후로 미루는 것은 스킬 자체의 고정표본 계산과 WIN/LOSE 판정뿐 ③ 기본 출력을 **5블록 기본 리포트**로 정하고 M0~M6 전체 표는 「상세」 요청 시로 한정. 자세한 내용은 위 각 절 참고.

### v1.2에서 달라진 것 (DEC-011 · 2026-08-27)

- **하류 지표는 형태로 층이 갈립니다** — **구간 전환율**(분모가 처치의 결과)은 **Secondary**, **누적 전환율**(분모 = Trigger Point)은 **Guardrail**입니다 (v1.3 · DEC-014). 구간 형태에 거부권을 주면 이긴 실험이 Guardrail에 걸립니다
- **Guardrail은 3관문**입니다 — 실패조건성 + **인과 연결성** + **형태(누적)**. **상류 지표와 구간 형태는 둘 다 Secondary로 강등**합니다 (v1.4 · DEC-017 — v1.3의 「상류는 삭제」는 폐기). 강등은 **거부권 회수**를 뜻합니다
- **variant는 개수가 아니라 `P와의 대응`으로 봅니다** (v1.4 · DEC-017) — 실험군 1개면 늘리고, 각 군이 **변경 묶음**이면 줄입니다. P가 지목하지 않은 변경은 빼거나, 그 변경마다 측정 항목을 붙입니다
- **Secondary는 임무 판정을 받습니다** — 개입 지점 이후 **화면 안 행동**을 재는 항목이 최소 1개 있어야 합니다 (v1.3 · DEC-014)
- **문구가 솔루션인 실험은 문구 변주가 variant**입니다 — 서로 다른 언어 프레임은 미세 변주가 아니라 가설 차이입니다
- **표본 산정은 `판정 군 수`로 합니다** — 대조군 + Variant + **운영 분기**. "분기별로 보겠다"고 선언한 순간 그 분기가 판정 단위이며, "탐색용"이라는 이름표는 표본을 면제해 주지 않습니다. 기간 병목은 **가장 작은 군** 기준입니다
- **E5에 `타겟 세그먼트 겹침 확인`이 생겼습니다** (하드 게이트 ⑦) — **타겟 세그먼트가 겹치는 실험은 동시에 진행하지 않는 것이 원칙**이고, 불가피하면 **1명의 유저가 2개 실험에 참여되지 않도록 배타적 설정**을 합니다. 직교 배정 + 상쇄 논증은 받아들이지 않습니다

## 실험 모니터링·종료 판정 (`cro-experiment-monitoring`)

실험을 **런칭한 직후부터 종료 판정까지** 담당하는 동봉 스킬입니다. "실험 모니터링", "런칭했어요 확인해줘", "SRM 봐줘", "샘플 찼나요", "이겼나요", "실험 종료해도 되나요", "연장할까요" 같은 요청에 이 스킬이 나섭니다.

**입력** — 필수 2개 + 보조 1개: **노션 실험설계서 URL**, **Amplitude 대시보드 URL 또는 Experiment 설정 URL**, (보조) **런칭일**. 런칭일이 없으면 경과일·최소 관찰 기간·요일 주기 판정이 `확인 불가`로 남습니다.

**담당자가 세팅한 화면이 정본입니다** (v1.1) — 대시보드·실험 분석 화면의 지표 정의를 그대로 따르고, 설계서와 다른 점(전환창·군 수·배분·배타 조건 등)은 게이트로 막지 않고 리포트 끝 「참고」 1줄로만 남깁니다.

**기본 출력은 5블록 리포트입니다** — ① variant별 트래픽 ② 지표별 전환율·Amplitude 표시값(Primary·Guardrail·**Secondary 전부**, 화면에 없는 Secondary는 variant별 실쿼리로 채웁니다) ③ 유의성 ④ 진행률·종료 판단 ⑤ 이상 징후, 그리고 설계서↔세팅 차이가 있을 때만 마지막에 「참고」 1줄. **M0~M6 전체 표(상세)는 "상세로 보여줘"라고 요청할 때만** 냅니다.

**접근 경로 사다리** — 이 스킬에 한해 "노션 MCP 비전제" 관례를 **읽기에만** 예외로 둡니다(기입은 여전히 사람이 합니다).
- 노션: 노션 MCP → claude-in-chrome으로 URL 열어 읽기 → 참가자 붙여넣기
- Amplitude: MCP 차트/대시보드 조회 → Chrome으로 대시보드 열어 읽기 → 설계서 지표 정의 + variant 프로퍼티로 실쿼리 재구성 → `확인 불가`

**2모드** — 모드는 스킬이 정하지 않고 진행률 표(M4)의 숫자가 정합니다.
- **헬스**: 건수·전환율·SRM만 봅니다. 샘플 도달 전에는 리프트·p·승패 어휘를 **절대 보여주지 않습니다.**
- **판정**: 전 variant가 필요 n에 도달하고 최소 관찰 기간·요일 주기·SRM 정상 조건을 모두 채운 뒤에만 stat-sig 판정(`WIN`/`LOSE`/`INCONCLUSIVE`/`지속`/`실험 설계 잘못됨`)을 냅니다.

**하드 게이트 6종**
1. **접근 경로 확정**(§2-3) — 노션·Amplitude 각각 실제로 시도한 경로를 M0에 남기고, 실측 수치마다 출처 5형식 중 하나를 붙입니다. 출처가 비면 그 행은 `확인 불가`입니다.
2. **화면 정본·매핑 기록**(§7-10, v1.1 — 하드 게이트에서 권고로 격하) — 담당자가 세팅한 대시보드·실험 분석 화면의 지표 정의를 그대로 기록합니다. 설계서와 다른 점이 있어도 판정을 막지 않고, 리포트 끝 「참고」 1줄로만 남깁니다. 화면에 없는 지표만 variant별 실쿼리로 채웁니다(group-by는 쓰지 않습니다).
3. **피킹 게이트**(§7-6) — **스킬 자체가 계산하는 고정표본 통계**(차이·리프트·z·p·CI·베이지안·승패 어휘)는 필요 n 도달 전에는 한 글자도 쓰지 않습니다. **Amplitude 화면이 표시하는 리프트·신뢰구간·유의성(순차검정)은 도달 전에도 항상 인용합니다** — 화면 표시값 인용과 스킬 자체 판정은 다른 규칙입니다. **참가자 동의로도 풀리지 않습니다.**
4. **SRM 우선**(§7-7) — SRM 경보가 뜨면 게이트 도달 여부와 무관하게 판정 필드를 출력하지 않고 「실험 설계 잘못됨」으로 종착합니다.
5. **램프업 구간 제외**(§7-8) — 램프업·설정 변경 구간의 관측치는 누적 n과 원표에서 빼고, 제외 건수를 비고에 남깁니다.
6. **PII 집계만**(§7-9) — 원천 PII는 어떤 표에도 옮기지 않고 위치만 말합니다. Chrome으로 화면을 여는 경로에서도 같습니다.

**산출물** — M0(인테이크·접근 경로) → M1(설계서 추출) → M2(대시보드 지표 매핑) → M3(헬스: variant 누적·헬스 체크·표시값) → M4(진행률·모드 확정) → M5(판정, 판정 모드에서만) → M6(이상 징후 체크리스트). **기록물은 만들지 않습니다** — 화면에 리포트를 내고 끝냅니다(계약 v1.2.2 · §4). 어디에 남길지는 결과 보고서 단계가 정합니다.

**코치 리뷰 모드** — "모니터링 리뷰"라고 말하면 진입: MR-1~MR-8 판정 + 통계 검산 재현 결과. 채점 방식은 실험설계 R1과 동일합니다(Warning은 Pass로 카운트, 품질 점수 = Pass ÷ 판정 대상).

**이 스킬이 하지 않는 것**
- 기록물 생성 — 노션·EXP 파일 기입은 물론 붙여넣기 블록·기록 위치 안내도 만들지 않습니다(계약 v1.2.2 · §7-12)

- 조기 종료 결정 확정 (조건 도달 사실만 보고, 판단은 코치)

## 실험 종료 의사결정 (`cro-experiment-decision`)

판정이 나온 실험을 **끝내도 되는지 확인하고, 끝났다는 사실을 어디에 남길지**까지 담당하는 동봉 스킬입니다. "실험 종료해도 되나요", "연장할까요", "끝내자", "결과 기록해줘", "C variant 내릴까요", "롤아웃 갈까요" 같은 요청에 이 스킬이 나섭니다.

**시작 문구 예**

```
실험 종료 판단해줘 — 노션 설계서 URL https://notion.so/... 앰플리튜드 화면값은 아래 붙여넣습니다
```

**준비물 3가지** — ① **노션 실험설계서 URL**(또는 본문 붙여넣기) ② **앰플리튜드 Experiment 화면값**(방금 모니터링을 돌렸으면 그 리포트를 그대로 붙이면 됩니다) ③ **런칭일·종료 예정일**. 셋째가 없으면 예상 도달일과 연장 종료일 제안이 `확인 불가`로 남습니다.

**이럴 때 이렇게 됩니다**

| 지금 상태 | 스킬이 내는 것 |
|---|---|
| 필요 인원이 아직 안 모였다 | `지속` — 지금 몇 %인지, 지금 속도면 며칠 뒤 채워지는지. **이 상태에서는 「종료」로 넘어가지 않습니다** |
| 군별 인원 배분이 설계와 어긋나 있다 | 「실험 설계 잘못됨」 — 숫자가 예뻐도 결과를 쓰지 않고, 결과 칸은 `결과 불사용`입니다 |
| 필요 인원을 채웠고 유의성이 95%를 넘었다 | `WIN`/`LOSE`/`INCONCLUSIVE` 중 하나 + 어느 갈림길을 어떤 값으로 지났는지 |
| 95%는 못 넘겼는데 80%는 넘었다 | 연장을 물어볼 두 가지 질문과, 늘린다면 새 종료일 후보 |
| 세 군 이상인데 한 군만 성적이 나쁘다 | 그 군만 내려도 되는지 확인할 세 가지 질문 |
| 결정을 이미 내렸다 | 붙여넣을 블록 세 개 (노션 · EXP 파일 · 상태 변경 안내) |

**결정은 여러분이 합니다** — 스킬이 채우는 것은 판정과 권고까지이고, `종료`/`연장`/`지속` 칸과 다음 갈래(`전면 반영`/`수정 후 재실험`/`폐기`/`연장`)를 고르는 칸은 **빈칸으로 나옵니다.** 어느 쪽인지 한 마디 주시면 그때 기록 블록이 만들어집니다. 늘릴지 말지는 지면이 며칠 더 묶이는지와 다음 실험 일정이 걸린 문제라, 그 비용은 팀만 압니다.

**하지 않는 것**
- 노션·파일에 직접 쓰기, git commit — 블록만 만듭니다
- 피처 플래그 조작·배분 변경·variant 끄기·실험 종료 버튼 — 할 일 목록만 냅니다
- 필요 인원·MDE·종료 기준 고치기 → 본체 `cro-experiment-design`의 STEP 4/5
- 「왜 이겼나」·「배운 것」 서술 → 동봉 스킬 `cro-experiment-report`가 채웁니다. 이 스킬은 그 칸을 `⚠️SP3`로 비워 넘깁니다
- 유의성 계산기 링크를 지어내는 것 — 앰플리튜드 화면값이 먼저이고, 검산은 동봉 스크립트로 합니다

**코치 리뷰 모드** — 「종료 의사결정 리뷰」라고 말하면 DR-1~DR-11 판정과 판정 재현 결과를 냅니다(채점 방식은 실험설계 R1과 같습니다).

## 실험 결과 보고서 (`cro-experiment-report`)

종료 의사결정이 끝난 뒤(또는 아직 끝나지 않았어도) **실험 1건의 결과 보고서 초안을 만들고, 받은 피드백을 반영해 다시 내는** 동봉 스킬입니다. "실험 결과 보고서 초안", "결과 보고서 써줘", "실험 결과 분석", "4장 채워줘", "왜 졌는지 정리해줘", "보고서 피드백 반영", "결과 리포트 v2", "노션 4장에 붙일 블록 만들어줘" 같은 요청에 이 스킬이 나섭니다.

**판정은 이 스킬이 만들지 않고 종료 의사결정에서 승계합니다.** 보고서가 하는 일은 그 판정 위에 **「왜」와 「다음」을 얹는 것**이고, 숫자가 마음에 들지 않는다고 판정을 다시 부르면 그 문서는 보고서가 아니라 사후 합리화가 됩니다.

**입력** — 필수 2개 + 보조 4개: **노션 실험설계서 URL**(또는 본문 붙여넣기), **앰플리튜드 Experiment 설정 URL 또는 대시보드 URL**(또는 화면 값 붙여넣기). 보조는 종료 의사결정 기록 블록 · 재계산 구간 · 정성 자료 · 코치 사전 조사 노트입니다. **설계서가 없으면 해석하지 않고 종료 경로로 닫습니다.**

**정본** — 출력 규격은 `er-output-contract.md` **v1.0**(DEC-024)이며, 사본은 `skills/cro-experiment-report/references/output-contract.md`입니다. 임계값은 이 스킬이 정의하지 않고 종료 의사결정 스킬의 `references/thresholds.md`를 **번호로만** 인용합니다 — 쓰는 것은 ⑤ 수집 최소 요건 · ⑥ 베이지안 구간 · ⑨ 계산 구현 우선순위 · ⑩ 하락 판정 넷입니다.

**출력** — **붙여넣기 코드블록 2개 + 로컬 초안 파일 안내 1개**입니다.

| 무엇 | 어디에 붙나 | 형태 |
|---|---|---|
| 노션 실험설계서 4장 `4-1)`·`4-2)`·`4-3)` 전문 | 참가자 정본 | 코드블록 1개 |
| repo EXP 파일 `## 3`·`## 4`의 **결과 보고서 소유 5칸** | 실험 1건의 SSOT | 코드블록 1개 |
| 로컬 초안 파일 | 부록(표·출처·변경 이력)이 남는 자리 | 안내 표 — **파일을 쓰는 것은 사람입니다** |

로컬 초안 파일 이름은 `{EXP-ID}_result-report_{interim|final}_v{n}_{YYYYMMDD}.md`이고, 기본 저장 위치는 `30_deliverables/experiments/reports/`입니다. **라벨이 `interim`에서 `final`로 바뀌어도 `v{n}`은 이어서 셉니다.**

**접근 경로 사다리** — 모니터링 스킬과 같습니다. **읽기에만** 적용되고 기입은 하지 않습니다.
- 노션: 노션 MCP → Chrome으로 URL 열어 읽기 → 참가자 붙여넣기 → 실패하면 **진행 불가·종료 경로**
- 앰플리튜드: 실험 분석·차트·대시보드 조회 → Chrome으로 화면 열어 읽기 → 화면에 없는 지표만 퍼널 실쿼리 재구성 → `확인 불가`

> ⚠️ **참가자 계정은 노션에 게스트라 1순위가 열리지 않는 것이 정상입니다.** 시도해 실패를 확인한 뒤 2순위로 내려가는 것이 참가자 세션의 정상 경로이며 결함이 아닙니다.

**하드 게이트 7종**
1. **종료 확인** — 종료·결정이 확인되지 않으면 전 출력 상단에 `중간 리포트 — 판정 잠정` 라벨을 고정합니다. **막는 것은 「최종 보고」이지 「분석」이 아닙니다** — 유형 분류·세그먼트·정성 판정은 그대로 하고, 막히는 것은 4-3의 확정 문장뿐입니다.
2. **판정 정본 우선순위** — ① 종료 의사결정 확정 기록 → ② 계산값 → ③ 화면 표시값. 다시 계산해도 **판정 어휘를 바꾸지 않고**, 흐름도는 인용만 합니다.
3. **근거 태그 필수** — 모든 해석 문장에 `[실측]`·`[계산]`·`[해석]`·`[가정]` 중 하나를 붙이고, `[해석]`에는 근거 행 번호를 병기합니다. **번호 없는 `[해석]`은 `[가정]`입니다.**
4. **사전 선언 세그만 판정** — 설계서에 미리 선언된 구간만 판정이고 나머지는 힌트입니다. 탐색적 세그먼트로 승패를 말하지 않습니다.
5. **PII 집계만** — 금융·보험 도메인이라 개별 사용자 행·원천 식별자는 어떤 표에도 블록에도 옮기지 않습니다. 세션 리플레이도 집계만 인용합니다.
6. **배포 반영 ≠ 승** — 반영 가능 여부는 「Primary 승 AND Guardrail·Secondary 불하락」이고, 설계서의 자체 허용 범위가 「불하락」을 대체하지 않습니다. 🚫 스킬이 「이겼으니 반영하면 된다」를 적지 않습니다.
7. **읽기 전용** — 노션·EXP 파일·로컬 파일에 어느 경로로도 쓰지 않고 git commit도 하지 않습니다. **읽기가 허용됐다는 사실이 쓰기를 허용하지 않습니다.**

**산출물** — S0(인테이크·접근 경로·보고서 라벨) → S1(설계값 전사) → S1b(설계↔화면 매핑) → S2a·S2b(실측·판정 수령) → S3(결과 유형 분류) → S4(유형별 분석) → S5a·S5b(세그먼트·정성) → S6a·S6b·S6c(조립) → S7(피드백 반영). **표 13종이 한 번에 나오고, 요약본과 상세본으로 나누지 않습니다.**

결과 유형은 판정에서 기계적으로 나옵니다 — `WIN`→**T1**, `LOSE`→**T2**, `INCONCLUSIVE`→**T3**, `실험 설계 잘못됨`→**T4**, `지속`이면 분류하지 않고 「중간 리포트」로 닫습니다. Primary와 Guardrail·Secondary의 방향이 어긋나면 유형 뒤에 혼합 플래그 **`M`**이 붙습니다. 유형별 고정 질문과 확인 순서는 `references/analysis-guide.md`, 빈 틀은 `references/report-templates.md`에 있습니다.

**세그먼트 축은 스킬이 고정하지 않고 매번 묻습니다** — 후보는 설계서 사전 선언 구간 · 디바이스 · 신규/재방문 · 연령대 · 유입 경로 · 후속 퍼널 단계 여섯이고, **사전 선언 구간은 항상 포함**됩니다.

**코치 리뷰 모드** — 「결과 보고서 리뷰」라고 말하면 SR-1~SR-10 판정과 리뷰 리포트 6구성을 냅니다(채점 방식은 실험설계 R1과 같습니다). **Critical이 하나라도 `Fail`이면 품질 등급과 무관하게 「이 보고서는 다시 봐야 한다」로 닫습니다.**

**이 스킬이 하지 않는 것**
- 종료·연장·지속 결정과 So Next 확정 — 종료 의사결정 소관이라 **승계하거나 빈칸**으로 둡니다
- 판정 흐름도의 재정의 — 인용만 하고 다시 그리지 않습니다
- 노션·EXP 파일 직접 기입과 git commit — 붙여넣을 블록을 만드는 데까지입니다
- 설계값 수정·재계산(필요 n·MDE·Target·Baseline·종료 기준) → 본체 `cro-experiment-design`
- 담당자 세팅 재감사 — 설계서와 화면의 차이는 S1b에 **기록만** 합니다
- 정성조사의 실행 — 필요 여부 판정과 질문 후보 3~5개까지이고, 조사는 「실험 결과 디브리프」 소관입니다
- 유의성 계산기 URL을 지어내는 것 — 값은 직접 돌려서 주시면 스크립트 계산값과 병기·검산해 드립니다

**시작 문구 예**

```
실험 결과 보고서 초안 — 노션 설계서 URL https://notion.so/... 앰플리튜드 실험 URL https://app.amplitude.com/experiment/...
```

**피드백 주는 법 — 코멘트는 5형으로 처리됩니다**

| 이렇게 주시면 | 이렇게 처리됩니다 |
|---|---|
| **숫자 정정** — "이 전환율이 다릅니다" | 출처를 다시 조회해 고칩니다. 재조회가 안 되면 붙여넣기 일시를 출처로 적고 고칩니다 |
| **해석 추가·수정** — "이 부분은 이렇게 보입니다" | **근거를 함께 주시면** `[해석]` + 행 번호, 근거가 없으면 `[가정]`으로 적습니다 |
| **분류 이의** — "이건 T2가 아니라 T3 아닌가요" | 판정과 유형은 유지하고, 대안 질문 세트로 **부록에 다시 실행**한 뒤 `[가정] 코치 확인 필요`를 붙입니다 |
| **구조** — "부록 순서를 바꿔주세요" | 부록은 자유롭게 바꾸고, **4장 구조(4-1·4-2·4-3)는 바꾸지 않습니다** |
| **판정·결정 어휘 변경** — "p가 0.07이니 INCONCLUSIVE로 바꿔주세요" | **거부합니다** — 종료 의사결정과 계산값 소관입니다. 변경 이력에 `거부 — 판정은 dc 소관`으로 남깁니다 |

반영하면 **v{n+1} 전문을 다시 냅니다** — 바뀐 부분만 내지 않습니다. 거부한 코멘트도 변경 이력에서 지우지 않습니다.

**사전 준비** — 모니터링·종료 의사결정 스킬과 같습니다. 앰플리튜드 MCP 연결은 선택이고, 연결이 안 돼 있어도 Chrome으로 화면을 열어 읽거나 값을 붙여넣는 경로로 동작합니다. 통계 계산은 모니터링 스킬의 `statsig.py`를 **경로로 호출**합니다(복사하지 않습니다) — 3군 이상이면 `--bonferroni {축소 후 비교 수 = 판정 군 수 − 1}`가 반드시 붙습니다.
