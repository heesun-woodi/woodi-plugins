## 1. 공식 (원문 그대로)

```
문제 Impact 점수 = (트래픽 영향 + 벤치마크 Gap + 정성 심각도) / 3   (각 10점 만점)
```

### 세 차원의 정의

| 차원 | 질문 | 10점 기준 | 근거 데이터 | 값을 어디서 받나 |
|---|---|---|---|---|
| **트래픽 영향** | 이 문제를 겪는 사용자가 얼마나 많은가 | 해당 영역 전체 사용자가 겪음 + 최대 트래픽 | 월 UV/PV, 전체 대비 비중 | **오전 워크숍 시트 축탭 S2** |
| **벤치마크 Gap** | 현재 baseline이 벤치마크 대비 몇 배 낮은가 (%p 아님, **배수**) | 벤치마크 대비 5배 이상 낮음 | Gap 배수 | **축탭 S7** |
| **정성 심각도** | CRO Checklist Fail 비율 + BIAS 진단 심각도 | Checklist Fail 80%+ 이고 BIAS Block/Act 9/10 | Fail율, BIAS 단계별 심각도 | **스킬이 제안** (STEP 2·3 결과) |

---

## 2. BIAS 가중치

정성 심각도 **원점수**에 다음을 더한 뒤 **10점으로 캡**한다.

| BIAS 단계 실패 | 가중치 |
|---|---|
| **Block 실패 포함** | **+2** |
| **Interpret 실패 포함** | **+1** |
| Act 실패 | 0 |
| Store 실패 | 0 |

```
심각도(가중) = MIN(10, 원점수 + (Block 실패면 +2) + (Interpret 실패면 +1))
```

이유: 같은 트래픽·같은 Gap이라면 **Block 문제가 Act 문제보다 먼저**다. Block에서 걸린 사용자는
Interpret 이후 단계를 아예 경험하지 못하기 때문이다. 가중치를 빼먹으면 Act 문제가 과대평가된다.

## 3. 계산은 시트가 한다 — 스킬은 원점수까지만

| 열 | 내용 | 누가 채우나 |
|---|---|---|
| F | 트래픽 점수 (1~10) | **참가자가 준 S2 값** 기반 |
| G | 트래픽 근거 — S2 값 인용 한 줄 | 필수 |
| H | Gap 점수 (1~10) | **참가자가 준 S7 배수** 기반 |
| I | Gap 근거 — S7 배수 인용 한 줄 | 필수 |
| J | 심각도 **원점수** (1~10) | 스킬이 제안 |
| K | 심각도 근거 — Fail율 + BIAS 한 줄 | 필수 |
| L | Block 실패 포함 (`Y`/`N`) | 스킬이 판정 |
| M | Interpret 실패 포함 (`Y`/`N`) | 스킬이 판정 |
| **N** | 심각도(**가중**) | **시트 수식 (회색) — TSV에 넣지 않는다** |
| **O** | **Impact** | **시트 수식 (회색) — TSV에 넣지 않는다** |
| P | 클로드 교차검증 Impact | 참가자가 **수기 입력** (스킬이 목록으로 제시) |

시트 수식 (데이터 첫 행을 n행이라 할 때):

```
N열: =IF(J{n}="","",MIN(10, J{n} + IF(L{n}="Y",2,0) + IF(M{n}="Y",1,0)))
O열: =IF(COUNT(F{n},H{n},N{n})=3, ROUND(AVERAGE(F{n},H{n},N{n}),1), "")
```

> **스킬의 자기 계산값은 교차검증용일 뿐이다.** 정본 Impact는 **시트 O열 값**이다.
> 두 값이 다르면 입력값을 의심하고 멈춘다.

## 4. 근거 필수 규칙

> **각 점수에는 반드시 근거 한 줄. 근거 없는 점수는 무효 처리한다.**

- ✗ "심각도 8"
- ✓ "심각도 8 — Checklist Fail 6/8=75%, BIAS Block 심각도 9/10 + Act 8/10"

**근거 없는 점수 무효 규칙** (계약 §2): G·I·K 근거 칸이 비어 있으면 해당 점수는 무효 —
코치가 검수 시 F/H/J를 지운다(그러면 수식이 Impact를 비운다).

### 값을 지어내지 않는다

- 트래픽(S2)·Gap(S7) 값을 참가자가 못 주면 → **해당 점수 칸 공란 + 근거 칸에 `코치 확인 필요`**
- 업계 평균·추정치·상식으로 채우지 않는다.
- 점수가 비면 시트 O열이 자동으로 비워진다. **그게 정상 동작이다.**

### 점수가 몰리면 의심한다

모든 문제가 8~9점으로 몰려 나오면 근거 없이 감으로 채점된 것이다.
**근거 칸을 먼저 채우고 점수는 그다음에 확정한다.** Impact는 같은 화면 안의 문제들을 서로
비교해 순위를 만드는 **상대 평가**이지 절대 점수가 아니다.

## 5. 정성 심각도 원점수를 제안하는 법

STEP 2·3 결과에서 다음 둘을 조합해 1~10 원점수를 제안하고, 근거 한 줄을 K열에 쓴다.

1. **Checklist Fail율** = Fail ÷ (Fail + Pass) — **N/A는 분모에서 제외**
2. **BIAS 진단 결과** — 어느 단계에 X가 몇 개 몰려 있는가

대략의 눈금 (기계적으로 적용하지 말고 근거와 함께 판단한다):

| Fail율 | BIAS 상태 | 원점수 대략 |
|---|---|---|
| 80%+ | Block 또는 Act에 X 다수 | 9~10 |
| 60~80% | X가 특정 단계에 몰림 | 7~8 |
| 40~60% | X 산발 | 5~6 |
| ~40% | X 소수, 대부분 △ | 3~4 |

CRO 진단을 생략한 경우(B축 축약 모드)에는 K열에
`BIAS 진단만 반영 (CRO 진단 생략)`이라고 명시한다.

## 6. ICE는 여기서 계산하지 않는다

> **ICE는 8/14(금) 백로그 워크숍에서 계산한다.** 이 세션의 Impact 점수는 그 ICE의
> **I(Impact) 근거값**일 뿐이다.

- **ICE 정본은 합산식 `ICE = I + C + E`다.**
- **곱셈식 ICE는 금지.** 스킬·문서·대화 어디에도 곱셈식 ICE가 등장하면 안 된다.
- 참가자가 ICE 계산이나 솔루션 아이데이션을 요청하면 금요일 워크숍으로 정중히 미룬다.

금요일에는 이 세션의 근거를 그대로 옮겨 적는다:
`I = 9 (문제정의 Impact 근거: 트래픽 10 / Gap 9 / 심각도 8)`
