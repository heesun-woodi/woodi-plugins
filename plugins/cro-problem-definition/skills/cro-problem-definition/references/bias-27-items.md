# BIAS 27항목 진단 — 항목 문구 + 판정 기준

> 출처: `03a_problem-definition-workshop-guide.md` §6 / CRO 방법론 KB `02_problem-definition.md` §3-3 / `BIAS_Framework_CRO_Auditor.md` / `BIAS_Framework_Master_Guide.md` (전술 라이브러리)
> **항목ID와 문구의 정본은 SSOT `50_reference/bias-checklist.md`**(근거: DEC-003)이고, 이 파일은 그 표를
> 판정 가이드와 함께 옮겨 놓은 것이다. 순서(B1→S4)를 바꾸지 않는다. 27개를 전부 판정한다.

## BIAS 4단계

| 단계 | 의미 | 뇌의 작동 원리 | 판별 질문 |
|---|---|---|---|
| **B — Block (차단)** | 뇌가 정보를 무시·차단하지 않게 | "무관하거나 복잡하면 무시한다" | 화면을 아예 보지 않는다 |
| **I — Interpret (해석)** | 정보를 쉽고 긍정적으로 해석하게 | "익숙한 방식으로 해석한다" | 보고도 반응하지 않는다 |
| **A — Act (행동)** | 행동에 필요한 마찰 제거 | "귀찮거나 두려우면 미룬다" | 반응하지만 끝까지 안 한다 |
| **S — Store (기억)** | 경험을 긍정 감정으로 저장 | "감정으로 기억한다" | 돌아오지 않는다 |

**우선순위: Block > Interpret > Act > Store.** 앞 단계 실패가 더 치명적이다 — Block에서 걸린
사용자는 Interpret 이후 단계를 아예 경험하지 못한다.

> 흔한 실수: 모든 문제를 Act로 진단한다. Act는 눈에 보이는 요소(버튼·폼)라 찾기 쉽기 때문이다.
> **Block 항목부터 먼저 판정**하고, Block에서 X가 나오는지 의식적으로 확인한다.

### 우선순위와 Impact 가중치의 연결

이 우선순위는 장식적 원칙이 아니라 `impact-scoring.md`의 계산식에 직접 들어간다: 정성 심각도
원점수에 **Block 실패 포함 시 +2, Interpret 실패 포함 시 +1**을 더한 뒤 10점으로 캡한다(Act·Store
가중치 0). 같은 트래픽·같은 Gap이라도 Block 문제가 Act 문제보다 Impact가 먼저 올라가는 이유는,
Block에서 걸린 사용자는 Interpret·Act·Store를 아예 경험하지 못해 그 뒤 단계의 모든 개선이 무의미해지기
때문이다. 그래서 T2 판정에서 **Block 항목을 먼저, 의식적으로** 확인하는 습관이 Impact 계산의
정확도를 좌우한다 — Block X를 놓치면 심각도 원점수에서 +2가 통째로 빠진다.

| `B2` | Block | 자기 관련성 — "나를 위한 이야기"로 느낄 개인화 요소가 있는가 |

| `I7` | Interpret | 발견 용이성 — 핵심 기능·정보가 쉽게 발견되는가 |

| `A3` | Act | 사회적 증거 — 다른 사용자의 행동(리뷰·구매 수 등)이 확신을 주는가 |
| `A4` | Act | 희소성/긴급성 — 지금 행동해야 할 명분이 있는가 |
| `A5` | Act | 단계 쪼개기 — 복잡한 과정이 작은 단계로 나뉘어 쉬운 선택부터 시작되는가 |
| `A6` | Act | 점진적 공개 — 처음엔 핵심만 보여주고 세부는 필요한 시점에 노출하는가 |
| `A7` | Act | 호기심 자극 — 정보를 일부만 보여줘 다음 행동을 부르는 장치가 있는가 |
| `S1` | Store | 즉각적 피드백 — 행동에 시각/청각 피드백이 즉시 제공되는가 |
| `S2` | Store | 안심 장치 — 개인정보 보호·완료 메시지 등으로 불안을 해소하는가 |
| `S3` | Store | Delighter — 예상 밖의 긍정적 마이크로 인터랙션·문구가 있는가 |
| `S4` | Store | 케어 신호 — 맞춤 추천 이유·과사용 경고 등 제품이 사용자를 아낀다는 느낌을 주는가 |

> **이력**: 이 체크리스트는 2026-08-11 DEC-003으로 15항목(B4/I4/A4/S3) → **27항목**(B9/I7/A7/S4)으로
> 확대됐다. 기존 항목ID는 전부 그대로 유지되고 신규 12개가 `B5`~`B9`·`I5`~`I7`·`A5`~`A7`·`S4`로 추가
> 채번됐으므로, 15항목 시기에 작성된 산출물의 항목ID 인용은 지금도 유효하다. 다만 `B4`는 이름이
> "인지 부하 최소화" → **"선택지 과부하 방지"** 로 정정됐고(판정 기준은 불변), 옛 이름은 신규 `I5`가
> 승계했다 — 두 항목을 혼동하지 않도록 주의한다. 일부 옛 문서의 "16항목" 표기는 그때도 오기였다.

## 판정 기준 (O / △ / X)

| 판정 | 의미 | 성립 조건 |
|---|---|---|
| `O` | **Pass** | 확정 전사에 충족을 보여주는 근거가 있다 |
| `△` | **부분 충족 / 판단 보류** | 일부만 충족, 또는 **근거가 부족**해 단정할 수 없다. `❓(판독 불확실)` Fact뿐인 경우도 여기 |
| `X` | **Fail** | 확정 전사에 **명확한 미충족 근거(Fact ID)**가 있다 |

### 판정 시 강제 규칙

1. **모든 `X`는 근거 Fact ID 필수.** 근거를 못 대면 `X`가 아니라 `△`다.
2. **`❓(판독 불확실)` Fact는 `X`의 근거가 될 수 없다.** 안 읽히는 글자를 "없다"로 단정하지 않는다.
3. **`X`·`△` 항목마다 고객 주어 문제 문장 초안**을 남긴다 (T2 6열). 형식은 `fact-vs-problem.md` 참조.
4. **27항목 전부 판정한다.** 빈 칸을 남기지 않는다 — 완료 판정 체크 2번 항목이다.
5. **"없음"도 근거다.** 요소가 화면에 아예 없다는 것이 확정 전사에 `없음`으로 기록돼 있으면,
   그것은 `X`의 정당한 근거다. 반대로 "전사에 안 적혀 있다"는 근거가 아니다 — 그건 `△`다.
6. **화면 레이아웃 전용 항목은 B축에서 `N/A`가 정상이다.** `B6`(무시 영역)·`B7`(광고 인접)은 카카오톡
   대화 전사에 대응 개념이 없다 — 억지로 `X`를 매기지 않는다.

### 판정하기 어려울 때 쓰는 단계 판별표

| 관찰 | 해당 단계 |
|---|---|
| 화면·메시지를 아예 보지 않는다 | Block |
| 보고도 반응하지 않는다 | Interpret |
| 반응하지만 끝까지 완료하지 않는다 | Act |
| 완료했지만 돌아오지 않는다 | Store |

## 항목별 판정 가이드

> 각 항목의 **판정 질문**은 화면(또는 대화 전사)에 대고 직접 던지는 질문이다. **O/△/X 기준**은 위
> "판정 기준"의 일반 규칙을 이 항목의 체크 내용에 적용한 것이다. **좋은 예/나쁜 예**는 이 스킬의
> CRO 체크리스트 발췌본(`data/checklist-excerpt-a.json`·`-b.json`)에 이미 실린 보험분석·카톡 상담
> 맥락의 판정 기준·신호를 재사용해 구성했다 — 새 사실을 지어내지 않고 같은 스킬 안의 근거를
> 재조합한 것이다. **흔한 오판**은 이 항목의 정의를 인접 단계·인접 항목과 혼동하는 지점을
> 짚는다(구체적 오판 사례가 원천에 없는 항목은 "원천 미수록"으로 남겨둔다).

### B1. 1초 직관성 (Block)

- **판정 질문**: 헤드라인과 메인 이미지만 1초 보여주고 가리면, "무슨 서비스/혜택인지" 답할 수 있는가?
- **O**: 헤드라인·메인 이미지만으로 무엇을 분석·제공하는 화면인지 즉시 파악된다는 근거가 전사에 있다.
- **△**: 헤드라인은 있으나 즉시 파악 여부를 판단할 근거가 부족하다(전사에 반응 기록 없음).
- **X**: 헤드라인이 일반 문구("분석 결과" 등)라 무엇을 분석했는지 알 수 없다는 근거가 전사에 있다.
- **좋은 예**: 헤드라인이 "OO님의 보장 공백 3가지"처럼 무엇을 분석했는지 설명적이고 눈에 띈다(LP-C1 근거).
- **나쁜 예**: 헤드라인이 "분석 결과"처럼 일반 문구라 무엇을 분석했는지 알 수 없다(LP-C1 fail_signal).
- **흔한 오판**: 글자가 작아 못 읽는 가독성 문제와 혼동한다. 1초 직관성은 "인지되는가"가 기준이지 "읽기 편한가"가 기준이 아니다 — 가독성이 나빠도 1초 안에 서비스가 파악되면 이 항목은 O일 수 있다.

### B2. 자기 관련성 (Block)

- **판정 질문**: "나를 위한 이야기"라고 느낄 이름·상황·맥락 언급이 화면에 있는가?
- **O**: 사용자의 상황(가족 구성, 기존 가입 여부 등)을 언급하는 개인화 요소가 전사에 있다.
- **△**: 개인화로 볼 만한 요소가 있으나 "나를 위한 것"으로 느껴질 수준인지 판단할 근거가 부족하다.
- **X**: 모든 사용자에게 동일하게 보이는 일반 문구뿐이라는 근거가 전사에 있다.
- **좋은 예**: 이름·상황을 직접 언급한다(예: "가족보험 있으신 것으로 확인됐어요") — `BIAS_Framework_Master_Guide.md`의 Cocktail Party Effect 전술.
- **나쁜 예**: 어투는 친근하지만 이름·상황 언급 없이 모든 사용자에게 같은 문구가 뜬다.
- **흔한 오판**: 부드러운 말투를 자기 관련성으로 착각한다. "친절한 톤"과 "나를 위한 맥락"은 다르다 — 상황·속성이 실제로 언급되지 않으면 톤만으로는 O가 아니다.

### B3. 패턴 파괴 (Block)

- **판정 질문**: 배너 광고처럼 보여 시선이 무의식적으로 피해가는 영역이 있는가?
- **O**: 이탈시키는 배너·광고성 영역이 없다는 근거가 전사에 있다(요소 상태 `없음`).
- **△**: 배너성 요소가 있는지 판단할 근거가 부족하다.
- **X**: 광고성 배너·외부 링크가 본문 사이에 끼어 있다는 근거가 전사에 있다.
- **좋은 예**: 리포트·상담 화면에 다른 상품 배너나 외부 링크가 끼어들지 않아 본문에 집중된다(LP-S3·CO-F4 근거).
- **나쁜 예**: 리포트 중간에 다른 보험 상품 광고 배너가 삽입돼 있어 사용자가 광고로 인식하고 넘긴다(LP-S3·CO-F4 fail_signal 응용).
- **흔한 오판**: 디자인이 세련되면 배너 블라인드니스가 없다고 오판한다. 판단 기준은 디자인 품질이 아니라 "광고처럼 보이는 위치·형태"인지다.

### B4. 선택지 과부하 방지 (Block)

- **판정 질문**: 이 화면에서 사용자가 지금 고를 수 있는 주요 선택지를 세어보면 5~6개 미만인가?
- **O**: 화면 내 주요 선택지를 실제로 센 결과가 5~6개 미만이라는 근거가 전사에 있다.
- **△**: 선택지 개수가 전사에 명시되지 않아 셀 수 없다.
- **X**: 주요 선택지가 5~6개 이상이라는 근거(전사에 나열된 개수)가 있다.
- **좋은 예**: 한 화면에 제시되는 보장·분석 항목이 소수로 제한돼 있다.
- **나쁜 예**: 한 화면에 10개 넘는 옵션이 한꺼번에 나열돼 무엇부터 봐야 할지 판단이 안 된다.
- **흔한 오판**: "복잡해 보인다"는 인상만으로 판정한다. 인지 부하는 인상이 아니라 화면 내 선택지 **개수를 실제로 세는** Fact로 판정해야 한다.

### B5. 직관 이해 (Block)

- **판정 질문**: 헤드라인·메뉴·입력 안내를 보고 별도 설명 없이 "무엇을 어떻게 해야 하는지" 즉시 알 수 있는가?
- **O**: 조작 방법이나 화면 구조를 설명 없이 직관적으로 이해할 수 있다는 근거가 전사에 있다.
- **△**: 구조는 파악되나 별도 노력 없이 직관적으로 이해되는지 판단할 근거가 부족하다.
- **X**: 화면 구조나 입력 방식을 파악하려면 의식적 노력이 필요하다는 근거가 전사에 있다.
- **좋은 예**: 점검신청 화면의 각 단계 레이블이 행동 동사로 적혀 있어 별도 설명 없이 다음에 무엇을 해야 하는지 바로 알 수 있다.
- **나쁜 예**: 카카오톡 상담방에서 상담사의 첫 질문이 "내용을 입력해 주세요"처럼 추상적이라 무엇을 입력해야 하는지 되묻게 된다(CO-F8 fail_signal 참조).
- **흔한 오판**: B1(1초 직관성)과 혼동한다. B1은 "이 서비스가 무슨 서비스인지 인지하는가"가 기준이고, B5는 "이 화면에서 무엇을 어떻게 조작해야 하는지 의식적 노력 없이 파악되는가"가 기준이다 — 서비스 정체는 알아도 조작 구조가 낯설면 B5는 X일 수 있다.

### B6. 무시 영역 회피 (Block)

- **판정 질문**: 핵심 정보가 상단 배너·우측 사이드바처럼 사용자가 습관적으로 무시하는 영역에만 배치되어 있지 않은가?
- **O**: 핵심 정보(CTA·보장 공백 요약 등)가 습관적 무시 영역 밖의 콘텐츠 흐름 안에 배치된다는 근거가 전사에 있다.
- **△**: 레이아웃 배치를 판단할 근거가 전사에 없어 무시 영역 해당 여부를 확인할 수 없다.
- **X**: 핵심 정보가 상단 고정 배너나 사이드바처럼 습관적으로 스킵되는 영역에만 있다는 근거가 전사에 있다.
- **좋은 예**: 보장 공백 요약과 점검신청 CTA가 리포트 본문 흐름 중간에 자연스럽게 삽입되어 스크롤 경로에서 만나게 된다.
- **나쁜 예**: 점검신청 안내가 화면 상단 고정 헤더 배너에만 표시돼 있어 사용자가 이미 무의식적으로 무시하는 영역과 겹친다.
- **흔한 오판**: B3(패턴 파괴)과 혼동한다. B3는 "광고처럼 생겨서 무의식적으로 피해 가는가"가 기준이고, B6는 "콘텐츠 형태와 무관하게 무시 영역으로 지정된 위치(상단 배너·사이드바)에만 있는가"가 기준이다. B6은 화면 레이아웃 전용 항목이므로 B축 카카오톡 대화 전사에서는 해당 위치 개념 자체가 없어 N/A가 정상 판정이다.

### B7. 광고 인접 회피 (Block)

- **판정 질문**: 중요 정보나 핵심 CTA가 실제 광고 또는 광고성 콘텐츠 바로 옆에 배치되어 함께 무시당하는 상황이 아닌가?
- **O**: 중요 정보 주변에 실제 광고·광고성 배너가 없다는 근거가 전사에 있다(LP-S3 근거).
- **△**: 주변 콘텐츠 성격을 판단할 근거가 전사에 없어 광고 인접 여부를 확인할 수 없다.
- **X**: 중요 정보나 CTA 바로 옆에 광고성 배너·외부 상품 링크가 붙어 있다는 근거가 전사에 있다(LP-S3 fail_signal).
- **좋은 예**: 점검신청 버튼 주변에 다른 광고·이벤트 배너가 없어 버튼만 눈에 들어온다.
- **나쁜 예**: 보장 공백 분석 결과 바로 아래에 다른 보험 상품 광고 배너가 배치되어 분석 결과와 광고가 함께 무시된다(LP-S3 fail_signal 응용).
- **흔한 오판**: B6(무시 영역 회피)과 혼동한다. B6은 "위치"(배너·사이드바 등 특정 레이아웃 영역)의 문제이고, B7은 "인접 콘텐츠"(옆에 실제 광고가 있는가)의 문제다 — 위치가 좋아도 광고 옆이면 B7이 X일 수 있다. B7 역시 화면 레이아웃 전용 항목이므로 B축 카카오톡 대화 전사에서는 N/A가 정상 판정이다.

### B8. 프라이밍 (Block)

- **판정 질문**: 핵심 메시지나 CTA를 보여주기 전에, 그것과 연결되는 단기 기억 정보(문제 인식·관련 수치 등)를 먼저 노출하는가?
- **O**: 주요 CTA·결론 전에 사용자 상황과 연결되는 관련 정보(보장 공백 수치, 위험 예시 등)가 먼저 노출된다는 근거가 전사에 있다.
- **△**: 정보 노출 순서를 판단할 근거가 부족하다.
- **X**: CTA나 핵심 메시지가 관련 맥락 없이 바로 제시된다는 근거가 전사에 있다.
- **좋은 예**: "OO님의 보장 공백 3가지"를 보여준 직후 점검신청 CTA를 배치해, 공백에 대한 문제 인식이 단기 기억에 남은 상태에서 신청 버튼을 만나게 된다(LP-C1 근거 응용).
- **나쁜 예**: 분석 수치나 문제 맥락 없이 상담방 오픈 화면에서 바로 "지금 신청하세요"로 시작한다 — 사용자가 왜 신청해야 하는지 단기 기억에 아무것도 없는 상태다.
- **흔한 오판**: I2(혜택 우선성)와 혼동한다. I2는 "CTA나 콘텐츠 자체에 혜택이 먼저 쓰여 있는가"이고, B8은 "CTA 직전 단계에서 관련 정보를 미리 노출해 수용 태세를 만들었는가"다 — 같은 화면에 혜택을 쓰는 것(I2)과 그 화면 이전에 관련 자극을 준 것(B8)은 다르다.

### B9. 패턴 브레이크 (Block)

- **판정 질문**: 반복되는 UI 패턴이나 대화 흐름 중에 사용자의 주의를 의도적으로 끌기 위한 패턴 이탈 요소가 있는가?
- **O**: 반복 패턴 속에서 의도적으로 다른 색상·형태·톤으로 주의를 끄는 요소가 있다는 근거가 전사에 있다.
- **△**: 디자인 요소의 일관성·이탈 여부를 판단할 근거가 부족하다.
- **X**: 화면·대화 전체가 동일한 패턴으로만 구성되어 특별히 눈에 띄는 요소가 없다는 근거가 전사에 있다.
- **좋은 예**: 카카오톡 상담방에서 연속된 질문 메시지 사이에 "잠깐, OO님만을 위한 팁이에요" 같은 색다른 형식의 메시지가 삽입되어 주의를 환기한다.
- **나쁜 예**: 리포트 전체가 같은 폰트·색상·카드 형식으로만 구성되어 어느 요소가 더 중요한지 주의를 끄는 포인트가 없다.
- **흔한 오판**: B3(패턴 파괴)와 혼동한다. B3는 "광고처럼 보이는 요소 때문에 시선이 회피되는가"를 막는 방어적 항목이고, B9는 "단조로운 패턴 속에서 의도적으로 시선을 끄는 요소를 심었는가"를 점검하는 공격적 항목이다 — B3가 X이면(광고형 요소 있음) 주의를 빼앗기지 않으려는 것이고, B9가 X이면(패턴 브레이크 없음) 주의를 끌지 못하는 것이다.

### I1. 익숙한 UX (Interpret)

- **판정 질문**: 클릭 가능한 요소가 별도 설명 없이도 눌러도 된다고 알아차려지는가(보편적 UI 패턴을 따르는가)?
- **O**: 버튼·링크가 보편적 시각 신호(둥근 모서리, 밑줄 등)로 클릭 가능함을 알린다는 근거가 있다.
- **△**: UI 패턴이 보편적인지 판단할 근거가 부족하다.
- **X**: 클릭 가능한 요소가 일반 텍스트와 구분되지 않는다는 근거가 있다.
- **좋은 예**: 버튼이 둥근 모서리·그림자 등으로 눌리는 요소임을 직관적으로 알 수 있다.
- **나쁜 예**: 텍스트 링크처럼 생긴 요소가 실제로는 버튼이라 클릭 가능한지 헷갈린다.
- **흔한 오판**: 새롭고 창의적인 UI를 "혁신적이라 좋다"며 O로 판정한다. 학습이 필요하면 Interpret 실패다 — 기준은 참신함이 아니라 익숙함이다.

### I2. 혜택 우선성 (Interpret)

- **판정 질문**: 기능 설명과 얻는 이득 중 어느 쪽이 더 크고 먼저 보이는가?
- **O**: 혜택 문구가 기능 설명보다 크고 먼저 보인다는 근거가 있다(LP-S7 근거: 핵심 혜택이 상단 명시).
- **△**: 혜택 문구는 있으나 기능 설명 대비 우선순위를 판단할 근거가 부족하다.
- **X**: 기능 설명만 있고 혜택 언급이 없다는 근거가 있다(LP-S7 fail_signal).
- **좋은 예**: 리포트 상단에 "맞춤 분석으로 보장 공백을 확인하세요" 같은 혜택이 기능 설명보다 먼저 보인다.
- **나쁜 예**: "AI 정밀분석 알고리즘 적용"처럼 기능 설명만 있고 고객이 얻는 이득은 안 보인다.
- **흔한 오판**: 혜택 문구가 하나라도 존재하면 O로 판정한다. 존재 여부가 아니라 "기능 설명보다 크고 명확하게" 보이는지가 기준이다.

### I3. 앵커링 (Interpret)

- **판정 질문**: 가격·가치를 판단할 비교 기준점(평균·이전 값 등)이 제시되는가?
- **O**: 비교 기준점이 제시된다는 근거가 있다(예: 업계 평균 대비 표기).
- **△**: 숫자는 있으나 비교 기준으로 쓰일 만한지 판단할 근거가 부족하다.
- **X**: 수치가 단독으로만 제시되고 비교 기준점이 없다는 근거가 있다.
- **좋은 예**: "업계 평균 대비 ○○% 저렴" 같은 비교 기준을 제시해 가치 판단을 돕는다.
- **나쁜 예**: 보험료가 단독으로만 제시되고 비교할 기준(평균가·이전 견적 등)이 전혀 없다.
- **흔한 오판**: 가격이나 숫자가 하나라도 보이면 앵커링이 있다고 오판한다. 비교할 기준점(전·후, 평균 대비 등)이 없으면 앵커링이 아니다.

### I4. 손실 회피 (Interpret)

- **판정 질문**: 지금 행동하지 않으면 잃게 되는 것이 문구로 시각화되어 있는가?
- **O**: "지금 안 하면 무엇을 잃는지"를 시각화한 문구가 있다는 근거가 있다.
- **△**: 손실 관련 문구가 있으나 시각화 수준을 판단할 근거가 부족하다.
- **X**: 혜택만 나열되고 지금 안 하면 무엇을 잃는지는 언급이 없다는 근거가 있다.
- **좋은 예**: "지금 점검하지 않으면 보장 공백이 방치됩니다" 같은 손실 프레이밍 문구가 있다(`BIAS_Framework_Master_Guide.md` Loss Aversion 전술).
- **나쁜 예**: 혜택만 나열되고 지금 안 하면 무엇을 잃는지는 언급이 없다.
- **흔한 오판**: 혜택 문구(I2)를 손실 회피(I4)로 착각한다. "얻는 것"을 강조하면 I2이고, "지금 안 하면 잃는 것"을 강조해야 I4다.

### I5. 인지 부하 최소화 (Interpret)

- **판정 질문**: 화면의 텍스트 분량·시각 복잡도가 낮아, 내용을 이해하기 위해 드는 인지 노력이 최소인가?
- **O**: 문단이 짧고 시각 요소가 명확해 해석에 드는 인지 노력이 낮다는 근거가 전사에 있다.
- **△**: 정보 밀도·시각 구조를 판단할 근거가 전사에 부족하다.
- **X**: 문단이 길거나 시각 요소가 복잡해 내용을 이해하는 데 의식적 노력이 든다는 근거가 전사에 있다.
- **좋은 예**: 보장 공백 리포트가 항목별로 짧은 문장과 아이콘으로 구성되어 긴 텍스트를 읽지 않아도 한눈에 파악된다.
- **나쁜 예**: 카카오톡 상담 메시지 하나에 5문장 이상의 설명이 들어 있어 다 읽지 않으면 무엇을 답해야 하는지 알 수 없다(CO-F5 fail_signal 참조).
- **흔한 오판**: B4(선택지 과부하 방지)와 혼동한다. B4는 화면 내 **선택지 개수를 실제로 세어** 5~6개 초과 여부를 판정하는 항목이고, I5는 선택지 개수와 무관하게 **문단 길이·시각 복잡도** 등 해석에 드는 인지 노력을 판정하는 항목이다. B4의 원래 이름이 "인지 부하 최소화"였다가 DEC-003에서 "선택지 과부하 방지"로 정정됐고 I5가 그 이름을 승계했으므로 용어 혼동에 특히 주의해야 한다.

### I6. Labor Illusion (Interpret)

- **판정 질문**: 분석·처리 대기 시간에 "지금 당신을 위해 일하는 중"이라는 가치 경험이 제공되는가?
- **O**: 대기 화면·메시지에서 처리 과정을 시각화하거나 언급해 기다림이 가치 있게 느껴진다는 근거가 전사에 있다.
- **△**: 대기 구간이 있는지, 있다면 어떻게 처리됐는지 판단할 근거가 부족하다.
- **X**: 대기 중 아무 안내 없이 그냥 기다리게 되어 지연이 방치된 느낌을 준다는 근거가 전사에 있다.
- **좋은 예**: 카카오톡 상담방에서 견적 산출 중 "OO님 보장 내역을 분석하고 있어요. 잠시만 기다려 주세요"처럼 진행 과정을 실시간으로 알려준다(CA-T7 근거 응용).
- **나쁜 예**: 견적 산출에 수십 초가 걸리는데 아무 메시지 없이 침묵이 이어져 시스템이 멈춘 건지 처리 중인지 알 수 없다(CA-T7 fail_signal 참조).
- **흔한 오판**: S1(즉각적 피드백)과 혼동한다. S1은 "행동 직후 즉시 반응이 왔는가"이고, I6은 "불가피한 대기 시간을 가치 경험으로 바꾸었는가"다 — 처리가 오래 걸릴 수밖에 없는 구간(견적 산출 등)에서 S1은 "처리 시작" 신호를 확인하고, I6은 그 대기 구간 전체를 얼마나 의미 있게 채웠는지를 별도로 판정한다.

### I7. 발견 용이성 (Interpret)

- **판정 질문**: 사용자가 필요한 순간에 핵심 기능·정보를 별도 탐색 없이 쉽게 찾을 수 있는가?
- **O**: 핵심 기능(점검신청, 견적 보기 등)이 사용 시점에 맞게 노출되어 쉽게 발견된다는 근거가 전사에 있다.
- **△**: 핵심 기능의 노출 위치나 타이밍을 판단할 근거가 부족하다.
- **X**: 핵심 기능·정보가 숨어 있거나 예상치 못한 위치에 있어 찾는 데 추가 탐색이 필요하다는 근거가 전사에 있다.
- **좋은 예**: 카카오톡 상담방에서 견적 확인 버튼이 정보 입력 완료 직후 대화 하단에 자연스럽게 등장해 별도 탐색 없이 발견된다(CA-T3 근거 응용).
- **나쁜 예**: 보험분석 리포트의 "자세히 보기" 링크가 스크롤 하단에만 있어 끝까지 내리지 않으면 존재 자체를 알 수 없다.
- **흔한 오판**: I1(익숙한 UX)과 혼동한다. I1은 "클릭 가능한 요소임을 알아차리는가"(UI 패턴 준수 여부)이고, I7은 "필요한 시점에 그 기능을 찾을 수 있는가"(노출 위치·타이밍)다 — 요소 자체는 익숙한 버튼 형태여도(I1 O) 예상치 못한 위치에 있으면 I7은 X일 수 있다.

### A1. 마찰 제거 (Act)

- **판정 질문**: 목적 달성에 불필요한 입력 필드·클릭 단계가 있는가?
- **O**: 불필요한 입력·클릭이 없다는 근거가 있다(CO-F5·F6 근거: 한 번에 하나 질문, 최소 정보만).
- **△**: 입력 단계 수를 셀 만한 근거가 부족하다.
- **X**: 불필요한 입력·클릭 단계가 있다는 근거가 있다(CO-F5·F6 fail_signal).
- **좋은 예**: 한 메시지에서 질문 하나만 물어 응답 부담이 없다.
- **나쁜 예**: 한 번에 여러 항목을 동시에 나열해서 물어 응답 부담이 크다.
- **흔한 오판**: 필드 개수가 적어 보이는 화면 인상만으로 O로 판정한다. 실제 클릭·입력 단계 수를 세지 않고 인상만으로 판단하면 안 된다.

### A2. 스마트 기본값 (Act)

- **판정 질문**: 추천 옵션이 기본 선택된 상태로 제시되는가?
- **O**: 추천 옵션이 기본 선택돼 있다는 근거가 있다.
- **△**: 옵션은 있으나 기본 선택 여부를 판단할 근거가 부족하다.
- **X**: 모든 옵션이 비어 있는 상태로 시작한다는 근거가 있다.
- **좋은 예**: 추천 보장 옵션이 기본 선택 상태로 제시돼 고민 없이 진행할 수 있다.
- **나쁜 예**: 모든 옵션이 비어 있는 상태로 시작해 사용자가 하나하나 직접 선택해야 한다.
- **흔한 오판**: 옵션이 존재하기만 하면 O로 판정한다. 옵션의 존재가 아니라 **기본 선택**돼 있는지가 기준이다.

### A3. 사회적 증거 (Act)

- **판정 질문**: 다른 사용자의 행동(이용 수·후기 등)을 보여줘 확신을 주는 요소가 있는가?
- **O**: 이용자 수·후기 등 타인의 행동을 보여주는 요소가 있다는 근거가 있다(PP-P2·PP-P5 근거).
- **△**: 관련 요소가 있으나 확신을 주는 수준인지 판단할 근거가 부족하다.
- **X**: 타인의 행동을 보여주는 요소가 전혀 없다는 근거가 있다(PP-P5 fail_signal).
- **좋은 예**: "이번 달 ○○명이 점검신청했어요" 같은 이용 데이터가 표시된다(PP-P5 근거).
- **나쁜 예**: 이용자 수·후기 등 다른 사람의 행동을 보여주는 요소가 전혀 없다.
- **흔한 오판**: 브랜드 로고(수상·언론 노출)를 사회적 증거로 착각한다. 사회적 증거는 "다른 사용자의 행동"이지 브랜드 자체의 신뢰 요소(PP-P1)가 아니다.

### A4. 희소성/긴급성 (Act)

- **판정 질문**: 지금 당장 행동해야 할 구체적 명분(시간·수량 제한)이 있는가?
- **O**: 지금 행동해야 할 구체적 명분(마감·우선 배정 등)이 있다는 근거가 있다(CA-T2 근거).
- **△**: 긴급성 관련 문구는 있으나 구체성을 판단할 근거가 부족하다.
- **X**: 지금 행동해야 할 이유가 전혀 제시되지 않는다는 근거가 있다(CA-T2 fail_signal).
- **좋은 예**: "지금 답변하면 우선 배정" 같은 긴급성 문구가 있다(CA-T2 근거).
- **나쁜 예**: 지금 행동해야 할 이유(마감·한정 등)가 전혀 제시되지 않는다.
- **흔한 오판**: 일반적인 안내 문구를 긴급성으로 착각한다. 손실 회피(I4)는 "잃는 것"을 알리는 정보 단계이고, 희소성/긴급성(A4)은 구체적 시간·수량 제한으로 행동을 직접 유도하는 단계라는 점에서 다르다.

### A5. 단계 쪼개기 (Act)

- **판정 질문**: 복잡한 과정이 사용자가 부담 없이 "예스"라고 답할 수 있는 작은 단계로 나뉘어, 쉬운 선택부터 시작되는가?
- **O**: 복잡한 과정이 단계별로 분할되어 한 번에 하나씩 소화되게 구성된다는 근거가 전사에 있다(CO-F5 근거).
- **△**: 단계 분할 여부를 판단할 근거가 전사에 부족하다.
- **X**: 여러 단계가 한꺼번에 요구되거나 과정이 분할되지 않아 부담이 크다는 근거가 전사에 있다(CO-F5 fail_signal).
- **좋은 예**: 카카오톡 상담 중 정보 입력을 한 메시지에 한 질문씩 순차적으로 진행해, 각 질문을 짧게 답할 수 있게 한다(CO-F5 근거).
- **나쁜 예**: 상담 시작 메시지 하나에서 이름·나이·직업·보험 가입 이력을 한꺼번에 물어 한 번에 다섯 가지 정보를 입력해야 한다(CO-F5 fail_signal).
- **흔한 오판**: A1(마찰 제거)과 혼동한다. A1은 "불필요한 단계·입력을 없애는 것"이고, A5는 "필요한 과정을 더 작게 나누는 것"이다 — A1은 제거(삭제)이고 A5는 분할(재구성)이다. A6(점진적 공개)과도 혼동하는데, A6은 "정보 노출 단위를 나누는 것"이고 A5는 "사용자 행동 단위를 나누는 것"이다.

### A6. 점진적 공개 (Act)

- **판정 질문**: 처음에는 핵심 정보·옵션만 보여주고, 세부 내용은 사용자가 필요한 시점이 됐을 때만 노출하는가?
- **O**: 처음에는 핵심 정보만 보여주고 세부는 단계가 진행되면서 순차적으로 노출된다는 근거가 전사에 있다.
- **△**: 정보 노출 순서와 시점을 판단할 근거가 전사에 부족하다.
- **X**: 처음부터 모든 세부 정보·옵션이 한꺼번에 노출되어 부담이 크다는 근거가 전사에 있다.
- **좋은 예**: 보험분석 리포트에서 처음에는 "보장 공백 3가지" 요약만 보여주고, "자세히 보기"를 눌러야 각 항목의 세부 수치와 설명이 펼쳐진다.
- **나쁜 예**: 상담방 오픈 직후 첫 메시지에서 앞으로 나누게 될 모든 질문 목록과 필요 서류를 한꺼번에 안내해 시작 전부터 압도된다.
- **흔한 오판**: A5(단계 쪼개기)와 혼동한다. A5는 "행동 단위(사용자가 해야 할 일)를 나누는 것"이고, A6은 "정보 노출 단위(사용자가 봐야 할 것)를 나누는 것"이다 — 한 질문을 두 번에 나눠 묻는 것은 A5이고, 한 화면의 정보를 "요약→상세" 2단계로 나눠 보여주는 것은 A6이다.

### A7. 호기심 자극 (Act)

- **판정 질문**: 정보의 일부를 미리 노출해 "더 알고 싶다"는 동기를 불러일으켜 다음 행동을 유도하는 장치가 있는가?
- **O**: 정보 일부를 먼저 보여주고 전체를 보려면 다음 행동이 필요하게 구성된다는 근거가 전사에 있다.
- **△**: 정보 공개 방식을 통해 호기심이 유발되는지 판단할 근거가 부족하다.
- **X**: 정보가 처음부터 모두 공개되거나 아무것도 미리 보여주지 않아 "더 보고 싶다"는 동기를 자극하는 장치가 없다는 근거가 전사에 있다.
- **좋은 예**: 보험분석 리포트에서 "OO님의 보장 공백이 발견됐습니다. 자세한 내용은 아래에서 확인하세요"처럼 결과를 암시하고 스크롤을 유도한다.
- **나쁜 예**: 점검신청 화면에서 상담을 통해 무엇을 얻을 수 있는지 아무것도 미리 보여주지 않아 신청을 해야 할 이유를 느낄 수 없다.
- **흔한 오판**: A4(희소성/긴급성)와 혼동한다. A4는 "지금 당장 행동해야 할 구체적 이유(시간·수량 제한)를 제시하는 것"이고, A7은 "더 알고 싶다는 호기심을 자극해 자연스럽게 다음 행동으로 이끄는 것"이다 — A4의 동기는 손실 회피(안 하면 잃는다)이고, A7의 동기는 궁금증 해소(더 알고 싶다)다.

### S1. 즉각적 피드백 (Store)

- **판정 질문**: 행동 직후 시각/청각 피드백이 즉시 제공되는가?
- **O**: 행동 직후 즉시 피드백(팝업·메시지 등)이 온다는 근거가 있다(CO-F9·PP-C6 근거).
- **△**: 피드백이 있는지 판단할 근거가 부족하다.
- **X**: 행동 후 아무 반응이 없다는 근거가 있다(CO-F9·PP-C6 fail_signal).
- **좋은 예**: 잘못 입력하면 그 자리에서 바로 재입력 요청 메시지가 뜬다(CO-F9 근거).
- **나쁜 예**: 버튼을 눌러도 접수됐는지 알려주는 반응이 없어 다시 눌러야 하나 헷갈린다(PP-C6 fail_signal).
- **흔한 오판**: 결과 화면 자체가 있으면 피드백이 있다고 오판한다. 기준은 **즉시성**이다 — 로딩 후 다음 화면으로 자연히 넘어가는 것과, 행동 직후의 즉각적 시청각 반응은 다르다.

### S2. 안심 장치 (Store)

- **판정 질문**: 개인정보 보호·완료 메시지 등으로 불안을 해소하는 문구가 있는가?
- **O**: 안심시키는 문구(정보 보호, 취소 시 불이익 없음 등)가 있다는 근거가 있다(CA-T8 근거).
- **△**: 관련 문구가 있으나 안심 수준을 판단할 근거가 부족하다.
- **X**: 민감 정보를 요구하면서도 안심 문구가 전혀 없다는 근거가 있다(CA-T8 fail_signal).
- **좋은 예**: "입력한 정보는 상담 목적 외 사용되지 않습니다" 같은 안심 문구가 있다(CA-T8 근거).
- **나쁜 예**: 민감정보를 입력하라고 하면서 어떻게 보호되는지 안내가 전혀 없다(CA-T8 fail_signal).
- **흔한 오판**: 개인정보처리방침 링크가 있으면 O로 판정한다. 약관 링크와 화면에 노출된 안심 문구는 다르다 — 링크를 눌러야만 보이는 정보는 화면 자체의 안심 장치로 보지 않는다.

### S3. Delighter (Store)

- **판정 질문**: 예상 밖의 긍정적 마이크로 인터랙션이나 문구가 있는가?
- **O**: 예상 밖의 긍정 요소(축하 문구·감동 연출 등)가 있다는 근거가 있다.
- **△**: 완료 화면은 있으나 Delighter 요소 유무를 판단할 근거가 부족하다.
- **X**: 완료 화면이 사무적인 안내뿐이라는 근거가 있다.
- **좋은 예**: 접수 완료 시 "축하합니다, 곧 전문가가 연락드려요" 같은 예상 밖의 긍정 문구가 뜬다(`BIAS_Framework_Master_Guide.md` Peak-End Rule 전술).
- **나쁜 예**: 접수 완료 화면이 사무적인 텍스트 한 줄뿐이라 아무 감정도 남지 않는다.
- **흔한 오판**: 정상적으로 작동하면(에러가 없으면) Delighter가 있다고 오판한다. 에러가 없는 것은 기본 기능이지, 예상 밖의 긍정 요소가 아니다.

### S4. 케어 신호 (Store)

- **판정 질문**: 맞춤 추천 이유, 불필요한 보장 경고, 따뜻한 톤의 메시지 등 제품이 사용자를 진심으로 아끼고 있다는 신호가 있는가?
- **O**: 사용자를 배려한다는 인상을 주는 요소(맞춤 이유 설명, 경고, 케어 문구 등)가 있다는 근거가 전사에 있다.
- **△**: 케어 신호로 볼 만한 요소가 있는지 판단할 근거가 부족하다.
- **X**: 단순 정보 전달에 그쳐 제품이 사용자를 아낀다는 느낌을 주는 요소가 전혀 없다는 근거가 전사에 있다.
- **좋은 예**: 상담사가 "OO님 나이와 가족 구성을 고려하면 이 보장이 더 유리합니다"처럼 맞춤 추천 이유를 설명하거나, 불필요한 보장에 대해 "이건 지금 OO님에게 꼭 필요하진 않아요"라고 솔직하게 안내한다.
- **나쁜 예**: 상담 내내 정해진 질문만 기계적으로 이어지고 맞춤 이유나 사용자를 생각했다는 표현이 전혀 없어 챗봇과 대화하는 느낌을 준다.
- **흔한 오판**: S2(안심 장치)와 혼동한다. S2는 "개인정보 보호·취소 가능 등 불안을 해소하는 방어적 안심"이고, S4는 "사용자 상황에 맞춘 배려·설명·경고처럼 제품이 적극적으로 아낌을 표현하는 것"이다 — S2가 "해치지 않는다는 신호"라면, S4는 "도움을 주고 싶다는 신호"다.
