> `prep-week/_specs/pd-output-contract.md`이며, 원본 개정 시 이 사본을 동기화합니다.
> 스킬은 아래의 **열 이름·순서·ID 체계·공식·TSV 규칙을 문자 그대로** 따릅니다.

> v1.2 변경: §6 규칙 1 — TSV는 섹션 **헤더 셀**(P1=A11/P2=A34/P3=A52/P5=A89)에 붙인다(헤더 겹쳐쓰기가 정상). 첫 데이터 셀에 붙이면 한 행씩 밀려 P5 수식이 깨진다.
> v1.1 변경: ① P3 D열 헤더를 `재해석·적용 힌트`로 통일(B축=카톡 재해석, A축=시그널플래너 화면 적용 힌트) ② §6 규칙 3 — P5 TSV는 A~M(13열)만, P열은 별도 목록 수기 입력(빈 셀이 수식을 덮어쓰는 사고 방지)

> **지위**: 이 파일이 **단일 정본(SSOT)**입니다. `03d`(CRO 발췌본)·`03f`(시트 확장 킷)·`cro-problem-definition` 스킬은 전부 이 계약의 열 이름·순서·ID 체계·공식을 그대로 복사합니다. 이 파일을 수정하면 세 산출물을 반드시 동기화합니다.
> **용도**: 8/10(월) 문제영역 선정 워크숍 직후 진행하는 **사용자 문제정의 라이브 세션(60~90분)**의 산출물 규격.
> **범위 주의**: 합성 인터뷰(03b)는 Sprint 1~2로 이연 — 이 계약에 P4(합성 인터뷰) 섹션은 없습니다.

## 2. 섹션 정의 (P0 ~ P6 + 완료 판정)

| 항목 | 채우는 값 | 출처 |
|---|---|---|
| 확정 문제영역 | 오전 워크숍 결과 | 탭4·5 |

### P1. 워크스루 Fact 로그 — **7열**

| 열 | 헤더 | 입력 |
|---|---|---|
| A | Fact ID | `F-01`, `F-02`, … (화면 1개 = 1회 실행 단위로 연번) |
| B | 스크린샷 파일명 | `A_01_보험분석결과_1진입.png` 형식 |
| C | 화면 내 위치/요소 | 예: 상단 헤드라인, 하단 CTA |
| D | 관측 사실(Fact) | 문구 전사 또는 "○○ 요소 없음" — **없음도 Fact** |
| E | 요소 상태 | `있음` / `없음` / `판독불확실❓` |
| F | 안 함 vs 못 함 | 해당 시: `클릭하지 않았다` / `클릭할 수 없었다` / `-` |
| G | 비고 | |

### P2. BIAS 15항목 진단 — **7열** (15행 프리필)

| 열 | 헤더 |
|---|---|
| A | 항목ID (`B1`~`B4`, `I1`~`I4`, `A1`~`A4`, `S1`~`S3` — 03a §6 순서 고정) |
| B | 단계 (Block/Interpret/Act/Store) |
| C | 체크 항목 (03a §6 문구 그대로 프리필) |
| D | 판정 (`O` / `△` / `X` 드롭다운) |
| E | 근거 Fact ID (P1 인용, 콤마 구분 — **X 판정은 필수**) |
| F | 근거(관측 사실 요약) |
| G | 사용자 관점 문제 문장 초안 (X·△만) |

판정 기준: O=Pass, △=부분 충족/판단 보류(근거 부족), X=Fail. **❓ Fact는 X의 근거가 될 수 없음.**

### P3. CRO 체크리스트 판정 — **8열** (03d 항목 프리필, B축 선택)

| 열 | 헤더 |
|---|---|
| A | 항목ID (아래 4절 체계) |
| B | 섹션 (예: Landing–Structure&CTA) |
| C | 체크 항목 (03d 문구 그대로) |
| D | 재해석·적용 힌트 (B축=카톡 재해석, A축=시그널플래너 화면 적용 힌트 — 03d 문구 그대로) |
| E | 판정 (`Pass` / `Fail` / `N/A` 드롭다운) |
| F | 근거 Fact ID |
| G | BIAS 단계 (03d 매핑 그대로 프리필) |
| H | 메모 |

항목 블록 아래 요약 행 3개(회색, 수식):
- **Fail율** = `=IFERROR(COUNTIF(E{시작}:E{끝},"Fail")/(COUNTIF(E{시작}:E{끝},"Fail")+COUNTIF(E{시작}:E{끝},"Pass")),"")` (N/A 제외, 판정 전 #DIV/0! 방지)
- **단계별 Fail 수** = `=COUNTIFS(G{시작}:G{끝},"Block",E{시작}:E{끝},"Fail")` (4단계 각각)
- **지배 병목 단계** = 페어가 텍스트로 기입(수식 아님 — 판단 기록)

### P5. 문제 리스트 + Impact — **16열** ★ 핵심 산출물

| 열 | 헤더 | 유형 |
|---|---|---|
| A | 문제ID (`PR-01`, …) | 입력 |
| B | 사용자 문제 (User Voice, 1인칭) | 입력 |
| C | BIAS 단계 | 입력 |
| D | 근거 ID (Fact/체크리스트 항목, 콤마 구분) | 입력 |
| E | 근거유형 (`관측` / `정성(VOC·인터뷰)` / `가설(합성)`※) | 입력 |
| F | 트래픽 점수 (1~10) | 입력(노랑) |
| G | 트래픽 근거 — **축탭 S2 값 인용** 한 줄 | 입력(노랑) |
| H | Gap 점수 (1~10) | 입력(노랑) |
| I | Gap 근거 — **축탭 S7 배수 인용** 한 줄 | 입력(노랑) |
| J | 심각도 원점수 (1~10) | 입력(노랑) |
| K | 심각도 근거 — Checklist Fail율 + BIAS 심각도 한 줄 | 입력(노랑) |
| L | Block 실패 포함 (`Y`/`N`) | 입력(노랑) |
| M | Interpret 실패 포함 (`Y`/`N`) | 입력(노랑) |
| N | 심각도(가중) | **수식(회색)** |
| O | Impact | **수식(회색)** |
| P | 클로드 교차검증 Impact | 입력 — 두 값이 다르면 입력값을 의심하고 멈춘다 |

※ `가설(합성)`은 Sprint 1~2 합성 인터뷰 도입 시 사용 예약 — 이번 세션에서는 나오지 않는 것이 정상.

**수식** (데이터 첫 행을 n행이라 할 때 — 절대 행 번호는 03f 이식 시 치환):
```
N열: =IF(J{n}="","",MIN(10, J{n} + IF(L{n}="Y",2,0) + IF(M{n}="Y",1,0)))
O열: =IF(COUNT(F{n},H{n},N{n})=3, ROUND(AVERAGE(F{n},H{n},N{n}),1), "")
```

**근거 없는 점수 무효 규칙**: G·I·K 근거 칸이 비어 있으면 해당 점수는 무효 — 코치가 검수 시 F/H/J를 지운다(수식이 Impact를 비움).

### P6. 문제트리 (3depth) — **6열** (라이브 범위 아님 — 과제용 자리)

| 열 | 헤더 |
|---|---|
| A | 노드ID (`N1`, `N1-1`, `N1-1-1` — depth를 하이픈으로 표기) |
| B | Depth (1/2/3) |
| C | 상위 노드ID |
| D | 내용 |
| E | 연결 문제ID (P5의 PR-xx) |
| F | 비고 |

### 완료 판정 체크 — 2열 (체크 항목 / Y·N)

1. 스크린샷 3장 전사가 "전사 확인"으로 승인되었는가
2. BIAS 15항목 전부 판정되었는가 (빈 D열 없음)
3. X·△ 항목마다 문제 문장 초안이 있는가
4. 문제 문장에서 솔루션이 자동으로 따라 나오지 않는가 (현상 아님)
5. User Voice가 전부 1인칭인가
6. 모든 점수(F/H/J)에 근거 한 줄이 붙어 있는가
7. Impact는 시트 수식값 기준인가 (P열 교차검증 완료)

## 5. Impact 공식 · BIAS 가중치 (정본 — 03a §5 원문)

```
문제 Impact 점수 = (트래픽 영향 + 벤치마크 Gap + 정성 심각도) / 3   (각 10점 만점)
```

- 정성 심각도 가중치: **Block 실패 항목이 있으면 +2, Interpret 실패 항목이 있으면 +1**을 더한 뒤 **10점으로 캡**. Act/Store 실패는 가중치 없음.
- 각 점수에 반드시 근거 한 줄 — 근거 없는 점수는 무효.
- **ICE는 이 단계에서 계산하지 않는다** (금요일 워크숍, **합산식 ICE = I+C+E**가 정본 — 곱셈식 금지). 스킬·문서 어디에도 곱셈식 ICE가 등장하면 안 된다.

## 6. TSV 출력 규칙 (스킬·프롬프트 카드 공통)

1. 붙여넣기 안내(대상 탭·섹션·예상 열 수·붙일 셀)는 **코드블록 밖** 본문에 쓴다. TSV는 헤더 포함이므로 **붙일 위치는 섹션의 헤더 셀**이다(절대 주소, 03f 행 맵 정본): **P1=A11, P2=A34, P3=A52, P5=A89** (과제 단계 산출물: P6=A112, 완료 판정 체크=A130). "기존 헤더 위에 같은 헤더가 겹쳐 써지는 것이 정상"임을 안내에 명시한다 — 첫 데이터 셀에 붙이면 전 행이 한 칸 밀리고 P5 수식이 #VALUE!가 된다. 예: "아래 블록을 `8_A축_문제정의` 탭 **A34**(P2 헤더 셀)에 붙이세요 — 7열로 갈라지고 헤더가 겹쳐 써지면 정상입니다."
2. 코드블록 안에는 **헤더 행 + 데이터 행만**, 탭(tab) 문자 구분. 주석·빈 행 금지 (주석이 셀에 들어가는 사고 방지).
3. 수식 열(P5의 N·O)은 TSV에 **포함하지 않는다** — 스킬 출력 P5 TSV는 **A~M열(13열)만** 낸다. 빈 탭으로 N·O 자리를 건너뛰는 방식은 금지: 빈 셀 붙여넣기가 시트 수식을 덮어써 지운다. **P열(클로드 교차검증 Impact)은 TSV에 넣지 않고**, 블록 아래에 `문제ID → 교차검증 Impact` 목록(텍스트)으로 제시해 참가자가 P열에 수기 입력한다.
4. 붙인 뒤 셀이 안 갈라지면: [데이터 > 텍스트를 열로 분리 > 탭] → 그래도 안 되면 RAW 존에 통짜로 붙이고 핵심만 손으로 옮긴다 (02c 규칙 1과 동일).
