# BIAS 15항목 진단 — 항목 문구 + 판정 기준

> 출처: `03a_problem-definition-workshop-guide.md` §6 / CRO 방법론 KB `02_problem-definition.md` §3-3 / `BIAS_Framework_CRO_Auditor.md` / `BIAS_Framework_Master_Guide.md` (전술 라이브러리)
> **항목ID와 문구는 이 파일이 정본**이다. 순서(B1→S3)를 바꾸지 않는다. 15개를 전부 판정한다.

---

## BIAS 4단계

| 단계 | 의미 | 뇌의 작동 원리 | 판별 질문 |
|---|---|---|---|
| **B — Block (차단)** | 뇌가 정보를 무시·차단하지 않게 | "무관하거나 복잡하면 무시한다" | 화면을 아예 보지 않는다 |
| **I — Interpret (해석)** | 정보를 쉽고 긍정적으로 해석하게 | "익숙한 방식으로 해석한다" | 보고도 반응하지 않는다 |
| **A — Act (행동)** | 행동에 필요한 마찰 제거 | "귀찮거나 두려우면 미룬다" | 반응하지만 끝까지 안 한다 |
| **S — Store (기억)** | 경험을 긍정 감정으로 저장 | "감정으로 기억한다" | 돌아오지 않는다 |

**우선순위: Block > Interpret > Act > Store.** 앞 단계 실패가 더 치명적이다 — Block에서 걸린
사용자는 Interpret 이후 단계를 아예 경험하지 못한다.

> 흔한 실수: 모든 문제를 Act로 진단한다. Act는 눈에 보이는 요소(버튼·폼)라 찾기 쉽기 때문이다.
> **Block 항목부터 먼저 판정**하고, Block에서 X가 나오는지 의식적으로 확인한다.

### 우선순위와 Impact 가중치의 연결

이 우선순위는 장식적 원칙이 아니라 `impact-scoring.md`의 계산식에 직접 들어간다: 정성 심각도
원점수에 **Block 실패 포함 시 +2, Interpret 실패 포함 시 +1**을 더한 뒤 10점으로 캡한다(Act·Store
가중치 0). 같은 트래픽·같은 Gap이라도 Block 문제가 Act 문제보다 Impact가 먼저 올라가는 이유는,
Block에서 걸린 사용자는 Interpret·Act·Store를 아예 경험하지 못해 그 뒤 단계의 모든 개선이 무의미해지기
때문이다. 그래서 T2 판정에서 **Block 항목을 먼저, 의식적으로** 확인하는 습관이 Impact 계산의
정확도를 좌우한다 — Block X를 놓치면 심각도 원점수에서 +2가 통째로 빠진다.

## 15항목 (판정 순서 고정)

| 항목ID | 단계 | 체크 항목 |
|---|---|---|
| `B1` | Block | 1초 직관성 — 헤드라인·메인 이미지만 보고 1초 안에 무슨 서비스/혜택인지 아는가 |
| `B2` | Block | 자기 관련성 — "나를 위한 이야기"로 느낄 개인화 요소가 있는가 |
| `B3` | Block | 패턴 파괴 — 배너처럼 보여 무의식적으로 무시되는 영역은 없는가 |
| `B4` | Block | 인지 부하 최소화 — 한 화면 내 주요 선택지가 5~6개 미만인가 |
| `I1` | Interpret | 익숙한 UX — 학습 없이 이해되는 보편적 패턴을 따르는가 |
| `I2` | Interpret | 혜택 우선성 — 기능 설명보다 얻는 이득이 더 크고 명확한가 |
| `I3` | Interpret | 앵커링 — 가격·가치를 판단할 비교 기준점이 있는가 |
| `I4` | Interpret | 손실 회피 — 지금 행동하지 않으면 잃는 것이 시각화되어 있는가 |
| `A1` | Act | 마찰 제거 — 불필요한 입력·클릭이 제거되었는가 |
| `A2` | Act | 스마트 기본값 — 추천 옵션이 기본 선택되어 있는가 |
| `A3` | Act | 사회적 증거 — 다른 사용자의 행동(리뷰·구매 수 등)이 확신을 주는가 |
| `A4` | Act | 희소성/긴급성 — 지금 행동해야 할 명분이 있는가 |
| `S1` | Store | 즉각적 피드백 — 행동에 시각/청각 피드백이 즉시 제공되는가 |
| `S2` | Store | 안심 장치 — 개인정보 보호·완료 메시지 등으로 불안을 해소하는가 |
| `S3` | Store | Delighter — 예상 밖의 긍정적 마이크로 인터랙션·문구가 있는가 |

> 원본 문서 일부에 "16항목"으로 표기된 곳이 있으나 실제 항목은 **15개**(Block 4 / Interpret 4 /
> Act 4 / Store 3)다. 15항목이 정본이다.

## 판정 기준 (O / △ / X)

| 판정 | 의미 | 성립 조건 |
|---|---|---|
| `O` | **Pass** | 확정 전사에 충족을 보여주는 근거가 있다 |
| `△` | **부분 충족 / 판단 보류** | 일부만 충족, 또는 **근거가 부족**해 단정할 수 없다. `❓(판독 불확실)` Fact뿐인 경우도 여기 |
| `X` | **Fail** | 확정 전사에 **명확한 미충족 근거(Fact ID)**가 있다 |

### 판정 시 강제 규칙

1. **모든 `X`는 근거 Fact ID 필수.** 근거를 못 대면 `X`가 아니라 `△`다.
2. **`❓(판독 불확실)` Fact는 `X`의 근거가 될 수 없다.** 안 읽히는 글자를 "없다"로 단정하지 않는다.
3. **`X`·`△` 항목마다 고객 주어 문제 문장 초안**을 남긴다 (T2 6열). 형식은 `fact-vs-problem.md` 참조.
4. **15항목 전부 판정한다.** 빈 칸을 남기지 않는다 — 완료 판정 체크 2번 항목이다.
5. **"없음"도 근거다.** 요소가 화면에 아예 없다는 것이 확정 전사에 `없음`으로 기록돼 있으면,
   그것은 `X`의 정당한 근거다. 반대로 "전사에 안 적혀 있다"는 근거가 아니다 — 그건 `△`다.

### 판정하기 어려울 때 쓰는 단계 판별표

| 관찰 | 해당 단계 |
|---|---|
| 화면·메시지를 아예 보지 않는다 | Block |
| 보고도 반응하지 않는다 | Interpret |
| 반응하지만 끝까지 완료하지 않는다 | Act |
| 완료했지만 돌아오지 않는다 | Store |

## 항목별 판정 가이드

> 각 항목의 **판정 질문**은 화면(또는 대화 전사)에 대고 직접 던지는 질문이다. **O/△/X 기준**은 위
> "판정 기준"의 일반 규칙을 이 항목의 체크 내용에 적용한 것이다. **좋은 예/나쁜 예**는 이 스킬의
> CRO 체크리스트 발췌본(`data/checklist-excerpt-a.json`·`-b.json`)에 이미 실린 보험분석·카톡 상담
> 맥락의 판정 기준·신호를 재사용해 구성했다 — 새 사실을 지어내지 않고 같은 스킬 안의 근거를
> 재조합한 것이다. **흔한 오판**은 이 항목의 정의를 인접 단계·인접 항목과 혼동하는 지점을
> 짚는다(구체적 오판 사례가 원천에 없는 항목은 "원천 미수록"으로 남겨둔다).

### B1. 1초 직관성 (Block)

- **판정 질문**: 헤드라인과 메인 이미지만 1초 보여주고 가리면, "무슨 서비스/혜택인지" 답할 수 있는가?
- **O**: 헤드라인·메인 이미지만으로 무엇을 분석·제공하는 화면인지 즉시 파악된다는 근거가 전사에 있다.
- **△**: 헤드라인은 있으나 즉시 파악 여부를 판단할 근거가 부족하다(전사에 반응 기록 없음).
- **X**: 헤드라인이 일반 문구("분석 결과" 등)라 무엇을 분석했는지 알 수 없다는 근거가 전사에 있다.
- **좋은 예**: 헤드라인이 "OO님의 보장 공백 3가지"처럼 무엇을 분석했는지 설명적이고 눈에 띈다(LP-C1 근거).
- **나쁜 예**: 헤드라인이 "분석 결과"처럼 일반 문구라 무엇을 분석했는지 알 수 없다(LP-C1 fail_signal).
- **흔한 오판**: 글자가 작아 못 읽는 가독성 문제와 혼동한다. 1초 직관성은 "인지되는가"가 기준이지 "읽기 편한가"가 기준이 아니다 — 가독성이 나빠도 1초 안에 서비스가 파악되면 이 항목은 O일 수 있다.

### B2. 자기 관련성 (Block)

- **판정 질문**: "나를 위한 이야기"라고 느낄 이름·상황·맥락 언급이 화면에 있는가?
- **O**: 사용자의 상황(가족 구성, 기존 가입 여부 등)을 언급하는 개인화 요소가 전사에 있다.
- **△**: 개인화로 볼 만한 요소가 있으나 "나를 위한 것"으로 느껴질 수준인지 판단할 근거가 부족하다.
- **X**: 모든 사용자에게 동일하게 보이는 일반 문구뿐이라는 근거가 전사에 있다.
- **좋은 예**: 이름·상황을 직접 언급한다(예: "가족보험 있으신 것으로 확인됐어요") — `BIAS_Framework_Master_Guide.md`의 Cocktail Party Effect 전술.
- **나쁜 예**: 어투는 친근하지만 이름·상황 언급 없이 모든 사용자에게 같은 문구가 뜬다.
- **흔한 오판**: 부드러운 말투를 자기 관련성으로 착각한다. "친절한 톤"과 "나를 위한 맥락"은 다르다 — 상황·속성이 실제로 언급되지 않으면 톤만으로는 O가 아니다.

### B3. 패턴 파괴 (Block)

- **판정 질문**: 배너 광고처럼 보여 시선이 무의식적으로 피해가는 영역이 있는가?
- **O**: 이탈시키는 배너·광고성 영역이 없다는 근거가 전사에 있다(요소 상태 `없음`).
- **△**: 배너성 요소가 있는지 판단할 근거가 부족하다.
- **X**: 광고성 배너·외부 링크가 본문 사이에 끼어 있다는 근거가 전사에 있다.
- **좋은 예**: 리포트·상담 화면에 다른 상품 배너나 외부 링크가 끼어들지 않아 본문에 집중된다(LP-S3·CO-F4 근거).
- **나쁜 예**: 리포트 중간에 다른 보험 상품 광고 배너가 삽입돼 있어 사용자가 광고로 인식하고 넘긴다(LP-S3·CO-F4 fail_signal 응용).
- **흔한 오판**: 디자인이 세련되면 배너 블라인드니스가 없다고 오판한다. 판단 기준은 디자인 품질이 아니라 "광고처럼 보이는 위치·형태"인지다.

### B4. 인지 부하 최소화 (Block)

- **판정 질문**: 이 화면에서 사용자가 지금 고를 수 있는 주요 선택지를 세어보면 5~6개 미만인가?
- **O**: 화면 내 주요 선택지를 실제로 센 결과가 5~6개 미만이라는 근거가 전사에 있다.
- **△**: 선택지 개수가 전사에 명시되지 않아 셀 수 없다.
- **X**: 주요 선택지가 5~6개 이상이라는 근거(전사에 나열된 개수)가 있다.
- **좋은 예**: 한 화면에 제시되는 보장·분석 항목이 소수로 제한돼 있다.
- **나쁜 예**: 한 화면에 10개 넘는 옵션이 한꺼번에 나열돼 무엇부터 봐야 할지 판단이 안 된다.
- **흔한 오판**: "복잡해 보인다"는 인상만으로 판정한다. 인지 부하는 인상이 아니라 화면 내 선택지 **개수를 실제로 세는** Fact로 판정해야 한다.

### I1. 익숙한 UX (Interpret)

- **판정 질문**: 클릭 가능한 요소가 별도 설명 없이도 눌러도 된다고 알아차려지는가(보편적 UI 패턴을 따르는가)?
- **O**: 버튼·링크가 보편적 시각 신호(둥근 모서리, 밑줄 등)로 클릭 가능함을 알린다는 근거가 있다.
- **△**: UI 패턴이 보편적인지 판단할 근거가 부족하다.
- **X**: 클릭 가능한 요소가 일반 텍스트와 구분되지 않는다는 근거가 있다.
- **좋은 예**: 버튼이 둥근 모서리·그림자 등으로 눌리는 요소임을 직관적으로 알 수 있다.
- **나쁜 예**: 텍스트 링크처럼 생긴 요소가 실제로는 버튼이라 클릭 가능한지 헷갈린다.
- **흔한 오판**: 새롭고 창의적인 UI를 "혁신적이라 좋다"며 O로 판정한다. 학습이 필요하면 Interpret 실패다 — 기준은 참신함이 아니라 익숙함이다.

### I2. 혜택 우선성 (Interpret)

- **판정 질문**: 기능 설명과 얻는 이득 중 어느 쪽이 더 크고 먼저 보이는가?
- **O**: 혜택 문구가 기능 설명보다 크고 먼저 보인다는 근거가 있다(LP-S7 근거: 핵심 혜택이 상단 명시).
- **△**: 혜택 문구는 있으나 기능 설명 대비 우선순위를 판단할 근거가 부족하다.
- **X**: 기능 설명만 있고 혜택 언급이 없다는 근거가 있다(LP-S7 fail_signal).
- **좋은 예**: 리포트 상단에 "맞춤 분석으로 보장 공백을 확인하세요" 같은 혜택이 기능 설명보다 먼저 보인다.
- **나쁜 예**: "AI 정밀분석 알고리즘 적용"처럼 기능 설명만 있고 고객이 얻는 이득은 안 보인다.
- **흔한 오판**: 혜택 문구가 하나라도 존재하면 O로 판정한다. 존재 여부가 아니라 "기능 설명보다 크고 명확하게" 보이는지가 기준이다.

### I3. 앵커링 (Interpret)

- **판정 질문**: 가격·가치를 판단할 비교 기준점(평균·이전 값 등)이 제시되는가?
- **O**: 비교 기준점이 제시된다는 근거가 있다(예: 업계 평균 대비 표기).
- **△**: 숫자는 있으나 비교 기준으로 쓰일 만한지 판단할 근거가 부족하다.
- **X**: 수치가 단독으로만 제시되고 비교 기준점이 없다는 근거가 있다.
- **좋은 예**: "업계 평균 대비 ○○% 저렴" 같은 비교 기준을 제시해 가치 판단을 돕는다.
- **나쁜 예**: 보험료가 단독으로만 제시되고 비교할 기준(평균가·이전 견적 등)이 전혀 없다.
- **흔한 오판**: 가격이나 숫자가 하나라도 보이면 앵커링이 있다고 오판한다. 비교할 기준점(전·후, 평균 대비 등)이 없으면 앵커링이 아니다.

### I4. 손실 회피 (Interpret)

- **판정 질문**: 지금 행동하지 않으면 잃게 되는 것이 문구로 시각화되어 있는가?
- **O**: "지금 안 하면 무엇을 잃는지"를 시각화한 문구가 있다는 근거가 있다.
- **△**: 손실 관련 문구가 있으나 시각화 수준을 판단할 근거가 부족하다.
- **X**: 혜택만 나열되고 지금 안 하면 무엇을 잃는지는 언급이 없다는 근거가 있다.
- **좋은 예**: "지금 점검하지 않으면 보장 공백이 방치됩니다" 같은 손실 프레이밍 문구가 있다(`BIAS_Framework_Master_Guide.md` Loss Aversion 전술).
- **나쁜 예**: 혜택만 나열되고 지금 안 하면 무엇을 잃는지는 언급이 없다.
- **흔한 오판**: 혜택 문구(I2)를 손실 회피(I4)로 착각한다. "얻는 것"을 강조하면 I2이고, "지금 안 하면 잃는 것"을 강조해야 I4다.

### A1. 마찰 제거 (Act)

- **판정 질문**: 목적 달성에 불필요한 입력 필드·클릭 단계가 있는가?
- **O**: 불필요한 입력·클릭이 없다는 근거가 있다(CO-F5·F6 근거: 한 번에 하나 질문, 최소 정보만).
- **△**: 입력 단계 수를 셀 만한 근거가 부족하다.
- **X**: 불필요한 입력·클릭 단계가 있다는 근거가 있다(CO-F5·F6 fail_signal).
- **좋은 예**: 한 메시지에서 질문 하나만 물어 응답 부담이 없다.
- **나쁜 예**: 한 번에 여러 항목을 동시에 나열해서 물어 응답 부담이 크다.
- **흔한 오판**: 필드 개수가 적어 보이는 화면 인상만으로 O로 판정한다. 실제 클릭·입력 단계 수를 세지 않고 인상만으로 판단하면 안 된다.

### A2. 스마트 기본값 (Act)

- **판정 질문**: 추천 옵션이 기본 선택된 상태로 제시되는가?
- **O**: 추천 옵션이 기본 선택돼 있다는 근거가 있다.
- **△**: 옵션은 있으나 기본 선택 여부를 판단할 근거가 부족하다.
- **X**: 모든 옵션이 비어 있는 상태로 시작한다는 근거가 있다.
- **좋은 예**: 추천 보장 옵션이 기본 선택 상태로 제시돼 고민 없이 진행할 수 있다.
- **나쁜 예**: 모든 옵션이 비어 있는 상태로 시작해 사용자가 하나하나 직접 선택해야 한다.
- **흔한 오판**: 옵션이 존재하기만 하면 O로 판정한다. 옵션의 존재가 아니라 **기본 선택**돼 있는지가 기준이다.

### A3. 사회적 증거 (Act)

- **판정 질문**: 다른 사용자의 행동(이용 수·후기 등)을 보여줘 확신을 주는 요소가 있는가?
- **O**: 이용자 수·후기 등 타인의 행동을 보여주는 요소가 있다는 근거가 있다(PP-P2·PP-P5 근거).
- **△**: 관련 요소가 있으나 확신을 주는 수준인지 판단할 근거가 부족하다.
- **X**: 타인의 행동을 보여주는 요소가 전혀 없다는 근거가 있다(PP-P5 fail_signal).
- **좋은 예**: "이번 달 ○○명이 점검신청했어요" 같은 이용 데이터가 표시된다(PP-P5 근거).
- **나쁜 예**: 이용자 수·후기 등 다른 사람의 행동을 보여주는 요소가 전혀 없다.
- **흔한 오판**: 브랜드 로고(수상·언론 노출)를 사회적 증거로 착각한다. 사회적 증거는 "다른 사용자의 행동"이지 브랜드 자체의 신뢰 요소(PP-P1)가 아니다.

### A4. 희소성/긴급성 (Act)

- **판정 질문**: 지금 당장 행동해야 할 구체적 명분(시간·수량 제한)이 있는가?
- **O**: 지금 행동해야 할 구체적 명분(마감·우선 배정 등)이 있다는 근거가 있다(CA-T2 근거).
- **△**: 긴급성 관련 문구는 있으나 구체성을 판단할 근거가 부족하다.
- **X**: 지금 행동해야 할 이유가 전혀 제시되지 않는다는 근거가 있다(CA-T2 fail_signal).
- **좋은 예**: "지금 답변하면 우선 배정" 같은 긴급성 문구가 있다(CA-T2 근거).
- **나쁜 예**: 지금 행동해야 할 이유(마감·한정 등)가 전혀 제시되지 않는다.
- **흔한 오판**: 일반적인 안내 문구를 긴급성으로 착각한다. 손실 회피(I4)는 "잃는 것"을 알리는 정보 단계이고, 희소성/긴급성(A4)은 구체적 시간·수량 제한으로 행동을 직접 유도하는 단계라는 점에서 다르다.

### S1. 즉각적 피드백 (Store)

- **판정 질문**: 행동 직후 시각/청각 피드백이 즉시 제공되는가?
- **O**: 행동 직후 즉시 피드백(팝업·메시지 등)이 온다는 근거가 있다(CO-F9·PP-C6 근거).
- **△**: 피드백이 있는지 판단할 근거가 부족하다.
- **X**: 행동 후 아무 반응이 없다는 근거가 있다(CO-F9·PP-C6 fail_signal).
- **좋은 예**: 잘못 입력하면 그 자리에서 바로 재입력 요청 메시지가 뜬다(CO-F9 근거).
- **나쁜 예**: 버튼을 눌러도 접수됐는지 알려주는 반응이 없어 다시 눌러야 하나 헷갈린다(PP-C6 fail_signal).
- **흔한 오판**: 결과 화면 자체가 있으면 피드백이 있다고 오판한다. 기준은 **즉시성**이다 — 로딩 후 다음 화면으로 자연히 넘어가는 것과, 행동 직후의 즉각적 시청각 반응은 다르다.

### S2. 안심 장치 (Store)

- **판정 질문**: 개인정보 보호·완료 메시지 등으로 불안을 해소하는 문구가 있는가?
- **O**: 안심시키는 문구(정보 보호, 취소 시 불이익 없음 등)가 있다는 근거가 있다(CA-T8 근거).
- **△**: 관련 문구가 있으나 안심 수준을 판단할 근거가 부족하다.
- **X**: 민감 정보를 요구하면서도 안심 문구가 전혀 없다는 근거가 있다(CA-T8 fail_signal).
- **좋은 예**: "입력한 정보는 상담 목적 외 사용되지 않습니다" 같은 안심 문구가 있다(CA-T8 근거).
- **나쁜 예**: 민감정보를 입력하라고 하면서 어떻게 보호되는지 안내가 전혀 없다(CA-T8 fail_signal).
- **흔한 오판**: 개인정보처리방침 링크가 있으면 O로 판정한다. 약관 링크와 화면에 노출된 안심 문구는 다르다 — 링크를 눌러야만 보이는 정보는 화면 자체의 안심 장치로 보지 않는다.

### S3. Delighter (Store)

- **판정 질문**: 예상 밖의 긍정적 마이크로 인터랙션이나 문구가 있는가?
- **O**: 예상 밖의 긍정 요소(축하 문구·감동 연출 등)가 있다는 근거가 있다.
- **△**: 완료 화면은 있으나 Delighter 요소 유무를 판단할 근거가 부족하다.
- **X**: 완료 화면이 사무적인 안내뿐이라는 근거가 있다.
- **좋은 예**: 접수 완료 시 "축하합니다, 곧 전문가가 연락드려요" 같은 예상 밖의 긍정 문구가 뜬다(`BIAS_Framework_Master_Guide.md` Peak-End Rule 전술).
- **나쁜 예**: 접수 완료 화면이 사무적인 텍스트 한 줄뿐이라 아무 감정도 남지 않는다.
- **흔한 오판**: 정상적으로 작동하면(에러가 없으면) Delighter가 있다고 오판한다. 에러가 없는 것은 기본 기능이지, 예상 밖의 긍정 요소가 아니다.
