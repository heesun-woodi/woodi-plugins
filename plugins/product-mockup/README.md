# product-mockup

플랫한 제품 디자인 파일 한 장으로, 실제 공간에 놓인 듯한 라이프스타일 목업 사진 세트를 만드는
Claude Code 플러그인입니다. 패키지, 인쇄물, 포스터, 책 표지, 라벨, 달력, 카드, 박스아트처럼
**인쇄면이 평면인 제품**이 대상입니다.

## 무엇을 하는가 — 하이브리드 전략

AI 이미지 모델이 **장면만** 그립니다. 조명, 소품, 카메라 앵글, 재질감, 그림자 — 사람이 손으로
만들기 가장 비싼 부분입니다. 그 위에 **원본 디자인 픽셀 자체를** 4점 원근 변환(homography)으로
제품 면에 얹고, 장면의 저주파 조명을 전사하고, 제본·스탠드 같은 디테일 밴드를 되살리고,
장면의 노이즈 플로어에 맞춰 그레인을 입힙니다. 결과적으로 연출은 AI가, 활자는 원본이 담당하는
합성 이미지가 나옵니다.

## 왜 AI 단독 생성으로는 안 되는가

이미지 모델은 작은 글자를 **그리는 게 아니라 흉내 냅니다.** 8pt 요일 헤더, 성분표, 가격, 전화
번호 같은 텍스트는 확대해보면 거의 항상 깨져 있거나, 더 나쁘게는 그럴듯하게 잘못된 값으로
채워져 있습니다. 프롬프트로 "정확하게 그려줘"라고 지시해도 고쳐지지 않습니다. 이건 프롬프트
품질 문제가 아니라 모델의 구조적 한계라, 세 번째 프롬프트 라운드는 돈과 시간만 씁니다.

상세페이지에 올라갈 이미지에서 잘못된 전화번호나 깨진 날짜 숫자는 그냥 결함이 아니라 **사고**
입니다. 그래서 이 플러그인은 프롬프트를 더 잘 쓰려고 하는 대신, 텍스트 재현을 아예 이미지
모델에게 맡기지 않습니다.

## 사전 요구사항

### 1. Gemini API 키
https://aistudio.google.com/apikey 에서 발급받아 작업 폴더의 `.env`에 넣습니다.

```
GEMINI_API_KEY=your_key_here
```

`.env`는 커밋하지 마세요. 8장면 기준 API 비용은 약 $1입니다.

### 2. Python 패키지 4종
작업 폴더 안에서:

```bash
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install google-genai opencv-python-headless numpy pillow
```

| 패키지 | 용도 |
|---|---|
| `google-genai` | Gemini 3 Pro Image 호출 (장면 생성) |
| `opencv-python-headless` | 원근 변환, 조명 전사, 엣지 피팅 |
| `numpy` | 픽셀 연산 전반 |
| `pillow` | 이미지 입출력 / 리사이즈 |

### 3. 준비물 (파일 2개)
- **제품 디자인 고해상도 원본** — 인쇄용 PDF를 내보낸 PNG 등. 최종 이미지 품질의 상한선입니다.
- **제품 실물 참조 사진 1장** — 제본, 스탠드, 힌지, 재질처럼 디자인 파일만으로는 AI가 추측할
  수 없는 물리적 디테일이 보이는 사진.

## 설치와 첫 사용

> 처음이라면 **[사용 가이드](https://claude.ai/code/artifact/8fd1d591-3d8e-43a9-862e-b9a8bf7564eb)**
> 를 먼저 보세요. 설치부터 첫 결과물까지 한 사이클을 따라가면서, 각 단계에서 무엇을 판단해야
> 하는지와 판정 결과를 어떻게 읽는지 설명합니다.

```
/plugin marketplace add heesun-woodi/woodi-plugins
/plugin install product-mockup@woodi-plugins
/reload-plugins
```

그다음 작업할 폴더에서:

```
/product-mockup
```

커맨드가 시작 키트(스크립트 5종, 예시 설정 파일, 빈 `source/` `scenes/` `final/` 폴더,
README, 응용 과제)를 현재 폴더에 복사하고 다음 단계를 안내합니다. 이후 진행은 복사된
`README.md`의 6단계를 따라가면 됩니다.

## 파이프라인 (6단계)

| 단계 | 하는 일 | 산출물 |
|---|---|---|
| 1 | 원본 디자인 정리, 인쇄면 네 꼭짓점 좌표 기록 | `source/design_full.png` |
| 2 | 6단계 구조로 장면 프롬프트 설계 | `prompts.json` |
| 3 | 장면 생성 (병렬, 장당 약 30초) | `scenes/*.png` |
| 4 | 확대 검수 → PASS / COMPOSITE / REGEN / FAIL 판정 | 판정표 |
| 5 | 재생성 또는 원본 합성 | `final/` + `_evidence/` |
| 6 | 배치 가이드 작성 | 배치 가이드 문서 |

첫 라운드에서 PASS가 하나도 안 나오는 게 정상입니다. 대부분의 장면은 5단계 합성을 거칩니다.

## 구성 요소

**스킬 1개** — `product-mockup`
전체 파이프라인, 프롬프트 패턴 카탈로그, 검수 체크리스트, 오케스트레이션 규칙. 관련 작업을
시작하면 자동으로 트리거됩니다.

**에이전트 4개**

| 에이전트 | 역할 |
|---|---|
| `mockup-scene-designer` | 장면 프롬프트 설계 (연출·조명 판단) |
| `mockup-verifier` | 생성 결과 검수 (읽기 전용) |
| `mockup-compositor` | 원근 변환 합성 (가장 기술적으로 어려운 단계) |
| `mockup-reviewer` | 최종 커머스 관점 리뷰 (읽기 전용) |

생성하는 에이전트와 판정하는 에이전트를 **의도적으로 분리**했습니다. 방금 자기가 만든 이미지를
스스로 검수하면 통과시킵니다. 검수 에이전트를 읽기 전용으로 선언한 것도 같은 이유입니다.

**커맨드 1개** — `/product-mockup`
현재 폴더에 시작 키트를 스캐폴딩하고 첫 단계를 안내합니다.

## 한계

- **평면 인쇄면 전제**: 4점 원근 변환은 평면 하나를 다른 평면으로 옮기는 연산입니다. 곡면(튜브,
  병)이나 주름진 패브릭은 이 방식의 명시적 한계 밖입니다. 꺾이는 제품(탁상 달력의 이젤 힌지,
  박스의 두 번째 면)은 면을 나눠 각각 합성하면 처리됩니다.
- **가림물은 수동 작업**: 제품 앞을 가리는 물체가 있는 장면은 폴리곤과 임계값을 직접 잡아야
  합니다. `probe_occluder.py`가 픽셀 분포를 재서 값을 제안해줍니다.
- **좌표는 장면마다 다시 측정**: 예시 설정의 좌표값은 참고용입니다. 그대로 쓰면 어긋납니다.
