# 응용 과제 — 내 제품으로 처음부터 끝까지

## 과제 목표

`README.md`의 6단계 워크플로우를, **본인이 고른 제품**으로 처음부터 끝까지 스스로 수행하세요.
`scripts/scenes.example.json`의 설정값은 벽에 거는 평평한 인쇄물 기준입니다. 다른 제품에
그대로 복사하면 대부분 어긋납니다 — 그 어긋나는 지점을 스스로 찾아내는 것이 이 과제의
핵심입니다.

## 과제 고르기

아래 중 하나를 고르거나, 본인이 실제로 다루는 제품을 쓰세요. 괄호 안은 그 제품이 특별히
어려워지는 지점입니다.

| 과제 | 어려워지는 지점 |
|---|---|
| **탁상용 달력** | 이젤 스탠드 때문에 인쇄면이 하나의 평면이 아님 + 내려다보는 시점 |
| **화장품 박스 / 튜브** | 곡면(튜브)이거나 두 면이 동시에 보임(박스) — 평면 가정이 정면으로 깨짐 |
| **책 / 노트 표지** | 펼쳐진 상태의 책등 곡률, 손에 들린 컷에서의 가림 처리 |
| **음료 / 와인 라벨** | 원통 곡면 + 유리의 반사·굴절, 라벨 가장자리에서 급격한 왜곡 |
| **포스터 / 엽서 세트** | 평면은 쉽지만 여러 장이 겹쳐 놓인 배치에서 가림물 처리가 핵심 |
| **패브릭 / 파우치 프린트** | 주름 때문에 4점 변환만으로는 부족한, 이 키트의 한계 지점 |

**처음이라면 탁상용 달력을 권합니다.** 평면 가정이 깨지긴 하지만 깨지는 지점이 명확해서
(접히는 힌지 하나) 무엇을 다르게 해야 하는지 배우기 좋습니다. 곡면 제품(튜브, 병)은 4점
원근 변환의 명시적 한계 밖이라, 어디까지 되고 어디부터 안 되는지를 확인하는 성격의 과제입니다.

## 소재 준비

이 과제는 **인쇄 원본 1장**과 **실물 참조 사진 1장**을 전제합니다(`README.md`의 "준비물" 참고).
`source/` 폴더는 비어 있으니 직접 채워야 합니다.

본인 제품이 없다면 아래로 대체하세요. 과제의 목적은 파이프라인을 돌려보는 것이지 실제 제품을
갖는 게 아닙니다.

- **인쇄 원본 대체** — 고른 제품의 "template"(예: "desk calendar template", "탁상달력 템플릿",
  "cosmetic box dieline")으로 검색해 무료 배포되는 PDF/AI 템플릿을 받아 고해상도 PNG로
  내보내세요. Canva·Vecteezy·Freepik 등의 무료 템플릿이면 충분합니다. **작은 글자가 또렷하게
  들어간 것**을 고르세요 — 이 키트가 증명하려는 게 바로 그 작은 글자의 보존이라, 큰 그림만
  있는 템플릿은 학습 효과가 없습니다. 직접 만들어도 됩니다(예: 스프레드시트로 날짜 그리드를
  짜서 PDF로 출력, 워드로 성분표·주의사항 문구를 넣은 라벨 만들기).
- **실물 참조 사진 대체** — AI가 추측 못 하는 물리적 구조가 보이면 됩니다. 집에 있는 비슷한
  물건을 직접 찍어도 되고, 쇼핑몰 상세 이미지를 써도 됩니다. 탁상 달력이면 **접히는 지점과
  세워지는 각도**, 박스면 **모서리 접힘과 마감**, 병이면 **라벨이 곡면을 감는 방식**이
  보여야 합니다.

받은 템플릿의 라이선스(재배포/상업적 이용 조건)는 확인하고 쓰세요. 과제 결과물을 외부에
공개할 계획이라면 특히요.

## 생각해볼 것 (힌트, 정답은 아님)

바로 답을 찾기보다, 아래 질문들을 스스로 던져보면서 프롬프트/합성 설정을 조정해보세요.

- **평면 가정은 언제 깨지나요?** 이 키트의 합성은 "제품 인쇄면 전체가 하나의 평면"이라는
  전제 위에 서 있습니다 — 4점 원근 변환은 평면 하나를 다른 평면으로 옮기는 연산이기
  때문입니다. 고른 제품을 실제로 놓고 여러 각도에서 보면서, 이 전제가 어디서부터 성립하지
  않는지 확인해보세요. (탁상 달력이면 이젤 힌지, 박스면 두 번째 면, 병이면 라벨 양 끝.)
  전제가 깨지는 장면에서 `quad`를 그대로 쓰면 결과가 어떻게 어긋날지, 그리고 무엇을 다르게
  해야 할지 스스로 정해보세요. **면을 나눠서 각각 합성하는 것**도 방법입니다.
- **카메라 시점이 달라집니다.** 벽에 걸리는 물건은 눈높이 정면으로, 책상 위 물건은 앉아서
  내려다보는 각도로, 손에 드는 물건은 더 가깝고 기울어진 각도로 찍힙니다. 제품이 실제로
  쓰이는 상황의 시점이 무엇인지 정하고, 프롬프트의 "카메라/조명" 절(6단계 프롬프트 구조 중
  5번째)을 거기에 맞추세요.
- **주변 소품의 스케일이 완전히 다릅니다.** 벽걸이 인쇄물 옆에는 소파·창문·가구가 있지만,
  책상 위 제품 옆에는 머그컵·펜·노트가, 욕실 제품 옆에는 수건·칫솔이 놓입니다. 소품 스케일이
  안 맞으면 무엇이 이상해 보일지, 그리고 review-checklist의 "이커머스 적합성" 체크가 이
  경우 왜 더 까다로워지는지 생각해보세요.
- **작은 제품은 화면에서 묻히기 쉽습니다.** 넓은 공간 안에서 작은 제품은 화면 면적을 적게
  차지합니다. "제품이 주인공이어야 한다"는 원칙을 지키려면 프롬프트의 배치/카메라 절을 어떻게
  조정해야 할까요? 크롭이나 클로즈업 변형을 추가로 넣는 것도 방법일 수 있습니다.

## 진행 방법

`README.md`의 6단계를 그대로 따라가되, 위 힌트를 반영해서 프롬프트와 `scenes.json` 설정을
직접 조정하세요. 막히면 스킬 레퍼런스를 먼저 찾아보고, 그래도 안 풀리면 어느 단계에서
막혔는지, 무엇을 시도했는지 기록해두세요.

**2단계에서 변형 축을 하나 바꾸세요.** 예시 프로젝트는 4장면 x (정면 / 측면) = 8장이었는데,
이번에는 4장면 x (**전체 연출 / 클로즈업 디테일**)로 잡으세요. 클로즈업 변형은 힌지·접힘부·
제본·마감 같은 물리적 구조가 프레임을 채우는 컷으로, 상세페이지에서 실제로 필요한 산출물이면서
동시에 "평면 가정이 어디서 깨지는지"가 가장 잘 드러나는 앵글입니다. 아래 자가 채점 9번이 이
변형을 요구합니다.

**막혔을 때 참고할 곳**: product-mockup 스킬의 레퍼런스 — 특히 prompt-patterns(프롬프트
구조/보강 카탈로그)와 review-checklist(판정 기준). Claude에게 열어달라고 하면 됩니다.

## 자가 채점 체크리스트

완성된 최종 이미지 세트를 아래 항목으로 스스로 점검하세요. 모두 통과해야 "완료"입니다.

1. [ ] 최소 4개 이상의 서로 다른 공간/배치 장면이 있는가 (동일 장면의 각도 변형만 있는 게
       아니라)
2. [ ] 모든 최종 이미지에서 인쇄면의 글자(숫자, 라벨 문구, 로고 등)가 원본과 완전히
       일치하는가 — `final/_evidence/`의 확대 크롭으로 확인
3. [ ] 4점 원근 변환이 제품의 실제 형태와 자연스럽게 맞는가 (특히 면이 꺾이거나 휘는
       지점에서 어색하게 끊기지 않는가)
4. [ ] 카메라 시점이 제품이 실제로 쓰이는 상황과 맞는가 (예시 프로젝트의 앵글을 그대로
       재사용하지 않았는가)
5. [ ] 조명 방향/색온도가 장면 배경과 합성된 제품 면 사이에서 어긋나지 않는가
6. [ ] 그림자(제품이 바닥/벽에 드리우는 접촉 그림자)가 있고 방향이 조명과 일치하는가
7. [ ] 주변 소품의 크기가 제품과 비례적으로 맞는가
8. [ ] 제품이 화면에서 시각적 주인공으로 보이는가 (배경 소품에 묻히지 않는가)
9. [ ] 최소 1장은 상세페이지용 클로즈업/디테일 컷(제본·힌지·마감 등 물리적 구조가
       보이는 샷)이 포함되어 있는가 — 2단계에서 변형 축을 "전체 연출 / 클로즈업 디테일"로
       잡았다면 자연히 충족됩니다
10. [ ] REGEN으로 판정된 장면에서 사용한 보강 문장이 "구체적 내용/개수/메커니즘을
        명시"하는 패턴을 따르는가 (막연한 "더 정확하게 해줘" 식이 아닌가)
11. [ ] 2라운드 안에 구조적 결함이 해결되지 않은 장면은 discard하고 다른 장면으로
        대체했는가 (cutoff rule 준수)
12. [ ] `final/` 산출물에 6단계에서 요구한 배치 가이드(용도별 정리 + 알려진 한계점)가
        함께 있는가

## 심화 과제

같은 제품으로 **계절 또는 조명이 다른 변형 세트**를 만들어보세요. 예: 같은 배치/각도를 유지한
채 "낮 자연광" 버전과 "저녁 무드등" 버전을 각각 만들고, 조명 변화가 합성 파라미터
(`light_sigma_frac`, `light_clip`, `grain`)에 어떤 영향을 주는지 비교해보세요. 동일한 `quad`를
재사용할 수 있는지, 아니면 장면마다 다시 측정해야 하는지도 확인해보세요.
