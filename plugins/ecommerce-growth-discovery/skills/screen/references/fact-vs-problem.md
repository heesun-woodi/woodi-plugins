# Fact와 문제를 가르는 규칙

`/ecommerce-growth-discovery:screen` STEP1(Fact 전사)과 STEP3(고객 문제 문장)에서 쓴다.
여기 실린 우리 몰 맥락 예시는 전부 **가상 예시**이며 실제 화면 확인 결과가 아니다.

---

## 1. 판별 테스트는 하나뿐이다

> **"이 문장에서 솔루션이 자동으로 따라 나오는가?"**
> 나오면 아직 **현상(Fact)**이다.

| | ✗ 현상 | ✓ 문제 |
|---|---|---|
| 문장 | "상품상세에서 장바구니로 안 넘어간다" | "고객은 이 상품상세에서 내가 쓸 곳에 맞는 사이즈가 어느 것인지 판단하지 못해, 고르지 못한 채 화면을 닫는다" |
| 왜 | "이탈률을 낮추자"는 구호만 남는다 | "무엇을 못 하는지"가 있으니 다음 단계에서 손댈 곳이 정해진다 |

현상을 버리는 게 아니다. **현상은 근거로 쓴다.** STEP1에는 Fact만, STEP3에는 Problem만
쓰고 두 층을 섞지 않는다.

| 층 | 정의 | 쓰는 자리 |
|---|---|---|
| **Fact 층** | 화면에서 관측된, 다시 볼 수 있는 사실 | STEP1 전사 |
| **Problem 층** | 그 Fact가 고객에게 만들어내는 경험 | STEP3 문제 문장 |

---

## 2. "그래서 고객이 무엇을 못 하나" 테스트

현상을 썼을 때 되묻는 질문은 하나다.

> **"그래서 고객이 무엇을 못 하고 있나요?"**

그 답이 문제다. 답이 안 나오면 아직 근거가 부족한 것이지, 문장을 더 세게 쓸 일이 아니다.

- 현상 ✗ "사이즈 실측표가 없다" → 솔루션("표를 넣자")이 바로 나온다
- 문제 ✓ "고객은 이 화면에서 내가 쓸 곳에 이 사이즈가 맞는지 확인하지 못해,
  실패할까 봐 담기를 미룬다"

한 쌍 더 (가상 예시):

- 현상 ✗ "후기 사진이 없다"
- 문제 ✓ "고객은 사진으로 색·두께를 확인하지 못해, 화면 색과 실물이 다를까 봐
  결정을 미룬다"

세 번째 (광고 랜딩, 가상 예시):

- 현상 ✗ "광고 문구와 랜딩 첫 줄이 다르다"
- 문제 ✓ "광고에서 본 할인을 기대하고 들어온 고객은 첫 화면에서 그 할인을 찾지 못해,
  잘못 들어왔다고 느끼고 바로 나간다"

---

## 3. 문장 형식 (고정)

```
고객은 이 [화면/상황]에서 [무엇]을 [못 한다 / 모른다 / 느낀다]
```

길게 쓸 때 순서: **왜 이 화면에 왔나 → 무엇을 겪었나 → 어디서 막혔나 → 그래서 무엇을 하나**

---

## 4. 규칙 3가지

| # | 규칙 | 설명 |
|---|---|---|
| 1 | **주어는 사람(고객)이다** | 화면·버튼·지표가 주어면 그건 Fact지 문제가 아니다. "장바구니 버튼이 작다" ✗ → "고객은 이 상품상세에서 옵션을 고른 뒤 무엇을 해야 담기는지 몰라, 화면을 위아래로 오가다 그대로 나간다" ✓ |
| 2 | **솔루션 역기술 금지** | "버튼을 키워야 한다" ✗. 솔루션을 뒤집어 문제처럼 쓴 "○○가 없다" ✗ 도 같다 |
| 3 | **근거 없는 추측 금지** | 전사에 없는 감정·수치·발화를 지어내지 않는다. 모든 문장에 Fact ID와 체크리스트 ID를 단다 |

### 솔루션이 자동으로 나오는 문장 — 금지 예시

| ✗ 이렇게 쓰면 안 된다 | 왜 |
|---|---|
| "장바구니 버튼을 키워야 한다" | 솔루션 그 자체 |
| "사이즈표를 옵션 위로 올리자" | 솔루션 그 자체 |
| "후기 사진이 없다" | "사진을 넣자"가 바로 나온다 |
| "상세 이미지가 너무 길다" | "줄이자"가 바로 나온다 |
| "옵션 이름을 알아보기 쉽게 바꿔야 한다" | 솔루션 그 자체 |
| "간편결제를 붙여야 한다" | 솔루션 그 자체 |

고쳐 쓰는 법은 항상 같다 — **"그래서 고객이 무엇을 못 하나?"**를 한 번 더 내려간다.

## 5. 공급자 언어 → 고객 언어

| ✗ 공급자 시선 | ✓ 고객 시선 |
|---|---|
| "CTA 버튼이 작다" | "고객은 이 첫 화면에서 지금 눌러야 할 것이 여러 개 중 어느 것인지 몰라, 고르지 못한 채 화면을 닫는다" |
| "전환율이 낮다" | "고객은 가격을 알 수 없어 살지 말지 판단을 못 한다" |
| "상세페이지 체류가 짧다" | "고객은 첫 화면에서 무엇을 파는지 알지 못해 그대로 나간다" |
| "클릭은 많은데 구매가 적다" | "광고에서 본 것을 랜딩에서 다시 찾지 못해 고객은 잘못 왔다고 느낀다" |

## 6. "안 했다" vs "못 했다"

전환이 낮은 이유를 **"안 했다"로 단정하지 않는다.**

| 상황 | 기록 | 의미 |
|---|---|---|
| 요소가 화면에 **있는데** 안 눌렀다 | `누르지 않았다` | 최적화 문제 — 개선 여지가 제한적 |
| 요소가 화면에 **아예 없다 / 비활성 / 가려짐** | `누를 수 없었다` | **부재 문제** — 개선 여지가 훨씬 크다 |
| 해당 없음 | `-` | |

---

## 7. "무엇이 없는가"도 Fact다

STEP1의 핵심은 무엇이 있는지가 아니라 **무엇이 없는지**를 보는 것이다.

- 없으면 `없음`으로 명시한다. "옵션 아래 사이즈 실측표 없음".
- "약하다"와 "없다"는 완전히 다른 문제다. 있는지 없는지를 먼저 확정한다.
- 단, **판독이 안 되는 것**(`❓`)과 **없는 것**(`없음`)은 다르다. 확대해도 안 읽히면
  `❓(판독 불확실)`이지 `없음`이 아니다.

---

## 8. 자가 테스트 3문항

문장을 내놓기 전에 스스로 돌린다.

1. 이 문장에서 솔루션이 자동으로 나오는가? → 나오면 아직 현상이다.
2. 그래서 고객이 무엇을 못 하고 있나? → 이 답이 실제 문제다.
3. 이 문장에 근거 ID가 붙어 있는가? → 없으면 추측이다. 지우거나 근거를 먼저 확보한다.
