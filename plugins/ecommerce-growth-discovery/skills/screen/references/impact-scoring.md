# Impact 점수 — 산식 · 값을 어디서 가져오나 · 계산 과정 노출

`/ecommerce-growth-discovery:screen` STEP4에서 쓴다.

---

## 1. 산식

```
Impact = (트래픽 영향 + 벤치마크 Gap + 정성 심각도) ÷ 3        (각 10점 만점)

정성 심각도 = MIN(10, 원점수 + (Block 실패면 +2) + (Interpret 실패면 +1))
```

Impact는 **소수 1자리**로 반올림한다.

**분모는 값이 채워진 항목 수다.** 세 항목이 다 있으면 `÷ 3`, 둘만 있으면 `÷ 2`,
하나만 있으면 그 값 자체다. `—`인 칸은 0으로 세지 않고 분모에서 뺀다(§2 참조).

| 차원 | 묻는 것 | 10점 기준 | 값의 출처 |
|---|---|---|---|
| **트래픽 영향** | 이 문제를 겪는 고객이 얼마나 많은가 | 해당 구간을 지나는 고객 거의 전부가 겪음 | `explore-findings.md` `## D`의 **세션 기준 표** / `## E` 채널 표 아래 **`Paid 소계` 행** |
| **벤치마크 Gap** | 지금 값이 벤치마크 대비 **몇 배** 낮은가 (%p 아님) | 벤치마크 대비 5배 이상 낮음 | `## D` 세션 기준 표의 **벤치마크 열** / `## E` 표 아래 **벤치마크 한 줄** |
| **정성 심각도** | 체크리스트 Fail율 + BIAS 판정이 얼마나 나쁜가 | Fail율 80%+ 이고 Block에 X 다수 | **이 스킬이 이번 판정 결과로 계산** |

## 2. 트래픽 영향 · 벤치마크 Gap을 정하는 규칙

**`explore-findings{-label}.md`(cwd → `config.output.dir` 순으로 찾는다, rules.md §10)를 읽어 §D·§E에 실제로 적혀 있는 값만 쓴다.**

### 트래픽 영향

**눈금의 출처는 세션이다.** 아래 두 곳만 본다.

- **상품상세 모드** → `## D. 퍼널`의 **세션 기준 표**(장바구니 담기율 / 결제 시작율 /
  구매 전환율). 이 문제가 걸린 단계의 값을 인용하고, 그 단계를 통과하지 못하는 세션의
  비중으로 눈금을 읽는다.
  같은 §D의 **퍼널 표(사용자 기준)** 도달률·이탈 사용자 수는 **보조 표기**로만 인용한다.
  분모가 다르므로 눈금에도, 벤치마크 비교에도 쓰지 않는다.
- **광고랜딩 모드** → `## E. 채널×전환율` 채널 표 **아래 `Paid 소계` 행**의
  **Paid 세션 · 세션 비중**을 본다. 세션 비중이 클수록 높다.
  `Paid 소계` 행이 없으면 트래픽 칸은 `—`다. **개별 채널 행을 직접 합산하지 않는다.**
- 눈금 (기계적으로 적용하지 말고 인용한 값과 함께 판단한다):

| 이 문제를 겪는 세션 규모 (§D 세션 기준 표 / §E `Paid 소계` 세션 비중) | 점수 |
|---|---|
| 전체 세션의 절반 이상 | 9~10 |
| 전체 세션의 20~50% | 7~8 |
| 전체 세션의 5~20% | 4~6 |
| 전체 세션의 5% 미만 | 1~3 |

### 벤치마크 Gap

- **배수**로 계산한다. `Gap 배수 = 벤치마크 값 ÷ 우리 값`.
- **상품상세 모드** → §D **세션 기준 표**의 `장바구니 담기율` 행. 우리 값과 벤치마크가
  같은 행에 있다.
- **광고랜딩 모드** → 우리 값은 §E 채널 표 **아래 `Paid 소계` 행의 `Paid 전환율`**,
  벤치마크는 §E **표 아래 벤치마크 한 줄의 `Paid Social` 전환율**이다.
  (§E 채널 표에는 벤치마크 열이 없다 — 표 안에서 찾지 않는다.)
  둘 중 하나라도 없으면 Gap은 `—`다.

| Gap 배수 | 점수 |
|---|---|
| 5배 이상 낮음 | 9~10 |
| 3~5배 낮음 | 7~8 |
| 1.5~3배 낮음 | 4~6 |
| 벤치마크 수준 이상 | 1~3 |

### 값이 없을 때 — 공란 규칙과 분모

`—`인 칸은 **0으로 세지 않는다. 분모에서 뺀다.** 분모 = 값이 채워진 항목 수다.

| 상황 | 채워지는 칸 | 분모 | 표기 |
|---|---|---|---|
| 세 칸 모두 있다 | 트래픽 · Gap · 심각도 | ÷ 3 | (없음) |
| `explore-findings.md` **파일이 없다** | 심각도만 | ÷ 1 | `(심각도만)` |
| 파일은 있는데 §D·§E가 비어 있다 | 심각도만 | ÷ 1 | `(심각도만)` |
| 벤치마크가 `—`다 (§D 벤치마크 열 / §E 벤치마크 한 줄이 없다) | 트래픽 · 심각도 | **÷ 2** | `(2항목 평균)` |
| §D·§E에 트래픽 값이 없고 벤치마크만 있다 | Gap · 심각도 | **÷ 2** | `(2항목 평균)` |
| **판정 가능 항목이 0이라 심각도도 못 낸다**(`Fail + Pass = 0`) | 없음 | — | **Impact를 계산하지 않는다** |

예: 트래픽 8 · Gap `—` · 심각도 6 → `(8 + 6) ÷ 2 = 7.0 (2항목 평균)`.
Impact 표의 해당 행 끝에 이 괄호 표기를 그대로 남긴다.

정성 심각도만으로 계산할 때는 **Impact = 정성 심각도** 그대로 쓰고, 표 아래에 반드시
이 한 줄을 붙인다.

> "트래픽·벤치마크 값이 없어 정성 심각도만으로 계산했습니다 — 문제들 사이 순서를
> 비교하는 용도로만 봅니다."

**분모가 0이 되는 경우 — Impact를 내지 않는다.** 화면 근거가 없어 판정 가능 항목이
0이면(`Fail + Pass = 0`) Fail율도 정성 심각도도 계산할 수 없다. 세 칸을 전부 `—`로 두고
Impact 표 대신 이 한 줄을 낸다.

> "화면 근거가 없어 판정할 수 있는 항목이 없습니다. Impact는 계산하지 않겠습니다.
> 모바일 스크린샷 3~5장(PNG/JPG)을 올려 주시면 이어서 보겠습니다."

이때 STEP3의 문제 문장은 텍스트 Fact 기준으로 내되 순위를 매기지 않고, 사용자가 고른
1개를 그대로 `problems{-label}.md`에 저장한다(`Impact:` 칸에는 `— (판정 가능 항목 0)`).

**없는 값을 만들지 않는다.** 업계 평균·추정치·상식으로 칸을 채우지 않는다. 사용자가
"대충이라도 넣어 달라"고 해도 넣지 않는다.

## 3. 정성 심각도 원점수 정하는 법

이번 STEP2 결과 두 가지를 조합해 1~10 원점수를 정하고, **근거 한 줄을 반드시 붙인다.**

1. **체크리스트 Fail율** = Fail ÷ (Fail + Pass) — `N/A`와 `미판정`은 분모에서 뺀다.
   `Fail + Pass = 0`이면 Fail율은 `—`이고 원점수를 매기지 않는다(§2 마지막 규칙).
2. **BIAS 판정** — 어느 단계에 `X`가 몇 개 몰려 있는가.

| Fail율 | BIAS 상태 | 원점수 대략 |
|---|---|---|
| 80%+ | Block 또는 Act에 X 다수 | 9~10 |
| 60~80% | X가 한 단계에 몰림 | 7~8 |
| 40~60% | X 산발 | 5~6 |
| ~40% | X 소수, 대부분 △ | 3~4 |

근거는 **세어서 확인할 수 있는 값**으로 쓴다.

(아래는 **가상 예시**다.)

- ✗ "심각도 8"
- ✓ "원점수 6 (체크리스트 Fail 9/16 = 56%, BIAS Block X 2건 B1·B4) + Block 가중 2 = 8"

---

## 4. BIAS 가중

| 실패한 단계 | 가중 |
|---|---|
| **Block 실패 포함** | **+2** |
| **Interpret 실패 포함** | **+1** |
| Act 실패 | 0 |
| Store 실패 | 0 |

**상한 10.** Block과 Interpret이 둘 다 실패면 +3까지 붙지만 10을 넘지 않는다.
근거는 `bias-27.md` §2 — Block에서 걸린 고객은 그 뒤 단계를 아예 경험하지 못한다.

## 5. 계산 과정을 숨기지 않는다

Impact 표를 내기 **전에** 문제마다 이 표를 먼저 낸다.
아래 숫자와 근거 문구는 형식을 보여주는 **가상 예시**이며 우리 몰의 실제 값이 아니다.

| # | 트래픽 | Gap | 심각도 원점수 | 가중 적용 | 심각도(가중) | Impact |
|---|---|---|---|---|---|---|
| 1 | 8 | 9 | 6 | Block 실패 +2 | 8 | 8.3 |
| 2 | 6 | — | 5 | Interpret 실패 +1 | 6 | 6.0 (2항목 평균) |
| 3 | — | — | 5 | Act 실패 0 | 5 | 5.0 (심각도만) |

각 점수 아래에 근거 한 줄을 함께 적는다.

```
① 트래픽 8 — §D 세션 기준 표: 장바구니 담기율 (값 인용) → 담지 못하고 끝나는 세션 비중
   (보조: §D 퍼널 표 사용자 기준 이탈 (값 인용) — 분모가 달라 비교에는 쓰지 않음)
② Gap 9 — §D 세션 기준 표: 장바구니 담기율이 벤치마크 대비 (배수) 낮음
③ 심각도 8 — 원점수 6(Fail 9/16 = 56%, Block X 2건 B1·B4) + Block 가중 2
→ (8 + 9 + 8) ÷ 3 = 8.3
```

**근거 칸이 비면 그 점수는 무효다.** 점수와 Impact를 `—`로 두고 근거 칸에
`값 없음`이라고 쓴다.

---

## 6. 점수가 몰리면 의심한다

모든 문제가 8~9점으로 나오면 근거 없이 감으로 채점된 것이다. **근거 칸을 먼저 채우고
점수는 그다음에 확정한다.** Impact는 같은 화면 안의 문제들 순서를 만드는 **상대 평가**이지
절대 점수가 아니다.

사용자가 점수나 근거에 이견을 내면(예: "이건 Block이 아니라 Interpret 문제 같은데요")
그 자리에서 값을 바꿔 다시 계산하고 표를 다시 낸다.

---

## 7. 여기서 하지 않는 것

- **ICE는 계산하지 않는다.** ICE는 다음 단계(`/ecommerce-growth-discovery:psr`)의
  몫이고, 여기서 나온 Impact는
  그 ICE의 **I 근거값**일 뿐이다.
- 솔루션·가설을 점수에 섞지 않는다.
