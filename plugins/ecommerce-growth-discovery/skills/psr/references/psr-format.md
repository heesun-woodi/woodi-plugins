# PSR 작성 규칙 — /ecommerce-growth-discovery:psr 2단계에서 읽는다

가설 하나 = **P(고객 문제) + S(무엇을 + 왜) + R(Metric · Baseline · Target · 기간)**.
셋 중 어려운 건 **R**이다. R이 없으면 실행한 뒤에도 됐는지 안 됐는지 판단할 기준이 없다.

> 이 문서의 모든 숫자는 **가상값**이다. 우리 몰의 실제 값이 아니다.

---

## 1. P — 고객 문제

- `/ecommerce-growth-discovery:screen`에서 확정한 문장을 **그대로** 쓴다. 다시 캐묻지 않는다.
- 주어는 **고객**이고 서술어는 "~못 한다 / ~모른다 / ~느낀다"다.
- 주어가 지표(전환율·이탈률)나 "우리"면 한 번만 되돌린다.
- 문장에서 솔루션이 자동으로 따라 나오면 그건 문제가 아니라 솔루션을 거꾸로 쓴 것이다.

| | 예시 (가상) |
|---|---|
| ❌ | "상품상세 전환율이 낮다" — 주어가 지표다 |
| ❌ | "상세페이지에 리뷰를 위로 올려야 한다" — 솔루션이다 |
| ✅ | "광고를 보고 들어온 고객이 첫 화면에서 이 이불이 광고에서 본 그 제품인지 확인하지 못한다" |

## 2. S — 무엇을 + 왜 될 것 같은가

두 줄이다.

- **무엇을**: 1단계 표의 `솔루션` + `어디를 바꾸나`를 합친다. 화면·지면까지 나와야 한다.
- **왜**: 사용자에게 먼저 묻는다("왜 이게 먹힐 것 같으세요?"). 답을 받은 뒤에 전술 원리 한 줄을 붙인다.
  근거가 없어도 진행한다 — Solution은 가설이지 확정이 아니다. 근거의 품질은 3단계 C 점수에서 다뤄진다.

| | 예시 (가상) |
|---|---|
| ❌ | "상세페이지를 개선한다" — 어디를, 무엇을 바꾸는지 없다 |
| ✅ | "무엇을: 광고 소재의 카피를 상품상세 첫 화면 헤드라인에 그대로 반복한다 / 왜: 광고에서 본 문구를 다시 보면 잘못 들어온 게 아니라고 인식한다(칵테일 파티 효과)" |

## 3. R — Metric · Baseline · Target · 기간

**한꺼번에 묻지 않는다. 순서대로 하나씩 확정한다.**

### 3-1. Metric — 선행지표 우선

`explore-findings.md`에 **이미 나온 숫자** 중에서만 고른다. **새 지표를 만들지 않는다.**
지금 처음 보는 지표는 나중에 아무도 다시 재지 않는다.

**선행지표 우선순위 (이 순서로 권한다)**

| 순위 | Metric | 어떤 솔루션에 맞나 | findings 위치 |
|---|---|---|---|
| 1 | **장바구니 담기율(장바구니÷세션)** | 상품상세·랜딩 화면을 바꾸는 가설 | `## D. 퍼널` 세션 기준 표의 `장바구니 담기율(장바구니÷세션)` 행 |
| 2 | **paid 전환율** | 광고 소재·타게팅·랜딩 일치를 바꾸는 가설 | `## E. 채널×전환율` 채널표 아래 `Paid 소계` 행의 전환율 |
| 3 | **재방문 비중** | 구매 후 경험·재방문 동기를 바꾸는 가설 | `## C. 신규/재방문` 표 `재방문` 행의 `세션 비중` |

**최종 지표(매출·전체 구매 전환율·객단가)는 R로 쓰지 않는다.** 이유 셋.

1. 솔루션과 지표 사이에 다른 행동이 여러 개 끼어 있어 **무엇 때문에 움직였는지 알 수 없다.**
2. baseline이 작아 2~4주로는 **차이가 났는지 판단이 안 된다.**
3. "장바구니는 늘었는데 결제가 안 됐다"는 다음 가설을 낳지만, "매출이 안 올랐다"는 아무것도 남기지 않는다.

사용자가 최종 지표를 말하면 한 번만 당긴다:
> "그 숫자는 솔루션에서 좀 멀어요. 솔루션 **바로 다음에** 반응하는 숫자로 당기면 어떤 게 가까울까요?"

### 3-2. Baseline

- `explore-findings.md`에 **있는 값만** 쓴다.
- 없으면 `—`로 두고 한 줄 남긴다: "`/ecommerce-growth-discovery:explore` 결과 표를 보고 채워 주세요."
- **추정치를 괄호로 넣는 것도 금지한다.** 근거 없는 수치는 쓰지 않는다.

### 3-3. Target — "왜 그 숫자인가요?"를 딱 한 번 묻는다

목표 숫자를 받으면 **한 번만** 되묻는다.

> **"왜 그 숫자인가요?"**

근거로 받을 수 있는 것은 둘뿐이다.

| 근거 유형 | 예 (가상) |
|---|---|
| **벤치마크** — `/ecommerce-growth-discovery:explore` 결과 표에 있는 값 | "벤치마크가 6.4%였으니 그 절반인 3.2%까지" |
| **내부 비교** — 다른 채널·다른 세그먼트의 우리 값 | "오가닉이 4.8%인데 paid가 0.6%니까, 일단 1.1%까지" |

근거가 안 나와도 **두 번 묻지 않는다.** 그대로 두고 근거 칸에 `(근거 없음)`을 적는다.
근거 없이 잡은 Target은 3단계에서 C 점수가 낮게 나오고, 그게 정상이다.

### 3-4. 기간

> "2주 / 4주 중 어느 쪽일까요?"

기본은 4주. 화면 문구 한 줄만 바꾸는 가벼운 가설이면 2주도 된다.

## 4. Result 문장 강제 형식

아래 한 문장이 나올 때까지 다듬는다.

> **"[기간] 안에 [Metric]이 [baseline]에서 [target]가 되면 성공"**

사용자가 준 답을 이 틀에 넣어 소리 내어 보여주고 "이렇게 정리하면 맞나요?"로 확인받는다.

### 좋은 예 / 나쁜 예 (전부 가상값)

| | 문장 |
|---|---|
| ❌ | "장바구니를 늘린다" — 기간·baseline·target이 전부 없다 |
| ❌ | "4주 안에 매출이 오르면 성공" — Metric이 최종 지표고 숫자가 없다 |
| ❌ | "4주 안에 장바구니 담기율이 2배가 되면 성공" — baseline이 없어 "2배"가 얼마인지 모른다 |
| ✅ | "4주 안에 장바구니 담기율이 5.1%에서 6.6%가 되면 성공" |
| ✅ | "2주 안에 paid 전환율이 0.62%에서 1.05%가 되면 성공" |

### 절반 문장 허용

**2~3번 다듬어도 한 문장이 안 나오면 Metric·기간만 채운 절반 문장으로 확정하고 넘어간다.**

> "4주 안에 **장바구니 담기율**을 본다 — baseline `—`, target 미정"

빈 칸은 나중에 채울 수 있다.
**절반 문장으로 넘어갈 때는 빈 칸이 무엇인지 한 줄로 남긴다** — "baseline은 `/ecommerce-growth-discovery:explore` 결과 표를 보고 채워 주세요."

## 5. "어떻게 다시 재나" 작성법

Result는 **다시 재야** 판정이 된다. 가설마다 한 줄로 적는다 — **GA4 어느 리포트 / 어느 `/ecommerce-growth-discovery:explore` 서브커맨드**인지.

| Metric | `/ecommerce-growth-discovery:explore` 서브커맨드 | GA4에서 직접 볼 때 |
|---|---|---|
| 장바구니 담기율(장바구니÷세션) | `explore funnel` → `## D. 퍼널` 세션 기준 표의 `장바구니 담기율(장바구니÷세션)` 행 | 「탐색」에서 `add_to_cart` 이벤트 수 ÷ 세션 수 |
| paid 전환율 | `explore channel-cvr` → `## E. 채널×전환율` 채널표 아래 `Paid 소계` 행의 전환율 | 「보고서 > 획득 > 트래픽 획득」에서 세션 기본 채널 그룹별 세션·구매 |
| 재방문 비중 | `explore traffic` → `## C. 신규/재방문` 표 `재방문` 행의 `세션 비중` | 「탐색」에서 측정기준 `새 사용자/재사용자` × 세션 |
| 구매 전환율(구매÷세션) · 객단가(매출÷구매) (Guardrail용) | `explore baseline` → `## A. baseline`의 `전환율(구매÷세션)` · `객단가(매출÷구매)` 행 | `config.ga4.revenue_metric`으로 고른 매출 지표(explore가 `## A`에 쓴 값) |

**한 줄에 반드시 들어가야 하는 것 3가지** — 이게 빠지면 다음에 잰 숫자와 지금 숫자를 비교할 수 없다.

1. **어디서**: 위 표의 서브커맨드 또는 리포트 이름
2. **같은 조건**: 같은 필터(`growth-discovery.config.json`의 `ga4.exclude_filters`), 매출은 `ga4.revenue_metric`에서 고른 지표. **비율 지표(담기율·전환율)는 기간 길이가 달라도 비교된다. 건수·금액은 기간 길이를 맞춰야 한다** — 4주 뒤 담기율을 보는 건 되고, 4주 구매 건수를 석 달 baseline과 맞대는 건 안 된다
3. **언제**: 시작일 + 기간 (예: "10/1부터 4주 뒤")

작성 예 (가상):

> `/ecommerce-growth-discovery:explore funnel`을 4주 뒤 다시 실행해 `## D` 세션 기준 표의 `장바구니 담기율(장바구니÷세션)` 행을 본다. **그때는 비교 기간을 지정해야 한다** — 기본 조회 기간은 `growth-discovery.config.json`의 `ga4.date_range`(기본 최근 90일)이므로, 그대로 두면 지금과 같은 기간을 다시 보게 된다. 예: "10월 1일부터 10월 28일까지로 다시 봐줘".

## 6. 셀프 체크 5줄 — 표에 넣기 전에

- [ ] P의 주어가 고객인가 (지표·"우리"가 아닌가)
- [ ] S에 **어디를** 바꾸는지가 들어 있는가
- [ ] R의 Metric이 최종 지표가 아니라 선행지표인가
- [ ] Baseline이 `explore-findings.md`에 실제로 있는 값인가 (지어낸 값이 아닌가)
- [ ] 이 세 줄만 읽고 **다른 사람이 I/C/E를 매길 수 있는가** — 못 매기면 무엇이 빠졌는지 되묻는다
