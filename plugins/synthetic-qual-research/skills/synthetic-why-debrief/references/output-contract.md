> **범위 밖**:
> - **가설 백로그 등재** — 스킬은 「'왜' 후보」까지만 만든다. 그 후보를 백로그에 정식 가설로 등재할지는 **사람이 결정**한다 (§7-9). 자동 등재를 하지 않는다.
> - **실험 결과 분석 본류** — 노션 4장의 결과·배움·후속 액션은 이 계약의 범위 밖이다. 향후 별도 결과분석 스킬의 소관이다.
> - **합성으로 실험 결과 재현** — "합성에서도 같은 방향이 나왔으니 맞다" 같은 사용은 금지 (킷 §1 ④ 경계 선언).
> - **A/B 시뮬레이션·전환율 예측** — 합성으로 전환율·리프트를 예측하지 않는다.
> - **새 문제정의** — 이 세션은 이미 실행된 실험의 결과를 놓고 "왜"를 캐는 것이며, 새로운 문제를 발굴하는 자리가 아니다. 새 문제가 나오면 문제정의 세션(활용 포인트 ①)으로 라우팅한다.
> - **ICE 재산정·근거유형 재정의·Confidence 밴드 변경** = `hb-output-contract.md` 정본. 이 계약은 **인용만** 한다 (§7-8).

## 0. 정의와 경계

> **"합성 인터뷰는 어디를 파야 하는지를 몇 분에 알려주는 가설 생성기입니다. 근거가 아닙니다."** (킷 §0)

실험 결과 디브리프는 **이미 실행된 실험에서 나온 실측 행동을 "겪은 일"로 페르소나에게 제시하고, 그 행동의 "왜"를 laddering으로 캐 들어가 다음 사이클의 가설 후보를 만드는 절차**다. 목적은 **원인 확정이 아니라 다음에 무엇을 검증할지 좁히기**다.

| 이 절차가 하는 일 | 이 절차가 하지 않는 일 |
|---|---|
| 실측 행동을 시나리오로 제시하고 **관찰된 반응**을 수집 | 실측 행동의 **원인을 확정** |
| **laddering으로 3단 이상 파고든 뒤** '왜' 후보를 뽑음 | 페르소나에게 결과를 **해석시킴** |
| 후보를 **가설 문장 + 원문 인용 + 검증 수단**으로 정리 | 후보를 **백로그에 등재** |

### 0-1. 킷 §6-④ 경계 선언 (그대로 인용 — 재정의 금지)

> - 합성으로 실험 결과를 **재현**하지 않습니다.
> - 합성으로 A/B를 **시뮬레이션**하지 않습니다.
> - 이 용도는 **오직 '왜' 가설을 만들기 위한 것**입니다. 나온 가설은 다음 사이클의 가설 카드로 들어가고, 거기서 다시 검증됩니다.
> - 실측 숫자는 **시나리오의 재료로만** 쓰고, 페르소나에게 "이런 결과가 나왔는데 왜 그럴까요"라고 **결과 자체를 해석시키지 마세요.** 그건 응답자가 아니라 분석가의 일입니다.

### 0-2. `ct`(합성 컨셉 테스트)와의 경계 — 실험 파이프라인의 앞/뒤

| | 합성 컨셉 테스트 (ct) | **실험 결과 디브리프 (wd — 이 계약)** |
|---|---|---|
| 시점 | 실험 **런칭 전** — 시안을 좁힌다 | 실험 **종료 후** — 결과를 놓고 "왜"를 캔다 |
| 입력 | 아직 만들지 않은 시안 2안 이상 | **이미 나온 실측 결과** 1건 |
| 방법 | blind 제시 + within-subject 비교 | 실측 행동을 시나리오로 제시 + laddering |
| 산출 상한 | 4종(걸리는 지점·못 푼 걸림돌·카피 후보·문구 보완 지시) | **'왜' 후보 최대 3개** |
| 착지 | 노션 `1-3` 「합성 UT 결과」 | 노션 **4장** 「'왜' 후보」 |
| 다음 소비자 | ed 세션(E2 선정 근거) | **사람** — 백로그 등재 여부 판단 |

### 0-3. `hb`(가설 백로그)와의 경계 — 판정권 상한

이 계약이 산출하는 것은 **후보까지**다. 후보를 가설 백로그에 정식으로 올리고 ICE를 매기는 것은 `hb-output-contract.md` 소관이며 **사람이 한다** (§7-9). 이 계약은 백로그 등재 절차를 만들지 않는다.

## 2. 입력 규격

### 2-1. 세션 단위 — 실험 1건의 실측 결과

입력은 **이미 종료된 실험 1건과 그 실측 결과**다. 아직 실측 결과가 없으면(런칭 전이거나 진행 중) 진행하지 않고 되돌린다 — 그 경우는 `ct`(런칭 전) 또는 실험 관제(진행 중) 소관이다.

- **run 1개 = 실험 1건 = 노션 4장 「'왜' 후보」 소절 1개.**
- **권장 N은 2~3명** — 킷 §1 ④가 "심층 2~3명" 규모를 전제한다. 스킬이 인원을 늘려 자동 디스패치하지 않는다 (§0 확정 사항).

### 2-2. 입력 3형

| 형태 | 내용 | 비고 |
|---|---|---|
| **노션 4장 결과 붙여넣기** | 실험설계서 4장에 이미 기록된 실측 결과 | **권장** |
| **구술 요약** | 참가자가 "이 지점에서 이탈했다"처럼 구두로 전달 | STEP 0에서 W0 필드로 정규화 |
| **실험 관제 대시보드 캡처·요약** | 앰플리튜드 등에서 확인한 수치를 텍스트로 옮긴 것 | 원본 수치는 W0에 두고, **시나리오(W2)로 옮길 때는 숫자를 지운다** (§7-2) |

- 노션 MCP를 전제하지 않는다. 입력은 붙여넣기, 출력은 코드블록 — 왕복은 참가자가 한다.

### 2-3. 정규화 필수 필드 (W0)

| # | 필드 | 없을 때 |
|---|---|---|
| 1 | WD run ID | §6 규칙으로 **제안**, 확정은 사람 |
| 2 | HYP ID · EXP ID | 질문 — 없으면 `⚠️미정` |
| 3 | 축 (A/B) | 질문 — ICP 카드 선택이 축에 걸린다 |
| 4 | **실측 결과** (무엇이 어떻게 나왔나) | 필수 — 없으면 진행하지 않는다 (§2-1) |
| 5 | **노출 세그먼트 조건** | 필수 — W3 표집 조건의 입력. 없으면 질문 |
| 6 | **시나리오 검토 완료 기록** — `{이름} / {역할(상담사·해당 축 PM 중)} / {검토 날짜}` | **완료 기록이 아니면** `검토 대기 — {담당}`으로 둔다 — GATE를 통과시키지 않는다 (§1 GATE 확인 사항 · §7-11) |

### 2-4. 프로젝트 제약

금융·보험 도메인이므로 원천 PII는 어떤 표에도 옮기지 않는다 — 위치만 말하고 `[마스킹]`. 두 리서치 소스(MME 조사·뉴닉 설문)는 모집단이 다르므로 수치 합산·직접 비교 금지 (킷 §8-4).

### 3-3. W2. 시나리오 명세 표 — 3열 (하드)

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 시나리오 문장 | *"당신은 [화면/단계]에서 [실제로 관찰된 행동]을 했습니다."* 형태. 관찰된 행동만 |
| 2 | 추측 혼입 검사 | `통과 — 관찰된 행동만` / `혼입 — {추측된 이유 문구}`. **혼입이면 문장을 다시 쓴다** |
| 3 | 금지 어휘 검사 | `통과` / `걸림 — {발견된 어휘}`. 검사 대상: `실험` · `A/B` · `전환율` + **숫자를 포함한 모든 표현(정규식 `\d`)**. `몇 %`는 이 정규식의 부분집합일 뿐이다 — `23%`·`0.7%p`·`3명 중 2명`처럼 `%`나 `몇`이 없어도 숫자만 있으면 걸린다 |

**하드 규칙**: 2·3열이 `통과`가 아니면 **참가자에게 넘기지 않는다**(§7-2·§7-3).

### 3-4. W3. 표집 조건 표 — 2열 (항목/값)

행(순서 고정 5행): `ICP 카드`(킷 §3 번호·이름 그대로) · `노출 세그먼트와 동일 조건`(예: "서울·수도권, 만 25~39세, 보험 점검 결과를 받아본 경험이 있는 사람") · `N`(2~3) · `표집 경로`(데이터셋 UUID / 인구통계 호출 중 어느 쪽인지) · `시드`(데이터셋 경로면 `random_state` 값, 인구통계 호출 경로면 `해당 없음 — 인구통계 호출 경로`)

- **행동 경험 조건은 실험에 실제로 노출된 세그먼트와 같은 조건이어야 한다** — "관심 있는 사람"이 아니라 "그 실험에 실제로 노출된 사람"으로 좁힌다 (킷 §6-④ "표집 조건: 실험에 노출된 세그먼트와 같은 조건으로 잡았습니다").
- **시드를 남겨도 이 계약은 신뢰등급을 올리지 않는다** — 이유는 §3-7 W6a 4부를 참고. 시드는 재현성 기록일 뿐이다.

### 3-5. W4. laddering 스크립트 표 — 3열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 단계 | `행동·장면` → `감정` → `가치(한 번 더 왜)` → `대체 행동` → `반사실` — 5단 고정 |
| 2 | 질문 문안 | 킷 §6-④ 5문항 그대로 또는 이 실험 맥락에 맞춘 변형 |
| 3 | 진행 원칙 | `한 번에 한 질문` — 스크립트 전체를 한 번에 던지지 않는다 |

- **이 표는 참가자에게 그대로 넘기는 산출물이다.** 스킬이 인터뷰를 대신 진행하지 않는다.

### 3-6. W5. '왜' 후보 표 — 4열 (최대 3행, 하드)

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 가설 문장 | `[누가] [어떤 상황에서] [무엇 때문에] [어떤 행동을 한다]` |
| 2 | **원문 인용** | 응답자가 스스로 쓴 표현 그대로 |
| 3 | **확인할 실제 데이터** | `앰플리튜드 이벤트` / `실제 UT` / `상담사 인터뷰` 중 |
| 4 | 교차 확인 | 몇 명이(2~3명 중) 서로 다른 어떤 장면을 근거로 이 방향을 말했는지. **값 도메인**: `n/N + 서로 다른 장면 확인됨` / `n/N + 장면 중복 여부 미확정` / `[단일 응답 근거 — 추가 확인 필요]`(1명뿐일 때) |

**하드 규칙**

- **행이 3개를 넘지 않는다** (§7-4). 넘으면 인터뷰가 얕았던 것 — 후보를 추리거나 laddering을 더 깊게 다시 한다.
- **4열이 1명 근거뿐이어도 행을 삭제하지 않는다** — `[단일 응답 근거 — 추가 확인 필요]`를 4열에 병기하고 W6a에도 그대로 옮긴다 (§7-5). 초안 단계에서는 후보를 지우기보다 표기해 남기는 쪽이 안전하다.
- **반사실 답변을 그대로 1열에 옮기지 않는다** — 그건 원인이 아니라 솔루션 제안이다 (§7-6).

### 3-7. W6a. 노션 4장 착지 블록 (코드블록) ★ 착지

노션 실험설계서 **4장 「'왜' 후보」** 소절에 붙일 내용을 코드블록으로 출력한다 — 참가자가 붙여넣는다.

**소절 구성(순서 고정 4부)**

| # | 구성 | 재료 |
|---|---|---|
| 1 | **경고문** (§7-10) | 킷 §8-5 문구 그대로. 최상단, 지우지 않는다 |
| 2 | `⚠️ 이건 가설입니다` 배너 | §7-1 문구 그대로 |
| 3 | W5 전문 (최대 3행) | 가설 문장 · 원문 인용 · 확인할 실제 데이터 · 교차 확인 |
| 4 | 근거 지위 + 다음 단계 안내 | `근거유형 합성 · Confidence 상한 1~3` + **`신뢰등급 C — 단일 run·대조군 없음 (킷 §9-3)`**(고정 문구) + `백로그 등재는 사람이 판단합니다 — 이 블록은 등재가 아닙니다` |

**규칙**

- 착지 위치는 노션 **4장** 「'왜' 후보」 소절 하나다. 4장의 결과·배움·후속 액션 칸을 건드리지 않는다 — 범위 밖.
- **신뢰등급은 항상 `C`로 고정한다 — 산출 절차를 두지 않는다.** `ct`의 §7-12 같은 등급 산출 규칙이 이 계약에는 없다. 이유는 킷 §9-3 정의 그대로다: W5의 표집은 항상 N=2~3·단일 run·대조군 없음이라 "단일 run, 대조 없음" 조건을 항상 충족한다. W3에 시드를 남겨 재현성을 기록해도 그것은 재현성 증빙일 뿐, 등급을 `B`로 올리는 조건(대조군 arm + 사전등록)을 이 절차는 애초에 갖추지 않는다.

## 4. 착지 규칙

- **정본 착지는 노션 4장 「'왜' 후보」 소절 한 곳.** 스킬은 블록과 안내만 출력하고 노션 기입은 참가자가 한다.

- **노션 4장의 다른 칸(결과·배움·후속 액션)은 건드리지 않는다.**

## 7. 판정 규칙 (정본 — 위반 금지)

**규칙마다 「판정 질문」이 붙는다. 서술로만 있으면 리뷰에서 쓰이지 않는다** — `ct` 계약이 이미 겪은 실패 패턴이다. 각 판정 질문은 **필수 출력**이며, 답이 "아니다"일 때의 처리를 그 자리에 적는다.

**7-1. 결과를 해석시키지 않는다 (하드).** 페르소나에게 "이런 결과가 나왔는데 왜 그럴까요"를 묻지 않는다. **그건 응답자가 아니라 분석가의 일이다.**
- **판정 질문(필수 출력)**: *"인터뷰 스크립트(W4) 어디에도 페르소나에게 결과를 해석시키는 질문이 없는가?"*
- **"아니다"일 때**: 해당 질문을 삭제하고 laddering 5단 중 하나로 재구성한다. 이미 진행된 인터뷰라면 그 답변을 W5 근거로 쓰지 않는다.
- 근거: 킷 §6-④ 경계 선언.

**7-2. 시나리오는 관찰된 행동만 (하드).** 추측한 이유를 시나리오에 섞지 않는다. 섞으면 페르소나가 그 이유를 연기한다.
- **판정 질문(필수 출력)**: *"W2 시나리오 문장에 실측된 행동 외의 추측·이유가 섞여 있는가?"*
- **"아니다"(=섞여 있다)일 때**: 문장을 관찰된 행동만 남기고 다시 쓴다. STEP 2를 통과시키지 않는다.
- 근거: 킷 §6-④ "시나리오는 실제로 일어난 행동만 담아야 합니다."

**7-3. 금지 어휘 (하드).** `실험` · `A/B` · `전환율` · **숫자를 포함한 모든 표현(정규식 `\d`)**을 페르소나에게 쓰지 않는다. `몇 %`는 이 정규식의 부분집합이다 — 리터럴 문자열만 보면 `23%`·`0.7%p`·`3명 중 2명` 같은 표현을 놓친다.
- **판정 질문(필수 출력)**: *"W2·W4 문안에 정규식 `\d` 매치가 하나도 없고, `실험`·`A/B`·`전환율`도 없는가?"*
- **"아니다"일 때**: 발견된 표현을 지우고 재조립한다. 참가자에게 이미 넘겼다면 회수하고 정정본을 다시 넘긴다.
- 근거: 킷 §6-④ 제시 프롬프트 + §5 "실측 숫자·비율을 시나리오에 넣지 않는다"는 문장·서술 규칙과의 정합.

**7-4. 후보 3개 상한 (하드).** 3개를 넘게 나오면 **인터뷰가 얕았던 것**이다. 깊게 판 인터뷰는 후보가 적고 뾰족하다.
- **판정 질문(필수 출력)**: *"W5 행이 3개를 넘는가?"*
- **"아니다"(=넘는다)일 때**: 셋으로 추리거나, laddering 3번(가치) 질문으로 더 파고들어 후보를 좁힌다. 추리지 못하면 **가장 근거가 약한 행부터 제외**하고 사유를 candidates.md에 남긴다.
- 근거: 킷 §6-④ 확인 포인트.

**7-5. 2~3명 교차 확인 (하드).** 서로 다른 응답자가 **각자 다른 장면을 근거로 같은 방향**을 말할 때만 근거가 튼튼한 후보로 올린다. 「다른 장면」의 경계는 이 초안이 v1.0 TODO로 남긴 미정 개념이므로(§9), 기계적으로 셀 수 있는 부분과 사람의 판단이 필요한 부분을 **두 질문으로 쪼갠다**.
- **판정 질문 ①(필수 출력 · 기계적)**: *"이 후보를 뒷받침하는 응답자가 2명 이상인가?"*
  - **"아니다"(=1명뿐)일 때**: 후보를 삭제하지 않는다. **§3-6에 따라 4열에 `[단일 응답 근거 — 추가 확인 필요]`를 병기**하고 W6a에도 그대로 옮긴다.
- **판정 질문 ②(필수 출력 · 판단)**: *"응답자별 인용이 서로 다른 장면에서 나왔는가?"*
  - **판단이 명확하면**: 같은 장면(같은 화면·같은 문구를 그대로 재인용)이 확인되면 후보에서 내린다.
  - **판단이 불가하면**: **`Warning`으로 표기**하고 후보는 유지하되 W6a에 `장면 중복 여부 미확정`을 병기한다 — 삭제하지 않는다.
- 근거: 킷 §6-④ 확인 포인트 · §9-1 「평균 회귀」 대처.

**7-6. 반사실 답변은 원인이 아니다 (하드).** 5번 질문(반사실) 답변이 "그럴듯한 개선안"으로 흐르는 것을 경계한다. 원인으로 적지 않는다.
- **판정 질문(필수 출력)**: *"W5 1열(가설 문장)에 반사실 질문의 답이 그대로 원인으로 옮겨진 행이 있는가?"*
- **"아니다"(=있다)일 때**: 그 행을 삭제하거나, "이건 솔루션 제안이지 원인이 아닙니다"로 재분류해 후보에서 제외한다.
- 근거: 킷 §6-④ 확인 포인트.

**7-7. 매끄러운 서사 의심 (하드).** 페르소나가 행동을 정당화하는 이야기를 만들었을 가능성을 항상 의심한다.
- **판정 질문(필수 출력)**: *"트랜스크립트의 답변이 앞뒤가 지나치게 딱 맞는가? 서로 다른 응답자의 표현까지 똑같은가?"*
- **"아니다"(=그렇다·매끄럽다)일 때**: 그 응답을 근거로 단독 채택하지 않고, 추가 교차 확인(§7-5) 없이는 후보에 올리지 않는다.
- 근거: 킷 §9-1 「매끄러운 서사」.

**7-8. 근거유형 `합성` + Confidence 상한 1~3 (하드 — 재정의 금지, 인용).** **정본은 `hb-output-contract.md` §2-6(근거유형 3값) · §7-4(C 앵커 4밴드·합성 하드 상한)**이며, 어긋나면 hb가 이긴다.
- 실험 결과라는 실측이 옆에 있어도 **이 가설 자체가 격상되지 않는다** — 격상되는 건 실측 쪽이다(킷 §8-3 · §6-④ 확인 포인트).
- **판정 질문(필수 출력)**: *"W6a에 근거유형 `합성`과 Confidence 상한 1~3이 적혀 있는가?"*
- **"아니다"일 때**: W6a 4부에 추가한다. 이미 착지했으면 정정한다.

**7-9. 백로그 등재는 사람이 한다 (하드 — 이 계약의 경계).** 스킬은 후보(W5)까지만 만든다. **자동 등재를 하지 않는다.**
- **판정 질문(필수 출력)**: *"이 산출물 어디에도 「백로그에 등재했다/한다」는 확정 문장이 없는가? W6a에 등재 여부를 사람에게 넘긴다는 안내가 있는가?"*
- **"아니다"일 때**: 등재 관련 확정 문장을 삭제하고 `백로그 등재는 사람이 판단합니다`로 대체한다. 착지 전이라면 GATE에서 막는다.
- 근거: `_common-brief.md` 확정 사항 — "가설 백로그 등재는 사람이 결정 — 스킬 범위 밖".

**7-10. 경고문 강제 (하드).** 산출물 최상단에 아래 문구를 **그대로** 넣는다 (킷 §8-5).

- **판정 질문(필수 출력)**: *"산출물 최상단에 이 경고문이 문구 그대로 있는가?"*
- **"아니다"일 때**: 넣고 다시 출력한다. 경고문이 없는 산출물은 착지시키지 않는다.

**7-11. 시나리오 사전 검토 게이트 (하드).** **시나리오(W2)는 실무자(상담사·해당 축 PM)의 검토 확인
없이 참가자에게 넘기지 않는다.**
- **판정 질문(필수 출력)**: *"시나리오를 누가 언제 검토했고, 그 기록이 W0에 남아 있는가?"*
- **"아니다"일 때**: **GATE를 통과시키지 않는다.** 실무자 부재로 지연되면 W0 6행에 `검토 대기 —
  {담당}`으로 두고 세션을 멈춘다. **등급을 낮춰 진행하는 우회는 두지 않는다** — 우회를 허용하면 이
  게이트는 사라진다.
- **근거 — 이 규칙만 다른 규칙들과 성격이 다르다**: **합성 응답자는 거짓 전제를 반박하지 않는다.**
  비현실적인 시나리오를 준 run에 **100명 전원이 그대로 연기하며 그럴듯한 숫자(4.13·80%)를
  만들었다**(킷 §6-③). **계기 결함은 분포 이상으로 잡히지만 시나리오 오류는 깨끗한 데이터를 만들어
  안 걸린다**(킷 §9-1). W2의 2·3열(추측 혼입 검사·금지 어휘 검사, §7-2·§7-3)은 이 스킬 **자기 자신이
  하는 검사**일 뿐이라, 시나리오가 실측 사실과 다르게 왜곡됐는지는 이 검사만으로 잡히지 않는다. 다른
  결함은 사후에 잡을 수 있지만 **이것은 사전 검토밖에 방법이 없다** — `ct-output-contract.md`
  §7-8과 같은 이유다.
