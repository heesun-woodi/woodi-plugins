## 0. 합성 컨셉 테스트의 정의

> **"합성 인터뷰는 어디를 파야 하는지를 몇 분에 알려주는 가설 생성기입니다. 근거가 아닙니다."** (킷 §0)

합성 컨셉 테스트는 **아직 만들지 않은 시안 2안 이상을 합성 페르소나에게 나란히 blind로 보여주고, 어디서 걸리는지를 수집하는 절차**다. 목적은 **좁히기**이지 고르기가 아니다.

| 이 절차가 하는 일 | 이 절차가 하지 않는 일 |
|---|---|
| 안별로 **어디서 걸리는지**를 응답자 원문으로 수집 | 어느 안이 이길지 **예측** |
| **어느 안도 못 푼 걸림돌**을 드러내 실험 설계에서 확인할 항목으로 올림 | 못 푼 안을 후보에서 **탈락** |
| 고객이 스스로 쓴 표현을 **카피 후보**로 채집 | 최종 문구 **확정** |
| 안의 문구에 대한 **보완 지시** 산출 | variant **순위·채택·기각 선언** |

### 0-1. 왜 안전장치가 이렇게 많은가 — 실측 실패 사례

**시안을 보여주는 순간 합성 응답은 아주 쉽게 망가진다** (킷 §6-③). 특히 **합성 응답자는 거짓 전제를 반박하지 않는다.**

> 실측 사례: 비현실적인 시나리오를 준 run에 **100명 전원이 그대로 연기**했고, 그럴듯한 숫자(**4.13 · 80%**)가 나왔다. **계기 결함은 분포 이상으로 잡히지만 시나리오 오류는 깨끗한 데이터를 만들어 안 걸린다.** (킷 §6-③ · §9-1)

그래서 이 계약은 **결과의 품질을 사후에 판정하지 않는다.** 사전등록(C1)·제시물 명세(C2)·blind 배정(C4)을 **실행 전에 파일로 못 박고**, 리뷰는 그 못 박은 것이 지켜졌는지만 본다 (§3-12 R1).

### 0-2. 실험설계(ed)와의 경계

| | 합성 컨셉 테스트 (ct — 이 계약) | 실험설계 구체화 (ed) |
|---|---|---|
| 목적 | **좁히기** — 어떤 언어 프레임을 실험에 태울지 후보를 줄이고 문구를 보완 | **세팅 준비** — variant를 확정하고 표본·기간을 산출 |
| 산출 단위 | 시안 후보 2안 이상에 대한 반응 1 run | 실험 1건의 설계서 |
| 시안 | **제시물 명세**(문구 전문 + 담은 팩트) — 만들지 않고 글로만 제시 | 변경 화면 명세 4슬롯 + 시안 상태 |
| 판정 | **사전등록 조건과의 대조까지** | Primary·Guardrail 확정, 28일 실현성 판정 |
| 착지 | 노션 `1-3` 「합성 UT 결과」 소절 | 노션 `1-3`(보강)·`1-4`·`1-5`·`3-1`~`3-5` + repo EXP 파일 |
| 근거 지위 | 근거유형 `합성` · Confidence 상한 **1~3** (§7-11) | 입력값을 그대로 읽어 씀 |

- **호출 순서**: ct는 ed **앞**에서 돈다. ed 세션이 이미 열려 E2를 쓰는 중이라면, ct 결과는 **E2 「Variant 간 차별점」 한 줄의 선정 근거로 인용할 수 있다** — E2 표의 칸을 ct가 채우지 않는다.
  - ⚠️ **ed 쪽 수신 필드는 아직 없다 (인수 항목).** `ed-output-contract.md` v1.3에는 「합성」이라는 말이 한 번도 나오지 않고, **E2에 이 결과를 받는 행도 R1 D-2에 그것을 보는 항목도 없다.** 따라서 현재 인용은 **참가자가 손으로 하는 것**이고, 계약이 강제하는 경로가 아니다. **ed 개정은 이 계약의 범위 밖**이며, 「E2에 합성 UT 수신 필드 신설 + D-2가 그것을 보게 하기」를 **ed 차기 개정 대상으로 남긴다.**
- **ct 없이 ed를 진행하는 것은 정상이다.** ct를 조건으로 걸어 실험 설계를 멈추지 않는다.

### 0-3. 판정권 상한 — 이 계약의 중심

이 계약이 스킬에 허용하는 산출은 **네 가지뿐**이다 (§7-10 하드).

| # | 허용 산출 | 형태 |
|---|---|---|
| 1 | **안별로 걸리는 지점** | 응답자 **원문 인용** 필수 |
| 2 | **어느 안도 못 푼 걸림돌** | 실험 설계에서 확인할 항목으로 **강등** |
| 3 | **고객 언어 카피 후보** | 응답자가 스스로 쓴 표현 그대로 |
| 4 | **문구 보완 지시** | "이 문구에서 무엇을 더 말해야 하는가" |

**금지 산출**: `채택 선언` · `기각 선언` · `variant 순위` · `variant 탈락` · `실험 미진행 권고`.

> 합성 전원 거부가 나와도 **실행동까지 그런지는 실측으로만 확정**된다. "전원 거부"는 실험 후보에서 지우는 근거가 아니라, **실험 설계에서 확인할 항목으로 강등하는 근거**다. (킷 §6-③)

```
├── stimuli.md            # C2 — 안별 문구 전문 + 담은 팩트 목록
├── drawn_personas.jsonl  # C3 — 실제로 표집된 N명의 원본 행 (데이터셋 경로일 때만)
├── assignment.md         # C4 — 응답자별 제시 순서(counterbalancing) 기록 — 사람이 읽는 표
├── assignment.json       # C4 — 같은 배정의 기계 판독본 (aggregate_arms.py가 읽는다)
├── results.json          # C5 — { "<uuid>": {3축 응답} }  (익명 리스트가 아님)
├── <ts>-<uuid8>.md       # C5 — persona-interviewee --save 트랜스크립트 (응답자 1명당 1개)

```

- **`phase_status` 키 6개**(이 계약이 정하는 값): `0_init` · `1_prereg` · `2_sample` · `3_field` · `4_aggregate` · `5_landing`. 값 도메인은 orchestration.md 그대로 `todo` / `pending` / `done`이며, **각 단계 끝에서 먼저 쓰고 다음으로 넘어간다.**
- **UUID 불변식**은 orchestration.md의 것을 그대로 쓴다: `results.json.keys ⊆ drawn_personas.jsonl.uuids`. 검증은 번들 스크립트 `scripts/validate_results.py`로 하며, **호출 형태를 아래로 못박는다 — 인자를 빼고 호출하지 않는다.**

  ```
  python ../synthetic-qual-research/scripts/validate_results.py \
      --drawn drawn_personas.jsonl --results results.json \
      --require "arms,counterfactual"
  ```

  - **`--require`를 반드시 넘긴다.** 스크립트의 `DEFAULT_REQUIRED`(`A1`·`A2`·`B1`·`B2`·`D1`·`E1`·`E4`)는 **설문 스킬의 답안 스키마**이고, concept-test의 `results.json`은 top-level이 `arms` / `counterfactual`이라 그 키들이 **존재할 수 없다.** 인자 없이 그대로 호출하면 **멀쩡한 데이터에 exit 3(전원 재디스패치) 판정**이 난다 — 실행으로 재현된 결함이다. **이 인자를 지우지 않는다.**
  - **exit 2는 하드 스톱**(표집되지 않은 uuid — 지어낸 값), **exit 3은 해당 슬롯만 재디스패치**, **exit 0이 통과**다. `arms`가 빈 `{}`인 응답은 exit 3으로 올바르게 걸린다.
  - **UUID를 지어내는 순간 파이프라인이 끊긴다** (킷 §4-7).
- **C4 배정은 `scripts/assign_arms.py`가 만든다** — 같은 배정을 `assignment.md`(사람이 읽는 표)와 `assignment.json`(기계 판독본) **두 파일로** 쓴다. 집계 스크립트 `aggregate_arms.py`가 읽는 것은 **json 쪽**이므로, md만 남기고 json을 지우면 집계가 돌지 않는다.
- **표집은 `scripts/draw_personas.py --filter --n --seed --out`으로만** 한다. 손으로 uuid를 타이핑하고 있으면 그 시점에 이미 척추가 부러진 것이다 (orchestration.md 불변식 체크 1).
- **human gate 2개** — orchestration.md의 「announce, then stop」 원칙을 승계한다.

| 게이트 | 언제 | 무엇을 확인받나 |
|---|---|---|
| **GATE 1** | STEP 1 끝 (실행 전) | C1 사전등록(**8행**) · C2 제시물 명세(팩트 대조) · C3 표집 조건 · **§7-8 도메인 실무자 검토 확인** · **`prereg_sha256` 앞 8자**. **가장 싸게 고칠 수 있는 지점이며, 여기를 통과하면 C1은 잠긴다** |
| **GATE 2** | STEP 4 끝 (착지 전) | C6 집계가 C1 조건과 대조됐는가 · **§7-10 판정권 상한을 넘는 문장이 없는가** · 신뢰등급(§7-12)과 재현성(§7-13) 표기 |

- **게이트를 자동으로 넘기지 않는다.** 확인받지 않은 채로 표집·필드·착지를 진행하지 않는다.
- **GATE 1 announce에 해시 앞 8자를 반드시 넣는다.** §7-1이 막으려는 1차 위협은 「사후 **수정**」이 아니라 **「사후 **작성**」**이다 — 사람이 조건을 눈으로 본 순간과 해시가 찍힌 파일을 묶어 주는 것이 없으면, 결과를 본 뒤에 C1을 처음 쓰고도 "사전등록했다"고 말할 수 있다. **해시 앞 8자를 게이트 화면에 띄우는 것이 그 묶음**이며, 사람은 그 값을 확인 시점 기록으로 남긴다.
  > announce 예시: `사전등록 잠금: prereg_sha256 = a3f19c02… (앞 8자) · 실행 예정일 2026-09-02 · 판정 단위 n/N (N=6). 이 값이 찍힌 뒤 C1을 고치면 등급 C로 강등됩니다. 진행하시겠어요?`

## 2. 입력 규격

### 2-1. 세션 단위 — 실험 1건 × 시안 후보 2안 이상

이 세션의 입력은 **가설(실험) 1건과 그 가설의 시안 후보 2안 이상**이다. 1안만 있으면 진행하지 않는다. 여러 실험을 요청받으면 1건씩 순서대로, 매 건 STEP 0부터.

- ⚠️ **「2안 이상」은 실행 최소조건이고, 「대조군 arm」(= 현행 운영 문구 1안 포함)은 그보다 좁은 등급 조건이다** — 두 층을 섞지 않는다. 새 프레임끼리만 비교해도 **실행은 정상**이며 **등급만 C 상한**이다 (§7-2·§7-12).

- **run 1개 = 실험 1건 = 노션 「합성 UT 결과」 소절 1개.**
- **권장 N은 5~8명**이며 within-subject(한 응답자에게 전 안 제시)이므로 **1명씩 디스패치**한다 (킷 §4-1 5단계 — 심층 자유응답은 1명씩). N을 늘려도 §7-11의 Confidence 상한은 움직이지 않는다 — **숫자가 아니라 근거의 종류가 상한을 정한다** (킷 §8-2).

### 2-2. 입력 3형 — 어느 것이든 정상

| 형태 | 내용 | 비고 |
|---|---|---|
| **노션 페이지** | 실험설계서 템플릿 페이지 본문 붙여넣기 | **권장** — `1-1`~`1-3`에서 가설·솔루션 핵심가치를 그대로 재료로 쓴다 |
| **hg G5b 블록** | 그루밍 세션의 Variant 후보 표 | 그루밍 직후 이어서 진행할 때 — 시안 후보가 이미 2개 이상이다 |
| **ed E2 초안** | 실험설계 세션에서 쓰다가 「어떤 프레임으로 갈지 모르겠다」에 걸린 경우 | E2 4슬롯 중 텍스트 슬롯만 재료로 받는다 |

- **노션 MCP를 전제하지 않는다.** 입력은 붙여넣기, 출력은 코드블록 — 왕복은 참가자가 한다 (ed·hg 승계).

### 2-3. 정규화 필수 필드 (C0)

**§3-1 C0 표의 11행과 문자 단위로 대응한다.** 아래 목록과 C0 행 목록이 어긋나면 §3-1이 정본이다.

| # | 필드 (= C0 행 이름) | 없을 때 |
|---|---|---|
| 1 | CT run ID | §6 규칙으로 **제안**하고 확정은 사람 |
| 2 | HYP ID · EXP ID | 질문 — **스킬이 채번하지 않는다**. 없으면 `⚠️미정` |
| 3 | 축 (A/B) | 질문 — ICP 카드 선택·질문 가이드가 축에 걸린다 |
| 4 | 가설 문장 (PSR 전문) | 필수 — 없으면 진행하지 않고 hg로 라우팅 |
| 5 | 솔루션 핵심가치 | PSR의 S. **제시물이 이 가치에서 이탈했는지 판정하는 기준** |

| 10 | 실무자 검토 담당 | §7-8 게이트의 대상자 (상담사 · 해당 축 PM) |
| 11 | **같은 지면·문구를 다루는 다른 run·실험** | `없음` 또는 `있음 — {run ID 또는 실험 ID}, {무엇이 겹치는가}`. **R1 B군 W-4의 작성 규격**이며, ed §3-6 `타겟 세그먼트 겹침 확인`에 대응하는 자리다 — 겹치면 **이 결과를 어느 설계서에 태울지**를 여기서 정한다. 겹침 자체가 중단 사유는 아니다 |

### 2-4. 데이터셋 유무 분기 (하드)

> 킷 §2 각주: **"데이터셋 미설치여도 됩니다. ①은 인구통계를 지정하면 데이터셋 없이도 동작합니다. 데이터셋이 필수인 건 설문(표집) 경로인 ②③ 뿐입니다."**

합성 UT는 인터뷰 경로(①)로 돌 수 있으므로 **데이터셋이 없어도 실행은 된다.** 다만 **재현성이 달라지고, 재현성이 등급을 정한다.**

| | 데이터셋 있음 | 데이터셋 없음 |
|---|---|---|
| 표집 | `scripts/draw_personas.py`로 **시드 기반 추출** | 인구통계 조건으로 페르소나 **호출** (`/nemotron-personas-korea:persona-interviewee "F 30대 서울"`) |
| C3 기록 | **UUID 목록 필수** + 시드 | 인구통계 조건 문자열 + `UUID 없음 — 인구통계 호출 경로` |
| UUID 불변식 | 적용 (`validate_results.py`) | **적용 불가** — C5는 `RSP-{n}` 라벨로만 식별 |
| 재현성 | 같은 조건·시드로 같은 표본 재현 가능 | **재현 불가** |
| **신뢰등급 상한** | **B 도달 가능** (대조군 arm + 사전등록 갖추면 — §7-12) | **C 상한** (재현 불가 — §7-13) |

- **데이터셋 없음 경로에서 등급 B를 주지 않는다.** 대조군 arm과 사전등록을 갖췄더라도 재현 불가면 상한은 C다.
- **분기 선택을 참가자에게 숨기지 않는다.** C0 9번 행의 답에 따라 **C3 산출 형태와 등급 상한을 그 자리에서 말한다.**

### 2-5. 프로젝트 제약 (ed §2-4 승계)

금융·보험 도메인이므로 **원천 PII는 어떤 표에도 옮기지 않는다** — 위치만 말하고 `[마스킹]`. 제시물에 실고객 정보(실명·연락처·증권번호·보험료·계약 정보)가 보이면 **값을 출력하지 말고 위치만** 말하고 마스킹본을 요청한다 (ed §7-12와 같은 원칙). 두 리서치 소스(MME 조사 · 뉴닉 설문)는 **모집단이 다르므로 수치 합산·직접 비교 금지** (킷 §8-4).

## 3. 표별 열 정의 (이름·순서 고정)

### 3-1. C0. 인테이크 정규화 표 — 2열 (항목/값)

**행 11개(순서 고정)**: `CT run ID` · `HYP ID · EXP ID` · `축` · `가설 문장(PSR 전문)` · `솔루션 핵심가치` · `실험 지면 · Trigger Point` · `시안 후보 목록` · `결정 시한` · `데이터셋 사용 가능 여부` · `실무자 검토 담당` · `같은 지면·문구를 다루는 다른 run·실험`

- **§2-3의 필수 필드 목록과 문자 단위로 대응한다** — 결손 시 처리는 §2-3 표를 따른다.
- PSR·솔루션 핵심가치는 **입력 그대로 옮긴다.** 이 세션에서 가설을 고치지 않는다 (§7-11).

### 3-2. C1. 사전등록 표 — 2열 (항목/값) ★ 하드

**실행 전에 파일(`prereg.md`)로 먼저 쓰고, SHA-256 해시를 C8b manifest에 남긴다** (§7-1).

행(순서 고정 8행):

| # | 행 이름 | 내용 |
|---|---|---|
| 1 | **이 테스트로 내릴 결정** | **주제가 아니라 행동**으로 쓴다. 두 선택지가 명시돼 있어 증거가 어느 쪽을 지지하는지 판정 가능해야 한다 (킷 §4-3) |
| 2 | **채택 조건** | `n/N` 단위로 쓴다 — 예: `N명 중 n명 이상이 ㉯에서 「무엇을 받는지 알겠다」는 취지로 답하고, ㉮에서는 「뭘 팔려는지 모르겠다」는 취지가 나오면 ㉯ 방향` |
| 3 | **기각 조건** | 예: `두 안의 반응 차이가 없거나, 두 안 모두 같은 장벽에서 막히면 문구가 아니라 다른 레버를 봐야 하는 것으로 판정` |
| 4 | **판정 단위** | `n/N` — N(응답자 수)을 숫자로 못 박는다. **백분율 단독 표기 금지** (§7-14 · 킷 §9-2 「절대 % 인용 금지」) |
| 5 | **시드** | 데이터셋 경로면 `random_state` 값(예: 42). 없는 경로면 `해당 없음 — 인구통계 호출 경로` |
| 6 | **실행 예정일** | 날짜. 해시 시점과 필드 시점의 순서를 사람이 볼 수 있게 |
| 7 | **대조군 안** | 어느 기호가 **현행 운영 문구**인가 (예: `㉯ = 현행`). 현행 문구가 없는 신설 지면이면 `없음 — 신설 지면(등급 C 상한)` (§7-2·§7-12) |
| 8 | **실무자 검토** | `{이름} / {역할} / {날짜}` — §7-8 게이트의 통과 기록 |

**하드 규칙**

- **실행 후 C1을 수정하지 않는다.** 수정하면 §7-1에 따라 **등급 C로 강제 강등**한다.
- **7·8행이 해시 안에 들어가는 것이 핵심이다.** 대조군 지정과 실무자 검토 기록을 C1 **밖**에 두면 **사후에 채워넣을 수 있고**, 그러면 T-3(대조군 arm)·T-9(실무자 검토)가 Critical인데도 **판정 근거가 없어 판정 불가**가 된다. 해시 대상 파일에 넣는 이유가 이것이다.
- **결과를 보고 조건을 만들면 합성은 항상 「좋다」고 나온다** (킷 §6-③ 장치 1). C1이 없는 run은 등급 C 상한이며, 이 표를 건너뛰고 STEP 2로 가지 않는다.
- **1행이 "주제"이면 되돌린다.** *"점검신청 사용자 조사"*는 주제일 뿐 어떤 답이 나와도 뭘 바꿀지 모른다 (킷 §4-3 나쁜 예).
- **의사결정을 바꿀 수 없는 질문은 넣지 않는다** (킷 §4-3 원칙). 2·3행을 쓸 때 *"이 답이 나오면 무엇을 하고, 저 답이 나오면 무엇을 하나"*를 말할 수 있어야 한다.

### 3-3. C2. 제시물 명세 표 — 안별 × 3항목 ★ 하드

**열**: `항목` · `안 ㉮` · `안 ㉯` · `안 ㉰` … (안 수만큼 좌→우)
**행(순서 고정 3행)**:

| # | 행 이름 | 내용 |
|---|---|---|
| 1 | **문구 전문** | 페르소나에게 보여줄 **문장 그대로**. 「헤드라인 변경」 같은 표기는 명세가 아니다 — 응답자가 읽을 텍스트가 그 자리에 있어야 한다 |
| 2 | **담은 팩트 목록** | 그 문구가 전달하는 **사실 항목을 하나씩 불릿으로** 분해 (예: `무료임` / `소요 시간 3분` / `결과를 즉시 본다`) |
| 3 | **정보량 대조 판정** | 네 값 중 하나 — ① `통과 — 팩트 집합 동일` ② **`프레임 비교 — 팩트 개수 동일 · 상이 국면 {목록}`** ③ **`⚠️ 정보량 상이 — 교란 선언됨 {어느 안에 무엇이 적은지}`** ④ `불일치 — 미선언`. **④면 실행하지 않는다.** ②는 정상 경로, ③은 교란 선언을 붙여야만 진행 가능하다 (§7-4) |

**하드 규칙**

- **정보량 통제는 「팩트 집합 동일」이 아니라 「팩트 개수 동일 + 각 팩트가 지면에서 참」으로 판정한다** (§7-4). 정보량이 다른 두 안을 비교하면 **표현의 차이가 아니라 정보의 차이를 측정**하게 되고, 그 결과로 문구를 고를 수 없다.
  - **② 프레임 비교(허용)** — 같은 사건의 **다른 국면**을 각각 집는 경우다. `보험나이가 오른다`와 `보험료가 오른다`는 **같은 상령일 사건의 두 면이고 둘 다 참**이므로, 팩트 개수가 같으면 통제가 성립한다. 이것이 이 계약이 서겠다고 선언한 자리(DEC-014 문구 실험)의 **대표 사례**다.
  - **③ 정보량 상이(교란 선언 필수)** — 한 안의 팩트가 실제로 적은 경우다. 예: `보험나이 오르는날 임박!`은 `D-23`이 없다. 이 안이 이기면 **프레임 때문인지 짧아서인지 구별할 수 없다.** 그래서 지우지 않고 **C2 3열에 「프레임 교란 — 어느 안이 이겨도 프레임 때문인지 정보량 때문인지 구별 불가」를 명시**하고 진행한다.
  - **④ 미선언(거부)** — 개수가 다른데 선언이 없으면 **실행하지 않는다.**
- **킷 §6-③ 장치 4와의 관계 — 부정이 아니라 적용 범위 분리다.** 킷 원문(*"비교하는 두 안은 담은 팩트가 같고 표현만 달라야 합니다"*)은 **「같은 메시지의 다른 표현」**을 비교하는 상황을 전제로 쓰였고, 그 전제 안에서는 지금도 그대로 옳다. **프레임 비교는 그 전제 밖**이다 — 무엇을 손실로 읽히게 할지 자체가 가설이므로 두 안이 집는 국면이 서로 다른 것이 **설계이지 결함이 아니다.** 따라서 이 계약은 킷의 규칙을 **두 경우로 나눠 적용**한다: 같은 메시지의 다른 표현 → 팩트 집합 동일(①) / 서로 다른 언어 프레임 → 팩트 **개수** 동일 + 각 팩트 참(②). **개수까지 다른 경우(③)를 킷이 잡는 것은 옳고, 이 계약도 그것을 통제 실패로 본다** — 다만 거부하지 않고 교란 선언으로 표기해 결과 해석을 제한한다.
- **라벨은 중립 기호만** — `㉮` `㉯` `㉰` `㉱`… 순서로 쓴다. `기존안` · `신규안` · `A/B` · `개선안` 같은 라벨을 표에도 프롬프트에도 쓰지 않는다 (§7-3).
- **어느 안이 대조군(현행 문구)인지는 C1 7행에만 적고 C2·프롬프트·응답자에게 노출하지 않는다.** C2에는 중립 기호만 남는다.
- **문구가 솔루션 핵심가치(C0 5행)에서 이탈했으면 표시한다** — `⚠️ 방향 이탈 의심 — {사유}`. 이탈 판정은 사람이 한다.
- **고객 언어 검증**: 문구에 내부·업계 용어(보험 도메인 전문 용어)가 들어가 있으면 `⚠️ 고객 언어 확인 필요`로 표시한다 (ed §3-3 승계).

### 3-4. C3. 표집 조건 표 — 2열 (항목/값)

행(순서 고정 6행): `ICP 카드` · `인구통계 조건` · `행동 경험 조건` · `N` · `시드` · `추출된 UUID 목록`

| 항목 | 작성 규칙 |
|---|---|
| ICP 카드 | 킷 §3의 **카드 번호와 이름**을 그대로 쓴다 (A축: 카드 1·2·3·5 / B축: 카드 4·5). **카드를 새로 만들지 않는다** |
| 인구통계 조건 | `load_persona.py` 필터 문법 또는 자연어 조건. 데이터셋 경로면 필터 문자열을 그대로 적는다 |
| **행동 경험 조건** | **"관심 있는 사람"이 아니라 "그 행동을 실제로 한 사람"으로 좁힌다** — 예: `최근 3개월 내 보험을 점검하거나 새로 알아본 적 있음` |
| N | 숫자. 권장 5~8 (§2-1) |
| 시드 | `random_state` 값. 없는 경로면 `해당 없음 — 인구통계 호출 경로` |
| 추출된 UUID 목록 | 데이터셋 경로면 **필수**. `draw_personas.py` 출력에서 **읽어** 적는다 — 타이핑하지 않는다. 없는 경로면 `UUID 없음 — 인구통계 호출 경로 (등급 C 상한)` |

**하드 규칙**

- **모집단 미스매치는 목표 문장 오류만큼 크다** (킷 §4-2 실측 사례). 같은 질문을 일반 성인에게 물었을 때 1위 브랜드 응답이 **실측 대비 +25~34p**로 튀었고, **구매 검토층으로 좁히자 +4p까지 붙었다.** 원인은 "합성이라 절대치를 못 쓴다"보다 **모집단 미스매치**의 몫이 컸다 — **살 생각이 없는 사람에게 물으면 가장 유명한 이름으로 도피한다.**
- 그래서 **`행동 경험 조건`을 비워둔 C3는 통과가 아니다.** 비울 수밖에 없으면 사유를 적고 R1에서 미충족으로 카운트한다.
- **데이터셋 경로에서 UUID 목록이 없으면 등급을 산출하지 않는다** (§7-13).

### 3-5. C4. blind · 순서 배정 표 — 4열 ★ 하드

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 응답자 | `RSP-{n}` + 데이터셋 경로면 `uuid8` 병기 |
| 2 | 제시 순서 | 실제로 제시한 순서를 **중립 기호로** (예: `㉯ → ㉮ → ㉰`) |
| 3 | counterbalancing 방식 | `순환(라틴방격)` / `역순 교대` / `무작위(시드 명기)` 중 하나 + 근거 |
| 4 | 금지 어휘 검사 | `통과` / `걸림 — {발견된 어휘}`. 프롬프트 조립 시점에 검사한 결과 |

**하드 규칙**

- **전원이 같은 순서를 보지 않게 하고, 선택한 방식(3열)대로 순열에 분산시킨다** (§7-5). 순서를 고정하면 **첫 안이 기준점이 되어 뒤 안이 항상 비교 대상으로 읽힌다.** 순서 기록이 없는 run은 순서 효과와 문구 효과를 분리할 수 없다.
  - **「전원이 서로 다른 순서」를 요구하지 않는다.** 2안이면 순열이 2개뿐이므로 N=5~8에서는 **같은 순열이 반복되는 것이 정상**이다 — 역순 교대(`㉮㉯ / ㉯㉮ / ㉮㉯ …`)가 규격대로 돌린 모습이다. 판정 기준은 **분산**이지 전원 상이가 아니다.
  - **미배정 순열이 남았으면 그 사실을 3열에 병기한다** (`역순 교대 — 미배정 순열 1종 남음`). 배정 스크립트가 경고를 내면 그 경고를 그대로 옮긴다 — R1 T-6에서 Warning으로 읽히고 Fail이 아니다.
- **금지 어휘 검사 대상(최소)**: `신규` · `기존안` · `저희가 만든` · `새로 준비한` · `개선한` · `A안/B안`. **프롬프트를 조립하는 시점에 검사하고 결과를 이 열에 남긴다** — 트랜스크립트를 사후에 훑는 것으로 대신하지 않는다 (§7-3).
- **N행 전부 채운다.** 응답자 1명이라도 순서 기록이 없으면 C4는 미충족이다.

### 3-6. C5. 응답자별 3축 표 — 6열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 응답자 | `RSP-{n}` (+ `uuid8`) |
| 2 | 안 | 중립 기호 (한 응답자 × 안 수만큼 행이 생긴다) |
| 3 | **멈춤** | 손이 먼저 멈추는가 — `멈춤` / `안 멈춤` / `애매함` + 한 줄 |
| 4 | **믿음** | 믿음이 가는가 — `믿음` / `안 믿음` / `애매함` + 한 줄 |
| 5 | **실행의향** | `넘긴다` / `본다` / `눌러본다` 중 **실제 행동으로** |
| 6 | **원문 인용** | 응답자가 스스로 쓴 표현 **그대로**. 요약·윤문 금지 |

**표 아래 필수 2줄** (응답자별로 1세트)

1. **반사실 답변**: *"이 화면을 보고도 안 누른다면 무엇 때문일까요?"* 에 대한 답 — **원문 인용**. 전 응답자에게 반드시 묻는다 (§7-7).
2. **페인 선행 구간 요약**: 시안 제시 **전에** 열린 질문으로 끌어낸 걸림돌 (§7-6).

**하드 규칙 — 3축을 합치지 않는다 (§7-9 · 반드시 조문으로 지킨다)**

- **멈춤(시선)과 믿음(신뢰)은 갈린다.** 킷 §6-③ 실측 사례에서 **"믿음은 A안, 팔로우는 C안"으로 교차 투표한 응답자들**이 나왔다.
- 따라서 **C5·C6은 3축을 끝까지 분리해 적는다.** **"좋다/나쁘다" 단일 축으로 접는 출력을 금지한다** — `종합 점수`·`선호도`·`총평 ★` 같은 열을 만들지 않는다.
- **감정 형용사만 있고 장면이 없는 답변은 근거로 쓰지 않는다** (킷 §9-1 「과공손」). "번거로웠어요"만 있으면 꼬리질문으로 **구체적 장면**을 확인하고, 못 얻으면 `장면 미확보`로 표기한다.
- **응답자들의 표현까지 똑같으면 「매끄러운 서사」를 의심한다** (킷 §9-1). 반대로 **서로 다른 응답자가 각자 다른 근거로 같은 논리에 도달했다면 신호 강도가 높다** (킷 §6-③).
- 데이터셋 경로면 **`results.json`의 키가 `drawn_personas.jsonl`에 있는 uuid인지** `validate_results.py`로 확인한 뒤 이 표를 낸다 — **호출은 §1에 못박은 형태(`--require "arms,counterfactual"` 포함)로** 한다.

### 3-7. C6. 집계 표 — 5열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 안 | 중립 기호 |
| 2 | 멈춤 | **`멈춤 n/N` + 3값 분포 병기** — 표기 예: `3/5 (멈춤 3 · 안 멈춤 1 · 애매함 1)` |
| 3 | 믿음 | **`믿음 n/N` + 3값 분포 병기** — 표기 예: `2/5 (믿음 2 · 안 믿음 1 · 애매함 2)` |
| 4 | 실행의향 | **`눌러본다 n/N` + 3값 분포 병기** — 표기 예: `2/5 (눌러본다 2 · 본다 1 · 넘긴다 2)` |
| 5 | **C1 조건 대조** | `사전등록 채택조건 충족` / `사전등록 기각조건 충족` / `조건 밖 — 대조 불가` + 어느 조건의 어느 대목인지 한 줄 |

**하드 규칙**

- **`n/N`으로만 적는다. 백분율 단독 표기 금지** — 합성에서 **절대 %는 인용 금지**이고 **분포의 모양은 논할 표본이 아니다** (킷 §9-2). `4/5`는 정상, `80%`는 위반이다. **괄호 안 분포도 세 축 모두 개수로 적는다** — 비율로 쓰면 같은 위반이다.
- **세 축 모두 `분자 n/N` + 3값 분포를 병기한다.** 분자는 축별로 고정이다 — 멈춤은 `멈춤`, 믿음은 `믿음`, **실행의향은 `눌러본다` 단독**이다(이 분자를 흐리면 더 나빠진다).
- **분포 안 값의 순서 규칙 (고정)**: **명명된 값을 먼저 쓰고 `애매함`을 마지막에 둔다** — `애매함`은 판정에 쓰이지 않는 잔여값이라 끝에 오는 것이 읽기 좋다. **실행의향은 행동 강도 내림차순**(`눌러본다 → 본다 → 넘긴다`)이며 같은 원리(강한 값부터)다. **예시만 보고 순서를 바꾸지 않는다** — 집계 스크립트의 축 상수와 같은 순서다.
  - 근거: **3값을 하나의 `n/N`으로 접으면 정보가 사라지고, 그 손실은 §7-9(3축을 합치지 않는다)가 금지하는 것과 같은 종류다.** 세 축이 모두 3값이라 같은 손실이 세 번 일어난다 — 실행의향에서 `본다`가 몇 명인지가 사라지면 "안 누르지만 읽기는 한다"와 "아예 넘긴다"가 같은 칸에 들어가고, **멈춤·믿음에서도 `애매함 2 / 안 멈춤 2`와 `안 멈춤 4`가 같은 칸에 들어간다.**
  - **분포를 뺀 채 분자만 적은 C6는 통과가 아니다 — 세 축 중 하나라도 빠지면 미충족이다** (R1 T-17).
- **5열은 「대조 결과」이지 「판정」이 아니다.** `사전등록 채택조건 충족`은 *C1에 적어 둔 조건과 이번 결과가 맞아떨어졌다*는 사실 진술이며, 이것을 **`㉯ 채택` · `㉮ 탈락` · `㉯ 1순위`로 번역하는 순간 §7-10 위반**이다. 번역은 ed 세션에서 사람이 한다.
- **3축을 합산하거나 평균하지 않는다** (§7-9). 축별로 따로 대조한다.
- 안이 3개 이상이면 행이 늘어날 뿐 열은 고정이다. **순위 열을 추가하지 않는다.**

| # | 열 이름 | 내용 |

| 1 | 후보 문장 | **응답자가 스스로 쓴 표현 그대로** (윤문·다듬기 금지) |

**하드 규칙**

- **①의 3열을 비우지 않는다.** 못 푼 걸림돌은 **실험 후보를 지우는 근거가 아니라 확인할 항목으로 강등하는 근거**다 (§7-10 · 킷 §6-③).
- **User Voice 문장에 솔루션이 섞이면 안 된다** — `비교표가 없어서 판단이 안 선다`는 OK, `비교표를 만들어야 한다`는 NG(솔루션 역기술) (킷 §7-1 · `_common-brief.md` §2).
- **②는 문구 보완 지시의 재료**다. 여기서 나온 표현으로 **문구를 확정하지 않는다** — 지시까지다 (§7-10).

### 3-9. C8a. 노션 갱신 블록 ★ 착지 (코드블록)

노션 실험설계서 `1-3) 솔루션 설명 및 근거` 안 **「합성 UT 결과」 소절**에 붙일 내용을 **코드블록(raw markdown)**으로 출력한다 — 참가자가 붙여넣는다.

**소절 구성(순서 고정 6부)**

| # | 구성 | 재료 |
|---|---|---|
| 1 | **경고문** (§7-14) | 킷 §8-5 문구 **그대로**. 소절 최상단, 지우지 않는다 |
| 2 | 사전등록 요약 | C1 1~4행 (결정 · 채택 조건 · 기각 조건 · 판정 단위) — **아래 인용 형식으로만 적는다** |
| 3 | 제시물 요약 | C2 1행(문구 전문) + **`정보량 대조: {C2 3행 값 그대로}`** — 4값 중 실제 값을 옮긴다. **③이면 교란 문장을 함께 옮긴다**(아래 하드 규칙) |
| 4 | 집계 | C6 전문 (`n/N` 표기 그대로) |
| 5 | 걸림돌 · 고객 언어 | C7 ① 3열 + ② 전문 |
| 6 | 등급 · 재현성 · 근거 지위 | `신뢰등급 {A/B/C}` 또는 **`등급 미산출 — 재현성 기록 없음`** + `— {근거}` · `시드 {값} / 모델 {값} / 표본 {N}` · `근거유형 합성 · Confidence 상한 1~3` (§7-13) |

**규칙**

- **3부 정보량 대조는 C2 3행 값을 그대로 옮긴다 (하드).** `통과`를 하드코딩하지 않는다 — 4값(§3-3) 중 실제 값을 적는다.
  - **③ `⚠️ 정보량 상이 — 교란 선언됨`이면 교란 문장을 3부에 함께 옮긴다**: `⚠️ 프레임 교란 — 어느 안이 이겨도 프레임 때문인지 정보량 때문인지 구별 불가 ({어느 안에 무엇이 적은지})`.
  - **이 한 줄이 없으면 교란 선언이라는 장치가 착지 경로에서 소멸한다.** 선언은 `stimuli.md`에만 남고, 그 파일은 §1·§4가 **「착지물이 아니라 증빙」**으로 못박은 파일이다. 정작 **그 제한을 읽어야 하는 사람이 읽는 유일한 면이 이 소절**(ed 세션)이며, §7-10이 말한 오독(*「팩트를 빼도 된다」로 읽는 것*)이 일어나는 자리도 정확히 거기다.
  - ③ run인데 `통과`로 적으면 **허위 진술이 고객사 노션에 남는다** — 값 불일치는 T-5 Fail이다.
- **2부 사전등록 요약은 인용 표기를 붙여 적는다 (하드).** C1 원문을 그대로 옮기되 **인용 블록으로** 감싸고 「사전등록 원문, 인용」을 병기한다 — 형식은 아래를 그대로 쓴다.
  ```
  > 이 테스트로 내릴 결정(사전등록 원문, 인용): …
  > 채택 조건(사전등록 원문, 인용): …
  > 기각 조건(사전등록 원문, 인용): …
  > 판정 단위(사전등록 원문, 인용): n/N (N=…)
  ```
  - **이 표기가 §7-10 검사의 예외 표식이다.** 채택 조건 문장에는 「~이면 ㉯ 방향」 같은 판정형 표현이 들어 있는데, 표기가 없으면 GATE 2 리뷰어는 **§3-9(필수 기입)와 §7-10(판정형 문장 삭제)이 같은 문장에 반대를 지시하는 상황**에 놓인다. **인용 표기가 붙은 줄은 검사 대상이 아니고, 표기 없이 같은 내용이 본문으로 적혀 있으면 §7-10 위반**이다.
- **착지 위치는 `1-3` 안의 소절 하나다.** `1-4`(지표)·`3-x`(설계)를 건드리지 않는다 — 그쪽은 ed 소관이다.
- **`1-3`의 기존 내용을 덮어쓰지 않는다.** 소절을 **신설**해 붙인다. 이 소절이 이미 있으면 `기존: … → 정정: …`으로 표기한다 (ed §3-9 · hg §3-8 승계).
- **ed E2가 이 소절을 「선정 근거」로 인용할 수 있다.** 인용은 **ed 세션에서 사람이 손으로** 하며(ed 쪽 수신 필드는 아직 없다 — §0-2), **이 블록이 E2 표의 칸을 쓰지 않는다.**
- **판정권 상한을 넘는 문장이 블록에 들어가면 착지시키지 않는다** (§7-10). GATE 2에서 검사한다.
- 코드블록 안에 코드블록이 중첩되면 **바깥 펜스를 4백틱(````)으로** 연다 (ed §3-10 승계).

### 3-10. C8b. run manifest 표 — 2열 (항목/값)

`manifest.json`에 남는 값을 사람이 읽을 수 있게 표로도 낸다. **스키마는 orchestration.md의 것을 그대로 쓰고, 아래 2개 키만 이 계약이 추가한다.**

행(순서 고정 8행): `slug` · `created` · `N` · `random_state` · `model` · `phase_status` · **`prereg_sha256`** · **`stimuli_sha256`**

| 항목 | 작성 규칙 |
|---|---|
| `slug` | `<YYYY-MM-DD>-<slug>-ct` (§6) |
| `N` · `random_state` | C3와 문자 단위 일치. 데이터셋 없는 경로면 `random_state: null` + C3에 사유 |
| `model` | 실제로 응답을 만든 모델 ID. **기억으로 적지 않는다** |
| `phase_status` | §1의 6키. 각 STEP 끝에서 먼저 쓴다 |
| **`prereg_sha256`** | `prereg.md`의 SHA-256 (예: `shasum -a 256 prereg.md`). **GATE 1 통과 시점에 기록하고 그 뒤 다시 계산하지 않는다** |
| **`stimuli_sha256`** | `stimuli.md`의 SHA-256. 같은 시점에 함께 기록 |

- **해시가 없으면 「사전등록했다」고 말할 수 없다** (§7-1). 해시 없는 run은 등급 C 상한이다.
- **리뷰 시 해시를 재계산해 대조한다** (§3-12 T-2 · R2 ⑤).

| W-5 | **S가 P를 정면으로 푸는가** (잣대 4) | 제시물이 가설이 겨냥한 문제를 **정면으로 건드리는가** — 우회면 Warning. 솔루션 핵심가치(C0 5행)에서 이탈했으면 Fail |
| W-6 | **문서 본문 동기화** (잣대 1·6 부수) | 결과가 노션 `1-3` **본문 소절**에 반영됐는가 — **하단 코멘트나 첨부에만 있으면 리뷰어는 못 읽는다** |
| W-7 | **인정은 그 자리에서 짧게** (잣대 8) | R2 ④에 잘 된 부분을 **위치와 함께** 구체적으로 남겼는가 (리뷰어 자신에 대한 체크) |

- **Warning은 Pass로 카운트한다** (hg·ed 정본 승계).
- **품질 점수 = Pass ÷ 판정 대상 × 100%** (Warning은 Pass 카운트, `N/A`·해당 경로 Optional은 분모 제외).
- **등급**: `A(90%+)` / `B+(80%+)` / `B(70%+)` / `C(50%+)` / `D(<50%)`. **이 문서 품질 등급은 §7-12의 신뢰등급(A/B/C)과 다른 축이다** — 혼용하지 않는다. 품질 등급은 규격 준수율, 신뢰등급은 합성 결과들끼리의 상대적 견고함이다.
- **T-1·T-2·T-11b가 Fail이면 품질 점수와 무관하게 착지시키지 않는다** — 사전등록과 판정권 상한은 이 절차의 존재 이유다. **T-14·T-15(등급·재현성) Fail은 착지를 막지 않는다** — 정직하게 표기된 미산출은 착지된다 (§7-13).
- **2026-08-31 이전 작성 문서에 이 계약을 소급 적용하지 않는다** (제정 배너).

## 7. 공식 · 판정 규칙 (정본 — 위반 금지)

**규칙마다 「판정 질문」이 붙어 있다. 서술로만 있으면 리뷰에서 쓰이지 않는다** — 이 프로젝트에서 실제로 그래서 결손이 통과한 사례가 있다(ed 계약 DEC-014 ③: 임무가 서술로만 있어 화면 안 행동을 재는 Secondary가 0개인 설계서가 통과했다). **각 판정 질문은 필수 출력**이며, 답이 "아니다"일 때의 처리를 그 자리에 적었다.

**7-1. 사전등록 불변 (하드).** C1을 **파일(`prereg.md`)로 먼저 쓰고** SHA-256 해시를 C8b manifest에 남긴다. 실행 후 C1을 수정하면 **등급 C로 강제 강등**한다.
- **판정 질문(필수 출력)**: *"C1이 필드 시작 **전에** 파일로 저장됐고, 지금 다시 계산한 해시가 manifest 값과 같은가?"*
- **"아니다"일 때**: 해시 불일치 → **등급 C 강제 강등** + R1 T-2 Fail. 파일 자체가 없으면 → **STEP 2로 넘어가지 않고 중단**, C1을 쓰고 다시 시작한다.
- 근거: **결과를 보고 해석을 만들면 합성은 항상 「좋다」고 나온다** (킷 §6-③ 장치 1).

**7-2. 대조군 arm 필수 (하드).** 시안 단독 제시를 금지한다. **한 응답자에게 전 안을 제시**한다(within-subject).

- **「대조군 arm」의 정의를 여기서 확정한다 — `현행 운영 문구 1안을 필수로 포함한 within-subject 제시`다.** 킷 §6-③ 장치 2가 *"시안 단독으로 묻지 않고 **기존안과 나란히** 보여준다"*이고 킷 §9-3의 등급 B가 그 어휘를 쓰고 있으므로, **「2안 이상」은 실행 최소조건이고 「대조군 arm」은 그보다 좁다.** 두 층을 섞지 않는다.

| 구성 | 실행 | 대조군 arm | 등급 |
|---|---|---|---|
| 현행 문구 + 새 프레임 1안 이상 (전원이 전 안을 봄) | 가능 | **있음** | 사전등록까지 갖추면 **B 가능** |
| 새 프레임 2안 이상, **현행 문구 없음** | 가능 | **없음** | **C 상한** (사전등록이 있어도 B로 올라가지 않는다) |
| 1안뿐 | **거부** | — | — |

- **판정 질문(필수 출력) 2단**: ① *"응답자 한 명이 **모든 안을 다 봤는가**?"* ② *"제시된 안 중에 **현행 운영 문구가 하나 들어 있는가**?"*
- **"아니다"일 때**: ①이 아니면 — 1안뿐이면 **실행 거부**(C0 7번 행으로 되돌린다), 응답자별로 서로 다른 1안만 봤으면(between-subject) 등급 **C 상한** + R1 T-3 Fail. ②가 아니면 — **실행은 하되 등급 C 상한**이며 C1 7행에 `없음 — 신설 지면(등급 C 상한)`으로 적는다. **②만 아닌 것은 Fail이 아니다**(설계 선택이지 결함이 아니다).
- **현행 문구가 실제로 없는 신설 지면은 ②의 정상 예외**다. 지면에 이미 문구가 있는데 넣지 않은 것은 예외가 아니라 누락이다.
- 근거: 킷 §6-③ 장치 2 · §9-3(대조군 arm이 등급 B의 조건).

**7-3. blind 유지 (하드).** 어느 쪽이 신규 시안인지 숨긴다. **금지 어휘를 프롬프트 조립 시점에 검사**하고 결과를 C4 4열에 남긴다.
- 금지 어휘(최소): `신규` · `기존안` · `저희가 만든` · `새로 준비한` · `개선한` · `A안/B안`.
- **판정 질문(필수 출력)**: *"프롬프트에 어느 안이 새 안인지 알려주는 표현이 **한 개도 없는가**? 라벨이 중립 기호뿐인가?"*
- **"아니다"일 때**: 조립 전 발견 → 어휘를 지우고 진행. **필드 후 발견 → 해당 응답자 응답을 집계에서 제외**하고 제외 사실을 C6 아래에 적는다. 전 응답자에 걸렸으면 run 전체를 등급 C로 강등하고 재실행을 권고한다.
- 근거: **"저희가 새로 만든 안"이라고 말하는 순간 답이 정해진다** (킷 §6-③ 장치 3).

**7-4. 정보량 통제 (하드 — 2단 판정).** **C2 3열 판정 통과가 실행 조건**이다. 기준은 **팩트 집합의 동일성이 아니라 「팩트 개수 동일 + 각 팩트가 지면에서 참」**이다.

- **판정 질문 ①(필수 출력)**: *"두 안의 **팩트 개수가 같고**, 각 안의 팩트가 **모두 지면에서 참인가**?"*
  - "그렇다" → C2 3열 `통과 — 팩트 집합 동일`(같은 메시지의 다른 표현) 또는 **`프레임 비교 — 팩트 개수 동일 · 상이 국면 {목록}`**(서로 다른 언어 프레임). **둘 다 정상 실행 경로다.**
- **판정 질문 ②(필수 출력, 개수가 다를 때만)**: *"개수가 다르면, 그 차이를 C2에 선언하고 **「프레임 교란 — 어느 안이 이겨도 프레임 때문인지 정보량 때문인지 구별 불가」**를 명시했는가?"*
  - "그렇다" → `⚠️ 정보량 상이 — 교란 선언됨 {어느 안에 무엇이 적은지}`로 **진행 가능**. 단 그 안이 이긴 결과는 **프레임 근거로 쓸 수 없다**(교란 선언이 그 제한을 문서에 박는 장치다).
  - **"아니다"(선언 없음) → 실행하지 않는다.** 팩트를 맞추거나, 그 팩트 자체를 실험 변수로 올려 **문구 테스트가 아니라 정보량 테스트임을 C1 1행에 다시 쓴다.** 미선언 상태로 돌린 run은 R1 T-5 Fail이며 결과를 문구 선택 근거로 쓸 수 없다.
- **왜 규칙을 이렇게 갈랐는가** — 종전 1단 판정(`팩트 목록이 항목 단위로 같은가`)은 **이 계약이 서겠다고 선언한 자리의 대표 사례를 GATE 1에서 거절했다.** `보험나이 오르기까지 D-23일`과 `보험료 오르기까지 D-23일`은 **같은 상령일 사건의 두 국면**이고 둘 다 참이지만 팩트 집합은 같지 않다(DEC-014 · ed §3-6). 반면 `보험나이 오르는날 임박!`은 **팩트가 실제로 적어**(D-23 없음) 이기더라도 원인을 가릴 수 없다 — **1단 판정이 후자를 잡는 것은 옳았고, 두 경우를 구분하지 못하는 것이 결함이었다.**
- **킷 §6-③ 장치 4와의 관계 — 부정이 아니라 적용 범위 분리다** (근거 서술은 §3-3 하드 규칙에 있다). 킷 원문은 **「같은 메시지의 다른 표현」** 을 전제로 쓰였고 그 전제 안에서는 그대로 옳다. **프레임 비교는 그 전제 밖**이며, 무엇을 손실로 읽히게 할지가 곧 가설이므로 두 안이 집는 국면이 다른 것이 설계다. **개수까지 다른 경우를 킷이 잡는 것은 옳다** — 이 계약도 그것을 통제 실패로 보되, 거부 대신 교란 선언으로 표기해 해석을 제한한다.
- 근거: 킷 §6-③ 장치 4 · ed §3-6(DEC-014 문구 변주 예외).

**7-5. 순서 counterbalancing 강제 (하드).** 제시 순서를 **순열에 분산**시키고 C4에 응답자별로 기록한다.

- **판정 질문(필수 출력)**: *"응답자 **N명의 제시 순서가 C4에 각각 적혀 있고**, **전원이 같은 순서를 본 것이 아니며 선택한 방식(§3-5 3열)대로 순열에 분산됐는가**?"*
- **「전원이 서로 다른 순서」를 요구하지 않는다.** 2안이면 순열이 **2개뿐**이고 권장 N은 5~8이므로, N=5에서 5개가 다 다를 수 없다. **역순 교대**(`㉮㉯ / ㉯㉮ / ㉮㉯ …`)가 규격대로 돌린 정상 모습이다 — 종전 문언(`순서가 서로 다른가`)은 기본 구성에서 Pass가 불가능해 **규격을 지킨 run이 문구 하나로 등급을 잃었다.**
- **"아니다"일 때 — 계단화한다.**

| 상태 | 처리 |
|---|---|
| 방식대로 분산됐고 **미배정 순열이 남았다**(배정 스크립트 경고 있음) | **Warning** — C4 3열에 경고를 그대로 병기하면 Pass로 카운트 |
| **순서가 1종뿐**(전원이 같은 순서) | **Fail** — 순서 효과와 문구 효과를 분리할 수 없으므로 **등급 C 상한** |
| 기록만 없다 | 트랜스크립트에서 **복원**해 C4를 채운다 (복원 불가면 Fail) |

- 근거: 킷 §6-③ 제시 프롬프트 *"제시 순서는 응답자마다 바꿔 주세요."* — 요구의 핵심은 **분산**이며, 배정 스크립트도 counterbalancing을 「순열 전체에 대한 균형」으로 구현한다.

**7-6. 페인 선행 (하드).** 시안을 보여주기 **전에** 열린 질문으로 걸림돌을 먼저 끌어낸다.
- **판정 질문(필수 출력)**: *"트랜스크립트에서 **첫 시안 제시보다 앞에** 걸림돌을 묻는 열린 질문 구간이 있는가?"*
- **"아니다"일 때**: 이미 필드했으면 → 해당 응답의 **걸림돌 항목(C7 ①)을 「시안 제시 후 회고」로 표기**하고 강도를 낮춰 읽는다. 아직 필드 전이면 → 프롬프트를 고쳐 다시 조립한다.
- 근거: 킷 §6-③ 장치 4(앵커링·칭찬 유도 방지) · §5 유도질문 금지 원칙.

**7-7. 반사실 필수 (하드).** **"이 화면을 보고도 안 누른다면 무엇 때문일까요?"** 를 전 응답자에게 묻는다.
- **판정 질문(필수 출력)**: *"**모든 응답자**의 반사실 답변이 원문으로 남아 있는가?"*
- **"아니다"일 때**: 빠진 응답자는 **C5 반사실 줄에 `미확보`로 남긴다**(지우지 않는다). 절반 이상 미확보면 R1 T-8 Fail.
- 주의: **반사실 답변은 "그럴듯한 개선안"으로 흐르기 쉽다** — 그건 솔루션 제안이지 원인이 아니다 (킷 §6-④ 확인 포인트). 개선안으로 흘렀으면 그 사실을 병기한다.

**7-8. 도메인 실무자 검토 게이트 (하드).** **시나리오·시안 설명은 실무자(상담사 · 해당 축 PM)의 검토 확인 없이 실행하지 않는다.**
- **판정 질문(필수 출력)**: *"이 시나리오와 시안 설명을 **실무자 누가 언제 검토했는가**? 그 기록이 run에 남아 있는가?"*
- **"아니다"일 때**: **실행하지 않는다.** GATE 1을 통과시키지 않는다. 실무자 부재로 지연되면 C0 10번 행에 `검토 대기 — {담당}`으로 두고 세션을 멈춘다(등급을 낮춰 진행하는 우회를 허용하지 않는다).
- **근거 — 이 규칙만 다른 규칙들과 성격이 다르다**: **합성 응답자는 거짓 전제를 반박하지 않는다.** 비현실적인 시나리오를 준 run에 **100명 전원이 그대로 연기하며 그럴듯한 숫자(4.13 · 80%)를 만들었다.** **계기 결함은 분포 이상으로 잡히지만 시나리오 오류는 깨끗한 데이터를 만들어 안 걸린다** (킷 §6-③ · §9-1). 다른 결함은 사후에 잡을 수 있지만 **이것은 사전 검토밖에 방법이 없다.**

**7-9. 세션 분리 + 3축 분리 (하드).**
- **세션 분리**: **시안을 만든 대화 세션에서 반응을 받지 않는다.** 같은 세션에서 만들고 평가하면 자기 확증이 된다 (킷 §6-③).
  - **판정 질문(필수 출력)**: *"이 시안을 **만든 세션과 반응을 받은 세션이 다른가**?"*
  - **"아니다"일 때**: 등급 **C 상한** + R1 T-10 Fail. 재실행 시 새 세션에서 필드한다.
- **3축 분리**: **멈춤(시선)과 믿음(신뢰)과 실행의향을 끝까지 분리해 적는다.** 킷 실측 사례에서 **"믿음은 A안, 팔로우는 C안"** 교차 투표가 나왔다.
  - **판정 질문(필수 출력)**: *"C5·C6에서 **세 축이 각각 따로 읽히는가**? '좋다/나쁘다' 단일 축으로 접은 열이나 문장이 있는가?"*
  - **"아니다"일 때**: 단일 축으로 접은 열·문장을 **삭제한다.** 종합 점수·선호도·총평 형태의 산출은 어떤 형태로도 출력하지 않는다. 이미 착지했으면 정정한다.

**7-10. 판정권 상한 (하드 — 이 계약의 가장 중요한 규칙).** 아래를 **산출하지 않는다**: `채택 선언` · `기각 선언` · `variant 순위` · `variant 탈락` · `실험 미진행 권고`.
- **허용 산출은 네 가지뿐**: ① 안별로 걸리는 지점(원문 인용) ② 어느 안도 못 푼 걸림돌 ③ 고객 언어 카피 후보 ④ 문구 보완 지시 (§0-3).
- **좁힐 수 있는 것은 프레임이지 팩트가 아니다.** 이 절차가 줄이는 것은 「어떤 언어 프레임을 실험에 태울지」의 후보 폭이며, **어떤 팩트를 지면에서 뺄지·넣을지는 이 결과로 정하지 않는다** — 팩트 구성은 실험 설계(ed E2)와 지면 정책의 몫이다. 정보량이 다른 안이 이겼을 때 그것을 「팩트를 빼도 된다」로 읽는 것이 §7-4가 교란 선언으로 막는 오독이다.
- **합성 전원 거부도 실험 후보에서 지우는 근거가 아니다.** **실험 설계에서 확인할 항목으로 강등하는 근거**일 뿐이다 (킷 §6-③).
- **C6 5열의 `사전등록 채택조건 충족`은 사실 진술이다** — 이것을 `㉯ 채택` · `㉮ 탈락` · `㉯ 1순위`로 번역하는 순간 위반이다. 번역은 ed 세션에서 사람이 한다.
- **예외 — 인용 표기가 붙은 사전등록 원문 줄은 검사 대상이 아니다.** C1의 채택·기각 조건에는 본래 판정형 표현(`~이면 ㉯ 방향`)이 들어 있고, C8a 2부는 그것을 **필수로** 기입하게 한다(§3-9). 그래서 **`> 채택 조건(사전등록 원문, 인용): …` 형식으로 표기된 줄은 이 규칙이 보지 않는다.** 표기 없이 같은 내용이 **본문 문장으로** 적혀 있으면 위반이다 — 예외는 **표기에 붙는 것이지 내용에 붙는 것이 아니다.**
- **판정 질문(필수 출력)**: *"이 산출물에 **어느 안을 쓰라거나 쓰지 말라는 문장이 있는가**? 안에 순위를 매긴 곳이 있는가? — **인용 표기가 붙은 사전등록 원문 줄은 세지 않는다.**"*
- **"아니다"(= 그런 문장이 있다)일 때**: **해당 문장을 삭제하고** 허용 산출 4종 중 하나로 다시 쓴다. 삭제하지 않은 채로 **착지시키지 않는다**(GATE 2에서 막는다). R1 **T-11b** Fail이면 품질 점수와 무관하게 착지 불가다.
- 근거: 합성은 **가설 생성기이고 근거가 아니다** (킷 §0). 판정을 대체하면 안 된다 (킷 §1 ④ 경계 선언과 같은 원칙).

**7-11. 근거유형 `합성` + Confidence 상한 1~3 (하드 — 재정의 금지, 인용).** **정본은 `hb-output-contract.md` §2-6(근거유형 3값) · §7-4(C 앵커 4밴드 · 합성 하드 상한)** 이며, 어긋나면 hb가 이긴다. 그루밍 쪽 대응은 `hg-output-contract.md` §7-5 Rationale 7유형 중 **유형 6 「합성소비자 UT」**(이 유형만 있으면 C 1~3 상한)다.
- 이 계약은 값을 **읽어 쓰기만** 한다 — 밴드를 새로 만들거나 상한을 조정하는 절차를 만들지 않는다.
- **인터뷰를 20명 돌려도 상한은 같다. 숫자가 아니라 근거의 종류가 상한을 정한다** (킷 §8-2).
- 실측(실사용자 UT·상담사 인터뷰)과 **같은 방향**이면 `혼합`으로 표기하고 삼각검증됨으로 격상할 수 있다 — **격상해도 합성 부분 자체가 근거로 승격되지는 않는다** (킷 §8-3).
- **판정 질문(필수 출력)**: *"착지면에 **근거유형 `합성`과 Confidence 상한 1~3**이 적혀 있는가?"*
- **"아니다"일 때**: C8a 6부에 추가한다. 이미 착지했으면 정정한다. R1 T-13 Fail.

**7-12. 신뢰등급 판정 (하드 — 킷 §9-3 정본).**

| 등급 | 기준 |
|---|---|
| **A** | **독립 표본 2개 이상**에서 재현됨 (다른 조건으로 한 번 더 돌려 같은 결론) |
| **B** | 단일 run이되 **대조군 arm + 사전등록**을 갖춘 설계 — 여기서 **대조군 arm = 「현행 운영 문구 1안을 포함한 within-subject 제시」**(정의는 §7-2) |
| **C** | 단일 run, 대조 없음 |

- **등급 B는 두 조건을 **모두** 갖춰야 한다** — 하나만 있으면 C다.
- **새 프레임끼리만 비교한 run(현행 문구 미포함)은 사전등록이 있어도 C다** (§7-2 표). 실행은 정상이며 Fail이 아니다 — **등급만 C 상한**이다.
- **데이터셋 없는 경로는 재현 불가이므로 C 상한**이다 (§2-4 · §7-13).
- **등급이 무엇이든 §7-11의 Confidence 상한 1~3은 그대로다.** 신뢰등급은 **합성 결과들끼리의 상대적 견고함**이지 실측을 대신하는 눈금이 아니다 (킷 §9-3).
- **판정 질문(필수 출력)**: *"이 run의 등급은 무엇이고, **그 등급을 준 조건이 run 파일에서 확인되는가**?"*
- **"아니다"일 때**: 확인되지 않는 등급은 **한 단계 내린다.** 근거를 못 대는 B는 C다.

**7-13. 재현성 (하드).** **시드 · UUID · 모델 · 타임스탬프를 기록한다. 없으면 등급을 산출하지 않는다.**
- **판정 질문(필수 출력)**: *"같은 조건으로 다시 돌리면 **같은 표본이 나오는지 이 문서만 보고 확인할 수 있는가**?"*
- **"아니다"일 때**: 데이터셋 경로인데 시드·UUID가 없으면 → **등급 산출 불가**. 인구통계 호출 경로면 → `등급 C 상한 — 재현 불가`를 **명시**해야 Pass다(빠지면 T-15 Fail).
- **`등급 미산출 — 재현성 기록 없음`은 착지 가능한 값이다 (착지를 막지 않는다).** C8a 6부의 값 도메인은 `신뢰등급 {A/B/C}`와 **이 값**을 함께 갖는다 — 등급 칸을 **비우지 않고 이 문자열을 적는다.** 빈 칸은 「아직 안 썼다」와 「쓸 수 없다」를 구분하지 못하고, 등급이 사라진 상태로 착지하면 읽는 사람이 **C로 읽거나 등급 없음을 무등급 통과로 읽는다.**
  - 착지를 막는 값은 §7-10 위반(T-11b)·§7-14 경고문 누락 두 가지이며, **재현성 결손은 그 목록에 없다** — 정직하게 표기된 미산출은 착지된다. 대신 `⚠️ 이 결과로는 등급을 말할 수 없습니다 — 재현 기록이 없습니다` 한 줄을 함께 적는다.
- **시드는 반드시 고정한다(예: 42).** 같은 조건으로 다시 돌렸을 때 같은 표본이 나와야 **"다시 해 보니 달랐다"를 판단할 수 있다** (킷 §4-7).
- **UUID를 지어내지 않는다.** `results.json`의 키가 `drawn_personas.jsonl`에 없으면 `validate_results.py` exit 2 — **하드 스톱**이다 (§1 불변식).

**7-14. 경고문 강제 (하드).** 산출물 **최상단**에 아래 문구를 **그대로** 넣는다 (킷 §8-5).

> ⚠️ 아래는 합성 인터뷰 결과로, 가설이지 근거가 아닙니다. 실제 고객 UT·상담사 인터뷰로 검증 전까지 확정된 문제로 취급하지 마세요.

- **문구를 고치거나 줄이지 않는다.** C8a 착지면에서도 지우지 않는다 — **문서가 옮겨 다니는 동안 이 한 줄이 유일한 표시다** (킷 §7).
- **판정 질문(필수 출력)**: *"산출물 최상단에 이 경고문이 **문구 그대로** 있는가?"*
- **"아니다"일 때**: 넣고 다시 출력한다. **경고문이 없는 산출물은 착지시키지 않는다.**
