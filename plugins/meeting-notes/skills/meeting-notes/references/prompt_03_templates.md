# 2차 가공 — 유형별 산출물 템플릿

## 유형 판별 (템플릿 적용 전에 먼저)

우선순위: **사용자 지시 > 파일명 키워드 > 캘린더 일정 제목 > LLM 분류**(앞 20분 발췌로 판단)

| 유형 | 신호 |
|---|---|
| 회의록 | 기본값. 여러 명의 논의·결정 |
| 강의 | 한 화자 발화 비중 70%+, 설명체, 질문이 뒤에 몰림 |
| 인터뷰 | 질문-답변 교대, 한 명이 주로 묻고 한 명이 주로 답함 |
| 워크샵 | 2시간 이상 + 강의와 실습 구간이 섞임 + 긴 무음/잡음 구간 |

## 공통 규칙 (모든 유형)

```
- transcript에 없는 내용을 추론해 넣지 않는다. 불확실하면 "확인 필요"로 남긴다
- 액션 아이템과 결정사항에는 근거 타임스탬프를 병기한다
- 말한 순서가 아니라 "다음 행동이 가능한 구조"로 재구성한다
- 화자 이름이 확정되지 않은 발언은 이름을 단정하지 않는다
- 숫자·날짜·금액은 원문 그대로 옮기고, 애매하면 [확인 필요]를 붙인다
```

---

## 회의록 (기본)

```markdown
# {날짜} {회의명} 회의록

## 회의 개요
- 일시 / 참석자 / 목적

## 핵심 요약
3~5줄. 이 회의에서 가장 중요한 것만.

## 주요 논의 내용
### {주제1}
맥락과 쟁점. 누가 어떤 입장이었는지.

## 결정사항
- [x] 결정된 내용 (근거: 00:23:15)

## 액션 아이템
| 담당 | 할 일 | 기한 | 근거 |
|---|---|---|---|

## 확인 필요사항 / 리스크
아직 모르는 것, 조심해야 할 것.

## 인사이트
다음 작업에 영향을 주는 해석. (AI의 해석임을 구분되게)

## 연결
- 관련 프로젝트 / 기존 노트 / 후속 산출물
- 원문: [[{날짜}_{slug}_transcript]]
```

## 강의

# {날짜} {강의명}

## 강의 개요
주제 / 강사 / 대상 / 길이

## 핵심 개념
### {개념1}
설명. 강사가 강조한 지점.

## 실습·예시
다룬 사례와 실제 진행 방식.

| 질문 | 답변 요지 |

## 활용 포인트
진행자의 프로젝트에 어떻게 적용할 수 있는가.

## 연결
- 원문: [[{날짜}_{slug}_transcript]]
```

## 후속 확인 질문
다음 인터뷰에서 물어야 할 것.

## 연결
- 원문: [[{날짜}_{slug}_transcript]]
```

## 워크샵 (장시간·노이즈 포함)

긴 워크샵 녹음은 **실습 시간의 배경음·잡담이 transcript 대부분을 차지**할 수 있다.
이때 "내용 없음"으로 처리하면 안 된다. 아래 세 구간을 중심으로 정리한다.

```markdown
# {날짜} {워크샵명}

## 워크샵 개요
주제 / 진행 / 참가자 규모 / 구성

## 도입·강의 파트
초반 소개와 강의 내용.

## 실습 중 코칭 메모
실습 시간에 오간 개별 코칭·질의. (배경 잡음 구간은 제외)

## 마무리 Q&A / 결정사항
후반부에 나온 질문과 결론.

## 참가자별 산출물
⚠️ transcript만으로 단정하지 말 것. 확인 필요로 남기고 별도 자료와 대조한다.

## 운영 개선점
진행상 아쉬웠던 점, 다음 회차에 반영할 것.

## 연결
- 원문: [[{날짜}_{slug}_transcript]]
```
