## 1. Problem Validation의 정의

**"진짜 문제고 비싼 문제여서 해결하면 지표가 많이 개선될 것이다"는 근거 찾기.**

- 진짜 문제 — 실제로 그 문제를 느끼는 사용자가 있고(정성), 데이터가 그 문제를 보여준다(정량).
- 비싼 문제 — 해결하면 최종 KPI가 금액/숫자로 얼마나 움직이는지 말할 수 있다(Uplift).

이 근거가 매핑 M1·M2를 타고 Impact를 움직인다. 근거 없는 Impact 점수는 방어되지 않는다.

## 2. V1~V5 차원 정의 (계약 §3-3)

| 차원 | 무엇을 보나 | 정본 규칙 |
|---|---|---|
| **V1 규모(트래픽)** | 이 문제를 겪는 사용자의 크기 — 대상 지면·타겟 기준 트래픽(월) | 정량은 트래픽 계산이 정본. 골트리 `current` 우선 |
| **V2 퍼널·병목** | 퍼널 어디서 새는가 — 해당 구간 전환·이탈의 실측과 **해석** | 수치만이 아니라 병목 해석 문장까지 (→ §5) |
| **V3 벤치마크 Gap** | 벤치마크 대비 얼마나 못하고 있나 | **Gap 배수 = 벤치마크 전환율 ÷ 현재 전환율** (비율이지 %p 차이가 아니다) |
| **V4 정성 심각도** | 사용자가 실제로 그 문제를 느끼는가 | 근거 어휘 5종(→ §3)만 사용. 유형별 행 분리 가능(V4a, V4b, …) |
| **V5 기회 손실** | 안 풀면 얼마를 잃나 | G3(Uplift)의 요약 한 줄 — 상세는 G3 (→ `uplift-calc.md`) |

G2 표는 6열 고정: `차원` / `근거` / `출처·조회조건` / `근거유형` / `판정` / `비고`.

## 3. V4 정성 근거 어휘 5종 (정본)

| 어휘 | 한 줄 설명 |
|---|---|
| **고객 인터뷰** | 실사용자를 직접 만나 문제 경험을 확인한 기록 (UT 포함) — 실행 가이드는 `interview-guide.md` (인터뷰 지원 서브플로우 I1~I3, 계약 §7-10) |
| **VOC** | CS 인입·리뷰·설문 등 고객이 남긴 실제 발화 — 이 문제로 얼마나 인입되는가 |
| **합성사용자 인터뷰** | 합성 페르소나 응답 기반 인터뷰 (03b 킷 경로) — 실사용자 아님 |
| **CRO 체크리스트** | 해당 지면을 CRO 체크리스트로 점검한 Fail 항목·비율 |
| **BIAS 체크리스트** | 문제가 걸린 BIAS 단계(B/I/A/S)의 실패 항목 점검 결과 |

**근거유형(실측/합성/혼합) 판별 규칙**

- 합성 포함 여부는 추론하지 않는다 — **참가자에게 직접 묻는다** (hb §2-6 방식). "이 인터뷰는 실사용자였나요, 합성 페르소나였나요?"
- 실사용자만 → `실측` / 합성 페르소나만 → `합성` / 섞였으면 → `혼합`.
- **합성 근거는 문제 검증(V4)에서 정상 인정된다.** 합성이라는 이유로 행을 지우지 않는다.
- 단, **합성-only의 C 상한 1~3은 Confidence(hb §7-4) 쪽에만 적용**된다 — V4 판정을 깎는 규칙이 아니다.

## 4. MCP 실쿼리 규칙 (계약 §7-6)

정량 차원(V1 트래픽·V2 퍼널·V3 Gap)은 Amplitude MCP 실쿼리를 허용한다 (검증 용도).

- **실쿼리 결과 값만 쓴다.** 추정·보간 금지.
- 조회조건(기간·필터·이벤트명)을 `출처·조회조건` 열에 남긴다.
- **골트리 정본값과 충돌하면 골트리 우선** + 차이를 `비고`에 `코치 확인 필요`로 기록한다.
- 골트리에 없는 노드의 실쿼리 값은 `[골트리 미등재 — 실쿼리 값]` 표기.
- 조회 실패·MCP 미연결이면 멈추지 않는다 — `코치 확인 필요`로 두고 진행한다.

## 5. V2 병목 해석 요령 — 숫자를 문장으로

V2는 수치 나열이 아니라 **병목이 어느 성격의 문제인지 읽어내는 해석 문장**을 판정 열에 쓴다. exp-014 스타일:

> 블로그 방문 3,723 → CTA 클릭 10건(0.27%) → 데모 제출 3건(30%). **"99.73%가 클릭조차 안 함 = CTA 거부가 아니라 노출·인지 문제. 2→3단계 30%는 양호 — 병목은 1→2 구간."**

해석 문장의 요건:

- 어느 구간이 병목인지 특정한다 (앞뒤 구간의 양호함과 대조하면 강해진다).
- 그 병목이 **무엇이 아닌지**까지 말한다 ("거부가 아니라 인지 문제") — 이 구분이 솔루션 방향과 BIAS 단계 정합(Rationale 유형 7)의 재료가 된다.
- 해빗팩토리 B축이라면: "첫 응답을 안 한 37.8%는 상담 거부가 아니라 무엇을 답해야 할지 모르는 상태"처럼 축 어휘로 쓴다.

## 6. 차원별 판정 기준 (강 / 중 / 약 / 공란)

판정은 "이 차원이 문제를 지지하는가"다. 공통 원칙: **실측·정본 출처 + 문제를 정면으로 지지 = 강, 간접·부분 지지 = 중, 방향만 맞고 근거가 얇음 = 약, 미확보 = 공란.**

| 차원 | 강 | 중 | 약 |
|---|---|---|---|
| V1 규모 | 골트리·실쿼리 실측 트래픽이 크고 문제 대상과 분모가 일치 | 실측이나 대상 세그먼트가 일부 어긋남(프록시 분모) | 트래픽 소규모, 또는 출처가 참가자 구술뿐 |
| V2 퍼널·병목 | 실측 퍼널에서 병목 구간이 특정되고 해석 문장이 성립 | 이탈은 실측되나 병목 성격(인지/거부 등)이 미해석 | 구간 데이터 없이 전체 전환율만 있음 |
| V3 벤치마크 Gap | 확인된 벤치마크(URL+확인일) 대비 Gap 배수가 뚜렷 | 벤치마크가 `2차 인용 — 원문 미확인`이거나 범위가 넓음 | 벤치마크 부재로 Gap 계산 불가(내부 비교만) |
| V4 정성 심각도 | 실측 정성(인터뷰·VOC)에서 같은 문제 발화가 반복 | 혼합 근거, 또는 실측이나 표본이 얇음(예: 단일 세그먼트 소수) | 합성-only, 또는 체크리스트 단독 |
| V5 기회 손실 | G3 3시나리오 완산 — 보수 시나리오도 유의미한 금액 | G3 계산됐으나 입력 일부가 참가자 답 의존 | Baseline 미확정 등으로 G3 미산출 (사실상 공란) |

- 판정 어휘는 `강` / `중` / `약` / `공란(미확보)` 4개뿐이다 — 점수화하지 않는다.
- 약·공란은 실패가 아니라 **다음 액션의 표시**다: 무엇을 실측하면 중→강이 되는지 `비고`에 남긴다.
- 완료 판정(계약 §9-2)의 최소선: **정성 1건 이상 + 정량(트래픽·Gap) 1건 이상이 실측 출처와 함께** 있어야 한다.
