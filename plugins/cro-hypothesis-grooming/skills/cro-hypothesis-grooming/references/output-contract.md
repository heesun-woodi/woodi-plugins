## 0. 그루밍의 정의 (정본 — 덱 슬라이드 2)

> **"가설의 근거를 탄탄하게 하여 ICE 점수를 높여서 스프린트 열차에 탈 우선순위라는 것을 주장하기 위해"**

그루밍은 **가설 문장을 바꾸는 작업이 아니라 같은 가설의 점수를 올리는 작업**이다. 문장에 손대는 것은 DEC-005 이관 정리(§2-3)까지이며, 가설의 의미는 바꾸지 않는다.

### 0-1. PSR → ICE 영향 매핑 (정본 — 덱 슬라이드 10)

그루밍의 모든 근거 작업은 이 매핑을 통해 점수로 번역된다. G6(ICE 전후 대조)의 `변화 사유`는 반드시 이 표의 경로 중 하나를 지목한다.

| # | PSR 요소 | → ICE 축 | 무엇이 점수를 움직이나 | 그루밍 단계 |
|---|---|---|---|---|
| M1 | **P**roblem | **Impact** | 진짜 문제로 느끼는 유저의 크기(트래픽) + 얼마나 진짜인가(정량 Gap·정성 근거) | ② Validation |
| M2 | **R**esult | **Impact** | 목표 Result 달성 시 비즈니스 지표 개선 영향도 — **Uplift 인과 사슬**: 정량 분석(Gap·트래픽) → Target 달성 가정 → 잔여 퍼널 통과 → **최종 KPI(계약) 증분 금액** → 이 값으로 Impact 판단. **양 축 모두 금액까지 간다** (DEC-007 · §3-4) | ② Validation |
| M3 | **R**esult | **Confidence** | 목표 Result **값**에 대한 근거의 품질 (= hb §7-4a Target 타당성) | ⑤ Target |
| M4 | **S**olution | **Confidence** | 솔루션 성공에 대한 근거의 **품질과 양** (Rationale 7유형) | ④ Rationale |
| M5 | **S**olution | **Ease** | 솔루션 구현에 필요한 자원(인력·시간) — 대안 솔루션·MVP 축소 | ③ Description |

## 2. 입력 규격

### 2-1. 세션 단위 — 가설 1건

이 세션의 입력은 **백로그에 이미 등록된 가설 1건**이다. 그루밍은 깊이 작업이므로 행 단위 일괄 처리를 하지 않는다. 여러 건을 요청받으면 1건씩 순서대로, 매 건 STEP 0부터.

입력 3형 — 어느 것이든 정상:

| 형태 | 내용 | 비고 |
|---|---|---|
| **노션 페이지** | 실험설계서 템플릿 페이지 본문 붙여넣기 | 권장 — 기존 작성분(1-2·1-3·2장)을 그대로 재료로 씀 |
| **H5b 블록** | repo 백로그의 `### {HYP ID}` 섹션 | |
| **문장 + 속성** | PSR 전문 + I/C/E·문제ID·R 노드 구술 | 최소 입력 — 나머지는 정규화에서 질문 |

### 2-2. 정규화 필수 필드 (G0)

| 필드 | 없을 때 |
|---|---|
| HYP ID (또는 가설 NO) | 질문 — **스킬이 채번하지 않는다** |
| PSR 전문 | 필수 — 없으면 백로그 스킬로 라우팅 |
| 문제ID (PR-*/SP-*) | 질문 |
| 현재 I / C / E | 공란이면 공란으로 기록 (결손도 정상 입력 — hb §3-6) |
| R 노드 + Baseline | 골트리 대조 (§7-6) |
| Target | 없으면 **이 세션의 핵심 산출 대상**으로 표시 |
| **Variant 후보 · 시안** | 후보가 1개 이하거나 시안이 없으면 **이 세션의 산출 대상**으로 표시 (§3-6a) |
| **(A축) 축 경계 전환율 · 계약 단가** | 없으면 골트리 B축 축 KPI·프로젝트 정본값으로 질문 — 스킬이 추정하지 않는다 (§3-4·§7-3) |
| 근거유형 (실측/합성/혼합) | hb §2-6 방식으로 질문 |
| 규칙 버전 | PSR 문장에 솔루션 형태가 있으면 **구 규칙(v1.2 이전)** 판별 → STEP 0.5 대상 |

### 2-3. 구 규칙 가설의 DEC-005 이관 (STEP 0.5)

DEC-005는 소급 적용하지 않는다 — **구 규칙 가설은 위반이 아니며, 이관은 그루밍의 첫 작업**이다.

| 이관 항목 | 처리 |
|---|---|
| 솔루션 형태가 문장에 포함 | 형태를 걷어 **Variant 후보**로 분리, 문장은 [솔루션 핵심가치]까지 |
| 앞머리 가설명 태그 | 가설명 필드로 분리 |
| 대괄호 템플릿 잔존 | 조사·어미를 이어 자연문으로 |
| 공급자 시점 화면 묘사 | 고객이 느끼는 것으로 치환 |
| 영역·세그먼트 중복 | 세그먼트를 `고객에게`로 축약 |

- **가설의 의미를 바꾸지 않는다.** 문제·가치·지표가 달라지면 이관이 아니라 새 가설이다 → 백로그 스킬로 라우팅.
- 이관 결과는 **"이관 확인"** 게이트를 통과해야 다음 STEP으로 간다.

### 2-4. 프로젝트 제약 (hb §7-10 승계)

리스트·시트·노션에 근거 사용 금지 규칙(예: "과거 실험 결과를 어느 방향으로도 인용하지 않는다")이 명시돼 있으면 스킬 기본 절차보다 우선한다. STEP 0에서 한 번 확인하고 전 STEP에 적용한다.

### 3-3. G2. Problem Validation 표 — 6열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 차원 | `V1 규모(트래픽)` / `V2 퍼널·병목` / `V3 벤치마크 Gap` / `V4 정성 심각도` / `V5 기회 손실` |
| 2 | 근거 | 수치·요지 한 줄 |
| 3 | 출처·조회조건 | 데이터 소스 + 기간 + 필터 (MCP 실쿼리면 쿼리 조건 명시) |
| 4 | 근거유형 | `실측` / `합성` / `혼합` |
| 5 | 판정 | 이 차원이 문제를 지지하는가 — `강` / `중` / `약` / `공란(미확보)` |
| 6 | 비고 | 골트리 정본값과 차이 등 |

- **V4 정성 심각도의 근거 어휘(정본)**: 고객 인터뷰 / VOC / **합성사용자 인터뷰**(03b 킷 경로) / **CRO 체크리스트** / **BIAS 체크리스트**. 유형별로 행을 나눠도 된다(V4a, V4b, …).
- **V1·V3 정량은 트래픽과 Gap 계산이 정본**이다. Gap 배수 = 벤치마크 전환율 ÷ 현재 전환율 (`_common-brief.md` §2).
- V5는 G3(Uplift)의 요약 한 줄을 담는다 — 상세는 G3.
- 합성 근거는 V4에서 정상 인정된다(문제 검증 용도). **합성-only의 C 상한 1~3은 Confidence(§7-4) 쪽에만 적용**된다.

### 3-4. G3. Uplift 3시나리오 표 — 8열 + 입력값 표

**입력값 표** (계산 전 반드시 먼저 출력·확인):

| 항목 | 값 | 출처 |
|---|---|---|
| 실험 영역(R 노드) · 대상 트래픽(월) · Baseline · 잔여 전환율(R 노드 이후 → 최종 KPI) · **(A축) 축 경계 전환율(상담방 오픈 → 계약)** · 최종 KPI 단가 · 데이터 기간 | | Baseline·비율 = 골트리 `current` / **인원수·잔여 전환율 = `problem-areas.md` 실측 또는 실쿼리** (골트리 JSON에는 절대 인원수가 없다) / **축 경계 전환율 = 골트리 B축 축 KPI(계약완료율)** / 단가 = 프로젝트 정본값 재확인 (§7-3) / 나머지 = 참가자 답 |

**시나리오 표**:

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 시나리오 | `보수` / `기본` / `낙관` — **낙관 = 실험 목표(Target)** |
| 2 | 기대개선율 | 상대 % |
| 3 | eCVR | Baseline × (1+개선율) |
| 4 | 개선 Users | 트래픽 × eCVR |
| 5 | Delta | 개선 Users − 현재 Users |
| 6 | 최종 KPI 증분(건수) | Delta × 잔여 전환율 |
| 7 | 최종 KPI 증분(금액/월) | 건수 × 단가 |
| 8 | 연 증분 | ×12 (계절성 크면 별도 표기) |

- **이 표의 최종 금액/숫자가 Impact 판단의 근거값**이다 (매핑 M2). G6의 I 변화 사유는 이 값을 인용한다.
- 계산 규칙(§7-3)을 따르고, **하류(잔여) CVR 고정 가정을 표 아래 한 줄로 반드시 명시**한다. 보수 시나리오는 잔여 전환율 할인을 권장한다.
- Baseline 미확정 상태에서는 이 표를 출력하지 않는다 (하드 게이트).
- **A축 사슬 확장 (DEC-007, 2026-08-23 — v1.0의 「A축 분기(단가 없는 축)」를 대체한다)**: **최종 KPI는 양 축 모두 `계약`이다.** A축의 R 노드는 축 KPI(상담방 오픈) 앞에 있지만, **거기서 멈춘 건수는 가설 간 우선순위를 가르지 못한다** — 오픈→계약 구간을 이어 **금액까지 낸다**. 7열·8열을 `—(단가 미정)`으로 비우는 것은 **더 이상 완성이 아니다**.
	- **A축 잔여 전환율 = (R 노드 → 상담방 오픈) × (상담방 오픈 → 계약).** 뒤 구간이 축 경계를 넘는 곱이며, 값은 **골트리 B축 축 KPI(계약완료율)**를 쓰고 조회조건을 출처 열에 남긴다.
	- **가정 2줄 필수** — ① "A축 개입이 B축 하류 전환율을 바꾸지 않는다고 전제한다" ② "축 경계를 넘는 곱이라 B축 가설의 금액보다 불확실성이 크다".
	- **축 KPI %p 증분은 그대로 병기한다.** 금액은 축 경계를 넘은 값이므로, 축 안에서 닫히는 값을 함께 보여야 실험 판정(축 KPI)과 사업 임팩트(금액)가 각각 읽힌다.
	- 단가는 §7-3의 단가 규칙을 따른다 — 스킬이 추정하지 않는다.

### 3-5. G4. Target 확정 표 — 2열 (항목/값)

행: `설정 방법` (벤치마크 / MDE 근사 / 내부 Gap 중 택1) · `산출 근거` (한 줄 — 예: "업계 중앙값의 60% 수준, 보수적 목표") · `Baseline → Target (Absolute)` · `상대 개선율 (Relative)` · `Uplift 기대개선율과 일치 여부` · `타당성 자기평가` (hb §7-4a 4분기 중 어디인가)

- MDE 방식은 **근사 계산까지만** 허용하고 `실험설계에서 재확정` 표기를 강제한다.

### 3-6. G5. Rationale 표 — 5열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 유형 | §7-5의 7유형 중 해당 (복수면 행 분리) |
| 2 | 내용 | 사례·수치 요지 한 줄 |
| 3 | 출처 | 3단계 표기 — `URL + 확인일` / `2차 인용 — 원문 미확인` / `확인되지 않음` (hb §7-5) |
| 4 | C 밴드 기여 | `1~3` / `4~6` / `7~9` / `10` 제안 — 확정은 사람. 합성-only면 1~3 초과 불가 |
| 5 | 비고 | |

- 표 아래 **Counter Rationale**(실패 시나리오 한 줄 + 무너질 지표) + **Guardrail 후보**(확정은 실험설계 소관 표기)를 별도 행으로.
- 대안 솔루션 확인: 그루밍 기준은 **문제당 솔루션 3개(대안 2개 이상)**. 부족하면 아이데이션을 진행하되, 대안이 별도 가설로 분화하면 백로그 스킬로 라우팅.
- **대안 → Variant 승격 판정 (DEC-007)**: 검토한 대안을 표에 `보류`로만 남기지 않는다. 각 대안에 **"같은 [솔루션 핵심가치]를 다른 방법으로 전달하는가"**를 묻고, 그렇다면 **같은 실험의 Variant 후보로 올린다**(§3-6a). 별도 가설로 내리는 것은 **가치나 문제가 다를 때**뿐이다.

### 3-6a. G5b. Variant · 시안 표 — 3열 (DEC-007, 2026-08-23 — 신설)

G1에서 분리한 **Variant 후보**를 아래 3열 표로 출력한다. 형태를 적어두는 데서 그치지 않고 **실험 가능한 상태인지**까지 본다.

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | Variant ID | `VAR-{HYP 숫자부}-{a,b,…}` (§6) |
| 2 | 전달 형태 | 같은 [솔루션 핵심가치]를 무엇으로 전달하는가 — 한 줄 |
| 3 | 시안 | `있음`(링크·첨부) / `없음 — 참가자 준비 필요` / `해당 없음`(문구 교체만) |

- **Variant 후보는 2개 이상이다.** 1개뿐이면 그 하나가 이겼는지 졌는지만 알 뿐 **어떤 전달 방법이 더 나은지**를 배우지 못한다. 대안 솔루션 표(§3-6)에서 승격 후보를 먼저 찾고, 없으면 아이데이션한다.
- **시안은 대조군(현행)과 실험군을 함께** 확보한다. 무엇이 어떻게 바뀌는지 화면으로 보이지 않으면 리뷰어·개발자가 같은 것을 상상하지 못한다.
- **스킬은 시안을 만들지 않는다** — 요청하고, 받은 것을 G7a `1-3`에 링크로 착지시키고, 없으면 완료 판정에 미충족으로 표시한다 (§7-9·§9).
- **운영 분기가 있는 Variant**(고객 상태에 따라 문구가 자동으로 갈리는 경우)는 **분기별로 지표를 볼 수 있는지**를 함께 확인한다. 판정은 전체로 하더라도 분기별 수치가 안 나오면 결과 해석이 막힌다 — 필요한 이벤트·프로퍼티를 G7a `1-4` 추가 태깅에 남긴다.

### 3-13. I2. UT 설계서 기획 블록 — 코드블록 ★ 착지 (노션 UT 설계서 템플릿 Step 1)

**인터뷰 지원의 착지 정본은 노션 UT 설계서 템플릿**(문서함 DB 「UT템플릿」 — Step 1 기획 / Step 2 진행 / Step 3 결과 정리)이다. I2는 그 **Step 1의 5개 섹션을 채우는 코드블록**으로 출력한다 — 참가자가 UT 설계서 페이지에 붙여넣는다.

| 섹션 | 채우는 재료 |
|---|---|
| `1) 문제 구체화` | 가설의 P에서 도출 — **"고객이 [어떤 일을 할 때] [어떤 문제를] 겪는다고 생각한다"** 작성형태로 1~3줄 (가설 문장을 그대로 복사하지 않고 이 형태로 번역) |
| `2) 퍼소나 설계` | I1의 퍼소나 3분류 |
| `3) 리크루팅` | I1의 리크루팅 경로·인원·리워드·스크리닝 질문 → 실행 계획 문장으로 |
| `4) 시나리오 스크립트&미션 작성` | **시나리오**("지금 당신은 ~하는 상황입니다") + **미션**("~를 진행해보세요") |
| `5) 세부 스크립트 미리 준비하기` | 아래 스크립트 구성(UT형/인터뷰형) 전문 |

**Step 2(UT 진행하기)는 참가자가 현장에서 수기로 채운다** — 인터뷰이 신상 요약 / 첫인상 / 미션 관찰 기록 / 미션 종료 후 인터뷰. 스킬은 채우지 않는다.

#### 세부 스크립트(1-5) 구성

**UT형 구성(순서 고정 — 마켓핏랩 UT 정본)**: ① 도입·감사·**녹화(화면 공유) 동의** ② 아이스브레이킹 — 퍼소나 특성 파악용 사전 질문 ③ **Think Out Loud 안내** ("평소와 같이 진행하시되, 머릿속에 드는 생각이나 느낌을 말로 계속 말해주세요") ④ **시나리오 설정** ("지금 당신은 ~하는 상황입니다" — 실제 사용 맥락 부여) + **미션 요청** ("~를 진행해보세요") ⑤ **관찰** — 개입하지 않고 특이 행동·발언 기록(조작 자체를 모를 때만 개입) ⑥ **미션 종료 후 인터뷰** — 관찰에서 발견한 행동의 맥락 질문 + 꼬리 질문(더 설명 요청·이유·기억나는 경험·감정·상위개념) ⑦ 마무리·리워드 안내.

**인터뷰형 구성**: ① 도입·동의 ② 배경 질문 ③ **문제 검증 질문** — 유도 금지: 문제를 언급하지 않고 경험을 먼저 묻는다 ④ (겸용 시) 솔루션 반응 — 시안 제시 후 개방 질문, 긍정 유도 금지 ⑤ 마무리.

- **유도 질문 금지(양형 공통)**: "이 기능 불편하죠?" ✗ → "이 기능을 사용하셨을 때 어떠셨어요? 편하셨다면/불편하셨다면 어떤 지점이 그랬나요?" ✓
- 질문마다 `[검증 대상: P/S/R 중 무엇]` 태그를 단다 — 분석(I3)에서 매핑 근거가 된다.
- 스크립트는 참가자가 수정해 쓰는 초안이다 — 고정 대본이 아님을 명시하고, **진행 전 내부 시뮬레이션 1회**를 권장한다.

**7-3. Uplift 계산 (Step A~H — `templates/uplift-simulation.md` 정본)**

```
A. 현재 CVR = Baseline (골트리 current 우선)
B. eCVR = CVR × (1 + 기대개선율)
C. 개선 Users = 대상 트래픽 × eCVR
D. Delta Users = 개선 Users − 현재 Users
E. 잔여 퍼널 캐스케이드: Delta Users × 잔여 전환율(R 노드 이후 → 최종 KPI)
   — 잔여(하류) CVR은 고정 가정. 반드시 표 아래 명시. 보수 시나리오는 할인 권장
F. 최종 KPI 증분(건수) = E의 결과
G. 월 금액 증분 = F × 최종 KPI 단가
H. 연 증분 = G × 12 (계절성 크면 실측 재계산 표기)
검산: G3 표의 각 열이 위 단계와 1:1 대응해야 한다
```

- 3시나리오(보수/기본/낙관) 필수. **낙관 = 실험 목표(Target)**.
- 해빗팩토리 관행 수치: **양 축 최종 KPI = 계약** (DEC-007). **계약 단가 = 6만원** (`problem-areas.md` 정본 — **DEC-010, 2026-08-23 확정**. 세션 중 언급된 7만원은 정본이 아니므로 인용하지 않는다). **A축**은 §3-4의 **A축 사슬 확장**을 따른다(축 경계 전환율을 곱해 금액까지).
- **입력값 없이 계산하지 않는다.** 단가·잔여 전환율을 스킬이 추정하지 않는다 — `problem-areas.md` 실측·실쿼리 또는 참가자 답. 단가 질문 예시에 특정 축의 관행값을 하드코딩하지 않는다.

| ③ transcript 분석 | 인터뷰 후 전사를 받아 근거 발화를 추출·해석·매핑 | I3 |

- **진행 형태 2형**: 마켓핏랩 정본은 **UT형**(User Test + Usability Test 혼합 — 시나리오·미션 수행을 Think Out Loud로 관찰한 뒤 사후 인터뷰)이다. 원격 대화만 가능한 경우 인터뷰형. 정본 참조: 푸드케어 「UT 세션_1차」·「UT 설계서」템플릿(기획 Step 1 → 진행 Step 2 → 결과 정리 Step 3).
- **솔루션 UT의 자극물 확정**: 목적이 `솔루션 UT`·`겸용`이면 **무엇을 보여줄지 먼저 정한다** — ① **§3-6a 시안**(DEC-007 이후 그루밍 완료 조건이므로 우선 사용) ② 기존 화면 재활용 ③ 목업 ④ 구술 설명. 정하지 않으면 솔루션 반응 질문이 성립하지 않는다. **구술 설명이면 I3 강도를 한 단계 낮춰 읽고 비고에 `자극물: 구술 설명`을 남긴다.** 시안 제작은 실험 설계 소관 — UT용 최소 자극물 선택까지가 이 계약 범위다.
- **유도 질문 금지 원칙**: 문제를 먼저 언급하지 않는다 — 경험을 개방형으로 묻고, 문제 언급이 자발적으로 나왔는지를 I3 신뢰 주석에 남긴다. 솔루션 반응 질문은 긍정 유도 없이. UT형 진행 팁: 침묵을 섣불리 끊지 않는다 · 특이 행동은 그 자리에서 메모하고 미션 종료 후 묻는다 · 머뭇거림·탄식("어?", "엥?") 같은 비언어 반응을 기록한다.
- **반증 은폐 금지**: 가설을 지지하지 않는 발화도 반드시 추출한다 (I3 `반증` 매핑) — Counter Rationale·C 하향 재료.
- transcript의 PII는 원문 출력하지 않는다 — 위치만 말하고 `[마스킹]` (진행 원칙 승계).
- I3 추출물의 근거유형은 **실측**. 합성사용자 인터뷰(03b 킷)와 구분한다 — 실제 유저 확보가 어려울 때의 대체 경로가 03b이며, 그 경우 근거유형은 합성.
- **착지**: 인터뷰 지원의 착지 정본은 **노션 UT 설계서 템플릿**(문서함 DB) — 기획 시 I2가 Step 1을, 분석 후 I3의 Step 3 갱신 블록이 Step 3을 채운다. Step 2(진행 기록)는 참가자 수기. 그루밍 세션에는 I3의 `그루밍 반영 요약`이 G2 V4·G5로 넘어간다 — UT 설계서와 실험설계서(가설 페이지)는 별개 문서다.
- 인터뷰 설계·분석의 방법 확장(코딩·새터레이션 판단 등)은 이 계약 범위 밖 — 스킬은 그루밍 근거 추출까지만.
