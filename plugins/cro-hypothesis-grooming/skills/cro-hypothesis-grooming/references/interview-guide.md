# 실제 유저 인터뷰 보조 — 타겟·스크립트·분석

> 정본: references/output-contract.md — 이 파일과 어긋나면 계약이 이깁니다.

— 인터뷰 지원 서브플로우(계약 §7-10, I1~I3)에서 읽는다

---

## 1. 서브플로우 개요 (계약 §7-10)

실제 유저 인터뷰는 **스킬이 수행할 수 없다** — 스킬은 앞뒤를 보조한다. 진입은 STEP 2(문제 검증 인터뷰)·STEP 4(솔루션 UT)에서, 또는 "인터뷰 도와줘" 류 요청으로 독립 진입.

| 단계 | 스킬이 하는 것 | 산출물 |
|---|---|---|
| ① 타겟 선정 | 가설의 P(세그먼트·문제)·S(솔루션)를 바탕으로 누구를 만나야 하는지 도출 | I1 |
| ② 스크립트 생성 | 문제 검증/솔루션 UT 구분, **유도 질문 금지** 원칙으로 초안 작성 | I2 |
| ③ transcript 분석 | 인터뷰 후 전사를 받아 근거 발화를 추출·해석·매핑 | I3 |

**합성사용자 인터뷰(03b 킷)와의 구분**: 이 파일은 **실제 유저** 경로다 — I3 추출물의 근거유형은 **실측**. 실제 유저 확보가 어려울 때의 대체 경로가 03b(합성사용자 인터뷰)이며, 그 경우 근거유형은 **합성**이고 합성-only C 상한 1~3(hb §7-4)이 걸린다. 어느 경로였는지를 산출물에 반드시 표기한다.

인터뷰 설계·분석의 방법 확장(코딩·새터레이션 판단 등)은 계약 범위 밖 — 스킬은 그루밍 근거 추출까지만 한다.

## 2. I1 — 타겟 선정 요령 (계약 §3-12)

I1은 2열(항목/값) 표. 행: `인터뷰 목적` (문제 검증 / 솔루션 UT / 겸용) · `진행 형태` (UT형 / 인터뷰형) · `타겟 세그먼트` · `퍼소나 3분류` · `제외 조건` · `권장 인원` · `리크루팅 경로 후보` · `리워드 후보` · `스크리닝 질문 2~3개`.

- **진행 형태 2형** — 마켓핏랩 정본은 **UT형**: 시나리오·미션 수행을 Think Out Loud로 관찰한 뒤 사후 인터뷰 (User Test + Usability Test 혼합). 원격 대화만 가능하면 인터뷰형.
- **퍼소나 3분류** (UT 세션 정본): ① 목표 행동을 잘 하는 사용자 ② 목표 미경험 고객 ③ 경험했으나 이탈한 고객. **달성 고객과 미달성 고객을 대비해 뽑는 것이 차이를 드러낸다** — 달성자는 왜 됐고 미달성자는 왜 안 됐는가. 한쪽으로 치우친 모집은 편향된 정보를 준다: 핵심 조건만 그루핑하고 나머지는 랜덤 선정.
- **리크루팅 3경로**: ① 타겟 세그먼트 문자 발송 → 신청 폼 → 선정 안내 (+리워드 — 실질 인사이트 최상) ② 지인 중 조건 해당자 (솔직한 답) ③ 동료 empathy (시나리오로 퍼소나 이입). 목표 인원의 2배수로 노출한다.

- **P의 세그먼트를 행동·지면 조건으로 번역한다.** 가설 문장의 심리 상태("무엇을 답해야 할지 몰라 부담을 느끼는")는 리크루팅 조건이 될 수 없다 — 심리 상태로 사람을 모집할 수 없기 때문이다. 관측 가능한 행동·지면 조건으로 바꾼다: "최근 30일 내 상담방을 열었으나 첫 응답을 하지 않은 사용자"처럼.
- **권장 인원은 문제 검증 5명 내외 기준.** 통계가 아니라 패턴 반복 확인이 목적이다 — 같은 문제 발화가 반복되면 충분하고, 더 필요하면 다음 라운드로.
- **제외 조건을 명시한다** — 문제를 이미 통과한 사용자(예: 계약 완료자)만으로 채우면 문제 발화가 나올 수 없다.
- **스크리닝 질문은 유도 없이.** 타겟 판별용 2~3개 — 가설의 문제를 노출하지 않고 행동 사실만 확인한다 ("최근에 보험 상담을 신청해 본 적이 있으신가요?" — "상담방에서 답장하기 어려우셨나요?"는 스크리닝부터 유도다).

## 3. I2 — 스크립트 작성 원칙 (계약 §3-13)

I2는 코드블록으로 출력한다 — 참가자가 현장에서 쓴다. 진행 형태에 따라 구성이 갈린다.

**UT형 (마켓핏랩 정본 — 순서 고정)**
① 도입·감사·녹화(화면 공유) 동의 ② 아이스브레이킹 — 퍼소나 특성 파악 사전 질문 ③ **Think Out Loud 안내**: "평소와 같이 진행하시되, 머릿속에 드는 생각이나 느낌을 말로 계속 말해주세요" ④ **시나리오 설정 + 미션 요청**: "지금 당신은 ~하는 상황입니다"로 실제 사용 맥락을 부여하고 "~를 진행해보세요"로 미션을 준다 ⑤ **관찰**: 개입하지 않고 특이 행동·발언을 기록한다 (조작 자체를 모를 때만 개입) ⑥ **미션 종료 후 인터뷰**: 관찰한 행동의 맥락을 묻고 꼬리 질문으로 파고든다 ⑦ 마무리·리워드 안내.

- **꼬리 질문 5법**: 더 설명해달라고 하기 / 이유 묻기 / 기억나는 경험 묻기 / 감정 묻기 / 상위개념으로 접근하기.
- **진행 팁** (UT 세션 정본): 침묵해도 충분히 지켜본다 — 섣부른 질문은 생각을 끊는다 / 특이 행동·발언은 그 자리에서 메모하고 미션 종료 후 묻는다 / 머뭇거림·"어?"·"엥?" 같은 **비언어 반응**을 기록하고 이유를 묻는다 / 반복 동작(헤매는 지점)을 중요하게 본다.
- 진행 전 **내부 시뮬레이션 1회**: 흐름이 어색한 지점, 얻으려는 내용이 실제로 수집되는지 점검.

**인터뷰형 (원격 대화만 가능할 때)**
① 도입·동의 (녹음 동의 포함) ② 배경 질문 ③ 문제 검증 질문 ④ (겸용 시) 솔루션 반응 ⑤ 마무리·추가 탐색.

**유도 질문 금지 — 이 파일의 제1원칙**

- **문제를 언급하기 전에 경험을 개방형으로 묻는다** ("~할 때 어떻게 하셨나요?"). 심화 질문은 그 이후에만.
- **자발적 문제 언급 여부가 근거 강도를 가름한다.** 묻지 않았는데 문제가 나오면 강한 근거, 유도 후에 나온 동의는 약한 근거다 — I3 신뢰 주석의 재료.
- **솔루션 UT는 시안·설명을 보여준 뒤 개방 질문.** "어떠세요?"까지만 — "편해 보이지 않나요?" 같은 긍정 유도 금지.
- 질문마다 **`[검증 대상: P/S/R 중 무엇]` 태그**를 단다 — I3에서 매핑 근거가 된다.
- 스크립트는 참가자가 수정해 쓰는 **초안**이다 — 고정 대본이 아님을 명시한다.

**좋은 질문 vs 유도 질문 — 대조 3쌍**

| ✅ 좋은 질문 (개방형) | ❌ 유도 질문 | 무엇이 문제인가 |
|---|---|---|
| "상담방이 열린 뒤에 어떻게 하셨나요?" `[검증 대상: P]` | "상담방에서 뭘 답해야 할지 몰라서 답장을 미루셨죠?" | 문제를 먼저 말해주고 동의만 받는다 — 어떤 응답이 와도 근거가 안 된다 |
| "그때 어떤 정보를 보고 결정하셨나요?" `[검증 대상: P]` | "정보가 부족해서 불편하지 않으셨어요?" | 부정 경험을 전제하고 묻는다 — '네'는 예의상 동의일 수 있다 |
| (시안 제시 후) "이 화면에서 무엇이 보이시나요? 다음에 뭘 하실 것 같으세요?" `[검증 대상: S]` | (시안 제시 후) "이렇게 미리 알려주면 답장하기 훨씬 쉬울 것 같지 않나요?" | 기대 답을 문장에 심었다 — UT가 아니라 설득이다 |

## 4. I3 — 분석 요령 (계약 §3-14)

I3은 6열 표: `#` / `발화 인용` / `해석` / `매핑` / `강도` / `비고`.

- **발화 단위로 추출한다.** 요약이 아니라 transcript 원문 인용 — 해석은 3열에서 따로 한다.
- **PII는 원문 출력하지 않는다** — 위치만 말하고 `[마스킹]` (진행 원칙 승계).
- **매핑 4분기**: `G2 V4(문제 검증)` / `G5 UT·인터뷰(솔루션 반응)` / `반증` / `신규 발견`. 질문의 `[검증 대상]` 태그가 매핑의 1차 근거다.
- **강도는 "N명 중 M명"을 병기한다** — `강`/`중`/`약`만 쓰지 않고 "5명 중 4명 동일 취지"처럼 분모를 남긴다.
- **반증 은폐 금지**: 가설을 지지하지 않는 발화도 반드시 추출한다. 반증은 실패가 아니라 **Counter Rationale·C 하향의 재료**다 — 숨긴 반증은 실험 실패 후에 더 비싸게 돌아온다.
- **신뢰 주석(비고)**: 유도 질문에 의한 응답인지, 자발적 언급인지 기록한다. 유도 후 동의는 강도를 올리는 데 쓰지 않는다.

**그루밍 반영 요약** (표 아래, 나눠서 출력):

| 반영처 | 내용 |
|---|---|
| G2 V4에 추가할 행 | 문제 검증 발화 — 근거유형 `실측`, 강도·출처(인터뷰 회차·일자) 병기 |
| G5에 추가할 행 | 솔루션 반응 발화 — 유형 3(UT·인터뷰), 출처 3단계 표기 |
| Counter Rationale 재료 | `반증` 매핑 발화 — 실패 시나리오·무너질 지표로 번역 |
| 신규 발견 | 별도 가설감이면 `cro-hypothesis-backlog`로 라우팅 — 이 스킬은 채번하지 않는다 |

**UT 결과 정리 3-Step** (푸드케어 UT 설계서 템플릿 정본): 기획(Step 1: 문제 구체화→퍼소나→리크루팅→시나리오·미션→세부 스크립트) → 진행(Step 2: 인터뷰이 신상 요약·실시간 관찰 기록·사후 인터뷰) → **결과 정리(Step 3: 영상 / 주요 코멘트·반응 / 인사이트)**. I3 분석 표는 Step 3의 "주요 코멘트·반응"과 "인사이트"를 그루밍 근거 형식으로 구조화한 것이다 — transcript 대신 Step 2 관찰 노트를 붙여넣어도 같은 절차로 분석한다.

## 5. 다른 파일과의 연결

- `validation-guide.md` §3의 V4 근거 어휘 중 **"고객 인터뷰" 경로의 실행 가이드가 이 파일**이다. I3의 V4 추가 행이 G2의 판정(강/중/약) 재료가 된다.
- 솔루션 반응 발화는 `rationale-target-guide.md` §1의 유형 3(UT·인터뷰)으로 들어간다 — C 밴드 기여는 그쪽 규칙을 따른다.
- 인터뷰로도 Baseline·정량이 채워지지는 않는다 — 정량은 `uplift-calc.md`·`validation-guide.md`의 골트리/실쿼리 경로다.
