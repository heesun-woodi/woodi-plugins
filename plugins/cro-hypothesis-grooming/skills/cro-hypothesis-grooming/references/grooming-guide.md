## 1. 그루밍의 정의 (계약 §0)

> **"가설의 근거를 탄탄하게 하여 ICE 점수를 높여서 스프린트 열차에 탈 우선순위라는 것을 주장하기 위해"**

그루밍은 **가설 문장을 바꾸는 작업이 아니라 같은 가설의 점수를 올리는 작업**이다.

**가설 문장 불변 원칙 (계약 §2-3·§5)**

- 문장에 손대는 것은 DEC-005 이관 정리까지 — 이관 5항목(`형태 분리` / `태그 제거` / `대괄호 정리` / `공급자 묘사 치환` / `중복 축약`)만 허용.
- 걷어낸 솔루션 형태는 **Variant 후보**로 분리한다 (`VAR-{HYP 숫자부}-{a,b,…}` 임시 표기).
- 문제·가치·지표가 달라지면 이관이 아니라 **새 가설**이다 → `cro-hypothesis-backlog`로 라우팅.
- "문장을 더 좋게 다시 써달라"는 요청에는 이관 항목 해당분만 처리하고 의미 변경은 거절한다.

## 2. PSR → ICE 영향 매핑 (계약 §0-1 정본)

그루밍의 모든 근거 작업은 이 매핑을 통해 점수로 번역된다. G6(ICE 전후 대조)의 `변화 사유`는 반드시 이 표의 경로 중 하나를 지목한다.

| # | PSR 요소 | → ICE 축 | 무엇이 점수를 움직이나 | 그루밍 단계 |
|---|---|---|---|---|
| M1 | **P**roblem | **Impact** | 진짜 문제로 느끼는 유저의 크기(트래픽) + 얼마나 진짜인가(정량 Gap·정성 근거) | ② Validation |
| M2 | **R**esult | **Impact** | 목표 Result 달성 시 비즈니스 지표 개선 영향도 — **Uplift 인과 사슬**: 정량 분석(Gap·트래픽) → Target 달성 가정 → 잔여 퍼널 통과 → **최종 KPI(계약) 증분 금액** → 이 값으로 Impact 판단. **양 축 모두 금액까지 간다** (DEC-007 · 계약 §3-4) | ② Validation |
| M3 | **R**esult | **Confidence** | 목표 Result **값**에 대한 근거의 품질 (= hb §7-4a Target 타당성) | ⑤ Target |
| M4 | **S**olution | **Confidence** | 솔루션 성공에 대한 근거의 **품질과 양** (Rationale 7유형) | ④ Rationale |
| M5 | **S**olution | **Ease** | 솔루션 구현에 필요한 자원(인력·시간) — 대안 솔루션·MVP 축소 | ③ Description |

## 3. 그루밍 5단계 (KB 04 §6)

| 단계 | 무엇을 하나 | 산출물 | 올라가는 ICE 축 |
|---|---|---|---|
| **① Problem Definition** | 고객 언어로 문제 재정의 | 고객 언어 문제 문장 | (전 항목의 전제) |
| **② Problem Validation** | 진짜 문제 + 비싼 문제 근거 확보 | 정성·정량 근거 + Uplift 시뮬레이션 | **Impact ↑** |
| **③ Solution Description** | 대안 솔루션 2개 이상 아이데이션 | 대안 솔루션 목록 | Ease ↑ (더 쉬운 대안 발견 시) |
| **④ Solution Rationale** | 솔루션이 통할 근거 확보 | 근거 유형별 레퍼런스 | **Confidence ↑** |
| **⑤ Result / 목표수치** | Result 지표 확정 + 향상 목표 설정 | Baseline → Target | Impact ↑ (목표 근거 품질) |

**① Problem Definition.** 주어가 지표(전환율·이탈률)·회사·"우리"면 공급자 언어다. 주어를 이 가설의 사용자(고객 또는 설계사)로, 서술어를 "~못 한다 / ~모른다 / ~느낀다"로 되돌린다. 백로그를 통과한 가설은 대부분 이미 고객 언어다 — 이 단계는 재작성이 아니라 확인이며, 문장 불변 원칙(§1)이 우선한다.

**② Problem Validation.** "진짜 문제고 비싼 문제"의 근거를 V1~V5 5차원으로 채운다(→ `validation-guide.md`). 진짜 근거는 정성(V4)+정량(V1~V3), 비싼 근거는 Uplift 시뮬레이션(V5, → `uplift-calc.md`)이다. 이 단계의 최종 금액이 매핑 M2를 타고 Impact 근거값이 된다.

**③ Solution Description.** 그루밍 기준은 **문제당 솔루션 3개(대안 2개 이상)**. 첫 솔루션이 Ease에서 막혔을 때 대안이 없으면 문제 자체가 백로그에서 사라진다. 대안이 있으면 문제를 살린 채 솔루션만 갈아탄다. 대안이 별도 가설로 분화하면 백로그 스킬로 라우팅 — 이 스킬은 채번하지 않는다.

**④ Solution Rationale.** 솔루션이 이 문제를 해결하는 데 얼마나 검증된 방법인지 7유형 근거로 채운다(→ `rationale-target-guide.md`). Counter Rationale(실패 시나리오 + 무너질 지표)과 Guardrail 후보까지가 한 세트다. ③과 ④는 실무에서 왕복한다 — 근거를 찾다 새 솔루션이 떠오르면 ③에 추가한다.

**⑤ Result / Target.** Result 지표는 골트리 노드 1개(문자 일치). Target을 3법(벤치마크 / MDE 근사 / 내부 Gap) 중 하나로 확정하고 산출 근거를 병기한다(→ `rationale-target-guide.md`). Uplift 낙관 시나리오와 Target은 일치해야 한다.

## 4. 축약 경로 — 시간이 부족하면 ②와 ④ 우선

**②(Impact 근거)와 ④(Confidence 근거)가 ICE 점수를 가장 크게 움직인다** (KB 04 §6 Step 5). 세션 시간이 부족하면 이 둘을 우선한다.

- G0의 `경로` 필드에 기록: `전체 5단계` 또는 `축약 ②+④`.
- 축약 경로에서도 하드 게이트는 그대로다: Baseline 미확정이면 G3(Uplift)을 출력하지 않고, 참가자 재점수 전에는 G6 스킬 제안을 내지 않는다.
- 축약으로 건너뛴 단계(③ 대안·⑤ Target 정밀화)는 완료 판정(계약 §9)에서 걸린다 — 미충족분은 종료 경로 표에 담당·해소 조건과 함께 남기고 종료한다.

## 5. Ease 최적화 — MVP 축소의 경계 (매핑 M5)

솔루션이 너무 어렵다고 판단되면 MVP 관점에서 재설계해 Ease를 올린다. 단, **검증 대상 자체를 빼면 안 된다.**

| 구분 | 정의 | 처리 |
|---|---|---|
| **Must have** | 가설 검증에 반드시 필요한 요소 — 이것이 빠지면 실험 결과가 가설에 대해 아무것도 말해주지 않는다 | 남긴다 |
| **Won't have** | 빼도 검증 가능한 요소 (개인화 로직·부가 기능·완성도 치장) | 뺀다 — 여기서 Ease가 올라간다 |

- 구현·QA 난이도가 낮은 지면을 실험 대상으로 잡는 것도 Ease를 올리는 방법이다.
- 축소 결과는 Variant 후보·G7a `1-3` 서술로 남긴다. **Ease 점수 자체는 스킬이 추정하지 않는다** — 담당자 답 기반 (계약 §7-9).

## 6. 워크드 예시 — 그루밍 전후 ICE 변화 (KB 05 예시 1 압축)

가설(익명화 — 구독형 커머스): "콘텐츠로 처음 유입된 신규 사용자에게 Best 3 콘텐츠를 적극적으로 추천하면 신규 사용자 평균 콘텐츠 조회수가 30% 증가할 것이다"

| 축 | 그루밍 전 | 그루밍 후 | 무엇이 바뀌었나 (매핑 경로) |
|---|---|---|---|
| I | 4 — "신규 유입이 꽤 있는 것 같다", 실측 없음 | 8 — 신규 UV 실측 + 해당 구간 이탈률 퍼널 최대 + Uplift 3시나리오 | M1·M2 (② Validation) |
| C | 3 — "추천은 보통 잘 되니까", 레퍼런스 없음 | 7 — 동종 3곳 채택 스크린샷 + 전술 원리 + 자사 유사 실험 | M4 (④ Rationale) |
| E | 7 — 실험툴 구현 가능할 것 같음 | 8 — MVP 축소: 개인화 알고리즘을 빼고 고정 Best 3로 실험툴 단독 구현 | M5 (③ MVP 축소) |
| **합** | **14** — QuickWin 아님 → 스프린트 탈락 | **23** — QuickWin (ICE ≥ 21) → 스프린트 배정 | |

**변한 것은 근거뿐이다. 가설 문장은 한 글자도 바뀌지 않았다.** 이것이 그루밍의 정의다.
