# cro-hypothesis-backlog

**문제정의 리스트를 입력받아 솔루션 아이데이션 → PSR 가설 → 1차 ICE → 가설 백로그 v1을 만드는 클로드 스킬입니다.**

문제정의가 확정된 다음 단계입니다. "무엇이 문제인가"가 이미 T4 리스트(또는 repo의
`problem-definitions-{A|B}.md`)에 담겨 있어야 합니다. 이 스킬은 그 리스트를 입력으로 받아
"어떻게 고칠 것인가"(솔루션)와 "왜 될 것인가"(Rationale) → PSR 가설 한 문장 → 1차(잠정)
ICE 점수 → 백로그 v1 표를 순서대로 만듭니다.

개발 지식은 전혀 필요 없습니다. 클로드가 **한 번에 하나씩** 물어보고, 여러분은 답만 하시면
됩니다.

### 두 가지 사용자 관점을 모두 다룹니다

| 사용자 | 문제 문장 | 시트 위치 |
|---|---|---|
| **고객** | 고객은 이 화면에서 ~를 못 한다/모른다/느낀다 | `A축_문제정의` / `B축_문제정의` 탭의 문제정의 리스트 (`PR-*`) |
| **설계사** | 설계사는 ~가 없어 ~를 못 한다 | `B축_문제정의` 탭의 **설계사 관점** 섹션 (`SP-*`) |

**설계사도 이 가설의 사용자입니다.** 카톡으로 고객을 응대하는 설계사가 자기 도구·화면(상담방
설계사 뷰·어드민·템플릿 발송 화면)에서 겪는 문제를 그대로 가설의 P로 세웁니다. 고객 문제의
원인이나 구현 제약으로 밀어넣지 않습니다 — 절차·공식은 같고 주어만 바뀝니다.

## 1. 설치

클로드 세션에 아래를 **한 줄씩 순서대로** 입력하세요.

**① 마켓플레이스 추가**

```
/plugin marketplace add heesun-woodi/woodi-plugins
```

**② 플러그인 설치**

```
/plugin install cro-hypothesis-backlog@woodi-plugins
```

**③ 확인**

```
/plugin
```

목록에 `cro-hypothesis-backlog`이 보이면 끝입니다.

> 로컬 폴더로 받으신 경우에는 ① 대신 폴더 경로를 넣으세요:
> `/plugin marketplace add /Users/본인계정/claude-cowork/woodi-plugins`

## 2. 첫 실행

설치가 끝나면 새 대화창을 열고 이렇게만 입력하세요.

```
가설 백로그 시작
```

"솔루션 아이데이션 시작"도 동일하게 작동합니다.

## 3. 준비물 — 세션 전에 챙기세요

| # | 준비물 | 설명 |
|---|---|---|
| ① | **문제정의 리스트 행 (15열)** | 시트 `A축_문제정의` / `B축_문제정의` 탭(고객 관점) 또는 **설계사 관점 섹션**에서 복사 — 또는 repo의 `problem-definitions-{A\|B}.md`에서 복사. **근거 칸(트래픽·Gap·심각도 근거, CRO 항목)까지 함께 복사**하세요, 솔루션 재료로 씁니다. 시트 4열 **`솔루션 아이디어`(`[적용 전술] 솔루션 한 줄`)** 도 함께 복사하면 STEP 1 아이데이션의 **1번 후보(씨앗)** 로 먼저 올라갑니다 — **비어 있어도 그대로 진행됩니다** |
| ② | **해당 화면 스크린샷** | 고객 가설이면 고객이 보는 화면, **설계사 가설이면 설계사가 보는 화면**(상담방 설계사 뷰·어드민). 근거 칸에 이미 화면 전사가 있으면 그것으로 대체 가능합니다. **카톡·설계사 화면 모두 PII(이름·전화번호·증권번호) 마스킹 먼저.** |
| ③ | **백로그 파일의 현재 최대 HYP 번호** | `hypothesis-backlog-{A\|B}.md`에서 가장 큰 번호 확인 — 스킬이 그 다음 번호부터 부여합니다 (예시 형식 `HYP-EX-*`은 제외) |
| ④ | **Ease를 답할 담당자 감각** | 구현 소요 워킹데이 기준 — 스킬이 추정하지 않고 여러분에게 묻습니다 |

## 4. 무엇이 나오나요

| STEP | 하는 일 | 나오는 표 | 착지 |
|---|---|---|---|
| STEP 0 | 인테이크 — 축·문제정의 리스트·스크린샷·최대 HYP 번호 확인 | — | — |
| STEP 1 | 솔루션 아이데이션 (BIAS 전술 매핑) | **H1 솔루션 카드 (7열)** | 대화에만 |
| STEP 2 | Rationale 확보 및 데스크리서치 | **H2 Confidence 근거 (5열)** | 대화에만 |
| STEP 3 | PSR 가설 조립 | **H3 PSR 조립 (6열)** | 대화에만 |
| STEP 4 | 개인 스코어링 완료 확인 후 1차 ICE | **H4 1차 ICE (9열)** | 대화에만 |
| STEP 5 | 백로그 v1 정리 | **H5a 백로그 메인 표 (6열)** + **H5b 가설 상세 섹션** | `hypothesis-backlog-{A\|B}.md` |

**착지 파일**: `habitfactory-cro-ssot/30_deliverables/hypothesis-backlog-A.md` / `hypothesis-backlog-B.md`.
H5a·H5b를 서기에게 전달하면 세션 마감 시 서기가 repo에 커밋합니다.

| 표 | 시트·파일 이식 |
|---|---|
| H1~H4 | 대화 기록만 — 파일에 남기지 않음 |
| H5a | 백로그 메인 표에 행 추가 |
| H5b | 같은 파일의 `### {HYP ID}` 섹션으로 추가 |

## 5. 알아두실 것

### 클로드가 거절하는 것

| 요청 | 클로드 응답 |
|---|---|
| ICE 점수를 곱셈 또는 평균으로 계산해 달라 | 합산식(최대 30)만 허용 — 다른 공식 출력 안 함 |
| Variant 문구안 A/B/C를 뽑아 달라 | Variant는 그루밍 이후 Sprint 1 소관 |
| Baseline·Ease를 스킬이 추정해 달라 | Baseline은 골트리 노드 실측값 사용, Ease는 담당자에게 직접 물음 |
| 그루밍·Uplift 시뮬레이션·실험 설계 | Sprint 1(8/17~) 소관 |
| 스킬 점수를 팀 ICE 점수로 바로 확정해 달라 | 개인 스코어링 → 분산 확인 → 조정 토론이 정본 절차 |
| 개인 스코어링 전에 ICE 점수를 먼저 보여 달라 | 앵커링 방지 게이트 — 스코어링 완료 확인 후 출력 |

### ICE 공식 (정본)

```
ICE = Impact + Confidence + Ease   (각 1~10점 합산, 최대 30점)
QuickWin = ICE ≥ 21   또는   (ICE ≥ 15 AND Ease ≥ 8)
```

Impact는 문제정의 리스트의 점수를 **그대로 이관**합니다. 스킬이 재계산하지 않습니다.

### 점수가 비어도 백로그에 올라갑니다

Impact를 잴 수 없거나(로깅 부재 등) Ease를 그 자리에서 답할 수 없으면, 스킬은 **추정하지 않고
공란으로 둡니다.** 이때 `ICE 합`과 `QuickWin`은 `-`로 표기되고 상세 섹션에 "무엇이 왜 비었는지"가
한 줄 남습니다. **점수가 없다는 사실 자체가 다음 주 그루밍의 첫 번째 할 일**이므로 가설은 그대로
백로그에 올립니다.

## 6. 폴백 — 잘 안 될 때

| 증상 | 대응 |
|---|---|
| 스킬이 안 뜬다 | "가설 백로그 시작" 대신 **"cro-hypothesis-backlog 스킬로 가설 백로그 만들어줘"** 라고 명시 |
| 그래도 안 뜬다 | `04c_psr-ideation-prompt-cards.md` 카드 5장으로 동일 산출물(H1~H5b)을 만들 수 있습니다 |
| 대화가 길어져 느려졌다 | 새 창을 열고 확정된 H3 표와 H2 표를 붙여넣은 뒤 **"STEP 4부터 이어서"** |
| 골트리 노드 이름이 맞지 않는다 | `data/goal-tree-nodes.json`의 `name` 필드와 **문자 단위 일치** 필요 — 스킬이 매핑 불가 노드명을 알려줍니다 |
