## 1. Rationale의 역할

Rationale은 ICE의 **Confidence(C) 점수의 근거값**이다. 근거가 없으면 Confidence는
1~3점을 넘을 수 없고, 그 가설은 스프린트에 타지 못한다. STEP 2는 솔루션마다
근거를 찾고, H2(Confidence 근거 표)에 채우는 단계다.

## 2. Rationale 근거 6유형 + Confidence 기여도

| 근거 유형 | 확보 방법 | Confidence 기여 |
|---|---|---|
| **경쟁사 UX** | 업계 1위 또는 다수 경쟁사가 같은 패턴을 쓰는지 조사. 스크린샷으로 증거 남김 | 다수 채택 = 높음 |
| **지식 레퍼런스** | 실험 플랫폼 벤더 성공 사례집, 공개 케이스 스터디, 업계 벤치마크 리포트 | 수치 있는 케이스 = 중~높음 |
| **행동경제학 근거** | 적용한 전술의 원리와 대표 연구. 소비심리학·인지과학 논문 | 이론만 있으면 중간 |
| **자사 과거 실험** | 같은 지면 또는 유사 지면의 과거 실험 결과. 실패 실험도 근거가 됨 | 자사 데이터 = 가장 높음 |
| **UT/정성** | 솔루션 시안을 사용자에게 보여주고 반응 관찰. 5명이면 충분 | 직접 관찰 = 높음 |
| **담당자 과거 경험** | 담당자가 이전 조직·다른 지면에서 해본 결과 | 기억 수준이면 낮음 |

최소 1개 유형을 채운다. **정량 근거(벤치마크 Gap 또는 유사 실험 개선율)를 최소 1건
포함**하는 것을 목표로 한다.

## 3. 데스크리서치 절차

### 3-1. 도메인 우선순위

아래 순서로 탐색한다. 앞 도메인에서 사례가 나오면 뒤 도메인은 보충으로 쓴다.

1. **보험** — 보험 비교·진단·다이렉트 가입 서비스
2. **핀테크** — 자산관리·대출 비교·마이데이터 기반 진단 서비스
3. **상담형·대화형 서비스** — 채팅 상담, 폼 분할 입력, 온보딩 문진 UX
4. **일반 커머스·SaaS** — 위에서 못 찾았을 때, 같은 전술의 사례로 한정

### 3-2. 사례 기록 형식 (사례당 1행)

사례마다 아래 5개 항목을 모두 기록한다. 하나라도 비면 그 사례는 근거로
쓰지 않는다.

| 항목 | 내용 |
|---|---|
| 서비스명 | 공개된 서비스 이름 |
| 어떤 화면·흐름인지 | 어느 지면에서 어떤 패턴을 적용했는가 |
| 우리 솔루션과 같은 점 / 다른 점 | 유사성과 맥락 차이를 모두 적는다 |
| 출처 URL | 실제로 열어 확인한 URL만 기재 |
| 확인일 | YYYY-MM-DD 형식 |

**민감정보 화면(보험·병력·개인정보 입력 등)의 사례는 그 서비스가 어떤 안심
장치(개인정보 고지, 진행률 표시, 보안 배지 등)를 함께 배치했는지를 반드시
함께 기록한다.**

### 3-3. 출처 확인 3단계

출처 처리는 아래 3단계로 구분한다. **웹 검색은 스니펫만 제공하므로, URL을 인용하려면 해당 페이지를 실제로 열어 확인해야 한다.**

| 상태 | H2 출처 칸 표기 | C 밴드 반영 |
|---|---|---|
| ① 페이지를 실제로 열어 확인 | `URL + 확인일 (YYYY-MM-DD)` | 정상 반영 |
| ② 검색 결과 요약에만 등장, 원문 미확인 | `2차 인용 — 원문 미확인` | 반영하되 **밴드 하단** |
| ③ 찾지 못함 | `확인되지 않음` | 미반영 |

- 그럴듯하지만 존재하지 않는 URL이 섞이는 것이 이 단계의 가장 흔한 실패다.
- "업계 평균 OO%" 같은 수치는 출처와 조사 시점이 함께 없으면 근거로 쓰지 않는다.

### 3-4. "확인되지 않음" 처리

찾지 못한 사례는 **"해당 도메인에서 확인되지 않음"이라고 그대로 기재**한다.
없는 사례나 수치를 지어내지 않는다. 사례가 1건도 없는 것 자체가 정보다 —
그 솔루션의 Confidence가 낮다는 신호다. 단, **외부 사례를 못 찾았다는 이유만으로 1~3점 밴드로 내리지 않는다**. 적용한 전술의 행동경제학 원리를 명시할 수 있으면 4~6 밴드 하단이 기준이다. 원리조차 제시하지 못하거나 직관 수준이면 1~3점 밴드다.

### 3-5. 웹 검색 불가 시 폴백

웹 검색이 불가능하거나 사례를 찾지 못했을 때, 다음 순서로 폴백한다.

1. **참가자가 이미 아는 사례를 묻는다** — "비슷한 패턴을 본 서비스가 있나요?
   어떤 화면이었나요?" 참가자의 구술값은 근거 유형 `담당자 과거 경험`으로 기록한다.
2. **자사 과거 실험을 확인한다** — 같은 지면 또는 유사 지면의 실험 결과가 있는지
   확인한다. 실패 실험도 근거가 된다.
3. 둘 다 없으면 **행동경제학 원리만** 근거로 쓰고, Confidence는 4~6점 **밴드 하단**으로 매긴다. 원리조차 제시하지 못하면 1~3점 밴드다.

## 4. C 앵커 밴드 — 근거 조합과 Confidence 범위

H2 표의 마지막 열 `C 앵커 밴드(제안)`은 아래 기준으로 제안한다.
**제안일 뿐, 확정은 팀 개인 스코어링이 한다.**

| C 밴드 | 해당하는 근거 조합 |
|---|---|
| **10** | 검증된 자사 데이터 + 경쟁사 대부분 채택 + 성공 경험 |
| **7~9** | 경쟁사 벤치마크 강함, 신뢰할 만한 레퍼런스 다수 (데스크리서치 3곳 이상) |
| **4~6** | 경쟁사 1~2곳 채택, 또는 케이스 스터디·행동경제학 이론 수준 |
| **1~3** | 근거 부족·직관 수준 — **합성 인터뷰만 있으면 여기가 상한** |

**적용한 전술의 행동경제학 원리를 명시할 수 있으면 4~6 밴드 하단**이다. 외부 사례를 못 찾았다는 이유만으로 1~3으로 내리지 않는다. **1~3은 합성-only, 직관, 원리조차 제시 못 하는 경우**다.

**합성 인터뷰만 있는 가설**: Confidence는 1~3점을 넘지 않는다. 이 규정은
`03b_synthetic-interview-kit.md` §0에서 비롯되며 협상 대상이 아니다. 합성 근거를
근거 유형에 기입했을 때 워크숍에서 Confidence 7점 이상을 주장하면 코치가 `03b` §0을
상기시킨다.

밴드는 점수 확정 전 방향 판단에만 쓴다. ICE 스코어링의 확정 규칙은 `ice-scoring.md`
소관이며 이 파일은 다루지 않는다.

## 5. Counter Rationale — 형식과 판정 기준

Counter Rationale은 "이 솔루션이 안 통할 시나리오와 그때 무너질 지표"다.
가설당 **1개 이상** 필수이며, Counter Rationale이 없는 설계서는 Sprint 1 그루밍
리뷰에서 Critical 처리된다.

**형식**:

```
{실패 시나리오 한 줄} → {무너질 지표}를 Guardrail 후보로 관찰
```

예시:
- "정보 항목 수를 미리 알려주면 오히려 '이렇게 많아?'로 읽혀 첫 응답률이 떨어질 수 있다 → 첫 응답률을 Guardrail 후보로 관찰"
- "리뷰 슬라이더가 상단 공간을 차지해 가격·옵션 인지가 밀리면 전환이 떨어질 수 있다 → 스크롤 깊이·옵션 선택률을 Guardrail 후보로 관찰"

**반려 기준**: "효과 없을 수 있다" 또는 "고객 반응이 예상과 다를 수 있다" 수준은
Counter Rationale로 인정하지 않는다. **무너질 지표를 명시**해야 한다. 지표가 없으면
무너졌을 때 무엇을 보아야 하는지 알 수 없다.

**Guardrail ≠ Result**: Counter Rationale에서 지목한 무너질 지표가 그 가설의 R과 같으면, **한 단계 뒤 지표**로 밀어 지목한다. 예: R이 진입률이면 Guardrail은 완료율. 측정 불가 노드를 Guardrail로 지목할 때는 `세팅 의존성`을 병기한다.

**보조 경로 — 참가자가 "그냥 효과 없을 수도 있죠"에서 막힐 때**: "어느 숫자가 먼저 나빠질까요?"만으로 부족하면, 스킬이 구체적 실패 시나리오를 1~2개 먼저 제시하고 참가자는 무너질 지표만 고른다.

> **예시 문답**
>
> 스킬: "두 가지 시나리오 중 어느 쪽이 가능성 있어 보이나요?
> ① 안내 문구가 오히려 '이렇게 많아?'로 읽혀 첫 응답률이 떨어진다
> ② 안내 문구를 보고 부담을 느껴 대화창을 닫는 비율이 오른다
> 어느 쪽이든 — 그때 먼저 나빠지는 지표가 Guardrail 후보입니다."
>
> 참가자: "①이 가능성 있어 보여요."
>
> 스킬: "그러면 첫 응답률을 Guardrail 후보로 기록합니다 — R(정보 입력 완료율)과 다른 지표니 적합합니다."

## 6. 15분 타임박스와 그 이유

Rationale 찾기에 **15분 타임박스**를 건다. 경쟁사 2~3곳 스크린샷 + 벤치마크
수치 1개면 충분하다. 완벽한 근거를 찾으려다 아이데이션이 멈추는 것이 더 큰
손해다. 이 단계는 "확신을 얻는 시간"이 아니라 "현재 아는 것을 기록하는 시간"이다.

근거가 부족하면 Confidence가 낮게 나오는 것이 정상이고, 낮은 Confidence를
인지한 채 우선순위를 논의하면 된다. 근거를 채우는 것은 Sprint 1 그루밍 과제다.

## 7. 환각 방지 — 절대 규칙

- **존재하지 않는 사례·수치·URL을 생성하지 않는다.** 그럴듯해 보이는 링크가
  실제로 없는 경우가 가장 흔한 실패다.
- **불확실한 것은 "확인되지 않음"이라고 그대로 쓴다.** 이 표현이 있는 행은
  근거 부족의 정직한 신호로 Confidence 밴드에 반영한다.
- 수치를 추정해서 채우지 않는다. Baseline이 없으면 `[Baseline 미확보 — Sprint 1 실측]`
  으로 남긴다.
- "고객에게 좋을 것 같아서"는 근거가 아니다. 출처가 붙지 않은 문장은 H2 표에
  올리지 않는다.

## 8. H2 표 연결 — 5열 구조

열 이름·순서는 `hb-output-contract.md` §3과 문자 단위로 동일하다.

| 열 | 이름 | 내용 |
|---|---|---|

| 5 | C 앵커 밴드(제안) | `1~3` / `4~6` / `7~9` / `10` — 제안, 확정은 사람 |

## 9. 설계사 가설의 근거 유형 매핑

설계사 문제(SP-N 계열)는 외부 벤치마크가 거의 잡히지 않으므로 Confidence가 낮게 나오는 것이 정상이다.

| 근거 자료 유형 | 6유형 분류 |
|---|---|
| 매니저 자료·상담 전사·설계사 인터뷰 | UT/정성 |
| 설계사 구술(담당자가 말해준 과거 경험) | 담당자 과거 경험 |
| 설계사 그룹 간 성과 격차 데이터 (자사 측정치) | 자사 과거 실험 |

설계사 도구(어드민·상담방 설계사 뷰) 개선은 경쟁사 사례 조사가 거의 불가능하다. Confidence가 4~6 밴드 하단으로 모이는 것은 정보 부족이 아니라 영역 특성이며, **그 자체가 Sprint 1 그루밍 과제다** — 현장 인터뷰·어드민 기능 확인으로 밴드를 올리거나, 낮은 C를 인지한 채 실험 설계를 단순화한다.
