## 2. 입력 규격 — 문제정의 리스트 정규화

스킬의 입력은 문제정의 리스트 행이며, 두 형식을 모두 수용해 아래 공통 필드로 정규화합니다. 정규화 결과를 참가자에게 "이렇게 읽었습니다"로 확인받은 뒤 진행합니다.

| 공통 필드 | 시트 T4 (14열, `pd-output-contract.md` §2) | repo 8열 (`problem-definitions-{A\|B}.md`) | 없을 때 |
|---|---|---|---|
| 문제ID | `문제ID` (예: PR-01) | `ID` (예: PR-B-01) | 필수 — 없으면 진행 불가 |
| 화면/구간 | `화면` | `구간` | 참가자에게 질문 |
| 고객 문제 | `고객 문제` | `고객 문제` | 필수 — 없으면 진행 불가 |
| BIAS 단계 | `BIAS 단계` + `BIAS 항목` | `BIAS` (예: `Act A2` — 단계+항목ID 결합) | 참가자에게 질문 |
| 트래픽 점수 | `트래픽 점수` | `트래픽` | 공란 + `코치 확인 필요` |
| Gap 점수 | `Gap 점수` | `Gap` | 공란 + `코치 확인 필요` |
| 심각도(가중) | `심각도(가중)` | `심각도` | 공란 + `코치 확인 필요` |
| Impact | `Impact` | `Impact` | 아래 규칙 |
| 근거유형 | `근거유형` (관측/정성/관측+정성) | 없음 — **참가자에게 질문** (실측/합성/혼합) | 참가자에게 질문 |

- **Impact가 비어 있으면** (04a 2-1): 참가자에게 즉석 근거 한 줄을 요청해 세 점수를 받아 산식대로 계산하고 **`추정` 표시**를 남깁니다. 스킬이 값을 지어내지 않습니다.
- 구 표기 매핑: 8/10 시트의 `PR-nn`은 repo의 `PR-{A|B}-nn`과 같습니다.

## 3. 표별 열 정의 (이름·순서 고정)

**표의 열 이름과 순서는 계약·스킬 출력 예시·착지 파일에서 문자 단위로 동일해야 합니다.**

### H1. 솔루션 카드 표 — 7열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 솔루션 ID | `SOL-01`, … (이 대화 한정 임시 ID) |
| 2 | 문제ID | 입력 리스트의 문제ID 그대로 |
| 3 | 적용 전술(단계) | 예: `⑩ Goal Gradient (Act)` — 전술 번호·이름·단계 |
| 4 | 솔루션(How) | 무엇을 **어떻게** 바꾸는가 — UI 형태·문구·트리거 시점까지. "개선한다" 금지 |
| 5 | Rationale 유형 | 6유형 중 해당 (경쟁사 UX / 지식 레퍼런스 / 행동경제학 / 자사 과거 실험 / UT·정성 / 담당자 경험) — 복수면 콤마 |
| 6 | Counter Rationale | 실패 시나리오 한 줄 + **무너질 지표** 지목 |
| 7 | MVP 메모 | MVP 축소 4문항 답 요약 (개발 의존 여부 포함) |

- 문제당 솔루션 **2개 이상** (행 2개 이상). 전술은 문제의 BIAS 단계와 일치해야 하며, 유일한 예외는 "긴급성 부재"(Act 문제 + Loss Aversion 차용)입니다.
- 솔루션이 화면 요소의 존재·부재를 전제하면, 그 전제는 **STEP 0.5 전사 결과 또는 입력 행의 근거 열**에서만 가져옵니다. 둘 다 없으면 해당 전제에 `확인 필요`를 답니다.

## 4. 표 출력 규칙

1. H1~H5a는 **마크다운 표로 대화에 렌더해** 출력합니다. 코드블록에 넣지 않습니다.
2. **유일한 예외 — H5b는 코드블록(raw markdown)으로 출력합니다.** H5b의 복사 대상은 시트 셀이 아니라 repo `.md` 파일이므로, 렌더된 상태가 아니라 원문 마크다운이 필요합니다. (형제 계약의 "코드블록 금지" 규칙은 시트 착지물 기준이며, 이 예외는 착지 매체 차이에서 나옵니다)
3. 표 바로 위 또는 아래에 착지 안내 한 줄 — 예: "H5a 행과 H5b 블록을 `hypothesis-backlog-B.md`에 옮길 수 있도록 서기에게 전달하세요."
4. 열 이름·순서는 3절과 문자 단위로 동일. 임의 추가·삭제·재배열 금지.
5. 셀 안 줄바꿈 금지 (콤마·슬래시·`→` 사용). PSR 전문도 한 문장 — 줄바꿈 금지.
6. 셀 첫 글자에 `=`·`+` 금지 (시트 수식 오인). 예: `+2 가중` ❌ → `가중 +2` ✅.

## 5. 문장·서술 형식 (정본)

**PSR 확장 공식** (KB `04_hypothesis-psr.md` — 이 공식만 사용):

```
"[영역/시점]에서 [문제]를 느끼는 [세그먼트]에게
 [솔루션 핵심가치]를 [솔루션 형태]로 제공하면
 [지표]가 [YY%] 개선될 것이다"
```

- **완결 기준**: 제3자가 이 문장만 읽고 추가 설명 없이 I/C/E를 매길 수 있어야 합니다.
- **솔루션 서술**: "개선한다" 금지 — How(UI 형태·문구·트리거 시점)까지. **Solution ≠ Variant**: 같은 솔루션의 문구안 A/B/C는 Variant이며 이날 만들지 않습니다.
- **Counter Rationale 형식**: `{실패 시나리오 한 줄} → {무너질 지표}를 Guardrail 후보로 관찰`. "효과 없을 수 있다" 수준은 반려.
- **고객 언어**: P의 문제는 입력 리스트의 고객 문제 문장을 그대로 씁니다. 주어가 지표인 문장("~률이 낮다")이 오면 문제정의로 되돌립니다.

## 6. ID 체계

## 7. 공식 (정본 — 위반 금지)

```
ICE = Impact + Confidence + Ease     (각 1~10점, 합산, 총점 최대 30점)

QuickWin = ICE ≥ 21   또는   (ICE ≥ 15 AND Ease ≥ 8)
```

- **곱셈식·평균식은 어떤 형태로도 출력하지 않습니다.** 과거 문서에 다른 표기가 있으면 I/C/E 원 점수만 살려 합산으로 재계산합니다.
- **I = 입력 리스트의 Impact 점수 이관. 재계산 금지.** `문제 Impact 점수 = (트래픽 영향 + 벤치마크 Gap + 정성 심각도) / 3`은 문제정의 단계(`pd-output-contract.md` §6)의 공식이며, 이 세션은 그 결과값을 근거로 옮겨 적는 것입니다.
- **BIAS 가중은 한 번만, 심각도 경로로만** (04a 4-4 원문): 문제정의에서 이미 정성 심각도에 Block +2 / Interpret +1이 반영됐으면 → I에서 아무것도 더하지 않습니다. Impact가 없거나 가중 반영이 불명확하면 → **정성 심각도에 +2/+1을 더한 뒤(10점 캡) `/3`을 재계산**하고 그 사실을 I 근거에 적습니다. **Impact 총점에 직접 +2를 얹지 않습니다** (심각도 경로는 ÷3을 거치므로 +0.67 — 경로가 섞이면 채점자 간 1점 이상 벌어집니다).
- **합성 근거 상한**: Confidence 근거가 합성 인터뷰뿐이면 **C는 1~3점을 넘지 않습니다** (`03b` §0).
- **Ease는 스킬이 추정하지 않습니다.** 참가자(담당자)에게 워킹데이 기준으로 묻고, `E 근거` 첫머리에 `(잠정)`을 강제합니다. Sprint 1 플래닝에서 지원 부서가 재조정합니다.
- **앵커 기준표** (04a 4-4 해빗팩토리 적용판):

| 축 | 점수대 | 기준 |
|---|:-:|---|
| I | 10 / 5 / 1 | 지표 20%↑ 개선·트래픽 대 / 10% 개선·트래픽 중 / 5% 미만·트래픽 하 — 단 실제 값은 이관 |
| C | 10 | 검증된 자사 데이터 + 경쟁사 대부분 채택 + 성공 경험 |
| C | 7~9 | 경쟁사 벤치마크 강함, 신뢰할 만한 레퍼런스 다수 (데스크리서치 3곳 이상) |
| C | 4~6 | 경쟁사 1~2곳 채택, 또는 케이스 스터디·행동경제학 이론 수준 |
| C | 1~3 | 근거 부족, 직관 수준 — 합성 인터뷰만 있는 문제는 여기 |
| E | 10 / 7~9 / 4~6 / 1~3 | 당일 구현 / 2~3일 / 5일 이내 / 10일 이상 (워킹데이) |

- **스킬 점수의 지위**: 스킬의 I/C/E는 "그루밍 전 1차(잠정)" **보조 참고값**입니다. 팀 점수가 되지 않으며, 개인 스코어링 → 분산 확인 → 조정 토론(평균 금지)이 정본 절차입니다. 스킬은 참가자의 개인 스코어링 완료 확인 전에 점수를 출력하지 않습니다.

## 9. 완료 판정 체크 (8항목 — 04a §6)

1. PSR 가설(목표: 축당 3~4개)이 확장 공식 한 문장으로 쓰였는가
2. 모든 가설의 R이 골트리 노드에서 선택되었고 선행지표인가
3. 모든 문제에 솔루션이 2개 이상인가
4. 모든 가설에 Rationale 1개 이상 + Counter Rationale 1개 이상이 있는가
5. 제3자 ICE 테스트(교차 리뷰)를 사람이 수행했는가 (스킬은 안내만)
6. ICE가 합산식(최대 30)으로 계산되고 QuickWin 판정이 붙었는가
7. 모든 행이 "그루밍 전 1차(잠정)"이고 `E 근거` 첫머리에 `(잠정)`이 적혔는가
8. 분산 기록란(사람 기록)을 남기도록 안내했는가
