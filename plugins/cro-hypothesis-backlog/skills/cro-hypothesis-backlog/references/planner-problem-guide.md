## 1. 사용자 유형 판별

문제 문장의 **주어가 설계사(상담사)이면 설계사 유형**이다. ID는 `SP-*`. 시트 열 이름은 `설계사 문제`.

걸러야 할 것은 **주어가 지표·회사·"우리"인 문장**(`~률이 낮다`, `전환이 안 된다`)이지, 설계사 주어(`설계사는 ~ 못 한다`)가 아니다. 설계사 주어는 공급자 언어가 아니라 **설계사 유형의 정상 문제 문장**이다 (계약 §2-1).

> **설계사는 이 가설의 사용자다.** 고객 문제의 원인이나 구현 제약이 아니라, 카톡으로 고객을 응대하는 설계사가 자기 도구·화면(상담방 설계사 뷰, 어드민, 템플릿 발송 화면)에서 겪는 문제 그 자체가 P다. 화면은 설계사가 보는 화면, BIAS 단계는 설계사 여정의 실패 단계, PSR의 세그먼트는 설계사, R은 설계사 반응 지표다.

## 2. 설계사 여정의 BIAS 재판별

시트 설계사 섹션의 BIAS 칸(`관련 고객 문제 단계`)은 **짝지어진 고객 문제의 단계**이지 설계사 문제 자체의 단계가 아니다. 그대로 쓰면 전술이 엉뚱한 문제 기준으로 선정된다 (계약 §2-4).

설계사도 자기 도구 앞에서 주목→이해→행동→기억을 거친다. **판별 질문 4개**:

| 단계 | 판별 질문 |
|---|---|
| **Block** | 설계사가 봐야 할 정보나 상태가 화면에 아예 없어 인지 자체가 불가한가? |
| **Interpret** | 정보는 보이지만 그 의미·맥락을 해석하기 어려운가? |
| **Act** | 취해야 할 행동을 알지만 도구·수단·권한이 없어 행동 자체를 할 수 없는가? |
| **Store** | 경험·패턴·지식을 나중에 재사용하도록 기억·학습에 축적하지 못하는가? |

### SP-N1~N11 BIAS 재판별 표

| SP ID | 설계사 문제 (요약) | 시트 원값 (관련 고객 문제 단계) | 재판별 단계 | 판별 근거 |
|---|---|---|---|---|
| SP-N1 | 첫 메시지 조정 수단 없음 | Block | **Act** | 도구 제약으로 첫마디 조정 행동 자체를 취할 수 없다 |
| SP-N2 | 입력 멈춤 알림 없음 | Act | **Block** | 고객이 멈춘 사실이 설계사 화면에 아예 보이지 않아 인지 자체 불가 |
| SP-N3 | 정보 요청 메시지 구성 조정 불가 | Interpret | **Act** | 메시지 순서·강조를 바꾸는 행동을 취할 수단이 없다 |
| SP-N4 | 상위 성과자 패턴 열람 불가 | - | **Store** | 상담 패턴을 학습·축적할 채널이 없어 기억이 쌓이지 않는다 |
| SP-N5 | 개략 금액 산출 도구 없음 | Interpret | **Act** | 금액 산출 행동을 취할 도구가 없어 적절한 답변 불가 |
| SP-N6 | 마이데이터 연동 불가 | Act | **Act** | 연동 행동 자체를 취할 수 없다 (시스템 연동 부재) |
| SP-N7 | 장문 뒤 응답 유도 스크립트 없음 | Act | **Act** | 발화 행동을 이어갈 스크립트(수단)가 없다 |
| SP-N8 | 3줄 요약 양식 없음 | Interpret | **Act** | 요약 붙이는 행동을 할 양식(수단)이 없다 |
| SP-N9 | 고객 읽음·입력 중단 지점 비가시 | - | **Block** | 고객 상태가 설계사 화면에 존재하지 않아 주목 자체 불가 |
| SP-N10 | 메시지 순서·분량 조정 불가 | Block | **Act** | 메시지 순서를 바꾸는 행동을 취할 수단이 없다 |
| SP-N11 | 축소안 도구 없음 | Interpret | **Act** | 즉석 축소안 작성 행동을 취할 도구가 없다 |

> 시트 원값은 버리지 않는다. H5b `연결` 블록에 `관련 고객 문제 단계(시트 원값): {단계}`로 따로 보존한다 (계약 §3-7).

## 3. STEP 0.5 화면 게이트 — 대상이 바뀐다

고객 화면이 아니라 **설계사가 보는 화면**을 요청한다.

| 케이스 | 요청 대상 |
|---|---|
| 설계사 조작 화면이 있는 문제 (SP-N1·N3·N7·N10 등) | 상담방 설계사 뷰 / 어드민 / 템플릿 발송 화면 스크린샷 |
| 정보·상태가 아예 없어 화면이 존재하지 않는 문제 (SP-N2·N9 등) | "그 정보가 없다"를 보여주는 **현행 어드민 화면** 스크린샷 |
| 화면 확보 불가 | 기존 코치 승인 경로 (화면 없이 STEP 1 진행, `화면 미확보` 표기) |

**PII 주의**: 설계사 화면에는 고객 보험 정보·건강 정보가 그대로 노출된다. 고객 화면보다 오히려 더 민감하다. 마스킹 기준은 동일하게 적용한다.

## 4. R(결과지표) 선택

설계사 가설의 R은 **설계사 반응 지표**다 (계약 §7-7). 솔루션 바로 다음에 일어나는 반응이 설계사의 행동이기 때문이다. 하류 고객 퍼널 지표는 `기대효과` 서술과 Guardrail로만 다룬다.

`data/goal-tree-nodes.json`의 `user_type: "설계사"` 노드에서 고른다. 없으면 `[트리에 추가 필요 — Sprint 1 그루밍에서 논의]`.

이 노드들은 **골트리 정본 `02a_goal-tree.md` §3-1(B축 설계사 선행지표)에 2026-08-14 등재**돼 있다 — 스킬이 임의로 만든 목록이 아니다. 정본이 바뀌면 JSON도 함께 고친다.

> **세팅 의존성이 기본값이다.** 설계사 노드는 대부분 현재 미측정 상태다. `note`에 `세팅 의존성` 표기가 붙어 있는 노드는 Sprint 1 그루밍에서 측정 방안을 먼저 논의한 뒤 R로 확정한다. Baseline이 없다는 사실을 숨기지 않는다.

대응 고객 문제 링크(`대응 고객 문제: PR-xx`)는 R이 아니다. H5b `연결` 블록에 병기하고, 기대효과 서술에서 "이 설계사 지표가 움직이면 하류 고객 지표 PR-xx 구간이 따라 움직일 것으로 본다"는 인과 가설로만 쓴다.

## 5. PSR 조립 예시 2건

### SP-N1 — 첫 메시지 분기 템플릿

> "구간 ① 상담방 오픈 직후 고정 자동발송 메시지만 나가 유입 맥락에 맞는 첫마디를 조정할 수 없는 설계사에게, 유입 경로별로 분기되는 첫 메시지 템플릿 선택 기능을 상담방 어드민 화면에서 제공하면, 첫 메시지 템플릿 분기 사용률이 [Baseline 미확보 — Sprint 1 실측]으로 [YY%] 개선될 것이다"

| 요소 | 내용 |
|---|---|
| P | 구간 ① / 유입 맥락에 맞는 첫마디를 조정할 수단이 없는 설계사 (Act 실패) |
| S | 유입 경로별 분기 첫 메시지 템플릿 선택 기능 / 상담방 어드민 화면 |
| R | 첫 메시지 템플릿 분기 사용률 (goal-tree-nodes 설계사 노드 / 세팅 의존성) |

### SP-N7 — 장문 뒤 응답 유도 스크립트

> "구간 ② 상담 시작 후 장문 안내 발송 뒤 응답을 끌어낼 다음 마디를 찾지 못하는 설계사에게, 장문 말미에 붙일 단문 닫힌 질문 스크립트 3종을 어드민 템플릿 화면에서 선택·발송 가능하도록 제공하면, 상담사 질문형 마디 발송률이 [Baseline 미확보 — Sprint 1 실측]으로 [YY%] 개선될 것이다"

| 요소 | 내용 |
|---|---|
| P | 구간 ② / 장문 뒤 다음 마디를 찾지 못하는 설계사 (Act 실패) |
| S | 단문 닫힌 질문 스크립트 3종 / 어드민 템플릿 화면 선택·발송 |
| R | 상담사 질문형 마디 발송률 (goal-tree-nodes 설계사 노드 / 세팅 의존성) |

## 6. ICE 주의

**I** — 시트 SP 행의 Impact 점수를 그대로 이관한다. 재계산 금지 (계약 §7-2).

**C** — 근거 유형이 매니저 자료·상담 전사인 경우 6유형 중 `UT/정성` 또는 `담당자 과거 경험`으로 매핑한다.

**E** — 도구·시스템 솔루션은 개발 공수가 커서 Ease가 낮게 나오는 것이 정상이다. Ease가 낮다고 가설을 버리지 않는다 — 낮은 E 자체가 정보다. 대신 MVP 축소 4문항을 반드시 훑는다:

1. 어드민 개발 없이 운영 규칙만으로 검증 가능한가?
2. 기존 템플릿 교체·문구 수정만으로 검증 가능한가?
3. 설계사 1인 수작업 프로토콜로 검증 가능한가?
4. 최소 2주 내에 배포 가능한 범위로 좁힐 수 있는가?

4문항 중 하나라도 "예"이면 Ease를 상향 재고하고 MVP 메모에 명시한다.

## 7. 대응 고객 문제 링크 활용

시트 SP 행의 `대응 고객 문제: PR-xx`는 **P를 대체하지 않는다**. H5b 사용 규칙:

| 위치 | 역할 |
|---|---|
| H5b `연결` 블록 | `대응 고객 문제: PR-xx` 병기 |
| H5b `기대효과` 서술 | "이 설계사 지표가 움직이면 하류 고객 지표 PR-xx 구간이 따라 움직일 것으로 본다"는 인과 가설 |
| PSR의 R | 고객 퍼널 지표 사용 금지 — Guardrail 후보로만 |
